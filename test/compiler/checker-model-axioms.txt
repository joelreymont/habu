# What the checker models state, and what they rest on.
#
# One `theorem` row per published result in formal/Common/Effects.v and then in
# formal/Common/Control.v - every `Example` each file declares - in the order
# the files declare them, and in the order formal/_CoqProject builds them.
# Every `theorem` row is followed by exactly one `type` row and then by its
# assumption rows. The two files are read as one inventory because they are one
# model: Control.v opens with `From Habu.Common Require Import Effects`, so a
# statement in one can name anything in the other, and a single manifest asks
# Rocq one question about both.
#
# `Example` rather than `Theorem` is not a weaker claim. Rocq's `Example` is
# `Definition` with a proof script, so an `Example` closed with `Qed.` is a
# constant of exactly the stated type, and the ascription this gate generates
# type-checks against it the same way it does against a `Theorem`.
#
# There is one assumption row per result and it is always `closed`, which is
# Rocq reporting "Closed under the global context". Both models rest on
# nothing, so test/compiler/checker-model-proof.f reads this manifest with
# assumption rows FORBIDDEN: an `axiom` row cannot be written here at all, and
# the observed set is additionally compared against the committed one. That is
# the same strength the interning manifest in test/compiler/ir-intern-axioms.txt
# and the structure manifest in test/compiler/ir-structure-axioms.txt claim.
#
# A `type` row is this file's copy of what that result states, written as Rocq
# prints the statement in the environment the generated obligations file sets
# up: Stdlib Bool, List and PeanoNat imported, list notations imported, and
# Habu.Common.Effects and Habu.Common.Control imported last so a bare name
# resolves to the models' own. Rocq's printer breaks a long statement across
# lines; a row is that statement with its line breaks turned into single
# spaces, which changes nothing Rocq reads. The parity gate turns each row into
# `Definition pinned_statement_<k> : <type row> := @<theorem name>.` in the file
# it asks Rocq to compile, so Rocq's own type checker decides whether the
# statement in the model still is the statement written here. It decides that
# up to conversion, so renaming a bound variable is not a change but weakening,
# strengthening, or trivialising a statement is. These rows are the authority:
# the generated file is a build output and never reads a statement out of a
# model, so changing a model alone cannot move the target it is checked against.
#
# Lines starting with `#`, and blank lines, are commentary. A `type` row is
# handed to Rocq. Every other row is compared byte for byte.
