Problem: the machine-code compiler calls whatever xt sits in HOOK-CELL (src/habu/habu2.f HOOK-CELL reads; habu1.f BSETCHECK, BSETPREFLIGHT; kernel-x64.f SET-CHECK-BODY), and the public engine words set-check, check@ and set-preflight make that cell a switch any program holds: on the installed hb, '0 set-check' before ': BAD ( -- n ) dup ;' lets BAD compile and run (exit 70, 'interpret stack underdepth') where it is otherwise refused. set-check appears in 73 files (359 lines), 13 of them engine sources (src/core sumtype.f render.f top-row.f checker.f; src/habu window-rewind.f aot-capture.f kernel-x64.f habu1.f habu2.f xref.f layout.f aot-common.f; src/os/linux-x86-64/target-layout.f). The switch costs suspend cells (layout.f SUSP-HOOK-CELL, SUSP-PREFLIGHT-CELL), installer guards, a hookless compile path (src/compiler/native/definition.f CHECK-HOOKLESS), HOOK-CELL tests in src/habu/definers.f, and checker rules for cells left in a window (render.f MD-TOP-UNKNOWN). The package LOWER-CERT-HOOK (src/core/check-hook.f; INSTALL, HOOK, TOP-SITE, TOP-SITE-PATH$, LINE-AT) is named for the mechanism. Joel 2026-11-02 (LESSONS.md 'the checker's switch') chose 'Remove the switch'.
