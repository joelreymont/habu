Problem: docs/forth.md is 86 KB, about 22K tokens, and every worker that writes Habu reads it whole early in its run and then re-reads those tokens on every later call (willow, measured over 2026-09-17/18 across kiba's workers: 19 of 238 runs read it in the first 25 calls; at 120 calls that is about 2.6M cache-read tokens per worker); Joel is short of tokens and asked for a card. Acceptance: docs/forth-card.md, at most 12 KB (about 3K tokens), that a worker reads INSTEAD of forth.md, with forth.md kept for lookups by section: naming and the package/public/private rules; stack comments, typed effects and locals syntax; the checked surface, stated as what the checker refuses and what it admits (loops and do/loop, tuck, +!, quotations, catch/throw, the words workers trip on) with every claim verified by loading a probe on the engine, not recalled; the storage definers (variable/create, PTR-VARIABLE, PERSISTED-PTR-VARIABLE, TYPED-VARIABLE, TYPED-BUFFER, PTR-U8-TABLE, DYNAMIC-BUFFER, LAYOUT-BUFFER, STRUCTURE) as a table of when each applies; the raw-cell pointer rule as landed (docs/effects.md, Raw storage never holds an address) and its repair; error naming and throw conventions (lib/errors.f, E- codes, die vs throw); require paths and load order; and a closing index mapping every other topic to the forth.md heading to open. Each section ends with the forth.md heading it condenses. The card is registered wherever docs examples are gated (tools/examples-test.f if it scans docs/*.md, else state why not); a size assertion keeps it under the cap (a test that fails when the card exceeds 12 KB, so it cannot silently regrow); CLAUDE.md's Language and implementation bullet points workers at the card first and forth.md for lookups. Files: docs/forth-card.md (new), CLAUDE.md, tools/examples-test.f or test/, docs/forth.md (a pointer line at the top). Verify: every probe run on bin/hb under the sandbox; the docs gate suites; test/run.f is not needed for a docs change unless a gated tool changes. Depends: none. Ownership: docs.
