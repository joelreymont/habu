The parity target needs a measured reference: add a clang -O2 column to the codegen comparison. One C twin per corpus row computing the SAME function as the habu word (same signatures, same answer vectors including NaN and edge inputs), compiled at harness build time with the host clang (-O2 -arch arm64); if clang is absent the column is absent LOUDLY (a printed line naming the missing compiler), never silently. Timing through lib/ffi-abi.f with the C column's own entry floor measured the same way the engine and chain floors are (an FFI call costs more than a bl — the floor subtraction must make the comparison honest, and the floor itself gets printed); answers pinned with the same VECTOR discipline; bytes from the object's symbol sizes (nm -m or size per symbol), printed beside the other two byte columns. The report gains 'chain vs clang' gap lines per row — informational adjudication first (named, not a finding), because parity is the goal being measured, not yet a gate. Acceptance: every corpus-1/2/4 integer row and every corpus-3 float row has a C twin with identical pinned answers; ten consecutive runs give stable gap ordering; the report prints a summary table of the ten largest chain-vs-clang gaps by time and by bytes — that table is the priority list for the optimization lanes (TCO, register convention, GVN/div-magic, LICM/unroll, peepholes, spilling, NEON).

SECOND REFERENCE (user requirement): our own committed chain baseline, so improvement is measured against ourselves and not only against clang. Snapshot the chain column as it stands at the baseline commit (master 5dcb2867: bytes per row exactly, costs as recorded reference numbers with the harness's own timing caveats) into committed per-corpus tables using the same machinery the engine's old-column baselines already use, with an --update flow scoped per corpus. The report prints, per row, chain-now vs chain-baseline: the byte delta adjudicated exactly (a byte REGRESSION vs our own baseline is a finding — we never get bigger without saying so; an improvement is named so the baseline gets re-pinned deliberately), the time delta informational under the established bar discipline. Every optimization lane that follows reports both gaps: closed-vs-clang and gained-vs-baseline.

Review alignment (CG review, measurement section): clang -O2 is an informational external reference — host-clang availability and FFI overhead are never part of correctness; record the new chain's own exact byte baseline per row; measure compile/publication latency separately from generated-code runtime; paired alternating samples for any timing verdict.
