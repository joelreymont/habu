Problem: src/lib/fs-mutate.f:973 ARM-EXIT-HOOK reads and writes the exit vector through EXIT-HOOK-N (:968, data-base EXIT-HOOK-CELL +), and data-base is the calling task's DATA region (docs/forth.md ~1273). FS:CLEANUP-TREE+ (and CLEANUP+, CLEANUP-DIR+) called only from a non-main task therefore arms the task's copy of the vector, never the main task's that process exit runs, so the registered paths survive a normal exit with no error. The registry itself is process-wide (comment at :978), so the registration is recorded but never run. Found from Maki: test/operation-run.f runs PROJECT-OPS builds on a task whose CHILD:ARG+ registers its job directory; every passing run of the saved image leaves $TMPDIR/maki-child-*/ with ~22 job-N.json files. Repro (saved Maki image REPL, TMPDIR set): $100000 TASK:TASK W / : WR s" intask" FS:MKTEMP-DIR 2dup FS:CLEANUP-TREE+ type cr 0 TASK:RETURN ; / : P AIO:START ['] WR W TASK:ACTIVATE W TASK:JOIN MATCH result ok OF drop ENDOF err OF drop ENDOF ;MATCH AIO:STOP ; P  -> the printed directory remains after exit; one more FS:MKTEMP-DIR + FS:CLEANUP-TREE+ on the main task removes both. Acceptance: a cleanup registered from any task runs at process exit (normal exit and die), once, with the previous hook chained as now; the arming site addresses the process's (main task's) vector whatever task calls it. Regression: a fs-mutate-test (or process-task-test) case registering a tree only from a non-main task in a child process and asserting it is gone after the child exits; it fails on master.
