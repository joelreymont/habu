Problem (aspen, Tender, 2026-09-19; notes ~/.cache/tender/habu-gaps/stripped-baked-data/notes.md): a stripped build refuses any program whose MAIN closure reaches a baked word that addresses the engine's own persistent DATA below the capture window: 'aot: address refers to data outside the restored span caller=INT>NUM target=STR-MIN-I64$' for 'require lib/fmt.f : MAIN 42 FMT:.INT cr ;', caller=STR-PARSE-POS target=STR-MAX-I64$ for parsing an integer (lib/string.f:64-65, create digit tables), caller=SHA256 target=SHA-U for hashing (src/core/sha256.f:35-72,191: constants KK and HH0, scratch buffers H/WS/SHA-TAIL/SHA-IO/SHA-DIGEST/PBLK and eighteen scratch variables). All three Tender images stop at one of these and ship as 30 MB --repl images. The owned-cell list (src/habu/aot-owned-cells.f) knows FRESH (zero is the right start), IMAGE-BASE, ENTRY-XT and TEXT-BASE; it has no kind for CONSTANT BYTES THAT MUST TRAVEL, and sha256's scratch is not on it. Decision: (1) a new claim kind CARRIED ( ptr a n -- ), by name with an explicit byte length: at link the linker copies the named bytes into a cell-aligned run inside the application's window (part of the blob the image writes) and MAPS every spelled address inside [a, a+n) to the copy plus its interior offset, through the same target map the closure walk already uses for re-interned literals (aot-closure.f DATA-TARGET / MAP-TARGET!), so no entry code runs and nothing below the window is written; the walker admits a spelled address inside a carried range. (2) The list gains STR-MAX-I64$ and STR-MIN-I64$ (STR-I64-DIGITS bytes each), sha256's KK and HH0 as CARRIED, and sha256's scratch cells and buffers as FRESH through a package word (SHA:OWNED-CELLS, the DYNAMIC-STORAGE:OWNED-CELLS pattern, since they are private) after reading that each is written before read within one call - state that fact per cell in the list's comment. No value heuristics, no dictionary-extent guessing, no copying of unclaimed cells. Acceptance: aspen's print.f and parse.f build stripped and print/parse correctly; a hashing program builds stripped and its digest matches the engine's; tools/hb-build-test.f gains a stripped case that prints, parses and hashes in one program with pinned stdout (the class regression), HBT-STRIPPED-UNOWNED-CELL still refuses TMP-PATH; aot-window-latch.f:72-77 and aot-owned-cells.f comments state the carried kind; docs/bootstrap.md or the AOT doc gets the rule (a baked constant an application reaches is carried by name). Files: src/habu/aot-owned-cells.f, aot-closure.f, aot-lib.f, aot-window-latch.f (comment), src/core/sha256.f (the OWNED-CELLS word only), tools/hb-build-test.f, docs.
