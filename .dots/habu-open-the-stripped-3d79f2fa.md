Problem: Joel 2026-09-18 ('fix this immediately'): a stripped build (tools/hb-build.f without --repl) refuses any application that touches persistent state of a library the maker child preloaded. Reproducer (aspen, ~/.cache/tender/habu-gaps/stripped-getenv/, read-only): ': MAIN ( -- ) s" hello" type cr ;' builds to 60 KB and runs; add 'require lib/process-env.f' and 's" HOME" GETENV type cr' and the build exits 74 with 'aot: address refers to data outside the restored span caller=GETENV region-off=3827104 value=13964108800 target=ENV-QU span=[13973422408,13974840872]'. Cause, measured on the line: tools/hb-build-lib.f:558 runs the maker child with stdin 'require tools/aot-build.f / AOT-LINK:BUILD-NATIVE'; tools/aot-build.f loads tools/aot-build-core.f inside EXECUTABLE-BUILD:WITH, and aot-build-core.f:2 requires src/habu/app-image.f whose LOAD requires src/habu/app-image-core.f, which requires lib/errors.f, lib/string.f, lib/memory.f, lib/fs.f, lib/fs-mutate.f, lib/process.f, lib/process-argv.f and lib/process-env.f (app-image-core.f:2-9); only then does AOT-LINK:NATIVE-BUILD (aot-build-core.f:44-48) call AOT-DATA-START (src/habu/aot-lib.f:51, HERE-N into BLOB-SRC plus NSTR:WINDOW-OPEN) and script-required the application, so the application's require of any of those eight modules resolves to the copy below the window and every persistent cell they own is outside the restored span; the linker's own src files (aot-decl.f, aot-closure.f, aot-lib.f, stack-abi.f, rt.f, crash.f, address-cells.f, code-span.f, src/arch/arm64/asm.f, icode.f) and lib/executable-build.f require no lib module. Every Tender image reads its parameters from the environment, so this refusal is what keeps Tender's three entries at 25-30 MB --repl snapshots instead of stripped images. Design: the maker child opens the window before anything the application could require is loaded, loads the application, closes the window, and only then loads the linker and its libraries above BLOB-END: tools/aot-build.f (inside WITH, tier 1) requires only lib-free files first (lib/executable-build.f, src/os/script-argv.f, src/habu/aot-decl.f, with the two latch words AOT-DATA-START and AOT-DATA-SPAN moved from aot-lib.f into aot-decl.f or a new lib-free src/habu/aot-window-latch.f so the window can open without the linker), then script-requires the application, latches BLOB-END, then requires tools/aot-build-core.f (linker, app-image-core.f and its eight libs land above the window; a module the application already loaded is shared in the harmless direction, the linker using the application's copy at build time only) and calls LINK; NATIVE-BUILD splits accordingly (options, open, load, close before the linker; LINK after). The invariant to state in docs/native-applications.md and assert in the fixture: nothing the application can require is loaded when the window opens, so the application's require closure is the only library content inside the span.
