## Design (Plan agent 2026-11-11, cut by the lead; probes ~/.cache/tmp/carl-arr on installed 38496dc3)

Layer: the `ARENA NAME t` definer (src/core/arena.f:28-109), which today makes runs of one. It generates two more words in the declaring section, with the element width baked as NAME-NEW bakes it:
- an allocation word `( ptr ARENA:arena n -- SPAN:span<t> )`: n zeroed elements, reach n x width bytes; a count of zero or less, or one whose bytes pass MEM-MAX-N, is E-MEM-SIZE before the arena changes; a refused mapping is E-MEM-MAP as ARENA:ALLOC's.
- an indexer `( SPAN:span<t> n -- ptr t )`: E-SPAN-RANGE unless 0 <= i and i * width + width <= reach; no division.
No dispose form, no growth, no empty run: no caller. No new definer, error code or cast in a user package.

Probed (hand-written copies of the generated words, load and tools/check.f rc 0): arr1.f elements n and r, a span stored in an ARENA record's field and fetched; arr3.f/arr4.f elements a STRUCTURE and `ptr node` (`ARENA NODE-REFS ptr node` is admitted). Corrections to the Plan's text: SPAN:MAKE refuses a layout pointee (`expected: ptr a n actual: ptr turn n`), so the generated word calls SPAN-SPAN:MAKE; `byte-view` refuses a layout pointee, so the definer also generates the reverse private cast `( ptr t -- ptr u8 )` for the indexer. A record field of `SPAN:span<ptr node>` is refused today: dot habu-let-a-field-bc04ba74.

Callers (planned, none reached from a Maki entry today): TRIM constructors maki src/trim.f:389-521 (15, 14, 7 cells), VERTEX :677, EDGE :710; ASSEMBLY STAGE-INSTANCE src/assembly.f:1488 (pose 12, shift 3, turn rows 24); OPS reference lists (tim 2026-11-11: a count and a fixed array of node pointers per node, replacing REFS, ops.f:1615).

Not verified: a refusal while the generated words are evaluated, after NAME-NEW is defined, rolls back; load time of two more generated words on each of Maki's ~70 record declarations; index cost against `i NAME` (inferred: one call, three compares, two multiplies).

Withdrawn (lead, 2026-11-11, before any question reached Joel): the generated allocation word and indexer above exist only because a word with a type parameter cannot learn its element's width (src/lib/span.f:75-80), the same limit every typed store's per-declaration `i NAME` works around. Joel 2026-11-11, on a word that let callers live with a language limit: "are you fixing the cause or the symptoms? how do you fix the cause? fixing the cause is always best for long term". So the two words are not built and their names are not asked; the design is of the limit's removal (checked code makes and indexes elements of any stored type through a type parameter), and Maki's arrays are ordinary use of it. Design running: Plan agent, read-only. The probes and the two corrections above stay as evidence for it.

## Design 2 (Plan agent on Fable, 2026-11-11; probes ~/.cache/tmp/carl-elem on installed 38496dc3; names are working names, Joel's to give)

Cause, deeper than span.f:75-80: a type parameter stands for a one-cell value and a record never binds one (src/core/checker.f LAYOUT-BLOCK? :3720-3734, reason :3490-3498; docs/forth.md:2239). Probed: SPAN:LEN refuses span<turn> (p1.f); a generic `( ptr run<t> -- n )` refuses ptr run<turn>, and so does a generic STRUCTURE's own accessor (q4.f, q2b.f, q6.f); `CAST: ( ptr u8 -- ptr t )` is E-CAST-LINEAR (p4.f). Finding: span<u8> passes where span<cell> is declared (q5.f), the hole span.f:16-21 describes; not closed here.

Decisions: (1) checker: a stored-type parameter kind beside TVK-CELL (checker.f:541-580), standing for any closed type CHECKER-ARENA-INFO (:26592) admits, only as a pointee or a family argument in a stored slot; a generic body may move, compare, pass and store `ptr t` of it, never fetch, store through, add to or byte-view it; stored-slot arguments pair exactly. The kind is derived, not written (as TFAM-WIDTH-SLOT?, type-family.f:1928). (2) `size<t>`: a built-in one-cell type, the byte size of stored type t, which no cast yields. (3) a way for a program to obtain a `size<t>` (the Plan proposed a top-level definer `TYPE-SIZE NAME t` in src/core/layout-buffer.f; the lead asked for sizes that come with the type instead: under review). (4) `size>n ( size<t> -- n )`. (5) in a `CAST:` row a variable occurring only as a pointee is a stored-type parameter, so a private `( ptr u8 -- ptr t )` is admitted. (6) src/lib/arena.f: `ARENA:array<a>` (count, step, elements after), `ARENA:ARRAY ( ptr ARENA:arena n size<t> -- ptr ARENA:array<t> )`, `ARENA:AT ( ptr ARENA:array<t> n -- ptr t )` (E-A-BOUNDS), `ARENA:COUNT`, `ARENA:RECORD ( ptr ARENA:arena size<t> -- ptr t )`. No change to T0, the JIT, tier 1, Wasm codegen or habu2.f; the only type-dependent bytes are a size literal in the part that spells t.

Then the `ARENA NAME t` definer goes (src/core/arena.f, its rows at checker.f:16280-16299, verify-source.f:2846, :3820, :3932, interpreter.f:2636): NAME-NEW becomes ARENA:RECORD; NAME-NEW-DISPOSE has no caller in the four repositories. Cutover: src/lib/net/mcp.f:1030, :1112, zen src/jobs/worker.f:542-543, :632, maki src/pattern.f:44, src/session.f:22 and two per Maki lane. Follow-up: HEAP NAME t the same way. TYPED-BUFFER and the other storage definers stay: each allots storage and bakes an address.

Not determined: whether a type spelled only as an applied family marks a linker dependency on its argument (the scan cuts at blanks, `:` and `"`; TYPED-BUFFER has the same exposure); the Wasm cell width; the kind check's load cost.

Second look (same Plan agent, 2026-11-11; probes r1.f-r3.f in ~/.cache/tmp/carl-elem): the declared size word (`TYPE-SIZE NAME t`) is withdrawn; the size comes with the type and no caller needs a declared one. Sources of a `size<t>`: (a) one more member generated by a `DERIVE addr` record's declaration, answering `( -- size<PKG:f> )` with the number F:BYTES bakes (src/core/sumtype.f TDECL-ADDR-PLAN :1996-2024), only when the family passes LAYOUT-MEM-OK? (checker.f:3685), private for an OPAQUE record; its tail becomes a refused field name (structure-decl.f:302-310), so `size` is out (26 fields are named size; elem, element, stored, stride have none in the four repositories); (b) three core constants for n, r and u8; (c) one constant `( -- size<ptr t> )` for every pointer, its variable binding only what STORAGE-PTR-POINTEE-OK? (checker.f:8417) admits. Not generated: a member for a generic family (r3.f: BOX-BYTES answers 16 where box<turn> takes 24) or for an ENUM/SUMTYPE, until a caller appears. Live `ARENA NAME t` element types are all `DERIVE addr` records (mcp.f:1022 peer; zen worker.f slot, buf-headers, request; maki session; maki pattern.f:44 layout not located). Two commits: first the checker kind, size<t> and its sources, the private generic cast rule and ARENA's array family and words, all additive; second ARENA:RECORD, the definer's deletion and the consumers' declarations. Not verified: whether stating the constants' and member's types takes one more case in the plan's authorising window.
