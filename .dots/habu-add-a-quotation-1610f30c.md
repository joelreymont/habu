The checker has exactly two type-variable kinds, TVK-ANY and TVK-RAW (src/core/checker.f around line 144), so no prim row can say "this operand must be an execution token of any effect". Two consequences, both live today. First, the new `xt!` primitive (dot habu-declare-persisted-cb-b150b5d5) carries `!`'s own prim row, PE-A PE-IN PE-PTR-A PE-IN, because that is the strongest thing the table can express: it holds the stored value and the pointee to the same type, so a quotation-typed cell can only be written with a quotation of exactly its own effect, but `xt!` into a plain integer cell also type-checks and would have the snapshot loader shift an ordinary integer by the region delta. Second, and the reason the callback-table bug was possible at all, nothing rejects a plain `!` of a quotation into a persisted cell: src/core/declaration-transaction.f wrote its seven callback cells with `!` for months and the checker had no rule to object, even though the pointee type there is literally `ptr [ n -- n ]`. The capability is a third TVK kind for quotation-typed variables, carried through minting (PE-), through unification (TVK-RAISE's trailed shape is the model), through E-COPY's persistence in EN.B and E-INST's freshening, so that a prim row can demand a quotation operand of any effect. On top of it, the rule this bug wants: storing a value of quotation type through a pointer whose pointee is quotation-typed must go through `xt!` and a plain `!` there is a reject, with the diagnostic naming `xt!`. Acceptance: a prim row can declare a quotation operand of arbitrary effect and reject a non-quotation argument; `xt!` declares that row instead of `!`'s; a checked fixture that stores a quotation into a `ptr [ ... ]` cell with plain `!` is rejected and names `xt!`; test/snapshot-xt-cell-decl.f keeps its lookalike-table row green, since that table's cells are not quotation-typed.
