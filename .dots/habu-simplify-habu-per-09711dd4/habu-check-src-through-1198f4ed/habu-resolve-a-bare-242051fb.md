Problem: tools/source-discovery.f decides whether a bare use may use a parses: row from the declarations of its tail over the whole replay (SD-R-USABLE?, SD-R-SHARES?), never from where the use sits in load order. A declaration in a scope the use falls through to (the global scope, the outer package) shadows the row only for a use made before the row's own declaration. Fixture twostart: entry.f `: W ( -- ) ; require d.f include a.f package DEMO include a.f ;package`, d.f `package DEMO public : W ( -- ) parse-name 2drop ; parses: W 1 ;package`, a.f `W \ require dep.f`. The engine prints LOADED (inside DEMO, W is DEMO:W, which parses `\`); discovery counts the global W, turns DEMO's row off for bare uses, reads `\` as a comment and misses dep.f, on master's tools and on lane disc. twostart2 and twostart3 (twostart3's files are lost) miss it too. No position-free rule gets both twostart and useearly right (entry.f `: W ( -- ) ; package P W require dep.f : W ( -- ) parse-name 2drop ; parses: W 1 ;package`: the use precedes P:W and is the global W): disc fold 3's rule found twostart and missed useearly. Only the context replay (SD-R-CONTEXT-BETWEEN) visits records in load order; the harvest walk does not. Acceptance: a bare use applies a row exactly when the engine resolves it to the row's declaration at that point of the load order, or discovery refuses (E-DISC-SHADOW) where one use site resolves differently in two loads; twostart, twostart2 and twostart3 find dep.f (twostart2/3 also need habu-refuse-a-replay-d5a112c0's c.f) and useearly keeps it; a tools/source-discovery-test.f case (suite row source-discovery) for twostart failing before. Files: tools/source-discovery.f, tools/source-discovery-test.f. Verify: tools/source-discovery-test.f; the fixtures; real-all user CPU against master's tools. Depends: lane disc landed (habu-key-discovery-records-b367e77e). Related: habu-refuse-an-ambiguous-bc0186a0. Ownership: tools/source-discovery.f. Claim: unassigned.

Lane disc fold 5 (ruling 2026-11-01): a bare spelling uses a package's row only where the row precedes it in the same file, and refuses E-DISC-SHADOW elsewhere, so twostart, useearly, useengine and usingearly refuse instead of missing dep.f. This dot's load-order resolution would let those uses apply the row instead of refusing, and would cover global rows, which still apply position-free as on master.

Census 2026-11-04: a disagreement between two implementations of one thing; it is closed by its parent removing the second implementation, not by patching that copy.
