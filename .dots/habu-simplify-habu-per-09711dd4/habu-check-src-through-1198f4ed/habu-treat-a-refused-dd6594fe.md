Problem: under tools/check.f --all-errors a rejected definer and a rejected colon word are kept differently. src/habu/verify-source.f VERIFY-DOES records the definer (DEFINER-RECORD, :1868-1871) only when the clause verdict is nonzero, so a rejected definer leaves no record, while a rejected colon word keeps its declared signature (tools/check-all-errors-core.f). Reproducer 1: ': MK ( n -- ) create , does> ( -- ) ;' then 'parses: MK 1' then ': C ( -- ) 2 ;' gives three packets, E-PARSES-ROW second; '5 MK foo' in place of the row gives E-UNDEFINED, where a rejected colon word's later mentions report nothing. Reproducer 2: ': P ( n -- ) @ + ;' then ': P ( -- ) ;' reports the duplicate; ': MYK ( n -- ) create , does> ( -- n ) @ + ;' then ': MYK ( -- ) ;' reports none. The rule is docs/architecture.md:305-309: a rejected definition is rewound, a mention of a rejected word is undefined, and a definition whose first defect is such a mention is counted rejected without being reported; by it the colon word's duplicate in reproducer 2 is the answer that disagrees. Source: parked lane commit 8d6da143. Acceptance: on both reproducers a rejected definer and a rejected colon word give the answers docs/architecture.md:305-309 states (or the doc changes first, with the user's approval), each seen failing first; met by the parent's check through the interpreter, not by patching verify-source.f, which the parent replaces.
