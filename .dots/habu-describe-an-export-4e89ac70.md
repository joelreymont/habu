Problem: SEE of an EXPORT alias of a word made by a create ... does> definer (package DTF public EXPORT DTE:KID, then SEE DTF:KID) prints 'kind colon' and 'effect none recorded', though the alias runs the child's body and has its effect. The interpreter's EXPORT copies only the DKIND:VAL kind bit to the alias record, so the alias has no DNAME-ALLOC and no stored facts text; src/habu/describe.f KIND$ reads the record's own flags. Found by the kind fold of stage 1 (habu-describe-a-published-501824c2). Acceptance: SEE of an EXPORT alias prints the kind and the effect of the word it exports, for a colon word, a constant, a variable, a created word, a does> child, a defer and an immediate word; describe.f reads them from where the engine and the checker hold them, with no second rule. Files: named by the root cause (src/habu/describe.f, the EXPORT path in src/habu/packages.f, the checker's EXPORT-META-SYM). Verify: test/describe-test.f cases for each kind of exported word. Depends: habu-describe-a-published-501824c2 landed. Ownership: unassigned. Cause (read and probed on 8959ee12): the alias-record primitive (src/habu/habu2.f DEFWRITE:ALIAS-RECORD :1075, src/habu/interpreter.f PKG-EXPORT :1167, src/habu/kernel-x64.f ALIAS-RECORD-BODY :4503) copies the code address, length, DNAME-IMM, WIDE, MIN-IN and DKIND:VAL only, and NAME-COPY (src/habu/habu2.f:787) zeroes the facts slot. The checker gives the alias's symbol its source's effect (src/core/checker.f CHECKER-EXPORT-ROW :16064) but nothing writes the alias's facts text: the export callback is installed bare (:18747), where the other registrars go through src/core/check-hook.f PENDING-FACTS (:193). So every alias reads 'effect none recorded', and an alias of a variable, a created word or a does> child reads 'kind colon'; an alias of a colon word, constant, defer or immediate word reads the right kind. Fix, effect: write the alias's facts text in RECORD-PUBLISHED-LOCAL's pend branch (checker.f :18157), as PENDING-FACTS does. Fix, kind: no flag marks an alias; the checker's source cell (CHECKER-SYM-SOURCE checker.f :17364, set by EXPORT-META-COPY :16044) names the source exactly, so describe.f can read the kind there. Copying DKIND:ADDR, DNAME-CELL and DNAME-ALLOC to the alias record instead changes what a compiled mention of the alias folds to (habu2.f :12416, src/compiler/native/dict.f :137, hir-word.f :908) and which record owns the storage (checker.f :17538-17579): not determined whether that breaks. Seen beside it: a constant, a variable and a created word have no facts text of their own ('effect none recorded', habu f94670f2's limit); XREF-FIND of a missing name throws 7231 in a probe, not checked against its contract.
