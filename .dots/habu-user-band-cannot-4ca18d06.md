## Design (Plan agent, 2026-11-11, cut by the lead; probes ~/.cache/tmp/carl-band p1.f-p3.f on installed 38496dc3; the agent ran out of context before its last probes)

Exists: USER-BAND src/habu/layout.f:1603-1608 ($5300..MEM-ABI:START $6790), claimed at src/habu/data-claims.f:265; engine bands carved below USER-REGION-END $8000 (layout.f:1465-1601); src/lib/task.f:164-178 (TASK-USER-NEXT, bounds, TASK-DEFER-OFF by hand), :1763-1771 (#USER, USER-NEXT: bounds only, admits an offset below the counter), :1783-1819 (+USER generates `: NAME ( -- ptr n ) data-base <off> + ;` by CODEGEN and INCLUDE-EVALUATE), :1789-1802 and :2302-2306 (SLOT-OBSERVER, OBSERVE-SLOTS: a hook with no caller), :1823, :2216 (TASK:HIS, tests only); task life :66 (TASK-REGION-BYTES $10000), :1226-1294 (TASK-REGION-INIT, TASK-PREPARE-RESOURCES), :1351-1366 ACTIVATE, :1466 EXPOSE, :1087-1115 TASK-RELEASE-MEM, :1071-1075 TASKS-LIVE-CELL. bootstrap/cg/forth.fs is gone (1d97c3f2): that part of this dot is moot. Callers thread the offset by hand: `TASK:#USER 7 + $FFFFFFFFFFFFFFF8 and SIZE TASK:+USER NAME drop` (Habu about 45 lines, Zen 14, Tender 4 files, Maki 3 plus scene-c1's 22).

Decisions (lead, by the long-term rule; no new public word):
1. Every slot has two homes. Main's copy is the slot's own program data: +USER becomes a create/does> definer whose body is one cell holding the slot's task offset k, then `size SCRATCH-ALLOT` (zero in every image, as SCRATCH-VARIABLE). A task's copy is in an area mapped after its region's header (TASK-REGION-BYTES), sized to TASK-USER-NEXT rounded to a page.
2. USER-BAND's 5264 bytes become one engine cell (a declared band claimed in data-claims.f, below $7FF8 like MEM-ABI:HEAD-OFF) holding the running thread's area base; a main region holds 0. Accessor: `data-base BASE-CELL + @`, 0 means the body's own bytes, else base + k. Effect stays `( -- ptr n )`. Wasm has only main and takes the first arm: no machine split. Chosen over one area for main at the top of DATA (linker cells, a build redirect, Wasm placement, and it keeps program code at build time sharing the builder's slots).
3. Task creation: TASK-REGION-INIT writes the base; ACTIVATE and EXPOSE map the region again when a prepared region's area is smaller than TASK-USER-NEXT. Task end unchanged (the area goes with the region's munmap).
4. A claim while a task is live (TASKS-LIVE-CELL nonzero) throws E-TASK-USER, as lowering and ROW-GROW already refuse then; chosen over a bounds check on every task access.
5. First step, alone, for Maki: the storage change with today's `( n n -- n )` and #USER kept, plus a check that the offset is not below the counter. No consumer edit. Second step: +USER's effect becomes `( n -- )` (bytes, cell-aligned by the definer), #USER, HIS, OBSERVE-SLOTS, UNOBSERVE-SLOTS and SLOT-OBSERVER-CELL are deleted, and Habu, Zen, Tender and Maki edit their lines in the same install.
Engine bands (STRING, FMT, FS, FS-MUT, MEM, GENIO) stay: machine code reads GENIO-ABI and FS-ABI:ERRNO-OFF at fixed offsets and each is sized by its protocol.

Measured: today's accessor is 8 instructions (tools/jitdump.f). Inferred: no consumer relies on a main slot's value across files at build time (a cold build runs the first file's top level, a warm build links it, so such a value already differs); nothing reads a prepared task's region before it goes live but the HIS tests.
