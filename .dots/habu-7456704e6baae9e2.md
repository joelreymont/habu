Location: src/compiler/compile.zig:5084-5123. Root cause: MethodDef stores IR pointer (method.body) and specializers array allocated with arena allocator (self.allocator). When second defmethod runs, arena is reset and old method IR is freed, causing segfault when generateMethodDispatcher tries to use it (line 5151). Solutions: (1) Deep-copy IR to globals.allocator, (2) Compile methods to bytecode/closures and store those instead of IR, (3) Store method as global function name and generate dispatcher that calls by name. Option 3 is simplest: each method becomes 'generic-name' function.
