Problem: a stripped hb-build image cannot read its environment even after the capture window opens before any library loads (habu-open-the-stripped-3d79f2fa, measured 2026-09-18 by that lane): ': MAIN ( -- ) s" HOME" GETENV type cr ;' with no require at all refuses with 'aot: address refers to data outside the restored span caller=GETENV region-off=3827104 value=13964108800 target=ENV-QU', because GETENV is engine code (src/os/env-base.f:81, baked into bin/hb: tools/bootstrap.sh SRC_COMMON, tools/build-fixpoint.f) whose cells are engine DATA below every window: ENV-DATA-PTR (env-base.f:6, a PTR-VARIABLE set to data-base at engine load; ENVP-BASE/ENVP read the process's envp through it) and the GETENV scratch cells ENV-QA/ENV-QU (env-base.f:72-73); the stripped entry (src/habu/aot-lib.f:41-42, :88, :111, :133) initialises only x20, S0-CELL and DP-CELL and leaves every other engine cell zero from the fresh mmap, so the refusal is correct fail-closed policy: GETENV would read an empty environment. Every Tender image reads its parameters from the environment (TENDERD_*), so this is what keeps tender-scrape, tenderd and tender at 25-30 MB --repl snapshots instead of 60 KB stripped images (Joel: fix this immediately). Design: the engine's environment is a runtime input like argv, not persisted data, so the stripped entry initialises it the way the engine's own entry does: it stores the envp it receives from the kernel where env-base.f expects it (ENV-DATA-PTR or the cell ENVP-BASE derives from, whichever the engine entry writes; read src/os/env-base.f and the engine entry in src/habu/habu2.f to find the single owner) and the closure walker admits, by declaration and not by value, the engine cells the stripped entry owns (ENV-DATA-PTR, ENV-QA, ENV-QU): one list in one place (src/os/env-base.f or src/habu/layout.f beside DP-CELL/S0-CELL) that both the entry emitter (aot-lib.f) and the walker (aot-closure.f, the outside-the-restored-span check) read, so a cell reaches the list only by being named there, never by being scratch. If ENV-DATA-PTR's initialisation must change in env-base.f the file is baked: three generations with cmp. Acceptance: the GETENV program builds stripped, runs and prints the variable; the negative fixture the window lane registered for it flips to positive and a new negative (an engine cell NOT on the list, e.g. one of the profiler's) still refuses with the same diagnostic; SCRIPT-ARGC/SCRIPT-ARGV$ keep working in the same image; PROC-ENV-INHERIT-MISSING and lib/process-env.f's inherited-environment path work in a stripped child (a fixture that spawns a stripped image reading an inherited variable); --repl unchanged; tools/hb-build-test.f, tools/hb-build-stripped-lib-test.f, test/aot-*, AOT chain suites and test/run.f green; Tender's three entries then build stripped (aspen verifies on their side against a read-only engine). Files: src/habu/aot-lib.f (entry), src/habu/aot-closure.f (walker), src/os/env-base.f and/or src/habu/layout.f (the owned-cell list), test/, docs/native-applications.md. Verify: the fixtures; three generations if a baked file changes; test/run.f. Depends: habu-open-the-stripped-3d79f2fa. Ownership: AOT linker and engine entry. Claim: unassigned.
