Add a consumer-side namespace import to the package system: 'using NAME' makes package NAME's PUBLIC wordlist visible to bare lookup in the current scope, without opening the package - privates stay sealed, no new definitions can land in NAME, and nothing joins any global surface. Motivation: package-qualified block-pair closers are unreadable (TEST:;SUITE at ~492 sites, ONNX:;ENC-SUB at 136); suite manifests are pure DSL files that should read 'using TEST ... SUITE foo ;SUITE'. Semantics to implement, engine and checker both: (1) 'using NAME' consumes the next token, rejects a missing or colon-bearing name and an unknown package; valid at top level and inside a package. (2) Scope: ends at ';using' (the FOO...;FOO convention), at ';package' when opened inside a package, or at end of load file - whichever comes first; multiple concurrent usings allowed. (3) Lookup order: current package scope (privates then own publics) first, then each used public wordlist; a bare tail resolving in MORE THAN ONE used public wordlist is a hard error (no silent shadowing, matching the no-duplicate wordlist discipline), and a tail found both in the open package and a used package resolves to the open package without error (inner scope wins). (4) A used package's PRIVATE words must not resolve bare - negative regression required. (5) 'using' inside a package must not leak into that package's export surface or persist past its block - negative regressions. (6) Qualified NAME:WORD lookup is unchanged and always available. (7) The checker resolves identically to the runtime - certification through a using scope must agree with execution, and the AOT/baked path must reproduce the same resolution (fixpoint proof). Implementation lives in the package/lookup machinery in src/core plus the checker's resolution; this is seed-affecting: install --force x2 byte-identical shasum required, plus a focused positive/negative fixture suite registered in the gate, docs/forth.md section Packages updated with the using rules, and the full battery. Follow-up migration is a separate dot.
