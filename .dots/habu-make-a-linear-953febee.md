Problem: a type declared with DEFLINEAR loads but cannot be named in a build: hb-build of a program requiring src/lib/power.f, byte-edit.f or pg.f ends rc 74 'unknown type' (reduced: DEFLINEAR QB:t then LINEAR: >T ( n -- QB:t ), or a colon signature naming it). Cause, measured 2026-11-10: in a build DEFLINEAR (src/core/roles.f:144) runs the target's copy of CHECKER-DEFLINEAR, whose CT-ADD-LINEAR writes the target copy's type table, while the running hb checks the build's signatures against its own table (CT-FIND); the table is not a registered store and a linear type is not a type entry, unlike a family (linker.f TYPE-ENTRIES, type-family.f TFAM-FIND). DECISIONS 'where the checker's facts live': a type is an entry whose text is its declaration. Acceptance: programs requiring the reduced files, power.f and byte-edit.f build; the E-LINEAR-SCOPE and E-LINEAR-OWNER refusals are the load's in a build; a warm build that links the declaring file equals a cold build; the engine rebuilds itself byte for byte; the suite passes. Files: src/core/checker.f, src/core/type-family.f, src/habu/linker.f. Verify: brief .jj-ws.noindex/carl-layout/.out/briefs/linear-type-is-an-entry.md. Depends: none. Ownership: carl. Claim: agent=carl worker workspace=.jj-ws.noindex/carl-deflin. Open beside it: VALUE-RECORD's table is not a registered store either (untested in a build; the lane tests it and reports); a program requiring pg.f on master stops earlier, at aio.f ('the cell ... in ROWS holds an address outside hb's data and the build's space'), which the host-loads lane removes.

Design (Plan agent, 2026-11-10; brief .jj-ws.noindex/carl-layout/.out/briefs/linear-entry-read-on-miss.md): the eager add at link (LINK-LINEAR, CHECK:READ-LINEAR) left the built target without the type: an hb built with --repl failed test/linear-suite.f asserts 93 and 94. Replaced by one route for host and target, the one families use: CT-FIND reads a linear type's entry from the types wordlist when a lookup first misses it and READ-PENDING reads the rest before a declaration; LIN-ANY? also holds while an entry may be unread; CT-REWIND of a linear row sets the pending flag; TYPE-ENTRIES skips a row already an entry (CHECK:LINEAR-ENTRY). No saved format changes: the entry text stays 'linear <pkg>'. Tests (a warm build in test/linear-suite.f with a SUMTYPE naming the type; two linear types named out of order, warm equal to cold) follow in a second brief.
