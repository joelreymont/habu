Problem (adversarial review of 534734bb..a6ce705f, HIGH, probes clob0/clob1/clob2): a throw pushes its code at the CURRENT data-stack depth (src/habu/habu1.f BDIV0? and every engine throw; the compiled divide's cold side src/compiler/native/emit.f PUT-SDIV 'str rd,[x19],#8' is a new site), and src/core/checker.f RSCATCH admits a depth-preserving quotation whose inputs are cells present at catch time and keeps their pre-catch types after the throw. So a throw from a word that consumed cells below the catch level overwrites a caller cell the checker still types: ': NOP ( -- ) ; 1 set-tier : D3 ( ptr u8 n n -- ptr u8 n ) {: p u d :} NOP u d / {: q :} p q ; 0 set-tier : T ( ptr u8 n n -- ptr u8 n n n ) [: D3 0 ;] catch ; s" hello" 0 T . drop type cr' prints -6400 and an empty line - the NOP call synced x19 to catch-level minus 24, the divide's cold side pushed -6400 there, and after catch the cell typed ptr u8 holds -6400 (type is a write(2) so it fails EFAULT silently; c@ would SIGSEGV). At tier 0 (no NOP) BDIV0? clobbers the same cell; at tier 1 with no call it prints hello because x19 lagged - which cell dies depends on the tier. Any throw has this root; the batch added the compiled divide to the sites. Decision (hazel 2026-09-18): the throw ABI changes, not the checker - refusing a caught quotation that consumes cells present at catch time would refuse the ordinary idiom ('7 0 [: / ;] catch'), and retyping the caller's cells unknown after catch would break every caller that relies on the depth-restored contract the checker already promises. So: a thrower never STORES its code below the catch level - the code travels in a register (x0, or whichever the engine's BTHROW entry reads) into the throw entry; `throw ( n -- )` keeps its checked surface but its compiled form and every engine primitive that raises (BDIV0?, the compiled divide's cold side src/compiler/native/emit.f PUT-SDIV, UF-* underflow refusals, E-DIV-ZERO sites, every `bl throw` the AOT relocates) load the code into the register and branch without writing the data stack; the catch handler restores SP to the frame's recorded depth FIRST and then pushes the code there, which is the only cell it may write. bootstrap/cg/forth.fs mirrors the entry. Acceptance: that shape landed, with the tier-0 and tier-1 clob probes intact after the catch (the caller's `ptr u8` cell still types to `hello`) and the stripped-image divide fixture still delivering -6400; state the ABI in docs/effects.md's catch section and docs/debugging.md's throw notes; red-first fixtures for clob0/1/2 in the checker's catch suite (find it: rg -l RSCATCH test) and a runtime fixture that shows the caller cell intact after a caught throw at both tiers; the 'contract holds at every tier' bullet in docs/forth.md stays true.
