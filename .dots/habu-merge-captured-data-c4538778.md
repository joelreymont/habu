Problem: tools/engine-size.f on the line-head engine (5112000 bytes, 2026-09-17) reports aot/data-run-rows 682320 bytes (13.3 percent): 85290 runs at 8 bytes a row (offset u32, length u32). The heap owner alone is 58035 runs for 1241138 bytes and SYMS-BOOT 26670 runs for 113678 bytes, so the rows cost more than a quarter of the bytes they describe. Merging is already done: d3cc6730 keeps a run open across zero gaps shorter than AOT-WINDOW:RUN-GAP-MIN (one row, src/habu/aot-decl.f) in aot-capture.f ACAP-RUN-CLOSE and aot-lib.f EACH-BLOB-RUN alike, so a run splits only where the gap already costs at least a row; the remaining lever is the row itself. Design: a row becomes two unsigned LEB128 varints, the gap from the previous run's end (the first row counts from offset 0) and the length; a gap is at least RUN-GAP-MIN and most gaps and lengths fit one or two bytes, so the row array should fall from 8 bytes a run to about 2 or 3 (expect 400 KB or more; measure the gap and length distribution on the line engine first and record it in the commit body). The format has one capture writer per side and one decoder, and every site changes together: capture (aot-capture.f run close and its row emission, aot-lib.f sparse header written with SPARSE-U32! over EACH-BLOB-RUN), the emitted boot decoder (aot-lib.f EMIT-DATA-COPY: x9 row cursor, x10 byte cursor, x13 destination, must decode both varints and add the gap to the previous end), the payload section S-WDATA and its readers and checks (aot-file.f RUN-AT / RUN-OFF@ / RUN-LEN@ / ?RUNS / ROW-BYTES-CHECKED, which today refuses a table that is not whole 8-byte rows: the run count stays in the header and the section length becomes the encoded byte length), the run emission in src/habu/habu2.f (BYTES, of RUN-BUF and the LNRUN count), aot-owned.f run attribution, tools/engine-size.f and tools/check-core.f CHK-RUN-N. bootstrap/cg/forth.fs carries no run words, so the change is one-stage, but tools/bootstrap.sh check must stay green. Acceptance: one row encoding shared by capture, payload, decoder and tools; ?RUNS still refuses an empty extent, out-of-order or overlapping rows and a byte total that disagrees with the section; the engine shrinks by the measured row saving; byte fixpoint converges (gen 3 when the host predates the change); test/run.f passes; tools/bootstrap.sh check green; engine-size reports the new row bytes.
