Replace stack-based bytecode with register-based IR:

PHASE 1: IR Design (src/ir/instruction.zig)
- Fixed 32-bit instruction format: [6-bit op][5-bit dest][5-bit src1][16-bit operand]
- 32 virtual registers (v0-v31), map to ARM64 x0-x30+sp
- ~50 orthogonal opcodes: mov, add, sub, mul, div, cons, car, cdr, call, ret, jmp, jz, jnz, typeof
- Eliminate combinatorial explosion (no more list_find_eq, list_find_equal variants)

PHASE 2: Register Allocator (src/ir/regalloc.zig)  
- Linear scan allocation (fast, good enough)
- Liveness analysis for virtual registers
- Spill slots for overflow (rare with 30 regs)
- Calling convention: a0-a7 args, v0 return, v8-v15 callee-saved

PHASE 3: Compiler Update (src/compiler/compile.zig)
- Emit register IR instead of stack bytecode
- SSA construction during compilation
- Phi nodes at control flow joins

PHASE 4: ARM64 Codegen (src/codegen/arm64.zig)
- Direct v-reg to x-reg mapping
- Instruction selection (IR op -> ARM64 op)
- Branch offset calculation
- Literal pool for large constants

PHASE 5: Zig FFI (src/ffi/zig.zig)
- Habu calling Zig: marshal tagged values to Zig types
- Zig calling Habu: wrap Zig functions as Habu closures
- Automatic type conversion (Value <-> i64, []u8, structs)
- @extern declarations in Habu source

PHASE 6: Migration
- Keep old VM for bootstrap/testing
- New pipeline: parse -> IR -> regalloc -> ARM64
- Validate equivalence on test suite
