On the name of the word that frees an arena, asked as CLOSE or RELEASE, he wrote "why not NEW / RELEASE?", then chose the option "NEW / RELEASE" (ARENA:NEW and ARENA:RELEASE, as HEAP's and today's arena's generated words say; OPEN and CLOSE mean files and connections in Habu), and wrote "do it". The words, final:
- `ARENA:arena`, an OPAQUE structure; a program holds `ptr ARENA:arena`.
- `ARENA:NEW ( -- ptr ARENA:arena )`, `ARENA:RELEASE ( ptr ARENA:arena -- )` (a null handle is a no-op), `ARENA:RESET ( ptr ARENA:arena -- )`, `ARENA:WITH ( R [ R ptr ARENA:arena -- S ] -- S )`, `ARENA:ALLOC ( ptr ARENA:arena n -- ptr u8 n )`.
- `ARENA:NEW-IN ( ptr ARENA:arena -- ptr ARENA:arena )`, a child arena (lead, by the pair he chose: the design's OPEN-IN).
- `ARENA NAME t` generates `NAME-NEW ( ptr ARENA:arena -- ptr t )` and `NAME-NEW-DISPOSE ( ptr ARENA:arena [ ptr t -- ] -- ptr t )` (lead: the design's name, after `C2-MEM:ALLOC-DISPOSE`).
- `TASK-BUFFER NAME t` (lead: the shorter of the design's two names; dot habu-give-the-running-e7761ea0).
The design file's OPEN, OPEN-IN and CLOSE read NEW, NEW-IN and RELEASE everywhere.
