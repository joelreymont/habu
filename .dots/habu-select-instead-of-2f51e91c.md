Full context: measured by tools/codegen-align-sweep.f, written up in docs/codegen-placement.md. The native chain compiles the same source as the engine into HALF the instructions and HALF the more branches: for "c 65 < if c exit then c 90 > if c exit then c 32 or" the engine emits cmp/cset/neg/cbz per test plus one b per early exit, four branch instructions in 148 bytes; the chain emits cmp, a b.cond to the then-arm, a b to the else-arm, and a b to the join per arm, six branch instructions in 76 bytes - three times the branch density. On a call-per-byte workload over pseudo-random printable bytes, with the callee entry held at each bodys OWN best 64-byte offset so placement is not in the comparison, the chain leaf costs 2704 and 2855 ps/call against the engine leafs 2108 and 2233 in two runs: 28 per cent slower, both times. It is also far more sensitive to where it lands - ten of sixteen entry offsets are in its bad window against the engines five - because the placement effect is driven by the callee OWN branch addresses (docs/codegen-placement.md part a). Work: teach selection to if-convert a branch-around whose arm is a single value-producing step into a csel-shaped selection, so the branch is removed rather than moved. That is the only change measured here that improves EVERY placement at once, and it should close the 28 per cent and shrink the placement window with it. Acceptance: the chain emits no branch for a two-arm selection whose arms are single moves, tools/codegen-align-sweep.f phase 3 shows the chain leaf at or below the engine leaf at matched best placement, and the chain sweeps span falls toward phase 5 branchless floor. Depends: src/compiler/native/select.f (the selector), tools/codegen-align-sweep.f (the measurement). Ownership: unassigned. Claim: unassigned.
