Problem: src/compiler/a64-effect.f (package A64EFF, 1,042 lines) is the typed machine-state contract every native pass reads - src/compiler/native/regalloc.f (50 refs), regalloc-verify.f (91), select.f (40), abi.f (65), emit.f (22), frame.f - and its content is target-neutral except its name and the ARM64 facts it fixes: a 32-register file (FILE-N), the link register x30 (LINK-N) with its own contract field, the zero/SP register 31, the reserved and engine masks, SP-ALIGN 16, FRAME-MAX, SLOT-REACH and the NZCV flag model. The x86-64 backend (src/compiler/native/x64ir.f, landed in the dialect slice of habu-lower-hir-to-6bf80d33) cannot hand A64RA a pool until the contract can describe a 16-register file with no link register, and duplicating 2,300 lines of allocator per target is worse than making the contract answer for the machine it is handed. Decision (hazel 2026-09-18, INTEL.md): GENERALISE, do not duplicate. Acceptance: (1) the contract module becomes target-neutral - the register-set, place-list, convention, control, frame and flags vocabulary stays, and every machine fact (file sizes, reserved/engine masks, SP alignment, frame bound, slot reach, whether a link register exists) is read from a description the backend supplies: src/compiler/native/regfile.f NREGFILE for the register files plus a small machine-facts record declared beside it (lane decides the spelling; the link field becomes 'none' on a machine without one and every LINK-CK reader admits that); (2) the arm64 backend supplies its description at one place (src/arch/arm64/backend.f or abi.f) and every existing reader keeps its behaviour; (3) the package is renamed to a target-neutral spelling (NEFF in src/compiler/native-effect.f) with the A64EFF references migrated (no compatibility alias left behind), unless measurement shows the rename costs a bridging generation the lane cannot afford - then rename in a second commit and say so; (4) proof of arm64 identity: test/compiler/native-emit.f, native-a64ir.f, native-regalloc.f, a64-effect.f (renamed with the module), native-select.f, native-chain.f all green on the fixpoint; three generations with cmp (gen2 == gen3; gen1 differs by layout only - decode one differing MOVZ immediate to show it is a data offset, as docs/bootstrap.md describes); (5) an x86-64 description instance in test/compiler/x64ir.f or a new suite proving a contract over the x64 register file (16 GPRs, rsp reserved, no link register, 16-byte alignment) builds and validates; (6) docs/x86-64.md and INTEL.md record the landed shape. Files: src/compiler/a64-effect.f (-> native-effect.f), src/compiler/native/regfile.f, regalloc.f, regalloc-verify.f, select.f, abi.f, emit.f, frame.f, src/arch/arm64/backend.f, test/compiler/*, docs/x86-64.md, INTEL.md. Verify: the suites named; three generations with cmp; test/run.f. Depends: none (the dialect slice is integrated at ced84910). Ownership: native chain.
