Problem: a deadline that expires in a build child reaches the gate as an ordinary failure. tools/native-build-core.f RUN and RUN-IMAGE (:616, :629) exit with the low byte of the caught throw code, so E-PROC-TIMEOUT from the smoke deadline (:33, :431) exits 58, the same status as E-A64EMIT-LAYOUT, and E-IR-BUILD-SLOTS, E-A64RA-FRAME and E-NELAB-TYPE all exit 124: no exit status carries a timeout unambiguously. tools/build-fixpoint.f BF-RC0 (:356) turns any nonzero child exit into E-BUILD-STATUS and BF-CLI (:2185) exits BF-BUILD-RC for every throw. Measured by the r4-deadline lane: a scratch copy with SMOKE-TIMEOUT-MS 1 makes the build-fixpoint-snapshot row RED kind=exit code=1. (The first statement of this dot blamed the boot check in an all --force child; only the install verb runs BF-CHECK-CANDIDATE, and a forced 1 ms boot deadline left the fixtures row PASS.) Acceptance: native-build and build-fixpoint exit with one named timeout status on E-PROC-TIMEOUT, defined once, that no other path of either tool or the engine produces; every other caught failure exits with a fixed named build-failure status and still prints its throw code; BF-RC0 and the build-fixpoint rows' child-status checks map the timeout status back to E-PROC-TIMEOUT; every caller that reads either tool's exit values is found and adapted; forced smoke deadlines (scratch copies only) in the snapshot row and in a fixtures-row all --force child go from kind=exit to TIMEOUT-UNDER-LOAD through test/gate-pool.f with the step still named; the tools/check-test-lib.f comment on the 54 s guard states the measured truth. Files: tools/native-build-core.f, tools/build-fixpoint.f, tools/build-fixpoint-test-lib.f, tools/check-test-lib.f, the library that defines the status.
