Problem: a linear (own) value cannot be held in a typed local: test/engine-suite.f rejects every {: x:own :} shape including a single move (CBAD-OWN-LOCAL-ONCE, -BRANCH, -MAKE), fail-closed. The handoff of 2026-09-19 sections 6-8 states the required semantics - binding moves ownership into the local, the first reference moves it out, a second reference rejects, EXACTLY once on every continuing path (a leak is a reject): if/else arms join to one ownership state and a terminating arm does not join; MATCH/CASE arms likewise; a repeatable back edge must carry the same ownership state as loop entry (an owner bound before a loop and consumed inside rejects unless the loop proves one execution); 'exit' validates every active obligation on its path; scope exit checks a branch-local owner before its frame is discarded; throw/unwind needs an explicit policy (fail closed on unsupported shapes) - and a candidate exists on experiment/wide-typed-locals@origin (4eeed7ba and the session's habu-linear-locals-candidate.zip, not in ~/Downloads) that was never validated by the native compiler. Acceptance, in two steps: (1) a design note in docs/forth.md "Owners and views" fixing the rules above as this checker's rules, decided after reading the candidate and the existing OWN machinery (checker.f linear tracking, RS-CAPTURE), naming the throw policy; (2) the implementation with the ~30 fixture shapes the handoff lists (single move, dup, leak, double free, branch agree/disagree, loops with LOOP/+LOOP/BEGIN-AGAIN/UNTIL/WHILE-REPEAT and zero-trip and LEAVE, shadowing, early return, wide linear values, closed parameterised owners) - the engine-suite CBAD rows that become accepted flip to COK with the reason stated. Files: src/core/checker.f, test/engine-suite.f, docs/forth.md. Verify: fixtures; three generations; test/run.f. Depends: habu-bind-a-wide, the parametric-annotation dot. Ownership: checker. Claim: unassigned. Alder's read of the draft (experiment/wide-typed-locals@origin e714ccdb): CF-LOC-REST truncates the locals table without checking the obligations it drops, and CF-+LOOP lacks the LOCUSED-BACKEDGE join the other loop forms have - both are the scope-exit and back-edge rules above, so the design note must state them before any of that code is reused. Also from alder's static read of that draft: MATCH/CASE paths neither restore nor join the new owner bits (rule 7.3 above is unimplemented there). The history's own list for the design note (sections 14-17, 67): exception ownership semantics defined BEFORE merging (throw/catch/finally: automatic cleanup, explicit unwind cleanup, prohibition, or a defined transfer - decide one, fail closed on the rest), and regression coverage for IF/ELSE, MATCH, CASE, every loop form, leave, exit and catch/finally; and the aliasing caveat: a moved owner can still have pointers into its backing storage - linear locals do not solve pointer lifetimes, so the note says what they do NOT promise.

The authorized source review found concrete reader handoffs in all three packages. Tender `src/xlsx-write/xml.f` threads a linear XML reader through sheet parsing and explicit catch/close; `src/score.f` threads a linear JSON reader. Kaizen `src/reader/opc.f`, `src/reader-office.f` and `src/reader/xlsx.f` close linear XML readers and sources after caught scan failures. Maki `src/projects.f` threads linear JSON readers through proposal and manifest parsing. A once-only local could name a token while scalar work runs, then move it back or close it. Repeated NEXT/EXPECT steps would still pass the token on the stack.

Linear locals do not govern these packages' ordinary fd, pid, ZIP, PostgreSQL or retained XML source-owner handles. Tender's multi-cell C2 owner and scoped-cleanup modules are tested candidates, not production entry points. Borrowed pointer lifetimes and retained source-owner aliases also remain separate from local ownership.

Confirmed scope: retain this language feature for clarity after build and test-speed work, with sound ownership tracking and explicit exception rules. Decide those rules before implementation: catch restores depth, not overwritten cells; a throw cannot revive a moved owner. Existing resource paths use explicit catch/finally or scoped C2 cleanup, and quotations do not capture enclosing locals. The review established useful ergonomics, not a new production blocker or an automatic destructor mechanism. Preserve fail-closed behavior until all continuing paths and unwind shapes account for each owner. Evidence is source inspection of Tender b3335787, Kaizen 9ce06aa0 and Maki 2a43e45a; no runtime qualification was performed.
