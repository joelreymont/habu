Problem: a linear (own) value cannot be held in a typed local: test/engine-suite.f rejects every {: x:own :} shape including a single move (CBAD-OWN-LOCAL-ONCE, -BRANCH, -MAKE), fail-closed. The handoff of 2026-09-19 sections 6-8 states the required semantics - binding moves ownership into the local, the first reference moves it out, a second reference rejects, EXACTLY once on every continuing path (a leak is a reject): if/else arms join to one ownership state and a terminating arm does not join; MATCH/CASE arms likewise; a repeatable back edge must carry the same ownership state as loop entry (an owner bound before a loop and consumed inside rejects unless the loop proves one execution); 'exit' validates every active obligation on its path; scope exit checks a branch-local owner before its frame is discarded; throw/unwind needs an explicit policy (fail closed on unsupported shapes) - and a candidate exists on experiment/wide-typed-locals@origin (4eeed7ba and the session's habu-linear-locals-candidate.zip, not in ~/Downloads) that was never validated by the native compiler. Acceptance, in two steps: (1) a design note in docs/effects.md (the ownership section) fixing the rules above as this checker's rules, decided after reading the candidate and the existing OWN machinery (checker.f linear tracking, RS-CAPTURE), naming the throw policy; (2) the implementation with the ~30 fixture shapes the handoff lists (single move, dup, leak, double free, branch agree/disagree, loops with LOOP/+LOOP/BEGIN-AGAIN/UNTIL/WHILE-REPEAT and zero-trip and LEAVE, shadowing, early return, wide linear values, closed parameterised owners) - the engine-suite CBAD rows that become accepted flip to COK with the reason stated. Files: src/core/checker.f, test/engine-suite.f, docs/effects.md. Verify: fixtures; three generations; test/run.f. Depends: habu-bind-a-wide, the parametric-annotation dot. Ownership: checker. Claim: unassigned. Alder's read of the draft (experiment/wide-typed-locals@origin e714ccdb): CF-LOC-REST truncates the locals table without checking the obligations it drops, and CF-+LOOP lacks the LOCUSED-BACKEDGE join the other loop forms have - both are the scope-exit and back-edge rules above, so the design note must state them before any of that code is reused.
