Problem: src/compiler/target.f knows aarch64 and ptx as CTARGET arch variants, and the native compiler requires src/arch/arm64/asm.f directly, so adding a tic6x (or arm32) target would tempt an unconditional per-arch require list that bakes every backend into bin/hb. Joel wants optional backends compiled in only when a program does that work. Acceptance: one registry in src/compiler/target.f where a backend module registers ( arch-id lowering emit ) when it loads, through a checked declaration with typed quotation rows (never a raw xt cell); CTARGET resolution asks the registry and an arch with no row refuses with a named E-CTGT-UNLOADED in lib/errors.f (family prefix E-CTGT-; a second registration of one arch is E-CTGT-REGISTERED, a full table E-CTGT-ROW); src/arch/arm64/ registers the same way (src/arch/arm64/backend.f, package A64BACK, owning the machines-served predicate) so the host backend is not a special case and the engine's own build proves the path; target.f keeps no per-arch require list; bin/hb bakes only what the prefix requires (arm64), leaving the recovery chain untouched. hb-build has no --target flag and nothing cross-compiles through one (hazel 2026-09-17), so the registry is the single resolution point every compilation passes through: a program that requires a backend module gets it, one that does not gets the refusal. Two sequential workers: (1) the registry rows (acceptance quotations, since target.f sits below the IR and cannot name pass types), the two stage gates A64IR:CHECK-TARGET and A64EMIT:TARGET-CK resolving through it, A64BACK, the errors, the tests; (2) the pass dispatch: src/compiler/compiler.f calling lowering and emit through typed quotation rows the backend registers above ir/build.f, keyed by the same arch value, so an engine carries only the backend it loaded. Files: src/compiler/target.f, lib/errors.f, src/arch/arm64/backend.f, src/compiler/native/a64ir.f and emit.f (the gates), src/compiler/compiler.f (worker 2), test/compiler/target-registry.f with the refusal test and the arm64 registration test, test/compiler/backend-boundary.f (the unloaded arches now answer E-CTGT-UNLOADED). Verify: bin/hb --load test/compiler/target-registry.f; bin/hb --load test/compiler/target-policy.f; full suite after the engine rebuild. Depends: hazel's stack-guard removal and engine rebuild landing first. Ownership: hazel runs it as a Habu lane (unclaimed by kestrel through 2026-09-17; Joel is starting the x86_64 backend, whose lowering dot habu-lower-hir-to-6bf80d33 depends on this registry) and reviews the contract before it lands.
