Lead note (2026-10-01, NX `habu-name-the-exit-ab1864c1` landed): a writer loaded after the capture compiles for the window's machine, because `CHECKER-REG:SEAL` (`src/habu/native-runtime.f`) runs `NCOMP:INSTALL` and the window's `NABI:BINDING` then reads the window's `target.f`; in the x86 window `native-emit.f`'s closure compiled to x86 inside the AArch64 engine and threw -8787 (`E-X64EMIT-PLACE`) at `ICODE-MAP>PTR`. So the x86 writer is compiled before the window opens, or the post-capture compiler handover changes. Until then `WRITER-MACHINE-CK` (`tools/native-build-core.f`) stops a foreign-machine window before the writer with rc 74, pinned by `FOREIGN-WINDOW-CASE` in `test/native-build-entry.f`; this leaf replaces that stop. From X2b: native-build does not yet load `src/habu/aot-shadow.f` or call `AOT-CAPTURE:SHADOW-CAPTURE`; the driver loads it before the window and calls it after `CAPTURE`, and the writer refuses empty shadow sections. The shadow sections count against `AOT-SECTION-CAP`; their size for a whole-engine cross-build is unmeasured.

Lead note (2026-10-01, X4b `habu-link-records-and-647852d3` landed): `src/habu/link-x64.f` (`X64LINK:LAYOUT`) builds the records, wids, protected-wid bitmap and name index at write time (the index is deterministic across hosts, so the writer builds it and the boot does not run `seed-ndict!`); this leaf writes `DICT$`/`CODE$` into the region and `BITS$`, `INDEX$`, `WIDN`, `T0-CELL`, `HIDXP-CELL`, `CLAIMS` and the heap floor into DATA, and stops the boot replacing them. Load order: `aot-decl.f` needs `AOT-SECTION-CAP`, which only `src/arch/arm64/icode.f` defines, and that file's globals `CODE`, `LBL`, `ASM-LEN` make a later `using X64CODE` refuse (`E-USING-SHADOW-GLOBAL`); the x86 writer's closure cannot load arm64/icode.f, so this leaf moves `AOT-SECTION-CAP` to a target-neutral file or otherwise settles the order.

Lead note (2026-10-01, KS `habu-key-shadow-rows-d4d1da9d` landed): shadow rows, site targets and XT rows are keyed by shipped record row (`SH-NUMBER` in `src/habu/aot-shadow.f`). A stripped live routine is carried only when an adjacent shipped row shares its emission; otherwise the capture refuses it by name (`SH-STRIPPED`, rc 74), and a site naming a stripped record is refused (`SH-UNSHIPPED`). So a live private helper called by a public word, the usual package shape, is refused under a shadow today. A stripped x86 product needs a carrier for unshipped live bodies (a format key for them, perhaps the payload's span rows, and a site tag naming one) before X4d can strip. `ACAP-TGT>REC` picks the lowest record at an entry, so a call to a private word a shipped alias re-exports is refused, not keyed to the alias.

Lead note (2026-10-01, batch 10 sweep): depends on habu-compile-definer-bodies-1292d049 (I7): `link-x64.f` refuses a record without an x86 routine, and a variable, created word, defer or `does>` child has none until I7.

Lead note (2026-10-01, batch 8-10 review fixes): (1) The writer places the window's DATA at `DATA-AT` and the boot's DP starts at `DATA-AT + AOT-DATA-SIZE`; nothing refuses `DATA-AT + AOT-DATA-SIZE > X64KERNEL:DP-CEILING`, the twin of `EM-AOT-RELOC-DATA`'s "hb: AOT data span out of range" (`src/habu/habu2.f`). This leaf adds that refusal, and settles `X64LINK:HEAP-FLOOR`, which docs/x86-64.md (the `INDEX$` and window-DATA rows) still calls the heap floor. (2) `src/habu/link-x64.f` now requires `src/arch/arm64/icode.f` for `AOT-SECTION-CAP` (aot-decl.f), so it loads standalone; the writer closure cannot load that file (above), so moving `AOT-SECTION-CAP` to a target-neutral file also drops that require. `src/os/linux-x86-64/elf.f` now requires `src/arch/x86-64/icode.f` and `src/os/image-bytes.f`; `tools/build-fixpoint.f`'s x86 cross stream appends image-bytes.f as plain source and loads no x86 icode.f, so this leaf supplies both as modules there. (3) A stripped or retired (`undefine`d) window record files no shadow routine. Its liveness is real reach (`ACAP-SHADOW-REACH`, `ACAP-SHADOW-LIVE?` in `src/habu/aot-capture.f`): from the named records (an `EXPORT` alias included), the declared code cells and every gap but a retired body, through ordinary and retired bodies alike, following an edge only out of a reached body. A live one is refused by name (`SH-STRIPPED`, rc 74) unless a shipped row over its emission carries it, and a shadow site or code cell naming one is refused (rc 74). ARM64 retention is unchanged: it keeps every retired body as a gap root and what that body calls. So a private word only dead retired code calls now captures rc 0 (it was refused as live), and `private : H2 7 ; public EXPORT H2` is refused naming H2 (the alias shipped with no routine); both are cases in `test/aot-shadow-capture.f`. The carrier for unshipped live bodies (KS note above) covers these cases too, the `EXPORT` aliases included.
