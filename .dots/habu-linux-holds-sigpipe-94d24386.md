Problem: FD:FD-NOSIGPIPE! sets a flag on one open file description on macOS (fcntl 73). Linux has no such command, so both Linux kernels emulate it by ignoring SIGPIPE for the whole process (src/habu/kernel-x64.f:1432-1444, src/habu/habu1.f:1020-1042) and nothing can put it back. After the first such call a Linux program gets E-FS-IO from every write to a broken pipe where the same program on macOS still dies of SIGPIPE: one machine behaves differently from another. Found while designing habu-a-log-line-839239b8, 2026-11-10. Acceptance: holding SIGPIPE off for one descriptor or one call means the same on every target, and can be undone on every target. Files: the Linux kernels' fcntl, src/lib/fd.f. Verify: a test that, on each target, two writes to two broken pipes are both refused with the process alive, that a program it then starts still dies of SIGPIPE on its own broken pipe, and that console output to a closed stdout ends the process by SIGPIPE. Depends: habu-a-log-line-839239b8 (adds FD:WITH-NOSIGPIPE). Ownership: the kernels' signal handling. Claim: agent=bob workspace=.jj-ws.noindex/habu-linux-holds-sigpipe-94d24386

Design inputs added 2026-11-10 (bob), from the census (/Users/joel/Work/reviews/habu-10x-2026-11-10/session2-notes.md "SIGPIPE census"): (1) Linux's spawn path never resets SIG_IGN before execve, so every program a Linux process starts after its first FD-NOSIGPIPE! inherits SIGPIPE ignored. (2) test/x86-64-kernel-syscalls.f:347 pins fcntl 73 with arg 0 as still ignoring SIGPIPE; on macOS arg 0 clears the flag. (3) The wake pipes at src/lib/curl.f:1063 and src/lib/ws.f:290 and the signal stub's self-pipe are never armed. (4) io_uring OP_WRITE gets no SIGPIPE handling; whether it raises is not determined. (5) No target has a word for the thread signal mask, pending signals or waiting for one. Not measured: whether macOS delivers a write's SIGPIPE to the writing thread.

Measured 2026-11-10 (bob), probes and outputs in the workspace's .out/sigpipe2/, summary in /Users/joel/Work/reviews/habu-10x-2026-11-10/session3-notes.md section C: on Linux arm64 and x86-64 a write's SIGPIPE goes to the writing thread, and block, write, zero-timeout rt_sigtimedwait, restore works for write, writev and inline io_uring; an io_uring write on io-wq leaves the signal on the worker thread, and a write that waits raises it on the submitter outside the call; a SIGPIPE pending before the write cannot be told apart. On macOS the signal goes to the process, not the writing thread, and there is no non-blocking wait; F_SETNOSIGPIPE is per open file description, shared by dups and inherited across fork and exec. So no one mechanism serves every target. The LOG feature review's F1 belongs here: two holds that overlap on one open file description undo each other (two processes sharing fd 2; src/lib/aio-macos.f:191-209 holds under another lock). Joel, 2026-11-10: a fix launches without waiting for him; its public items go to him as facts. The design is running.

Design 2026-11-10 (Fable, /Users/joel/Work/reviews/habu-10x-2026-11-10/sigpipe-design.md): every Habu process ignores SIGPIPE from start-up on all three targets (beside the crash handlers: crash.f G-INSTALL-CRASH-X11, boot-x64.f SETTLE,); every program it starts gets the default back (Linux: before each execve; macOS: the spawn attribute's default set); a checked write to a broken pipe is refused (E-FS-IO); console words, which have no result, end the process by SIGPIPE when stdout's reader is gone (G-OUT); SIGNAL refuses 13. Removed: FD:FD-NOSIGPIPE!, FD:WITH-NOSIGPIPE, FD:F-SETNOSIGPIPE, FD:F-GETNOSIGPIPE, fcntl 73 on Linux with both emulations, tcp4.f MSG-NOSIGNAL, the arming lines in lsp-core.f, process.f, aio-macos.f and the tests. Added: nothing. Why: the measurements leave the process-wide disposition as the one mechanism that works for every write path on every target, and it cannot be switched per call without racing other tasks. The Verify sentence above was the lead's, written before the measurements, and is replaced: no descriptor is armed any more. DECISIONS.md:1924-1928 lists FD-NOSIGPIPE! among FD's public words; the landing corrects it. The LOG stack lands first with its hold; this feature removes the hold. Four facts are measured before anything is built (design section 9); the worker runs in this workspace, outputs in .out/sigpipe3/.
