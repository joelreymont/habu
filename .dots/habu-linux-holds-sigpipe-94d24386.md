Problem: FD:FD-NOSIGPIPE! sets a flag on one open file description on macOS (fcntl 73). Linux has no such command, so both Linux kernels emulate it by ignoring SIGPIPE for the whole process (src/habu/kernel-x64.f FCNTL-ROW, src/habu/habu1.f:1004-1026) and nothing can put it back. After the first such call a Linux program gets E-FS-IO from every write to a broken pipe where the same program on macOS still dies of SIGPIPE: one machine behaves differently from another. Found while designing habu-a-log-line-839239b8, 2026-11-10. Acceptance: holding SIGPIPE off for one descriptor or one call means the same on every target, and can be undone on every target. Files: the Linux kernels' fcntl, src/lib/fd.f. Verify: a test that, on each target, two writes to two broken pipes are both rejected with the process alive, that a program it then starts still dies of SIGPIPE on its own broken pipe, and that console output to a closed stdout ends the process by SIGPIPE. Depends: habu-a-log-line-839239b8 (adds FD:WITH-NOSIGPIPE). Ownership: the kernels' signal handling. Claim: unassigned

Design inputs added 2026-11-10 (bob), from the SIGPIPE census: (1) Linux's spawn path never resets SIG_IGN before execve, so every program a Linux process starts after its first FD-NOSIGPIPE! inherits SIGPIPE ignored. (2) test/x86-64-kernel-syscalls.f:347 pins fcntl 73 with arg 0 as still ignoring SIGPIPE; on macOS arg 0 clears the flag. (3) The wake pipes (AIO:WAKER-OPEN, src/lib/aio.f:805-807, opened at src/lib/net/curl.f:1838, src/lib/net/ws.f:1624 and src/lib/net/http.f:1115) and the signal stub's self-pipe are never armed. (4) No target has a word for the thread signal mask, pending signals or waiting for one. Not measured: whether macOS delivers a write's SIGPIPE to the writing thread.

Measured 2026-11-10 (bob): on Linux arm64 and x86-64 a write's SIGPIPE goes to the writing thread, and block, write, zero-timeout rt_sigtimedwait, restore works for write and writev; a SIGPIPE pending before the write cannot be told apart. On macOS the signal goes to the process, not the writing thread, and there is no non-blocking wait; F_SETNOSIGPIPE is per open file description, shared by dups and inherited across fork and exec. So no one mechanism serves every target. The LOG feature review's F1 belongs here: two holds that overlap on one open file description undo each other (two processes sharing fd 2). Joel, 2026-11-10: a fix launches without waiting for him; its public items go to him as facts. The design is running.

Design 2026-11-10 (Fable): every Habu process ignores SIGPIPE from start-up on all three targets (beside the crash handlers: crash.f G-INSTALL-CRASH-X11, boot-x64.f SETTLE,); every program it starts gets the default back (Linux: before each execve; macOS: the spawn attribute's default set); a checked write to a broken pipe is rejected (E-FS-IO); console words, which have no result, end the process by SIGPIPE when stdout's reader is gone (G-OUT); SIGNAL rejects 13. Removed: FD:FD-NOSIGPIPE!, FD:WITH-NOSIGPIPE, FD:F-SETNOSIGPIPE, FD:F-GETNOSIGPIPE, fcntl 73 on Linux with both emulations, tcp4.f MSG-NOSIGNAL, the arming lines in lsp-core.f, process.f and the tests. Added: nothing. Why: the measurements leave the process-wide disposition as the one mechanism that works for every write path on every target, and it cannot be switched per call without racing other tasks. The Verify sentence above was the lead's, written before the measurements, and is replaced: no descriptor is armed any more. The LOG stack lands first with its hold; this feature removes the hold. Three facts are measured before anything is built; the worker runs in this workspace.

Measured 2026-11-10 (bob). (1) macOS: raw syscall 46 with Habu's record (handler 1, trampoline 1, mask 0, flags 0) returns 0; four threads, one created after the call, 10000 writes each to reader-less pipes: all EPIPE, nothing pending, process alive. (2) macOS: POSIX_SPAWN_SETSIGDEF is 0x4 in the short at +0 of the attribute record and the default set is the u32 at +4 (SIGPIPE is bit 12); raw syscall 244 with Habu's record plus flag 4 and bit 12 starts the child at SIG_DFL (it dies WTERMSIG 13); without it the child inherits the ignore. (3) All three: kill(getpid, SIGPIPE) after SIG_DFL ends the process WTERMSIG 13; with SIGPIPE blocked in every thread the kill returns, so the exit-141 fallback is needed. The design stands; the lanes are briefed once the LOG stack has landed, since they remove its hold.
