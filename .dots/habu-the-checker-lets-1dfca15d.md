Problem: 'create T 4 cells allot : S ( ptr n -- ) T CELL-VIEW 0 ptr-field ! ;' certifies (rc 0 on the installed hb under --load, tools/check.f and --verify-only), while the same line without CELL-VIEW is refused E-RAW-CELL-PTR ('ptr-field: base is an undeclared raw storage cell'). cell-view (src/habu/prims.f, ( ptr u8 -- ptr n )) answers a concrete ptr n from raw storage, and RAW-FIELD-TOK? / RAW-FIELD-BASE? (src/core/checker.f) refuse only a base whose pointee is still a RAW variable, so ptr-field's row ( ptr a n -- ptr ptr b ) turns a scalar cell into a pointer cell. A store through it marks no address cell, so a build copies the address as bytes: this is how src/lib/queue.f's Q-RECS crashed a built program (dot habu-a-built-program-3cee92c8). A third open launder beside the two docs/forth.md 'Raw storage never holds an address' lists. Reach: src/lib/task.f (the TASK definer, 'here CELL-VIEW ... 0 ptr-field !' with a hand ptr-cell-mark) and src/lib/error.f ROW, use the pattern and mark by hand, so they work today and a stricter check refuses them: they move to a declared form in the same change. Not searched: addresses laundered as integers (FFI:>CELL then !) into raw storage. Acceptance: the line above is refused with E-RAW-CELL-PTR naming the cell; task.f and error.f lay their pointer cells with a declared form and no hand mark; docs/forth.md and the card state the rule; the suite passes. Files: src/core/checker.f, src/habu/prims.f (rows), src/lib/task.f, src/lib/error.f, docs/forth.md, docs/forth-card.md. Verify: a rejected-program test through the real load path; the full suite (shared checker behaviour). Depends: none; after the incremental-builds stack lands. Ownership: unassigned. Not brief-ready (lead, 2026-11-10). The rule cannot be written as stated: `cell-view` answers a concrete `ptr n`, so "refuse ptr-field after cell-view" is "refuse a scalar-pointee base", which also refuses plain readers (src/lib/error.f ROW-PREV `( ptr n -- ptr n ) 0 ptr-field @`, src/lib/task.f's TASK) and leaves the `( ptr a -- ptr ptr u8 )` parameter variant open. It is the same hole as habu-refuse-ptr-field-331a9731 and habu-refuse-a-scalar-030be3ad (rule F1, 205 sites, BUF's header a public change). No declared form lays a pointer cell inline in a create'd record. Next step is a census, not a fix: a log line in src/core/checker.f RAW-FIELD-TOK? classing each ptr-field base's pointee (RAW variable, other variable kind, pointer, concrete atom) with its source line, on an engine rebuilt twice (the second build checks the engine's own sources) plus `tools/check.f -- FILE` over src/lib, tools and test.
