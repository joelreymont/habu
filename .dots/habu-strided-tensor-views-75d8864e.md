Design gap surfaced 2026-07-20 by Joel's question 'do we have view semantics on tensors like in pytorch?'. Answer today: NO stored view objects - tensor values carry (rows, cols, dtype, layout) where layout is an ENUM of contiguity order ONLY, and maki/tensor-value.f:54 explicitly reserves the successor: 'v1: contiguity order only; strides arrive with cad-1'. What substitutes today (and stays): equation-level index freedom (transposes/broadcasts are free by INDEX POSITION in SPEC: lines - no materialized transpose; K enters S=Q·Kᵀ transposed by writing indices), zero-copy window binding (EX-BIND binds caller slices - the batch loop binds TxC windows of the B*T buffer), and the SSA-shaped graph (every node output owns its arena slot, EX-NODE-PTR - no in-place ops inside the differentiable graph, so PyTorch's in-place-op-invalidates-saved-tensor bug class is STRUCTURALLY ABSENT; keep it that way). The one aliasing hazard lives at the host facade (mha.f alias-unsafe, recorded in habu-own-multi-head-c863298a). BUILD the v2 when a consumer binds: the concrete drivers are (a) KV-cache windows for incremental generation (the generation dot's declared follow-up - ring-buffer views over the context), (b) head-split views for multi-head attention (H views into one QKV buffer without re-indexing per equation), (c) non-contiguous device transfers (TMA box strides - the PROMOTE leg already carries extent magnitudes). Design constraints: views stay READ descriptors (offset+strides+extents over immutable-during-run storage) so the SSA no-mutation property is preserved - do NOT import PyTorch's mutable-view semantics and its bug class; the checker types a view like a tensor with provenance to its storage extent (the extent-role machinery is the natural host); adjoints of view reads are scatter-adds into the storage adjoint (the GATHER adjoint pattern already landed). Sequence: after the multi-head attention dot proves which views it actually needs - do not design ahead of the first consumer. Territory: maki/tensor-value.f layout v2 + executor read path + checker extent provenance + tests.
