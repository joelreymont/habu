PRIM: cannot be written in a test file either (internal after the seal). The honest design is not a wider public API: a whitebox suite runs against an engine built WITHOUT the seal, where internal words are ordinary words with checker rows and checked bodies call them directly; test/cold-engine.f already builds a content-keyed cold fixture engine per gate. Acceptance: the gate can declare a suite whitebox (test/gate-stdlib-cases.f), and such suites run on an unsealed cold engine built once per gate (same content key, one extra flag), never on the product engine; test/internal-word-gate.f keeps pinning the product seal; the 424 sites convert to checked definitions on that engine, suite by suite, with case counts unchanged (the sweep lane classifier and per-suite counts are the method); the TRUSTED: count under test/ drops by that number. Files: test/cold-engine.f, test/gate-stdlib-cases.f, lib/test/runner.f, tools/build-fixpoint.f or the cold build entry (a no-seal switch), the whitebox suites. Added 2026-09-17 (harness lane, ff1c88e1): the mechanism behind the recovery-engine refusals is that a created word (variable/constant) publishes its checker effect only if the check hook is installed when it is defined (habu2.f LASTC-TRUST:FIND-ACTIVE), so every variable and constant src/core/checker.f creates before check-hook.f is checker-unknown on a from-source-prefix engine and checker-known on a seeded one. The honest long-term fix is to trim those rows out of the baked store so every engine class exposes the same surface; each whitebox suite that names such a word (test/structure-make-suite.f and the declaration suites name CHECKER-PACKAGE-PUBLIC and TK-* at top level; TK-PRODUCT is sealed on hb-stdin) then needs a public probe or an unsealed engine.
