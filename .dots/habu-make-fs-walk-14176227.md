Problem: lib/fs.f keeps the WALK-FILES state process-wide (FS-WALK-BUF and FS-DIR-BUF: 32 depths of PATH-CAP and 4096 bytes, FS-DEPTH, the FS-BASES/FS-FDS/FS-NS/FS-OFFS/FS-RECS stacks, FS-WALK-ACTIVE, FS-CHILD-U, FS-NAME-A/U; lib/fs.f:116-128) and REMOVE-TREE walks through it (lib/fs-mutate.f:139). lib/fs-mutate.f keeps every per-call buffer process-wide (lib/fs-mutate.f:32-45): FS-MUT-PATHZ2-BUF (the second NUL path of RENAME-FILE, MAKE-SYMLINK, COPY-FILE), FS-MUT-TMP-PATH (MAKE-TEMP-DIR returns a span INTO it, line 257), FS-MUT-ATOMIC-PATH, the 8 KiB FS-MUT-COPY-BUF and five copy cursors. Tasks are pthreads (docs/threads.md), so two tasks in MAKE-TEMP-DIR, RENAME-FILE, COPY-FILE, ATOMIC-WRITE-FILE, WALK-FILES or REMOVE-TREE at once corrupt each other, and any task's MAKE-TEMP-DIR overwrites another task's returned path. Found by cedar for Tender (pin 806f0654, engine 274f9bea): two fill tasks cannot own, rename or clean their files, so Tender holds one execution lock around fs and sha until both are safe. Witnessed reproducer /home/joel/.cache/tender/habu-gaps/fs-call-state/repro.f (run.log beside it; run from that frozen root with TMPDIR=/home/joel/.cache/tmp bin/hb --load repro.f): task A's MAKE-TEMP-DIR return shows task B's path after a barrier, rc 1. Constraint: fs-mutate.f is loaded by tools/native-build-core.f, so task-local storage is a declared band in src/habu/layout.f (docs/threads.md, Which mechanism), and a task region is 0x10000 bytes whose band run 0x5300..0x8000 already holds STRING-ABI, FMT-ABI, FS-ABI (1328 bytes) and USER-BAND: the walk (about 164 KiB) and the copy buffer cannot be per-task; the three path buffers and six cursors (about 3.1 KiB) can only if the run has the room. Acceptance: (1) a caller-owned walk context: a byte-size constant and typed words that walk a tree and remove a tree through a context span the caller allots (names per the card), every walk cell in the context or in typed locals, no process-wide cell on that path; WALK-FILES and REMOVE-TREE keep their effects as wrappers over one static context (header and docs/threads.md keep them single-task) or go with their 16 and 16 caller files migrated. (2) fs-mutate.f per-call scratch is task-local or caller-owned so a task's MAKE-TEMP-DIR, TMPDIR-MKDIR and HB-TMP-MKDIR return stays valid until that task's next call and RENAME-FILE, MAKE-SYMLINK, COPY-FILE, COPY-FILE-STREAM and ATOMIC-WRITE-FILE from two tasks share nothing: a declared FS-MUT-ABI band for the path buffers and cursors with an FS-BAND-AGREE-style load assertion if it fits, else caller-owned destination variants with the old words documented single-task wrappers; the copy buffer becomes a caller-owned span or a band-sized chunk, copy throughput measured before and after. (3) the cleanup registry (CLEANUP-RESET/RUN/AT-EXIT, 64 paths) stays the process-wide exit registry; a registration claims its slot atomically or both header and docs/threads.md say it is main-task-only. (4) both headers and the lib/fs.f row of docs/threads.md state the new classes; the context words are the vocabulary Tender adopts. Tests: a two-task MAKE-TEMP-DIR row in the reproducer's shape in lib/fs-mutate-test.f and a two-task walk row through distinct contexts in lib/fs-test.f; the Tender reproducer is the consumer check. Files: lib/fs.f, lib/fs-mutate.f, src/habu/layout.f, lib/fs-test.f, lib/fs-mutate-test.f, docs/threads.md. Verify: the two test files, the WALK-FILES and REMOVE-TREE callers' tests, the chain (a layout change). Depends: none. Ownership: lib/fs.f, lib/fs-mutate.f.
