Joel-directed 2026-07-21: build a vLLM-class INFERENCE ENGINE in Habu, tailored to the GB10's unified memory (128 GB coherent pool, ~273 GB/s bandwidth shared CPU/GPU). Why this is tractable: UMA deletes vLLM's hardest machinery - no swap tier, no block migration between GPU and host memory, no staged copies; weights mmap straight into GPU-visible memory; the scheduler collapses to bookkeeping over one allocator watermark. Habu already has the harder substrate: near-Triton MMA GEMM (tf32/fp16/bf16, autotuned), device RMSNorm/LayerNorm/softmax/RoPE, the GPT-2 tokenizer at exact tiktoken parity, a generation/sampling loop, exception-safe CUDA lifecycles - and inference needs NO autograd. Sequencing: phase 1 foundation (safetensors weight loading + UMA residency, paged KV allocator, sampling ops, SwiGLU) -> phase 2 the crux (fused decode-attention kernel over paged KV: online softmax, block-table gather, TMA page fetches per the ISA probe - consumer-Blackwell path, no tcgen05) + the GPT-2 124M real-weights end-to-end milestone -> phase 3 continuous batching -> phase 4 NVFP4 quantization (THE lever: decode is bandwidth-bound, bf16-7B caps ~20 tok/s at 273 GB/s; NVFP4 proven working on this chip) -> phase 5 serving front end. First real model = GPT-2 124M (tokenizer and every kernel except decode attention already landed); LLaMA-family second (RMSNorm+RoPE landed; needs GQA, SwiGLU, its tokenizer). UMA cautions baked into the design: CPU and GPU share bandwidth so host work stays off the decode path; Grace cores do sampling/detokenize overlapped. Related standing dots referenced NOT blocked: habu-op-mha-fused-0fa2ef1b (training/prefill graph node), habu-gb10-batched-attention-3055d565 (prefill leg), habu-ptx-opt-layer-325b9507 (tile-IR; flash-tiled attention is its acceptance target). Joel-directed focus: NOT blocked behind the type chain; type-DSL migration of these modules rides the standing migration waves later.

PLAN OF RECORD 2026-07-21: docs/inference-engine-plan.md (external review, incorporated by Joel's direction). Thesis CORRECTED: not "UMA deletes vLLM's hardest machinery" but "GB10 UMA removes the discrete-memory offload tier, enables one capacity planner, avoids full-weight staging copies, and lets the remaining serving machinery specialize for one architecture and a small concurrency envelope." Paged KV and continuous batching remain REAL problems inside one pool (dynamic growth, fragmentation, prefix sharing, chunked prefill, fairness, backpressure); vLLM V1 already dropped its CPU swap tier, so the differentiation is the narrow execution contract + GB10 memory policy + model-specific compilation, not swap avoidance. Product contract: GPT-2 is the integration ORACLE, not the product; the first product gate is a modern dense 7-8B (GQA+RoPE+RMSNorm+SwiGLU) with a pinned checkpoint; an MoE flagship only after. Compiled model-pack format (pack once, boring loads) and explicit allocation classes (each with owner/lifetime/alignment/access/sync/cleanup/accounting) are design pillars. No public performance claim before the M0 measurement contract exists. Release gates, benchmark protocol, and scope exclusions per the doc.
