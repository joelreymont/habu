Problem: since 234ddc96 every FS:ATOMIC-WRITE-FILE syncs the sibling and the directory (F_FULLFSYNC on macOS). The build cache writes its objects through it (tools/native-definition-cache.f, tools/native-unit-file.f, tools/keyed-image.f): an estimated 170 objects per cold macOS build at about 11 ms each, about 1.9 s, unmeasured; the cache already treats a damaged entry as a miss. The other way round, FS:REPLACE-STAGED (src/lib/fs-mutate.f:1044; callers tools/hb-build-lib.f, tools/install.f, src/lib/svg-pdf.f, src/habu/link-map.f, src/habu/link-data.f, src/habu/linker.f) and snap-lib's image publish (src/habu/snap-lib.f:559-579, RESERVE-SIBLING then RENAME-FILE) rename with no sync, so a crash can leave an installed hb or built image empty under its name (fsync review findings 5 and 6). Step 1, the lead's measurement: a cold-cache engine build (`rm -rf .out`; `bin/hb --load tools/native-build.f -- <out>/hb`) at f07bec12 and at 234ddc96 on spark, same engine both sides (docs/debugging.md "Timing a change"), plus the count of syncs in one cold macOS build times a probe's per-call F_FULLFSYNC cost. Step 2: a design for which publishers sync, with that evidence; it changes failure recovery, so it goes to Joel before any worker. Files: per design. Verify: per design. Depends: none. Ownership: unassigned. Claim: unassigned.

Step 1 (measure) done: spark cold engine builds (173 files) without the sync 116.4 s, 119.7 s; with it 120.4 s, 119.9 s, user 115.4-118.6 s throughout (spark:/tmp/carl-linux/syncrun/summary.txt). macOS, 200 FS:ATOMIC-WRITE-FILE of 4 KiB: 165-260 us per call unsynced, 10.3-10.5 ms synced; about 1.8 s of a cold macOS build (inferred, not measured end to end).
Step 2 (design, Plan on Fable) done. For builds: the build cache keeps the sync (an unsynced word would be a new public word the 2026-11-05 ruling excluded and would extend the per-definition cache the file linker replaces). The rest is durability, not build speed: FS:REPLACE-STAGED syncs the sibling after fill and the directory after the rename (a public contract change); native-build-core, keyed-image, seed, bundle-lib-core, zip-raw and hb-build's map pair move onto it; CODESIGN:PROMOTE-EXECUTABLE and PROMOTE-SIGNED-EXECUTABLE go (public removals).
