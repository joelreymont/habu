Joel-directed 2026-07-20: implement BPE for real GPT-2 text, not just char-level Shakespeare. GPT-2's scheme is byte-level BPE: 50257-token vocab = 256 byte tokens + 50000 learned merges + 1 special (<|endoftext|>), operating on UTF-8 BYTES (every input encodable, no unknown-token case) with the regex pre-split pattern partitioning text into word-ish chunks before merges apply within each chunk. Two deliverables, sequenced: (1) ENCODE/DECODE against a COMMITTED vocab+merges fixture - load merges (rank-ordered pairs) + vocab, greedy lowest-rank merging within pre-split chunks, byte-level round-trip proven (decode(encode(x)) == x for arbitrary bytes incl. invalid-UTF-8 sequences), plus parity fixtures generated once from the reference tiktoken/nanoGPT encoder on known strings (the torch-ref pattern: adam-torch-ref-data.f) - exact token-id sequences pinned; (2) TRAIN-MERGES on a corpus (the from-scratch path): learn merge ranks from tiny-shakespeare, deterministic (tie-breaking rule fixed and documented), locked merge table for the committed corpus. Follow the landed tokenizer discipline (fe907212): every public word bounds-checked and domain-validated red-first, ready-state gated, named E-codes in a free block, canaries, no partial writes on rejection. The regex pre-split needs a decision: implement the GPT-2 pattern honestly over bytes (no regex engine exists in-tree - a hand-rolled matcher for exactly that pattern with its own tests) or document a principled simplification with measured parity impact on the fixtures - NO silent approximation. Storage: the 50257-vocab tables are ~MB-scale - decide committed-fixture vs runtime-loaded artifact with the DATA budget measured (the tiny trained-merges table IS committed; the full GPT-2 vocab likely runtime-loaded from a checked file). Territory: maki/examples/nanogpt/ (bpe.f + test + fixtures) with genuinely generic pieces (merge machinery?) extracted to library only if another consumer emerges - default app-side. Serialize behind nothing; independent of the capacity/attention chain.
