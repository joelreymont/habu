Why: the measured production command spends 146.468 seconds in authenticated `GPT2:OPEN` but only 0.818 seconds generating 64 tokens. A persistent process therefore needs the existing prompt-to-text path factored so one `GPT2:model` survives many requests instead of reopening per request.

Result: package `GPT2` adds `CONTEXT-LEN ( GPT2:model -- GPT2:model CAD-NUM:item-count )` and `EOS-ID ( GPT2:model -- GPT2:model n )`, both read from the model's validated config and preserve the same owner. New package `GPT2-GEN` in `maki/infer/gpt2-generate.f` owns the current authenticated BPE plus greedy-generation composition. It publishes `PROMPT-CAP = 4096` and `OUTPUT-CAP = 8192` as `CAD-NUM:byte-len`, and `MAX-TOKENS = 4096` as `CAD-NUM:item-count`; these are the existing encode-id, BPE-decode, and continuation-id staging capacities, not new limits. It owns the existing `E-PROMPT = -5665` and `E-STATE = -5666` errors moved from `GPT2-CLI`, plus `E-LIMIT = -5667`. `OPEN ( FS:path -- result<GPT2:model,n> )` authenticates and installs the pinned merges exactly once before opening the model. `GENERATE ( GPT2:model ptr u8 CAD-NUM:byte-len CAD-NUM:item-count ptr u8 CAD-NUM:byte-len -- GPT2:model result<CAD-NUM:byte-len,n> )` encodes the nonempty prompt before model mutation, rejects `max_tokens <= 0`, `max_tokens > MAX-TOKENS`, and checked `prompt_id_count + max_tokens - 1 > CONTEXT-LEN`, resets the model, feeds every prompt id, greedily generates at most the requested count, stops before `EOS-ID`, decodes only continuation ids into caller-owned output, and returns the model in every arm. The `- 1` is the exact autoregressive step count: the last selected token is returned by the preceding logits row and is not fed back. Stack-preserving BPE wrappers convert throws to generic results; no quotation passed to `catch` receives, captures, or consumes the live model. Caller output remains untouched on refusal. The existing CLI becomes a thin one-request consumer of `GPT2-GEN` with 64 requested tokens and must retain byte-exact behavior.

No new declared data type is permitted: reuse `GPT2:model`, `FS:path`, `CAD-NUM:byte-len`, `CAD-NUM:item-count`, and generic `result<T,n>`. Owner: model metadata accessors and transport-free GPT-2 generation composition only. Production red: `maki/infer/gpt2-cli.f` opens and closes the 548 MB authenticated model inside every request and exposes no reusable model-preserving generation call. Acceptance: metadata queries return the pinned config values without changing ownership; zero, `MAX-TOKENS + 1`, the exact context boundary and one over, BPE refusal, model refusal, EOS, decode-capacity refusal, exact and one-short output all preserve the model and caller buffer rules; a valid request immediately after a pre-mutation refusal matches the pinned ids and bytes; the unchanged direct CLI still matches all 64 pinned ids and exact bytes through the same `GPT2-GEN:GENERATE` body; owner counts return to baseline. Forbidden: tokenizer refactor or owner, second BPE algorithm, scheduler, cache abstraction, HTTP, socket, JSON, transport, thread, server state, sampling configuration, allocation framework, ABI/version, compatibility, manifest, lint, suite, fallback, or copied generation loop. Smallest owning checks: `bin/hb --load maki/infer/gpt2-generate-test.f -- gpt2-model` and the existing exact `maki/infer/gpt2-cli-device-test.f` production command.
