Problem: docs/x86-64.md (campaign habu-campaign-c6-targets-86bb56bb): the compiler's target-free half (hir.f, hir-word.f, elaborate.f, loop.f) stops at a machine IR that only exists for ARM64 (a64ir.f, select.f, emit.f). Acceptance: x64ir.f, select-x64.f and emit-x64.f as a backend module that registers its lowering and emitter through the target registry when loaded, so bin/hb for arm64 does not carry it; calls between compiled words use the internal convention (stack cells in memory, live values in registers within a routine); relocatable literals are mov r64, imm64; the module compiles the compiler's own test programs from the arm64 host for the x86_64 contract, and the emitted bytes for a fixed set of words are pinned in a test. Decide the emitter's sink first (hazel 2026-09-17, from the assembler lane): src/compiler/native/emit.f is a fixed four-byte word sink (INSN-BYTES 4 in INSN-CAP, SIZE, WORD@, MAP-OFFSET@ and the one-pass layout) and so is src/arch/arm64/icode.f EMITW, while X64ASM appends variable-length bytes into a lib/byte-buffer.f BUF header passed as each encoder's last operand and sizes an instruction only by encoding it into a scratch buffer; so emit-x64.f is either a parameterised emit.f whose layout pass works in bytes or a separate emitter over BUF, and the choice is recorded in docs/x86-64.md before code is written. Relocation of the literal patches at MOV-RI64-IMM-OFF (2) inside the 10-byte mov r64, imm64, the site kind the OS-seam lane calls MOVABS.
