Problem: src/habu/habu1.f BPOLL collapses every poll(2) error to -1 (`0 0 MOVN`), so lib/process.f PROC-POLL-CAPTURE cannot tell EINTR from EBADF and raises E-PROC-OUTPUT on any signal; poll is never restarted by SA_RESTART. Measured 2026-09-16 (profiler lane): with the 1 kHz sampling profiler armed, poll returns -1 after 1 ms instead of rc 0 after 2001 ms, and `include tools/native-build.f` dies at its final child-spawn phase with E-PROC-OUTPUT after about 99 s. Any signal breaks child capture, not only the profiler; lib/process-fork.f and lib/serial.f already loop over EINTR, the capture path does not.
