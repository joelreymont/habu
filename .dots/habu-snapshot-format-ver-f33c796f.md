Slice-3a destruction review NOTE 3 obligation, ahead of 3b. Once 3b bakes nonzero EN.E (hidden fields) into the effect-node arena persisted in a snapshot DATA region, a pre-3a engine restoring such an image silently misreads hidden fields as logical params (review proved new engine reading old image reads EN.E 0 = logical, so the skew is one-directional). Requirement: bump the snapshot format version so a pre-3a engine REFUSES a post-3b image with a NAMED diagnostic, never a silent misread; new engine reading old image must still restore (EN.E 0).

DETERMINATION (done this session, tfam-2b-iii from c6972032): the sole sound enforcement point is habu2.f, which is item-12-owned, so per the ownership constraint I stopped without implementing. Evidence: (1) the snapshot trailer is WRITTEN in src/habu/snap-lib.f:195 as 40 bytes / 5 fields: magic at 0 (SNAP-MAGIC E5321, src/habu/layout.f:10), CANONICAL text base 0 at 8, ndict at 16, region-len at 24, data-len at 32 -- NO version field, and offset 8 is not spare (the reader loads it as the snapshot-time text base x21 for relocation). (2) The ONLY runtime RESTORE path is native emit EM-SNAPSHOT-RESTORE (src/habu/habu2.f:2879): it checks magic at :2886 (C-NE -> snomag = skip restore, cold boot, no diagnostic), reads the trailer fields, then EM-SNAPSHOT-COPY-DATA (:2903) copies the DATA region -- this copy is exactly where a pre-3a engine would ingest post-3b EN.E and misread it. Any version check + named reject must sit after the magic match and before that copy, i.e. inside EM-SNAPSHOT-RESTORE (habu2.f). (3) src/os/image-bytes.f is a byte-cursor writer with no format-version field or reader. (4) tools/imgdump.f SNAP-CORE? validates a trailer (magic, ndict, region/data lens) but only to DUMP image info -- it never restores the DATA region into a live engine, so it cannot be the misread/enforcement point. (5) No checked warm-image / --under loader restores DATA outside the native EM-SNAPSHOT-RESTORE.

MECHANISM to implement in item-12 3b (where the format change itself lands): (a) add a format-version field to the trailer -- widen it from 40 to 48 bytes (snap-lib.f SNAP-WRITE-BYTES: write version at TRL+40 and DRV-WALL 40 -> 48; habu2.f EM-SNAPSHOT-RESTORE: the trailer base math 12 12 40 SUBI becomes 48, and load the version) -- do NOT repurpose text-base@8 (reader uses it for relocation). (b) In EM-SNAPSHOT-RESTORE, after the magic match (:2886) and before EM-SNAPSHOT-COPY-DATA (:2903), load the image version, compare to a supported-version constant baked in the engine; if image-version > supported, print a NAMED diagnostic (e.g. new named code E-SNAP-VERSION in layout.f, message like snapshot: unsupported format version) and NR-EXIT-GROUP, mirroring the snbad rc-79 corrupt-trailer path but with a distinct named code. Version starts at 1 for post-3b images; a 0/absent version (old 40-byte trailer) restores as today (EN.E 0 = logical). (c) update tools/imgdump.f SNAP-CORE? and the 40->48 trailer-size assumption. (d) NEGATIVE REGRESSION: a pre-3a engine (or an engine with supported-version < image-version) reading a version-1 image -> named reject (assert the E-SNAP-VERSION code + message); a new engine reading a version-0/old image -> restores, EN.E reads 0. Files: snap-lib.f, habu2.f (item-12), layout.f (new named code), imgdump.f, plus a build-fixpoint/warm-image negative fixture. Depends on / merge with item-12 slice 3b.
