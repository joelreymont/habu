Problem: the engine image (5,832,896 bytes, docs/engine-size.md) carries far more than an engine needs: 8,022 package-private dictionary records with names, their checker signatures in the user-signature store and their symbols in the symbol tables (private words are not reachable from the REPL once their package is closed), a sparse DATA encoding whose run headers are 2.06 MB for 0.79 MB of content, build-time table residue, and the toolchain metadata (records, code spans, call-site and address tables) that only hb-build, xref, imgdump, the profiler and the debugger read. Joel (2026-09-16): Habu itself is machine code plus a REPL and JIT; the image should carry what the REPL can reach, its names and type signatures, and nothing else. The tree already seals seven system packages by name (src/core/checker.f CHECKER-SEALED-PKG?, E-EXPORT-SEALED) but every other engine package can be reopened by user source, which is the one thing that keeps private names and signatures alive. Contract: (1) every package captured into the engine is sealed at capture: user source that reopens it or qualifies into it is refused by name (E-EXPORT-SEALED or a sibling), multi-file reopening stays available for the application own packages; (2) the image holds the code of every word, and records, names, signatures and symbols only for global and package-public words plus the keep-set the interpreter itself resolves by name at boot (one named table, one comment per entry); (3) private records, names, signatures and symbols are dropped at capture, and the toolchain metadata that tools need moves to a sidecar beside the image (`<image>.names` or a section the engine never maps) that hb-build, xref, imgdump, the profiler and the debugger read when present; (4) the DATA image is dense: run headers only where they pay, the signature store laid out without interleaved zero cells, build residue trimmed; (5) reported before and after with tools/engine-size.f, with the full gate, the stripped-application suites, Radar, Tender, Loom and Maki green on the result. Children: habu-merge-short-zero-512051d8 (headers), habu-capture-the-heap-3b453b61 (tables and residue), habu-ship-no-dictionary-2fee2dea (records, names, sidecar), habu-bind-baked-call-e4d5b58f (site tables), and the two new children filed with this dot: seal every captured package, and drop private signatures and symbols at capture.
