Problem (Joel, 2026-09-18, via aspen: 'implement this now'): the checker types a pointer's pointee but not its reach, so every copy into a buffer and every indexed dereference is bounded by a hand-written 'u cap > if throw' or by nothing; one forgotten check is an overrun (Tender-refuse-an-overrun-e2ed1dff). The reach half of habu-bound-ptr-arithmetic-8bf6b54a measured 4209 stepped-and-dereferenced sites in 2552 definitions (4115 bare +), so a rule alone cannot land; a TYPE that carries the reach with the address can, staged in bands. DESIGN (decided; docs/type-system.md gains the section with band 0): a span is one two-cell nominal value, base ptr t plus reach n counted in elements of t (bytes for span u8, cells for span n), a generic PRODUCT family 'STRUCTURE span 1 FIELD base ptr a FIELD len n ;STRUCTURE' in lib/span.f, package SPAN, so it travels on the stack like every family value and needs no engine change. The read-only ( ptr u8 n ) source pair stays the string idiom (it already carries its length); a span is the WRITABLE destination and the indexed view, so the migration is buffer owners, copies and indexed readers of hostile bytes, not every string call. Minting: SPAN:MAKE ( ptr t n -- span t ) is the one audited crossing, admitted in lib/ and src/ only (the lint refuses it elsewhere); producers publish spans directly: SPAN-BUFFER: NAME n ( -- span u8 ), n SPAN-CELLS: NAME ( -- span n ), MEM:ALLOC-SPAN ( n -- span u8 ) and its release, the TYPED-BUFFER span form. Narrowing: SPAN:SKIP ( span t n -- span t ), SPAN:TAKE ( span t n -- span t ), SPAN:SUB ( span t n n -- span t ), each refusing past the reach with E-SPAN-RANGE and never yielding a wider span. Access: SPAN:AT ( span t n -- ptr t ) bounds-checked element address, SPAN:C@ ( span u8 n -- u8 ), SPAN:C! ( u8 span u8 n -- ), SPAN:@ ( span n n -- n ), SPAN:! ( n span n n -- ), SPAN:LEN ( span t -- n ), SPAN:$ ( span u8 -- ptr u8 n ) handing a span to a ( ptr u8 n ) reader, SPAN:BYTES ( span n -- span u8 ) scaling the reach. Copy: SPAN:COPY ( ptr u8 n span u8 -- ) refusing a source longer than the destination's reach with E-SPAN-CAPACITY, no partial copy (supersedes habu-add-a-bounded-de082fc4's BYTES-INTO), SPAN:FILL ( u8 span u8 -- ). Errors: an E-SPAN block in lib/errors.f. What the checker refuses first: nothing new in band 0 — the nominal keeps a bare pointer and a span distinct, and tools/lint/bare-copy-lint.f refuses BYTE-COPY and SPAN:MAKE in checked source outside lib/ and src/, naming site and replacement, as the consumer gate; the checker rule (band 3) refuses arithmetic-then-dereference on a pointer whose origin is raw storage outside lib/ and src/, last, after the sweeps, as the record narrowings are. Performance: bounds checks are runtime; static elimination is a later optimisation (release quality first). BANDS: 0 lib core (this campaign's first child), 1 lib buffer owners by file group, 2 consumers (Tender server/ by aspen; kiba, loom, maki, radar by their owners), 3 the checker rule. Acceptance: every band's child dot closed; a program that copies past a span's reach is refused by name at the copy, an indexed read past it at the read, and no site under lib/ or a converted consumer carries a hand-written capacity check; docs/type-system.md states the type. Files: lib/span.f, lib/errors.f, lib/memory.f, src/core/pointer-storage.f or lib/ for the definers, tools/lint/, docs/type-system.md, docs/forth-card.md. Verify: the children's suites; test/run.f. Depends: none. Ownership: type system. Parent: habu-campaign-c2-mem-c3d7662b. Claim: unassigned.
Band 0 measurement 2026-09-18 (hazel-span): STRUCTURE span 1 FIELD base ptr a FIELD len n ;STRUCTURE loads and instantiates as span<u8> / span<cell> / span<NUM:index>; family arguments unify with the integer WIDENING lattice (span<u8> is accepted where span<cell> is declared, and span<u8> <-> span<n> both ways), so an element-counted reach is unsound and the reach is counted in BYTES: every accessor scales its index by its own element size and checks against the byte reach; the byte set (AT, BYTE@, BYTE!) is over span<u8>, the cell set (CELL-AT, CELL@, CELL!) over span<cell>; the pointee is strict only at SPAN:MAKE. Public tails avoid every global word so 'using SPAN' is importable. TYPED-BUFFER's span form is out of band 0 (its accessor is an index function at the sealed generative boundary); SPAN:MAKE over its accessor result is the way. Band 3 note: the widening of family arguments is checker arg unification, not a rule; if a strict span<t> is ever wanted, that is a checker change.
