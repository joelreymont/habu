Problem (adversarial review of 77fe4a87..fba695f8, CRITICAL, measured): the offset-null fence loses its mark when a stepped pointer is bound AWAY to a callee's fresh quantifier - TVK-MEET answers ANY for OFF meeting an ordinary var - so ': ID ( ptr a -- ptr a ) ;  : W2 ( ptr a -- ptr a ) 8 + ID ;  : F ( -- ptr ptr n ) NULL-PTR W2 ;  F @ @' certifies and reads a cell (engine 2bb46473) while the one-word wrapper is refused. The obvious fix - OFF meeting ANY answers OFF, both orders (tried as f31a24ff, chained as CI) - reddens 43 suites: with the mark kept, a stepped pointer later meets a callee's quantifier whose PERSISTED kind is NULL because that callee admits a null through the input-only excuse (lib/vector.f vec-dispose -> VEC-RELEASE-STORAGE: E-NONPARAMETRIC-EFFECT 'declared type variable a is restricted to a base address'), and meet(OFF, NULL) = DBASE turns 'this word accepts a null' into 'this pointer IS a null offset'. The current lattice cannot distinguish a LITERAL null (NULL-PTR's own pointee) from a null-ADMITTING quantifier (a callee's excused input), and the rule 'an offset null is a DATA-base pointer' is only right for the former. Acceptance: (1) split the two at the kind or at instantiation - e.g. a callee's excused-null quantifier instantiates as ANY at the call (the excuse is the callee's internal fact; docs/effects.md 'input-only excuse'), or a distinct kind for 'admits null' that meets OFF as OFF - decided after reading NP-KIND-EXCUSED?, E-INST/E-COPY's persisted kinds and FENCE-WHY; (2) then OFF meeting ANY answers OFF so the mark rides a plain quantifier; (3) the two-word program refused with the DBASE reason, the same route on an ordinary pointer certifying, and every null idiom in the tree still certifying (the 43 suites: run the full suite, not a sample); (4) docs/effects.md's offset-null paragraph states the literal/admitting distinction.
