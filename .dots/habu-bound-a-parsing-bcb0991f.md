Problem: the source verifier keeps `parses:` rows only from files its scan reads (src/habu/verify-source.f:2965-2979; the load checks a row and keeps nothing, src/core/cell-effects.f:60). A file hb already contains is answered 'held' and not read (verify-source.f:3275), so a row beside a word hb contains never reaches the row store: TOP-PARSER finds no row (PRS-FIND 0) and stops the scan at the word (TOP-OPAQUE, :3151-3152). Probes: .jj-ws.noindex/carl-aio/.out/ra/p (p1-p5), .jj-ws.noindex/carl-layout/.out/lib-base. Direction (not designed): hb keeps the row with the word's binding, as it keeps `generates:` and `names:` (DECLARED-RENDER? verify-source.f:3006-3010, CHECKER-OWNER-ABI:BINDING-GENERATES), and TOP-PARSER and EXPORT-PARSES fall back to it. That changes what a checker record's facts text holds, a saved format: the design goes to Joel before a worker. Not determined: where the terminators of a `parses-through:` row are kept.
