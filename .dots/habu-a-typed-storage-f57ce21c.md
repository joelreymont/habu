Problem: a typed-storage definer (typed variable, typed buffer, dynamic buffer, heap, arena, layout buffer, STRUCTURE with OPAQUE) whose name goes into a sealed package is refused under the load with the definer's generated name and no line, where the source declared one token at one line. The definers' name checks (src/core/layout-buffer.f:65 LBUF-NAME-OK?, src/core/heap.f, src/core/arena.f) load before everything the seal test reads (src/habu/interpreter.f:1429 DEF-SEAL-GUARD, :351 SEALED-FAIL, layout.f, xref.f, check-hook.f). Twelve probes: in-tvar, out-tvar, in-tbuf, in-dbuf, in-heap, in-arena, in-lbuf, out-lbuf, out-dbuf, out-heap, out-tbuf and in-opaque; their files are lost. With 'package SP public variable X seal-package ;package' and 'STRUCTURE rec DERIVE addr FIELD id n ;STRUCTURE', 'HEAP SP:Y rec' loads as "E-SEALED-PACKAGE habu: <file>: 'SP:Y-NEW' is sealed", rc 84, and 'HEAP Y rec' or 'ARENA Y rec' inside SP after seal-package as 'Y-NEW' or 'Y-NEW-PTR', no line; 'TYPED-VARIABLE SP:Y n', '8 TYPED-BUFFER SP:Y n', 'DYNAMIC-BUFFER SP:Y n' and 'TYPED-VARIABLE Y n' inside SP load as "E-SEALED-PACKAGE habu: <file>:<line>: 'SP:Y' is sealed" (or 'Y'), rc 84, and the check gives E-SEALED-PACKAGE at the token for each of these; 'ARENA SP:Y rec' is refused as a qualified name (load: "habu: in SP:Y: qualified name 'SP:Y'", rc 70; check: E-BAD-STORAGE). Source: Joel: "i want all issues identified to be dotted and fixed".

The same name checks give four more faults. (a) A typed-storage duplicate into a sealed package disagrees between the load and the check: with 'package SP public variable X seal-package ;package', each of 'TYPED-VARIABLE SP:X n', bare 'TYPED-VARIABLE X n' inside the package and '8 TYPED-BUFFER SP:X n' exits 78 with no output under the load (LBUF-NAME-OK? throws E-DUP-DEFINITION before any seal test) while the check says E-SEALED-PACKAGE SP:X in its three modes. (b) Under --load a duplicate typed-storage or heap name exits 78 with no message (the check prints nothing either); an ARENA or OPAQUE structure refused for a duplicate or taken name prints at 'pt' with no file and uncaught throw code 7102 or 7110. (c) For 'TYPED-VARIABLE 12 n' and a keyword as the name tools/check.f prints the load's prose with rc 70 and no JSON packet under --json-errors. (d) A refusal of the name a '+FIELD' or 'FUNCTION:' defines prints the file with no line under the load, where docs/forth.md:194 promises '<file>:<line>' and the check gives the place: with the package above, 'begin-structure S9 8 +FIELD SP:X end-structure' loads 'E-SEALED-PACKAGE: SP:X at <file>' (check: 6:29, bytes 79-83); 'require src/lib/ffi-abi.f' then 'PROCESS-SYMBOLS FUNCTION: SP:X getpid ( -- n ) ;FUNCTION' the same (check: 7:27); an unsealed or global duplicate prints 'duplicate definition: UP:X at <file>'. Related: habu-locate-storage-syntax-4eb9fae5.

Settled 2026-11-10 by the long-term rule, two commits. One: a public guard word beside the definers in src/habu/interpreter.f that each typed-storage definer's generated text calls first with the declared name, so the refusal names the declared token. Two: a refusal inside evaluated text reports the place of the outer statement in the file; this reverses test/load-reject-diag-test.f:571 TEST-EVALUATED-PLACE and the rule at src/core/checker.f:29239 CHECK:LINE-AT. Its brief starts by establishing whether habu2.f LSRCAT is reached under --load; if it is, that part joins the interpreter's replacement. For (b), (c) and (d) a hunt first names each silent exit, missing packet or missing line as path:line, and whether commit two's cause is theirs.

Acceptance: each of the twelve probes is refused E-SEALED-PACKAGE at the declared token and its line, the same under the load and the check; (a) agrees between the load and the check; each (b) case prints a diagnostic naming the declared token and its place under the load and the check; both (c) cases print a packet with code, token and place that passes the record check; both (d) programs and the duplicate print the name's line under the load; tests pin them.
