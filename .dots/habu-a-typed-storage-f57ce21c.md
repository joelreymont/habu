Problem: a typed-storage definer (typed variable, typed buffer, dynamic buffer, heap, arena, layout buffer, STRUCTURE with OPAQUE) whose name goes into a sealed package is refused under the load with the definer's generated name and no line, where the source declared one token at one line. The definers' name checks (src/core/layout-buffer.f:65 LBUF-NAME-OK?, src/core/heap.f, src/core/arena.f) load before everything the seal test reads (src/habu/interpreter.f:1415 DEF-SEAL-GUARD, :351 SEALED-FAIL, layout.f, xref.f, check-hook.f). Twelve probes: in-tvar, out-tvar, in-tbuf, in-dbuf, in-heap, in-arena, in-lbuf, out-lbuf, out-dbuf, out-heap, out-tbuf and in-opaque; their files are lost. With 'package SP public variable X seal-package ;package' and 'STRUCTURE rec DERIVE addr FIELD id n ;STRUCTURE', 'HEAP SP:Y rec' loads as "E-SEALED-PACKAGE habu: <file>: 'SP:Y-NEW' is sealed", rc 84, and 'HEAP Y rec' or 'ARENA Y rec' inside SP after seal-package as 'Y-NEW' or 'Y-NEW-PTR', no line; 'TYPED-VARIABLE SP:Y n', '8 TYPED-BUFFER SP:Y n', 'DYNAMIC-BUFFER SP:Y n' and 'TYPED-VARIABLE Y n' inside SP load as "E-SEALED-PACKAGE habu: <file>:<line>: 'SP:Y' is sealed" (or 'Y'), rc 84, and the check gives E-SEALED-PACKAGE at the token for each of these; 'ARENA SP:Y rec' is refused as a qualified name (load: "habu: in SP:Y: qualified name 'SP:Y'", rc 70; check: E-BAD-STORAGE). Source: Joel: "i want all issues identified to be dotted and fixed".
