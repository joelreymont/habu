Problem: tools/check.f's pre-pass rejection outranks the run even when it follows a top-level token the pre-pass left to the run (an undeclared renderer such as evaluate, a name only rendered text may define), where the walk only guesses how the tokens after it read. On master: 's" : x ;" evaluate {: require :}' loads with E-UNDEFINED at {: 1:20 but check.f gives E-MISSING-SOURCE for ':}' at 1:31; 's" : x ;" evaluate nosuch {: require :}' loads with E-UNDEFINED nosuch 1:20, check.f gives ':}' 1:38; a rendered parsing word (s" : P ( -- ) parse-name 2drop ;" evaluate, then 'P is', 'P postpone', 'P variable' or 'P {:' before definitions) makes the walk misread the definitions after it. A count definer with no count does the same with no token left to the run: `LAYOUT-BUFFER X n` loads with E-INPUT-UNDERFLOW at 1:1, but check.f gives E-BAD-STORAGE at 1:17, because verify-source.f RECORD-LAYOUT-BUFFER takes the previous token as the count and judges the name and type first (checker.f CHECKER-DEFLAYOUT-BUFFER, CHECKER-DEFTYPED-BUFFER). TYPED-BUFFER, CWORK-BUFFER, CWORK-SPAN and TASK:+USERS with no count, and a count word of the wrong type, behave the same (/tmp/carl-q07-cause.md, /tmp/carl-q07/*.f). The walk's own stops do the same past a top-level call that may move the source root, which the walk finds only when spelled qualified: in a directory with sub/lib.f (`: LIB-ONE ( -- n ) 1 ;`), `: GO ( -- ) s" sub" SOURCE-ROOT:ROOT! ; GO require lib.f LIB-ONE drop` and `using SOURCE-ROOT s" sub" ROOT! ;using require lib.f LIB-ONE drop` (one form per line) load and pass --verify-only, but plain check.f and --all-errors give the walk's E-MISSING-SOURCE for lib.f (tools/check-core.f CHK-KEPT-UNREAD? counts text the composition left to the run as unread). Plain check.f also writes a walk's stop where --all-errors writes it only at a place the composition never read (CHK-EXPAND-REPORT; CHK-SEND-FIRST once the pre-pass and the run pass): with other/b.f defining RRB:B, `: GO ( -- ) s" other" [: s" b.f" required ;] SOURCE-ROOT:WITH ; GO RRB:B .` loads and passes --verify-only and --all-errors, but plain check.f gives E-MISSING-SOURCE for b.f. Acceptance: the load and check.f (plain and the first --all-errors record) print the same record for each reproducer, and check.f passes where the load passes; a test pins it. Depends: none. Claim: unassigned.
