Problem: three marks say "not for everyone" and overlap: DNAME-INT (hidden engine word), the trusted-only flag (src/habu/prims.f ETRUSTED-ONLY!, 19 rows; src/core/checker.f PRIM-TRUSTED-ONLY!) and DNAME-OWNED (owner-only). With internal words private to the system package and stripped from the product, none of them carries anything privacy does not.
Ruling (Joel, 2026-10-08): none survive; privacy plus the build's strip only.
Acceptance: DNAME-INT, DNAME-OWNED and the trusted-only flag, with every reader and writer (internal-mark.f's marking, the prompt/tick refusals "internal engine word" and "trusted-only tick", the AOT capture's mark field), are deleted; a hidden word is simply absent from the product.
Files: src/habu/layout.f (DNAME-* bits), src/core/internal-mark.f, src/habu/prims.f, src/core/checker.f, src/habu/aot-capture.f, src/habu/habu2.f (prompt/tick refusals), tests naming the marks.
Verify: full suite on the built hb; product probes for formerly internal names answer E-UNDEFINED.
Depends: the dot moving internal primitives into the system package. Ownership: lead. Claim: unassigned.

Acceptance case (S5c census 4, 2026-11-06, /tmp/jerry-ckrows/census4.md G): inside a build (LINKER:WITH), after the product's src/core/internal-mark.f has run, the startup driver's top-level REQUIRE-BOOT-FREEZE is refused "hb: internal engine word" (rc 70), so a build cannot finish hb's startup list. With the marks deleted, the build's driver completes the list's freeze step.

Acceptance cases (linker-built hb, 2026-11-09): a linked hb carries no DNAME-INT mark, so two suite assertions that leaned on it were removed, and the strip has to bring them back as absent names: (1) a checked definition calling LOWER-CERT:BYTES (src/core/lower-cert-base.f:170) is refused (was test/engine-suite.f `CERT-BYTES-BAD`); (2) source cannot store into the reserved view family `-1 C2-READ-FAM !` (src/core/checker.f:1114, a global variable read by checker.f, type-family.f and sumtype.f; was test/c2-read-effects.f "source cannot replace the reserved view family identity"). C2-READ-FAM needs a package's private section before the strip can remove it.

Acceptance case (file objects, carl census rounds 13-14, 2026-11-07, carl-dots/.out/kept/c5a2/scale/iter.log): src/core/util.f REG-PROTECT stores a host record index (`ndict@ 1 -`) in REG-PROT-IDX, a data cell, and later files register into it too (about 30 cells in the program). A file's object therefore depends on the host's record count at the build's open: 13 more host records moved every such cell by +13 and one more moved it by +1, while one more package (a record and 2 wordlist ids) moved it exactly as one more record did. The linker's key covers the record count at the open (LINKER KEY! `8 U64, FIRST-REC`) so such an object compiles instead of linking wrong. With REG-PROTECT and its index table deleted, no object or program depends on the host's record count.

Acceptance case (file objects, carl census with the type registry scoped to a build, 2026-11-07): a cold build of hb's startup files inside LINKER:WITH ends at src/core/internal-mark.f with LINKER:E-STORE (-9691): its marking changes the flags of records earlier files made, which the decision "a file that changes what earlier files made" refuses. With the marks deleted, the file changes no earlier record and the census continues past it.

Finding (2026-11-07, carl, on the installed hb): DNAME-INT's tick refusal is load-bearing, so the marks cannot go before the privacy move (habu-move-engine-internal-fc2ba551). A checked call of a rowless prefix word is refused by the checker alone (`: X ( -- n ) REG-PROT-COUNT ;` -> E-CAP-TRUSTED via checker.f CALL-AUTHORITY once CHECKER-EFFECT-AUTHORITY:SEALED?), and so is a top-level call, but a tick then execute at top level runs a word the checker refuses: `check@ 0 set-check : W ( -- n ) 5 ; set-check  ' W execute . cr` prints 5, rc 0 (/tmp/carl-m5.f), while `W . cr` is E-CAP-TRUSTED (/tmp/carl-m4.f). Today `' REG-PROT-COUNT` dies `hb: internal engine word` only because of DNAME-INT. The authority seal (CHECKER-EFFECT-AUTHORITY:SEAL, a plain variable store internal-mark.f's IMK-SEAL makes) is separate from the marks and can stay as a plain call.
