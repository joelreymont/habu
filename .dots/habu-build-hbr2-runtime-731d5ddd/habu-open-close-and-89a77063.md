Problem: every job, request and component belongs to a scope whose lifecycle decides when late results drain and handles are released (HBR2 §5.1, §1.4); Habu models none of it. RUNTIME opens scopes with SCOPE-OPEN (§5.1), issues requests that each end in one terminal outcome (§5.2) and measures deadlines in the root clock domain (§4.5). §1.2 says native and headless embeddings implement the same portable boundaries, but HBR2 specifies that boundary only as the Wasm wire (§24.5, Appendix A), and the wire registry goes to lib/browser/ (habu-pin-hbr2-wire-0b340032), which RUNTIME may not import. Acceptance: in package RT-SCOPE: the scope creates the runtime epoch's two counters, one for ComponentInstanceIds and one for PlacementIds (RT-ID:COUNTER over cells it owns exclusively), holds them in private fields with no replacement API, draws every identity from them through RT-ID:NEXT, and closes them with the epoch; `defer SUBMIT ( rt-request -- submit-result )` over an `rt-request` handle type that RT-SCOPE declares with the port (the request dot defines its record and states over it) and `defer WAKE ( -- )`, bound once by the embedding; `DELIVER ( rt-request outcome-record -- )` and `TIME! ( f64-ms -- )` / `TIME@` as the embedding's only inputs; `submit-result` an ENUM of §24.5's eight results defined once here; root time never read from a host clock; a headless host under test/browser/ answering SUBMIT from a recorded script, queuing WAKE as a later step and writing a replayable trace (§28.3); BROWSER maps request kinds to opcodes (§27.4). Application, Document, Component, Gesture, Job and Plugin scopes; the local scope record exists before SCOPE-OPEN goes out through SUBMIT; dependent requests queue locally until acceptance, and a rejection closes the scope without sending them; a parent must be live and of an admissible kind (a Component scope under an Application or Document scope), so parents cannot cycle; the states Opening, Open, Closing, Draining, Closed and Revoked, Draining, Closed exactly as §5.1 draws them; Closing refuses new requests, cancels cancellable children, detaches observers and drains late results; Closed only after owned handles are released or transferred to a live parent; a tombstone stays while completion tokens name the scope, and generation reuse waits for its retirement; runtime death revokes the whole incarnation. Files: lib/runtime/scope.f (new, package RT-SCOPE; mints E-RT-SCOPE-FIRST/LAST -9590..-9599 in its owning file), lib/errors.f (one comment line), test/browser/headless-host.f (new), test/browser/scope-test.f (new), test/gate-stdlib-cases.f. Verify: bin/hb --load test/browser/scope-test.f against the headless host: a rejected open sends none of its queued requests; a result arriving after close is drained and its handle released; a slot is not reused while its tombstone is referenced; revocation closes every descendant; replaying the written trace reproduces every outcome; bin/hb --load test/run.f.
