Generalisation of habu-fuse-a-call-36c0286e, which states the straight-line case (CALL-FAN-N reloads a live value and stores it straight back). The loop case is the one that decides CODEGEN-CORPUS2:T-RES-WALK, and it needs the same fact computed ACROSS blocks. Measured from the emitted code of CODEGEN-CORPUS2:T-RES-WALK-N (76 bytes, 19 instructions, against the engine's 36 and 9): five of the ten extra instructions are a value moving between a register and a data-stack slot it never leaves. offset 12 'ldr x0,[x19]' lifts the routine's own argument out of slot 0; offset 16 'str x0,[x19]' writes it straight back into slot 0 as the call's argument; offset 32 'ldr x0,[x19]' lifts the call's first result out of slot 0 again; offset 60 'str x1,[x19]' writes it back into slot 0 as the routine's own result; and offset 48 'orr x1,xzr,x0' is the edge copy into the after-loop block's argument, which exists only because that value was in a register at all. The engine emits none of the five: its T-RES-WALK never touches the cell, because the callee's result cell IS the next call's argument cell and the routine's own result cell. What to build: a residency fact over the values of one routine - a value is resident at data-stack slot s when the memory at base+8s holds it - computed as a forward fixpoint over the blocks (a block argument is resident at s when every value handed to it is), plus the backward companion (a value needs a register only when some use that is not an elided store needs one). Then src/compiler/native/select.f emits no DSTORE for a value already resident at the slot it would write, no DLOAD for a result no use needs in a register, and no block argument for a value that never reaches a register - which is what removes the edge copy. THE POINTER MOVES ARE NOT PART OF THIS: DTAKE, DBYTES, DBACK and DPUBLISH stay exactly as they are, because they place the pointer and say nothing about which cells are written; the separate dot habu-place-the-data-9f128e58 covers them. Blast radius: every routine that hands a value it received straight to a call, and every loop that carries one. Owner: A64SEL, with the independent re-derivation in src/compiler/native/regalloc-verify.f - VDSTACK-CK today requires exactly one DLOAD per argument at the head of the entry block and VCALL-SITE requires a full store run and load run with DBYTES and DBACK standing for their lengths, and both contracts have to become 'the omitted ones are the resident ones', re-derived there rather than taken from the selector. Acceptance: T-RES-WALK-N falls from 76 to 56 bytes with identical answers, CALL-FAN-N and CALL-LOOP-3-N fall too (which is 36c0286e's own measurement), no row of any corpus regresses, tools/codegen-compare.f 0 findings.
