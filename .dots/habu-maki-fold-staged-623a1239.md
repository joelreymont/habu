SLICE 4 folded MVV-FREE movement (reshape/slice) into EW/RED/MM load base pointers (maki/move-view.f MVW-RESOLVE-OFF; lower-ew/red/mm LEW/LRED/LMM-APPLY-VIEWS), but MVV-STAGED (transpose) dissolved into a compute region fails closed E-MVW-STAGED (maki/move-view.f:MVW-OFF-ELEMS). A transpose is a lane permutation dst[i,j]=src[j,i], not a constant base offset, so folding it needs a per-element remapped load (compute i=e/dst_cols, j=e mod dst_cols, src=j*src_cols+i in the kernel body) - the same permutation lower-move.f LMV-BODY-TRANSPOSE already emits for the materialized copy. Fix: extend the EW flat-index/RED row/MM K-loop loaders to accept a per-input transpose remap (expose the flat index reg from EMIT-GRID-CTX), or have fusion-plan.f materialize a transpose prologue instead of dissolving it. Device-proven cases today: SLICE into EW/RED/MM. Reproduce: MODEL: TG ( x:4x8 -- y ) TRANSPOSE GELU ; FP-BUILD 0 LEW-ANALYZE -> E-MVW-STAGED (maki/lower-mv-test.f).

HOST HALF LANDED (2026-07-06, workspace minion-fold). Per-class verdicts, decided from the code:

- EW: FOLDED. The flat kernel's per-element load index absorbs the permutation. lib/ptx/cg.f EMIT-GRID-CTX records its flat index reg (CG-GRID-IDX, read via EMIT-GRID-INDEX); EMIT-XPOSE-OFF emits src_flat = (e mod dstC)*srcC + e/dstC (rem/div/mad, dims as emit-time immediates - no new kernel params). maki/move-view.f gained MVW-STAGED? / MVW-XPOSE-DIMS / MVW-CHECK-EW; maki/lower-ew.f LEW-LOAD-IN routes a staged input through the remapped offset (base stays at slot origin; LEW-APPLY-VIEWS skips staged). PERF caveat documented at LEW-LOAD-IN: the folded read is STRIDED (adjacent lanes stride by srcC) - whether the fold beats materialize-then-coalesced is a DEVICE measurement (eval-triton 3c lesson), pending zed.
- RED: MATERIALIZED, not folded (strided-collective verdict from the code). cg-collective.f EMIT-ROW-SPAN/EMIT-ROW-LOAD is a collective contract - one block per ROW, lane = column, one coalesced row read whose bounds/identity seeding (-inf for inactive lanes) the reductions depend on. A transposed input means each lane reads a COLUMN of the source; that replaces the whole row-load collective (span math AND masking), not an offset. So the planner (maki/fusion-plan.f FP-STAGED-FOLDABLE? = CLASS-EW only, consulted in FP-JOIN?) MATERIALIZES a staged transpose feeding RED: the transpose becomes its own copy region (LMV-BODY-TRANSPOSE, coalesced write) and RED reads the materialized buffer coalesced via the slice-5 cross-region handoff. E-MVW-STAGED stays in LRED-CHECK-OPS (MVW-CHECK) as defense-in-depth, proven by a hand-forced fixture (TNX).
- MM: DEFERRED (materialized), same mechanism. The K-loop A/B addressing (row*K+kk / kk*N+col) plus the blocked/MMA paths staging As/Bs to shared cannot absorb a per-element permutation without a new staging layout. Planner materializes; E-MVW-STAGED stays in LMM-CHECK-OPS/LMM-CHECK-PROLOGUE as defense-in-depth, proven by a hand-forced fixture (TMX).

Plans are lowerable-by-construction again: FP-JOIN? refuses to dissolve a staged transpose into a RED/MM consumer, closing the plan-fuses-then-lower-rejects gap for TG/TN/TM.
