CHECKER SOUNDNESS HOLE (found by the vector-seal lane, 2026-07-27, full reproducer below): when a package defines a tail that case-insensitively shadows a core primitive (VEC:@ is the production instance), a body compiled in ANOTHER FILE that reopens the package resolves a bare reference to that name DIFFERENTLY in the checker and the compiler - the checker certifies against the core primitive (its diagnostic proves it: at '@' expected: ptr a) while the compiler binds the package word. The definition certifies and then executes wrong code: SIGSEGV exit 134 from a certified program. Same-file bodies are consistent; only the reopen path diverges. Static invariant: one name, one resolution - the checker must certify the exact binding the compiler will use, for every scope path including reopen. Owned result: make checker and compiler resolution identical on the reopen path (single shared resolution authority, not two lookups), add the two-file negative regression (must REJECT or must bind consistently - decided by which resolution is correct per the package model; the in-package word is the intuitive winner since same-file bodies after the definition see it), and a sweep for existing reopen bodies that reference core-shadowing package tails bare. Production trigger: package VEC publishes @ and ! tails; any future file reopening VEC with a bare @ silently compiles wrong certified code. Reproducer (two files, verbatim from the lane): FILE pkglib.f: require lib/errors.f / package PKGF / private / BEGIN-STRUCTURE REC-BYTES / PTR-FIELD: REC.P / CELL +FIELD REC.A / CELL +FIELD REC.B / END-STRUCTURE / create REC REC-BYTES allot / public / : DECLARE ( -- ) create REC-BYTES CELL / 0 ?do 0 , loop does> ( -- ptr a ) ; / : SET ( -- ) 7 REC REC.B ! ; / : GET ( -- n ) REC REC.B @ ; / : @ ( ptr a n -- n ) {: base:ptr off:n :} base off cells + @ ; / ;package. FILE pkguse.f: require pkglib.f / PKGF:DECLARE W / package PKGF / public / : GET-REOPENED ( -- n ) REC REC.B @ ; / : W-SET ( -- ) 9 W REC.B ! ; / : W-GET ( -- n ) W REC.B @ ; / ;package / then RUN comparing same-file GET (=7 ok) vs GET-REOPENED (wrong/crash). Acceptance: the two-file fixture rejects or binds consistently at check time; a negative regression pins it; the vector-test white-box readers can stop routing around the trap (the call-site comment in lib/vector-test.f names this dot's subject).
