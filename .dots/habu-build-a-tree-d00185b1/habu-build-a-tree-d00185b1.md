Problem: tools/native-build.f run from a host engine whose baked src/lib/string.f still declares package STR dies in one second with 'duplicate definition: BYTE-LEN>N' on a tree where STR moved to src/lib/string-roles.f (chain N on 02b08bae from the fccb4a02-class host /tmp/hazel-fM2, 2026-09-16 20:55): the host answers the tree's `require src/lib/string.f` with its own baked module (PFX-PROVIDE-ROW, src/habu/habu2.f), so the tree's src/lib/string-roles.f reopens the host's STR and redeclares its casts. tools/build-fixpoint.f does not fail because its stage source rewinds the prefix to core (PREFIX-REWIND:TO-CORE, build-fixpoint.f:1234) before loading the tree's modules; an engine built from the moved tree (the lane's NR-N) builds the head. Any change that moves or removes words out of an engine-provided module reproduces it, and the manifest dot habu-bake-only-what-4039004a will do that repeatedly. Acceptance: native-build.f builds such a tree from a host that still bakes the old module, by rewinding to core and loading the tree's copies as the build-fixpoint stage does, or refuses before compiling with a message naming the provided module and the file that reopens it; docs/bootstrap.md states which hosts can build which trees; a fixture builds a tree that moves a package out of an engine-provided module from a pre-move host. Files: tools/native-build-core.f, tools/native-build.f, src/habu/habu2.f (provide rows), docs/bootstrap.md, test/. Verify: the fixture; tools/native-build.f fixpoint on the current head from /tmp/hazel-release/hb-class and NR-N-class hosts. Depends: none. Ownership: build driver. Claim: unassigned.

Ruling 2026-10-29 (Joel): no per-start fingerprint or reload in hb ("4.8mb and a heavy toll"); no Gforth in routine builds; follow established practice. Design (Astra, /tmp/jerry-astra-b1/out.txt): every build entry cold-loads the tree's startup files before it runs any of its own helpers, as Factor and CCL cold-load and SBCL keeps host and target names apart. Ordinary hb starts pay nothing; a build pays one reload (~3 CPU-s measured on the prototype, to be measured on the real build). The step is tools/cold-load.f, package COLD-LOAD, word COLD-LOAD:RUN (Joel's name); the ordered startup list is src/habu/boot-files.f, package BOOT-FILES (Joel's name). A tree that needs a host operation the installed hb lacks is refused by name; the remedy is an intermediate native hb.

Lanes: L1 (startup list into BOOT-FILES, byte-equal engine) in jerry-b1-l1, reviewed, fold-ins running; M1 (measurements, reload prototype /tmp/jerry-b1-m1/reload-b.f) done. Next: L2 COLD-LOAD at hb-build.f and its support child; L3 the other entries (native-build.f, fixpoint and its certification child); L4 startup files as support-cache inputs; L5 the old-host rename fixture in native-build-edit-e2e.f; L6 delete the fixpoint watermark machinery, docs.

Joel 2026-10-29 (after L2's support child died on its 180 s deadline: cold-load at tier 1 ~95 s CPU, at the default tier the maker then runs a JIT-compiled compiler past 600 s): hb-build builds in its own process and saves the product; no support child, support image or maker child; app, REPL and engine become one build path differing by modules and by how the result is saved, unless the code shows a reason not to. All build timeouts go ("a build that takes too long is a bug"), HB_BUILD_TIMEOUT_MS included. Whitebox is a Forth variable build setting; HABU_WHITEBOX_IMAGE goes. COLD-LOAD stays (the driver cold-loads). Census /tmp/jerry-big/b1-oneproc-census.md; feature design (Fable, Plan) from /tmp/jerry-big/b1-oneproc-design-brief.md replaces lanes L3-L6.

REPL and cache check (read-only, probes /tmp/jerry-b1-repl): no mark rewinds to the post-cold-load state (CHECKER-BOUND:REWIND stops at the core-prefix seal; a failed-evaluate rollback restores ndict and cp but FFI and IMAGE-LIFECYCLE rows survive, and a later snapshot fails "snapshot address map mismatch" rc 97, see habu-clear-the-address-maps); a second cold load rewinds records only, leaving the driver's code as dead bytes (+3.2 MB) with EXIT-HOOK-CELL pointing into them. SNAP:PERSIST ends in die (snap-lib.f:738-751); RUN-SAVED must come from the outer stream. Cache identity: FILE-KEY hashes ENGINE-ID:KEY$ of the running binary; the compiler role is set only by INSTALL-ROLES at an engine build and HOST-ACTIVE-COMPILER$ (native-build-core.f:282-290) requires the role's code in engine text, so a cold-loaded host reuses nothing ("files reused 0 compiled 155").

Lead rulings 2026-10-29: (1) the save returns: SNAP:PERSIST and the engine finish return to the build, which then installs, writes the sidecar and reports; (2) the REPL product is the snapshot of the build process after its modules load; the driver stays in it as APP-BUILD does today; no second route, no rewind; (3) producer identity for the per-file cache = the engine key plus the digest of every file the cold load read: an unchanged tree reuses, any startup edit misses; the engine-text requirement goes; (4) no deadline anywhere in a build, the 10 s smoke child included. Lanes: E1 one-process --engine (brief /tmp/jerry-big/b1-engine-brief.md, workspace jerry-b1-e1, on ptyyulqs rebased onto master); E2 app and REPL on the same path; E3 NATIVE-BUILD -> BUILD (habu-name-the-build-abed309a); then L3-L6 as listed.
