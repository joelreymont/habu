Problem: habu-deliver-process-signals-b844698f (aspen) needs a handler that is async-signal-safe, which no Forth word is: a machine-code stub installed through sigaction that only writes the signal number to a self-pipe. The stub is emitter work, like the crash handler aot-lib.f EMIT-CRASH-HANDLER already bakes, and the Tender server stops through a polled file until it exists. Design (frozen contract with aspen 2026-09-17): the emitter bakes a second handler next to the crash handler (EMIT-SIGNAL-HANDLER, label LSIGH): it loads a process-wide fd word, and if it is nonzero writes the 4-byte signal number in x0 to that fd with one write syscall, then returns; it touches no Forth state and only the registers the syscall clobbers. The fd word lives where the stub can reach it PC-relative and a program can write it, the image's rw segment or another fixed process-wide location, never a per-task header cell (a new task's region starts zeroed and a handler runs on whichever thread receives the signal). layout.f gains package SIGNAL-ABI with two DATA cells, process-wide in the LOCK-CELL class and rows in DATA-CLAIMS: STUB-CELL, the stub's address, and FD-PTR-CELL, the address of the fd word, both published at boot the way the AOT-SPAN cells are; bootstrap/cg/forth.fs mirrors the emitter under the two-stage rule. Acceptance: the two cells read nonzero on a booted engine; a test installs the stub with sigaction through FUNCTION:, stores a pipe's write end through FD-PTR-CELL, raises SIGUSR1 with kill on itself and reads the number back from the pipe; a second test shows a signal with the fd word zero is absorbed; byte fixpoint; bootstrap check; test/run.f. Files: src/habu/aot-lib.f, src/habu/habu2.f (boot publication), src/habu/layout.f, bootstrap/cg/forth.fs, test/. Verify: the two tests; fixpoint; tools/bootstrap.sh check. Depends: none.
