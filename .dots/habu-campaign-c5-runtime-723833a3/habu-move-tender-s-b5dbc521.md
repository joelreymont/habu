Problem: Tender's HTTP/1.1 server (tender server/http.f, server/http/{arena,request,response,router,body,static}.f, 2,685 lines) runs on lib/net/tcp4.f, lib/aio.f, lib/task.f and lib/queue.f: a listener task and worker pool with a catch boundary per request (http.f:1-7, :167-172), 400/413/431/501 refusals (request.f:6-9), keep-alive, chunked bodies, ETag static files. It is application code; Maki's viewer needs it (maki docs/habu-needs.md). Joel decided on 2026-09-30 to move it into Habu's lib. Generic, moving to package HTTP in lib/net/http.f, http-arena.f, http-request.f, http-response.f, http-router.f, http-static.f: all of the above plus ON-WORKER-START/EXIT and STOP's LEFT/KILLED accounting. Tender-specific, staying in Tender (Finch's lane): the ApiErrorBody JSON (response.f:1-3, :323-347) becomes an installed hook `HTTP:ON-ERROR ( [ response n ptr u8 n ptr u8 n -- ] -- )` with a plain-text default; the SvelteKit cache rule (static.f:100-104) and the /api/ client-route fallback (static.f:238-256) become two installed rules defaulting to no-cache and no fallback; body.f (BODY-FIELD) stays; codes -9730.. (arena.f:25-32) become block -9300 in lib/errors.f. Decided: keep the fixed pool of 8 worker TCBs (http.f:42-50), a behaviour-preserving extraction. Acceptance: lib/net/http-test.f, from tender test/server/http-test.f: CURL client for a JSON route, a static file with ETag then 304, keep-alive, 404 and 405 with Allow, a throwing handler answered 500 with the worker surviving, raw TCP4 for 400/413/431/501, STOP with KILLED-TASKS 0; the suite writes build/http-transcript.txt (status line and headers per case) and asserts it. Files: those, docs/http.md, a docs/stdlib.md row, test/gate-stdlib-cases.f. Verify: bin/hb --load lib/net/http-test.f; SUITE http in bin/hb --load test/run.f. Depends: none. Ownership: lib/net/http*.f, docs/http.md; coordinate the split with Finch. Tender's switch to the library is Finch's follow-up. Claim: agent=zephyr workspace=.jj-ws/http-lib.
