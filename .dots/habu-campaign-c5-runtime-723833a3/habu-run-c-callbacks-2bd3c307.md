Problem: docs/curl.md:78-83: C cannot call back into checked code. Maki's OCCT facade and libc qsort need callbacks on the calling task and on foreign threads. Design (bounded; annex, landing as docs/ffi-callback.md, fixes every register and word): Engine: layout.f claims a per-region band at $41C8 - the VM frame (CB-XDS/DBASE/NDICT/CP-CELL) every outbound call core saves after its pops and restores after the BLR, LIFO, XDS 0 = none; CB-OWNER-CELL, the thread pointer (TPIDR_EL0 Linux, TPIDRRO_EL0 macOS) a call claims when 0; CB-FRAME-CELL, the live marshal frame; CB-XTS/CB-REGIONS-CELL naming the library's 16-slot tables. prims.f row `callback-entry ( n -- n )`: 16 stubs into one thunk that saves C's callee-saved set as BTASK-ENTRY does, parks x0-x7/d0-d7, requires CB-OWNER = self or CAS 0->self and a frame, loads the VM and BLRs the slot's `( -- )` xt; refusals exit ENGINE-ERROR:CALLBACK 104; task-abi.f EXPOSED; kernel-x64.f REFUSEs the row until habu-port-the-ffi-676f745d adds the SysV twin. lib/task.f: `EXPOSE ( ptr n -- )` (resting frame, TASK-LIVE+, EXPOSED), `UNEXPOSE` (E-TASK-STATE while CB-OWNER <> 0 or a slot names the region), `CONTEXT ( ptr n -- n )`, `SELF-CONTEXT ( -- n )`; ACTIVATE/KILL refuse EXPOSED, the sweep dies. lib/ffi-callback.f, package FFI-CB: `CALLBACK: NAME ( in -- out ) clauses ;CALLBACK`, register arguments only (in n/i32/u32/r/ptr u8, out n/i32/u32/r/none; E-FFI-ARITY past INT-REGS 8 AAPCS64 / 6 SysV or 8 floats; `n FALLBACK`/`r FFALLBACK` required for a value result; E-FFI-CALLBACK-FULL at slot 17), generates `NAME ( -- callback )`, `TYPED-VARIABLE NAME-BODY [ in' -- out' ]` and a `( -- )` dispatch reading `ARG@/FARG@/PTR-ARG@` from CB-FRAME and running the body under `[: ;] catch` (fault and fallback on a throw); `ENTRY ( callback -- n )`, `CONTEXT ( callback n -- )`, `UNBIND`, `FAULT@`, `CLEAR`.
