Problem: docs/curl.md:78-83 states Habu cannot hand libcurl a callback into checked code; lib/ffi-abi.f:1-12 marshals outbound calls only, and the trampolines (src/habu/habu1.f:1840-1848) rest on x19 being callee-saved, so when C calls back every VM register holds C's values. Maki's OCCT facade needs callbacks (maki docs/habu-needs.md), and OCCT reports progress from its own threads. Design (bounded; send to alder before implementation): lib/ffi-callback.f, package FFI-CB. `CALLBACK: NAME ( args -- result ) ;CALLBACK` declares a callback whose body is a quotation of that effect, at most 8 integer and 8 float arguments, no stack arguments (refused at declaration); `FFI-CB:ENTRY ( callback -- n )` is the C function pointer; `FFI-CB:CONTEXT ( callback ptr n -- )` names the TCB it runs on; `FFI-CB:FAULT@ ( callback -- n )` reads a throw the body raised (the body runs under catch, returns its declared fallback, never unwinds C frames). Engine: one hand-written thunk beside BTASK-ENTRY (habu1.f:2025-2050 already loads XDS, DATA, DBASE, NDICT, CP from a TCB and stores it at TASK-TCB-CELL), a fixed pool of 16 stubs (adr x16, slot; b thunk) and 16 descriptor cells in src/habu/layout.f, so no code is emitted at declaration; the thunk saves C's callee-saved registers, loads the VM from the descriptor's TCB, pushes x0..x7/d0..d7 per the effect, executes, pops x0/d0, restores. Calling task: context is TASK:SELF (lib/task.f:1406). Foreign thread: context is a task prepared by TASK:PREPARE and never activated (own stacks and region, counted live so the compiler refuses), one per concurrent foreign thread; the thunk dies by ENGINE-ERROR when its descriptor is already running on another thread. Decided: ship calling-task and foreign-thread callbacks in this dot; fixed pool of 16 stubs, no runtime code emission. Acceptance: lib/ffi-callback-test.f: libc qsort with a Habu comparator on the main task and in a worker; a throwing comparator (qsort finishes, FAULT@ answers); pthread_create through FUNCTION: with a callback start routine on a prepared task, joined result checked; artifact build/ffi-callback-transcript.txt. Files: lib/ffi-callback.f, its test, src/habu/habu1.f, src/habu/prims.f (rows), src/habu/layout.f, docs/ffi-callback.md, docs/curl.md:78 note. Overlaps: prims.f rows feed ENGINE-PRIMS:COMPLETE (docs/porting.md:81-86), so the x86-64 kernel (habu-build-the-x86-15b47b0b) and the SysV FFI (habu-port-the-ffi-676f745d) must add bodies; layout.f is serialised with habu-finish-the-linux-57cb3952.
