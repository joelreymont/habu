Problem: docs/curl.md:78-83: C cannot call back into checked code. The three outbound cores (src/habu/habu1.f:1875-1999) rest on callee-saved x19 and park x20 in the frame (:1922, :1970), so a callback sees C's registers; TASK:SELF is null on the main task (lib/task.f:557) and TCB.STACK is an allocation base (:1017), so BTASK-ENTRY's loads (habu1.f:2034-2039) cannot restore an active caller. Maki's OCCT facade and libc qsort need callbacks on the calling task and on foreign threads. Design (bounded; annex, landing as docs/ffi-callback.md, fixes every register, cell state and word): Engine: layout.f claims the per-region band $41C8..$4208, one data-claims.f row, and aot-owned-cells.f LIST claims it FRESH-BYTES because every cell is correct at zero: CB-XDS/DBASE/NDICT/CP, the VM frame every outbound core saves after its pops and restores after the BLR, LIFO, XDS 0 = no frame; CB-OWNER, the thread pointer (TPIDR_EL0 Linux, TPIDRRO_EL0 macOS, Apple libsyscall os/tsd.h) of the one thread allowed on the region, 0 = free; CB-FRAME, the live marshal frame; CB-XTS/CB-REGIONS naming the library's 16-slot tables, read only through the main-region address DATA-VA. Owner protocol, in this order and never the reverse: a call core LDARs CB-OWNER; equal to self it is nested and claims nothing; 0 it CASALs 0->self; any other value or a failed CAS exits ENGINE-ERROR:CALLBACK 104 with the region untouched; only then does it push its $30 frame ([sp+8] stays the x20 park, the four saved cells and the claim flag take the rest) and publish the live cursors; LEAVE restores the cells first and, if it claimed, STLRs 0 last, so a thread that acquires the owner sees a complete frame or XDS 0. prims.f row `callback-entry ( n -- n )`: 16 stubs into one thunk that saves C's callee-saved set as BTASK-ENTRY does, parks x0-x7/d0-d7, and claims the slot before it touches any region: LDAR REGIONS[k] answers 0 (die), R|1 busy (proceed unclaimed only when CB-OWNER = self, else die) or R (CASAL R->R|1, a failed CAS dies); then the owner as above; then CB-XDS <> 0 or die; loads the VM, BLRs the slot's `( -- )` xt, restores CB-FRAME, STLRs 0 to the owner if it claimed it and R to the slot if it claimed it. Every die writes hb: callback: <reason> to fd 2 and exit_groups 104; task-abi.f EXPOSED 5; engine-error.f 104 CALLBACK, effect row beside STACK-BOUNDS in engine-error-effects.f; kernel-x64.f REFUSEs the row until habu-port-the-ffi-676f745d adds the SysV twin. lib/task.f: `MAIN-BASE ( -- ptr n )` (DATA-VA); TASK-LIVE+/- move the main region's count through it, so a worker's ACTIVATE, JOIN, EXPOSE and UNEXPOSE count where the compiler looks (habu1.f:1300); `EXPOSE ( ptr n -- )` (PREPARE, CONSTRUCTED only, resting frame from TCB.STACK/DBASE/NDICT/CP, OWNER and FRAME 0, TASK-LIVE+, EXPOSED); every release path refuses a named region with E-TASK-STATE (TASK-JOIN-RELEASE and the CONSTRUCTED arm of TASK-KILL, so JOIN, KILL and ACTIVATE of a DONE task; JOIN drops its joiner claim on that refusal so it can be retried after UNBIND); ACTIVATE and KILL refuse EXPOSED; the capture sweep dies on EXPOSED. lib/ffi-callback.f, package FFI-CB: `CALLBACK: NAME ( in -- out ) clauses ;CALLBACK`, register arguments only (in n/i32/u32/r/ptr u8, out n/i32/u32/r/none; E-FFI-ARITY past INT-REGS 8 AAPCS64 / 6 SysV or 8 floats; `n FALLBACK`/`r FFALLBACK` required for a value result; E-FFI-CALLBACK-FULL at slot 17), generates `NAME ( -- callback )`, `TYPED-VARIABLE NAME-BODY [ in' -- out' ]` and a `( -- )` dispatch reading `ARG@/FARG@/PTR-ARG@` from CB-FRAME and running the body under `[: ;] catch` (fault and fallback on a throw), stored into the XTS slot at declaration (typed quotation storage, relocated by capture); REGIONS[k] is a raw cell 0 / R / R|1. `ENTRY ( callback n -- n )` binds the slot to context n from TASK:CONTEXT or TASK:SELF-CONTEXT (CASAL 0->n; an idle or busy binding to n is idempotent; any other binding E-FFI-CALLBACK-STATE), publishes the two table bases into MAIN-BASE CB-XTS/CB-REGIONS with atomic!, arms the capture sweep and only then answers `k callback-entry`; `UNBIND ( callback -- )` CASALs R->0, E-FFI-CALLBACK-STATE while R|1; `FAULT@`, `CLEAR`. The capture sweep (IMAGE-LIFECYCLE:REGISTER, as TASK-ARM-SWEEP) clears idle bindings and dies on a busy slot: a binding is process state, made by ENTRY and dropped by capture, which is why a stripped image's zero header is its correct start. Lifetime contract: a binding lives from ENTRY to UNBIND, and the caller stops and drains C's calls (returns from qsort, joins the pthread) before UNBIND, UNEXPOSE and release; the engine enforces every ordering it can observe (a busy slot refuses UNBIND, a named region refuses UNEXPOSE/JOIN/KILL, a held owner refuses UNEXPOSE, EXPOSED refuses KILL/ACTIVATE), and a call arriving after UNBIND or UNEXPOSE fails closed with 104 and never touches a released region, because a thunk reaches a region only through a slot it claimed and UNBIND clears a slot only by CAS from idle.
