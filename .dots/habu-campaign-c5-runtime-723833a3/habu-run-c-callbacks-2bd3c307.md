Problem: docs/curl.md:78-83: C cannot call back into checked code. The three outbound cores (src/habu/habu1.f:1875-1999) rest on callee-saved x19 and park x20 in the frame (:1922, :1970), so a callback sees C's registers; TASK:SELF is null on the main task (lib/task.f:557) and TCB.STACK is an allocation base (:1017), so BTASK-ENTRY's loads (habu1.f:2034-2039) cannot restore an active caller. Maki's OCCT facade and libc qsort need callbacks on the calling task and on foreign threads. Design (bounded; annex, landing as docs/ffi-callback.md, fixes every register, cell state and word): Engine: layout.f claims the per-region band $41C8..$4208, one data-claims.f row, and aot-owned-cells.f LIST claims it FRESH-BYTES because every cell is correct at zero: CB-XDS/DBASE/NDICT/CP, the VM frame every outbound core saves after its pops and restores after the BLR, LIFO, XDS 0 = no frame; CB-OWNER, the thread pointer (TPIDR_EL0 Linux, TPIDRRO_EL0 macOS, Apple libsyscall os/tsd.h) of the one thread allowed on the region, 0 = free; CB-FRAME, the live marshal frame; CB-XTS and CB-ROWS naming the two 16-slot tables (CB-POOL), read only through the main-region address DATA-VA. A slot row (CB-ROW-BYTES 16: CB-ROW-REGION, 0 unbound or the region; CB-ROW-OWNER, 0 idle, the thread pointer of the thread inside through this slot, or CB-ROW-BUSY 1 while a bind, unbind or drop transitions it) lives in main DATA, which is never unmapped, and is the claim a thread must hold before it reads the region the row names; a region is mapped while any row names it, because UNEXPOSE and TASK-END are the only words that release a named region and both drop its rows first. Owner protocol, in this order and never the reverse: a call core LDARs CB-OWNER; equal to self it is nested and claims nothing; 0 it CASALs 0->self; any other value or a failed CAS exits ENGINE-ERROR:CALLBACK 104 with the region untouched; only then does it push its $30 frame (claim flag at [sp], the existing x20 park at [sp+8], XDS/DBASE/NDICT/CP saved at [sp+$10..$28]) and publish the live cursors; LEAVE restores the cells first and, if it claimed, STLRs 0 last, so a thread that acquires the owner sees a complete frame or XDS 0. prims.f row `callback-entry ( n -- n )`: 16 stubs into one thunk that saves C's callee-saved set as BTASK-ENTRY does, parks x0-x7/d0-d7 in its marshal area, and keeps the row address, region, both claim flags and the saved CB-FRAME on its own SP-relative frame, because checked dispatch may hold state in x21..x25 and x29 (src/compiler/native/abi.f:64-72). It claims before it dereferences: LDAR the row owner; equal to self it is nested through this slot and claims nothing; 0 it CASALs 0->self; anything else or a failed CAS dies. Only then LDAR the row region (0 dies), then CB-OWNER of that region as above, then CB-XDS <> 0 or die, then the xt (0 dies); loads the VM, BLRs the slot's `( -- )` xt, restores CB-FRAME, STLRs 0 to CB-OWNER if it claimed it and 0 to the row owner if it claimed it, in that order. TASK-END drops every row naming the ending task's own region before its single DONE signal (a row in flight there dies: only a thread already dying 104 can hold one), so a DONE region is never named and no release path refuses: TASK-JOIN, TASK-JOIN-RELEASE and TASK-KILL keep their shape; KILL of EXPOSED runs UNEXPOSE then releases; ACTIVATE refuses EXPOSED; the capture sweep dies on EXPOSED or a row in flight and drops idle rows, since a binding is process state. lib/ffi-callback.f, package FFI-CB, owns declaration and dispatch: `CALLBACK: NAME ( in -- out ) clauses ;CALLBACK`, register arguments only (in n/i32/u32/r/ptr u8, out n/i32/u32/r/none; E-FFI-ARITY past INT-REGS 8 AAPCS64 / 6 SysV or 8 floats; `n FALLBACK`/`r FFALLBACK` required for a value result; E-FFI-CALLBACK-FULL at slot 17), generates `NAME ( -- callback )`, `TYPED-VARIABLE NAME-BODY [ in' -- out' ]` and a `( -- )` dispatch reading `ARG@/FARG@/PTR-ARG@` from CB-FRAME (E-FFI-CALLBACK-STATE outside a live frame) and running the body under `[: ;] catch` (fault and fallback on a throw), stored into the XTS slot at declaration (typed quotation storage, relocated by capture). `ENTRY ( callback n -- n )` publishes XTS into MAIN-BASE CB-XTS with atomic!, runs `n k TASK:CONTEXT-BIND`, and only then answers `k callback-entry`; `UNBIND ( callback -- )` is `k TASK:CONTEXT-UNBIND`; `FAULT@`, `CLEAR`.
