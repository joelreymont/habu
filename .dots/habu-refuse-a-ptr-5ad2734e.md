Problem: a checked word can read and write memory at any integer address with no TRUST row by passing the integer through a plain variable: 'variable V  : PEEK ( n -- n ) V ! V @ @ ;  : POKE ( n n -- ) V ! V @ ! ;' both certify and run on the integrated engine 6fb809de (probe 2026-09-17: TARGET NULL-PTR - PEEK returned TARGET's cell, POKE stored through it, rc 0). Each mention of a plain variable answers a pointer to a cell of a fresh unknown type, so the n stored by one mention comes back from the next as a value the checker lets @ and ! use as an address. The engine's own sources lean on it: src/habu/aot-lib.f reads the data span through 'DSCAN @ @' and src/habu/aot-closure.f DATA-CELL@ through 'DCELL ! DCELL @ @' (name-cell lane 1188f268, which documents the pun). docs/effects.md:330 claims a pointer cannot be laundered into a cell pointer and then cell-loaded; this is a second route to the same forgery. Campaign: habu-campaign-c2-mem-c3d7662b. Acceptance: a plain variable's cell has one type for the whole program (n unless declared otherwise through the typed declarations docs/forth.md:872 already requires), so a value fetched from it is never accepted as an address; rejected-program regressions for the PEEK and POKE shapes above and for the same pun through a create'd cell and a TASK:+USER cell; the engine sources that use the pun move to a declared checked view (an explicit, tested n-to-cell-view boundary word owned by the checker or layout, not a per-file variable); sweep src lib tools test for every site the new rule rejects and convert each; docs/effects.md states the rule. Files: src/core/checker.f, src/habu/aot-lib.f, src/habu/aot-closure.f, the swept sites, docs/effects.md, a rejected-program test under test/compiler. Verify: the regressions; byte fixpoint; tools/bootstrap.sh check; test/run.f. Depends: none. Ownership: checker. Claim: unassigned.
