Problem: an agent in a Habu session learns a word's binding, declared effect and source only by reading the implementation or guessing; the facts exist (a definition's facts on its dictionary entry, src/core/checker.f CHECK:FACTS@; the checker's effect query, EFFECT-QUERY and its EFFECT-DIN-*/DOUT-* readers; src/habu/xref.f), but no REPL word answers from them: SEE and XREF (src/habu/xref.f) print a word's raw record (name, start, length, flags, wordlist), and tools/lsp-hover.f renders kind, effect, package and file:line for an editor, not for the REPL.
Acceptance: one public word takes a name in the caller's actual scope and returns its resolved qualified identity, canonical declaration and effect, kind and call authority, and source location when the definition was loaded in this session; absence and ambiguity are reported explicitly; an engine-held word reports no source rather than inventing one; a definition loaded in the session is distinguished from edited source not yet loaded; a readable effect alone never claims the caller may call the word. The answer is owned data or a copy into a caller-owned buffer, built from the existing records and renderers; no JSON or request shape inside the REPL call. Which EFFECT-* readers are public after sealing is established first; the word exposes the checked operation, not the storage. Documented in docs/forth-card.md with one copyable REPL interaction. Joel, 2026-11-10: the word answers from the source index as well as the live dictionary: a word defined in the Habu source but not loaded, or not visible where it is asked about, is reported with its defining file and the reason it is not visible, never as absent.
Depends: none.

Design (bob, settled by the long-term rule). Public: `SEE NAME` prints the description; `XREF NAME` keeps the raw record. `XREF:DESCRIBE ( dst cap name len -- n )` writes into a caller-owned buffer as FS-LIST:NAMES does (src/lib/fs-list.f:251), E-CAPACITY on a short buffer, with a `names:` row; SEE types its text. Lines, one each: name (qualified), effect and tags (the entry's facts text), kind (from the record's flags), scope (global, public of PKG, private of PKG, sealed), callable (resolved by the interpreter's own lookup from the asking scope, never inferred from a readable effect), source. Absent: `SEE: NAME not found in this session`; ambiguous: both rows, marked. A private word asked from outside its package is described with scope 'private of PKG' and 'callable no', found by a walk of the namespace rows; a word after undefine is described as retired. Today's SEE answers 'xref: not found' for a private word inside its package and for a public word under 'using', which the interpreter runs (xref.f:361 XREF-FIND reads global or qualified-public only), and xref.f loads before the interpreter, so it cannot call its lookup. The callable line therefore comes from one new public word of package INTERPRETER factored from LOOKUP-GO, XT-GATE and SCOPE-ENTRY-GUARD (src/habu/interpreter.f:468-503), which the interpreter itself then calls, so there is one lookup; XREF:DESCRIBE and SEE live in a module loaded after the interpreter, and xref.f's SEE (:812) is removed. A session-made constant, created word or variable has an empty facts text until habu-c2d-write-declarations-f94670f2 lands, so commit one prints 'effect none recorded' for those.
