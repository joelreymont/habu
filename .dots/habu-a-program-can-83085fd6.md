Problem (read, not probed; from the owner-columns design 2026-11-11): the storage definers lay NAME#base and NAME#ctl as ordinary words and no rule in checker.f or verify-source.f was found that refuses a program's store into them, so '1000000 N-TAG#ctl !' would defeat the bounds check (dynamic-storage.f ADDRESS :145-153). Related: habu-checked-src-can-d80dc074, habu-user-src-arms-bc2ab900. Acceptance: a probe shows whether checked source outside the definer can name or store into the two cells; if it can, the cells are private to the definer's generated words and a rejected program proves it. Files: src/core/layout-buffer.f, src/core/checker.f. Verify: the rejected program in every mode. Depends: none. Ownership: carl. Claim: agent=carl workspace=none (cause found; fix design owed by the lead).

Probed 2026-11-11 (engine carl-arena3/bin/hb, probes ~/.cache/tmp/carl-abuf-probe/q5-same.f, q5-other.f, q5-known.f): `--load` admits `1000000 TB#ctl !` and `SPOT TB#base !` at top level and in a body, from the buffer's own package and from another (`DBQ:TB#ctl`): rc 0, prints 1000000. `tools/check.f` (--all-errors and --verify-only) refuses the same source: E-UNDEFINED-TOP-LEVEL at TB#ctl, E-UNDEFINED in the bodies, rc 70. So load and check disagree. Not run: an index after the store.

Cause (hunt 2026-11-11, workspace carl-ctl retired, probes and logs ~/.cache/tmp/carl-ctl runA.txt runB.txt runC.txt): the definers generate the cells as ordinary source (DBUF-SOURCE src/core/layout-buffer.f:536-537 `PTR-VARIABLE NAME#base`, `create NAME#ctl`, run by LBUF-EVAL :157), so they land in the section open at the declaration and resolve like any word: from the declaring package always, from others when the buffer is public (h1-priv.f: a private buffer's cells are E-UNDEFINED outside). tools/check.f refuses only because CHECKER-DEFDYNAMIC-BUFFER (src/core/checker.f:16268, :16276-16278) records NAME, NAME-RESERVE and NAME-RELEASE and never the cells; no rule names `#`. Observed under --load: p1-bound.f stores and reads 800 bytes into a 64-byte capacity after `1000000 TB#ctl 3 cells + !` (rc 0); p1-fresh.f an unreserved buffer answers null plus 7992 for index 999; TYPED-BUFFER TT#base, LAYOUT-BUFFER LB#base, CWORK-BUFFER CB#base and public CWORK:MEM#ctl admit the store the same way (a store 100 cells past a 4-cell buffer ran). PTR-U8-TABLE lays no cell. Sources that name a cell outside the definers: src/compiler/workspace.f:31,34,36,89; src/habu/t0.f:1580; test/wasm/storage.f:91,102; test/dynamic-buffer.f:88,129,161,164,168,188,191,193,196,201-203. Not probed: DEFER-LAYOUT-BUFFER's NAME#base (layout-buffer.f:389-403); a store past the mapping's page; Wasm. Also found: DYNAMIC-STORAGE:PUBLISH and ADDRESS (dynamic-storage.f:160) are public and take the two cells; comments checker.f:16226-16227 and above verify-source.f:2814 say three published words where five are.
Fix (lead, to design): the generated cells are not words checked source can name, in the declaring package included; only the definer's generated accessors reach them; load and check then agree. The six callers get what they read another way (a null test on the head; the record handed to DYNAMIC-STORAGE).
