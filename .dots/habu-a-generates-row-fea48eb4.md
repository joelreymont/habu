The source pre-pass then takes the next token as the product's name: e2-trust-gen.f (a trust after such a row) fails the check with E-STATEMENT-THROW 7158, rc 70, while the load accepts it, rc 0; d1-gen-noname.f and d2-eval-gen.f read ':' as the product and defer the next definition while the load refuses its undefined word. Both engines, before and after the deferral-cause commit. Files: src/core/checker.f (CHECKER-GENERATES), src/habu/verify-source.f. Verify: the three programs under --verify-only and --load. Depends: none. Ownership: the source pre-pass. Claim: unassigned.

Hunt (report briefs8/reports/genrow-hunt.md, cases cases8/genrow, table.txt): CHECKER-GENERATES (src/core/checker.f) accepts a row when D resolves, nothing already creates and the effect parses; it never asks whether D reads the source after it. The pre-pass then takes the token after a call of D as the made name (verify-source.f RECORD-DEFINER? through RAW-TRUST-NEXT), while the load runs D, which reads nothing. Clearest case n4-misread.f: --verify-only certifies it, the load refuses E-UNDEFINED FOO. Fix: refuse the row as `parses:` refuses a word that reads no source (PARSES-READS-NONE): a D without CTL-PARSES, or a deferred D, is E-GENERATES-ROW. Left open by that fix: a word that reads its name on one path only keeps CTL-PARSES, the same kind of false claim as a row whose effect is wrong.
