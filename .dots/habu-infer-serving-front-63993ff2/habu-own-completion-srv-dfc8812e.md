Why: listener and fixed server storage need one lifetime separate from an iteration. Result: package SERVE owns one linear server with SOCK-OS listener, one SCHED scheduler or SCHED:terminal, its SCHED:id, fixed connection rows and buffers, pollfd storage, exactly one fixed SCHED result table and byte arena, response-id counter, active model name, and idle timeout. SCHED owns the result schema, capacity calculation, and sole writer but stores no result table or byte arena; SERVE lends its storage to each TICK. OPEN obtains ID once for terminal-state ownership; each accept threads the healthy scheduler through SERVE-CONN:OPEN, which derives the connection binding itself. STOP stops accepting and walks every connection once. With a healthy scheduler it calls SERVE-CONN:CLOSE until completion or the first cancellation failure; from that result onward it threads SCHED:terminal through CLOSE-AFTER-SCHED-FAIL. If STOP begins with a terminal scheduler from TICK-AND-ROUTE, it uses the guarded close from the first connection. Public CLOSE-AFTER-SCHED-FAIL with an identity mismatch returns the original terminal and connection to its caller unchanged and does not enter a server STOP-only state. Every connection stored inside a server derives the server id privately, so the internal STOP walk has no mismatch arm. STOP records whether each descriptor was attempted, attempts each at most once, and attempts the listener once after a completed connection walk. It returns stopped or stopped-with-close-errors(error-set) when no live request remains; both consume every descriptor and server owner. A cancellation or scheduler-stop refusal returns a STOP-only owner containing SCHED:terminal, id, buffers, exact live handles, and every not-yet-attempted connection. A later STOP retries only scheduler reclamation, then attempts each previously unattempted descriptor once; attempted descriptors never reappear. FOOTPRINT reports exact server and connection bytes. Owner: SERVE OPEN, STOP, scheduler binding, result storage, and footprint only. Production red: an unrelated terminal can otherwise authorize another server teardown, and stopping after the first cancellation failure can strand later unattempted descriptors. Acceptance: package/type gates accept the bound capability chain; two servers have distinct ids; connection OPEN has no substitutable id input; swapping healthy schedulers at admission rejects before SUBMIT; A terminal paired directly with B connection returns both unchanged, while every server-internal terminal walk is matching by construction; zero, one, or several connections consume every descriptor once across immediate and retried STOP; partial OPEN, result bounds, healthy failures, terminal failures at every connection position, immediate port reuse, and exact footprint follow ownership. Forbidden: terminal fabrication, id substitution, socket-close retry, poll loop, result writing, thread, general event loop, DNS, dynamic rows, signal handler, plugin, version, or compatibility path. Smallest owning check: bin/hb --load maki/serve/server-test.f.
