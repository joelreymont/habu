Why: listener and fixed server storage need one lifetime separate from an iteration. Result: package SERVE owns one linear server with SOCK-OS listener, one SCHED scheduler or SCHED:terminal, its SCHED:id, fixed connection rows and buffers, pollfd storage, one caller-owned SCHED result table and byte arena, response-id counter, active model name, and idle timeout. SCHED owns request state, result-row schema, and the only result writer; each TICK caller owns its table and arena; SERVE owns that storage in the product plus listener and connections. OPEN obtains ID once for terminal-state ownership; each accept threads the healthy scheduler through SERVE-CONN:OPEN, which derives the connection binding itself. STOP stops accepting and walks every connection once. With a healthy scheduler it calls SERVE-CONN:CLOSE until completion or the first cancellation failure; from that result onward it threads SCHED:terminal through CLOSE-AFTER-SCHED-FAIL. If STOP begins with a terminal scheduler from TICK-AND-ROUTE, it uses the guarded close from the first connection. Any identity mismatch returns the terminal and untouched connection in a STOP-only refusal; it never closes. STOP attempts the listener close once after a completed connection walk. It returns stopped or stopped-with-close-errors(error-set) when no live request remains; both consume every socket descriptor and server owner. A cancellation or scheduler-stop refusal returns a terminal STOP-only owner containing SCHED:terminal, id, buffers, and exact still-live handles but no attempted socket descriptor. A later STOP may retry only non-socket cancellation and scheduler teardown through SCHED:STOP; already attempted descriptors never reappear. FOOTPRINT reports exact server and connection bytes. Owner: SERVE OPEN, STOP, scheduler binding, and footprint only. Production red: an unrelated terminal can otherwise authorize another server's teardown. Acceptance: package/type gates accept the bound capability chain; two servers have distinct ids; connection OPEN has no substitutable id input; swapping the healthy schedulers at request admission rejects before SUBMIT; A's terminal against B's idle and live connections rejects before close, while matching terminal entry with zero, one, or several connections consumes every connection and listener descriptor once; partial OPEN, result storage bounds, healthy failures, terminal failures, immediate port reuse, and exact footprint follow ownership. Forbidden: terminal fabrication, id substitution, socket-close retry, poll loop, result writing, thread, general event loop, DNS, dynamic rows, signal handler, plugin, version, or compatibility path.
