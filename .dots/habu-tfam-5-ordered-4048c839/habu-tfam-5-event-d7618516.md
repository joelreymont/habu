REMAINING, NOT LANDED because it regresses master (BLOCKING):

D3 - replace tools/check-core.f CHK-SCAN-DEPS with ordered-event (DISCOVER:RUN) closure. BLOCKER (evidence): DISCOVER:RUN (tools/source-discovery.f SD-WALK/SD-COLON/SD-SKIP-BODY) skips every colon body, so it CANNOT observe the dominant real idiom 'guarded include/require behind a colon-defined helper', e.g. tools/check-all-errors-core.f:7-10 CA-MAYBE-VERIFY-SOURCE conditionally 's" src/habu/verify-source.f" required' then bare-calls it. Today's whole-file CHK-SCAN-DEPS (check-core.f:468-473) DOES catch this (it lexes the entire token stream incl. bodies). Swapping to DISCOVER would make the checker see FEWER deps than the runtime = soundness regression, breaking real source-list gate flows (test/gate-engine-lib.f GE-ENGINE-STDLIB-CHECK; tools/check-test-lib.f CKT-TEST-REQUIRE-FACADE). Also test/run-worker.f:34 'path pathu included' (dynamic) and src/habu/driver-io.f:11-14 (UNDEFINE-IF-DEFINED of loader words via helper) evade DISCOVER. The census/plan intended events 'recorded AFTER EVALUATION' via runtime-instrumented loaders, i.e. a REAL load with EVENT-ON — but a real load before preverify is circular (the file may not compile; that is what check is verifying). Correct fix = design decision: either (a) two-pass load-and-record discovery, (b) DISCOVER executes-and-records colon-wrapped loaders, or (c) fail-closed manifest when a colon-wrapped/dynamic loader is present. Until decided, check-core keeps the whole-file static scan; extend CHK-SCAN-DEPS to also capture include/included/provided (currently require/required only) as a strictly-non-regressing partial improvement.

D4 - '--all-errors --source-list' redrive of ORIGINAL files. Today source-list all-errors is effectively a NO-OP: CHK-MATERIALIZE-LIST (check-core.f:532-545) flattens to a temp of only 's" path" required' lines and CHK-RUN-ALL-CURRENT (check-core.f:903-906) runs all-errors on that temp, which has zero colon defs, so nothing is checked. Fix: iterate CHK-DEP-ORDER (the existing dep closure preverify already redrives) and run all-errors per ORIGINAL file, replaying prior source-list entries as support first so cross-file prefix state is preserved. Needs a new cross-file-support entry on tools/check-all-errors-core.f + tests. Non-regressing (combo is not gate-tested today) but substantial; deferred with D3 since the plan frames both 'via the event log'.

CROSS-CONSUMER NOTE (merge review): tools/event-closure-lib.f (hb-build cache keys + public-signatures pre-scan, landed with habu-tfam-5-public-3a692040) builds its closure from DISCOVER:RUN and therefore inherits the same colon-body blindness: a loader call guarded inside a colon helper is invisible to the closure, so hb-build keys miss conditional deps (still strictly better than the old entry-only key) and PS pre-scan misses conditionally-opened package scope. Whatever design (a/b/c) resolves D3 must also migrate EC:BUILD so all event-log consumers share one sound closure source.

DESIGN DECIDED (docs/design-tfam-5-redrive.md): static whole-file ordered-event producer (body-scanning lexer, superset-sound via the monotone load-if-absent guard argument) shared by preverify/EC:BUILD/hb-build-keys/public-signatures, plus a fail-closed manifest ONLY for the dynamic tail (run-worker.f path-variable included; driver-io.f loader retirement). Candidates (a)/(b) refuted by probe: undefined words through included/evaluate hard-fault uncatchably, so harvest-on-failure cannot work. NEW GAP the implementation must close: s" require" UNDEFINE-IF-DEFINED (driver-io.f:11-14) is invisible to DISCOVER (colon body) and to reserved-name-lint (which only flags loader-named definitions, not undefines) - the producer must treat loader-word retirement as a fail-closed manifest trigger. Implementation blocked until habu-tfam-5-const-b89c90f0 worker releases check-all-errors-core.f/public-signatures-core.f.
