The native chain's IR module lifetime has no reclaim path for a module a later pass has superseded, so per-routine arena pressure is the SUM of every module the chain builds rather than the number live at once. Creating one builder is seventeen arena allocations (src/compiler/ir/build.f:229) and the registry holds SLOT-MAX=64 (src/compiler/ir/arena.f:62), so three chained builders (selection + combine + spill) is 51 slots plus the model and tape arenas, and it overflows: E-IR-ARENA-SLOTS (-6657). IR-ARENA:SCOPE-RELEASE only unwinds a builder whose CONSTRUCTION failed (build.f TX-ABANDON); a builder that was published successfully commits its slots (TX-COMMIT) and nothing ever gives them back until the context retires. Found by dot habu-select-the-immediate-6d9ee29a: folding a small constant into an add/sub makes A64COMB:REWRITE fire on most rows instead of the few with a multiply-add pair, so routines that also spill now chain all three builders. test/compiler/native-migrate.f SPILL-CASE is the reproducer - it is the second case in NMIGRATE-TEST:RUN and dies with -6657. After A64COMB:REWRITE returns the new module, the module it read is provably dead: its spans and symbols were copied into the new one and no reader remains. Needed: a way to retire a published module's arenas (walk the builder slot's table arenas and free each registry slot, as SCOPE-POP does with AGEN!), called from src/compiler/native/migrate.f COMBINED on the superseded module, so peak pressure is the number of modules LIVE at once and not the number ever built. Raising SLOT-MAX is not the fix: it is a magic value that moves the same wall, and the pressure would still grow with every pass added to the chain. Acceptance: SPILL-CASE green with the combine rewrite firing; a negative test proving a retired module's views are refused rather than read stale; peak slot count asserted.
