Scheduled by Joel 2026-10-27 ("dot and implement then"), part of carrying tier 1's register use into tier 0 before tier 1 is deleted. Was deferred by Joel 2026-10-26: tier 0 join allocation is T0-04 minus aliases (join layouts at if, parallel-copy reconcile at else/then, selective spills). This dot holds the excluded part: let a local and a stack value share one register until either is written, instead of reloading the local from its frame slot. Not scheduled: tier 1 has no such aliasing (it also reloads locals from frame slots) and the zz classification shows no tier 1 gain in allocation/spills/locals (f = -45 of 2598 samples, habu-classify-tier-1-df654e77). Take it up only if a measured tier 0 residual after the join allocator is attributed to local reloads.

Problem: C-LBRACE-BIND-VS (src/habu/habu2.f ~6586) stores every bound value to a frame slot, and C-LOCAL-REF (habu2.f ~6932) emits a fresh ldr into a new pool register on every read; nothing is cached, and the binding value's register is freed. Acceptance: between a local's binding (or its last write) and the next call, join or spill, a read reuses the register already holding the value instead of loading; writes keep the slot and any cached copy coherent; behaviour at every call, join, spill, `exit`, throw and nested locals group is unchanged. Tests: the tier0-inline-prims harness shows a repeated local read emits no ldr; runtime-regression rows for writes, joins and calls. Measure zz and tender run instructions before/after. Gate: test/compile-floor-gate.f. Files: habu2.f (C-LBRACE-BIND-VS, C-LOCAL-REF, local writes), jit.f/regalloc.f as the design needs. Depends: none. Ownership: tier 0 locals codegen.

Measured and rejected, 2026-10-27 (lane jerry-locals, Fable's "separate cache register" design, not landed): run instructions rose zz 14.21G -> 14.85G (+4.5%) and tender 309.0G -> 321.1G (+3.9%), outputs identical. Cause: a cache hit is `mov xR,xC`, the same one instruction as the base `ldr xR,[sp,#slot]`, and a miss is `ldr xC; mov xR,xC`, two; the cache is cleared at every call (LVSPILL), join (LVSETF) and loop head (LVLOCREL), so most hot reads miss (SCAN-CHAR loop 16 -> 19 per iteration, PARSE-JSON 145 -> 163, FACT-OWNER 37 -> 41). Copying out of a cache register can never cut instructions; "cache on bind only" at best returns to base counts. The form that can win: a hit pushes a VS entry that borrows the cached register instead of copying it (read-only consumers use it in place; operand-writing consumers LVBINPREP/LVBINIPREP, LVSWAPX/LVNIPX, LVDROP pick a fresh destination; LVSPILL stores without freeing it; LVRECON/LVSETF/LVSNAP copy borrowed registers into snapshot registers), so a hit costs 0 and a miss 1. That is a new VS entry kind across the allocator and needs a design before a lane.

Design review of the borrowing form (Fable, against these lanes): a borrowed entry still dies at every LVSPILL, LVSETF and LVSNAP, and in every measured hot loop each local is read once per iteration after a loop head or if, so hits stay zero. The form that can win hoists loads: at begin/do load each bound scalar local into a free register and record pins in the snapshot frame, LVSPILL marks pins dead, LVSETF keeps pinned registers claimed, the back edge reloads only used-and-dead pins (SCAN-CHAR 13 -> 10 insns per iteration). Take it up only if a measurement after habu-remove-tier-0-3f9fc4c3 lands attributes residual cost to local loads.
