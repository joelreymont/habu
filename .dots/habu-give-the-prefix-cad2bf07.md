Problem: PTR-VARIABLE and PERSISTED-PTR-VARIABLE publish ( -- ptr ptr a ) with the inner a RAW-kinded (the create stamp), so under the raw-storage rule (habu-refuse-a-ptr-5ad2734e) the cell takes an address and refuses an address of an address: 'PTR-VARIABLE V  : G ( -- ptr ptr u8 ) V @ ;' is E-RAW-CELL-PTR while TYPED-VARIABLE X ptr ptr u8 certifies; but TYPED-VARIABLE and TYPED-BUFFER throw E-LAYOUT-BUFFER until src/core/include.f:945 arms TDECL-EVAL-ARMED, which is after checker.f, layout-buffer.f, env-base.f and include.f's head, so in the engine prefix PTR-VARIABLE is the only declared form and src/core/checker.f's arena reads ATOMA, PARAMA, CT-NAME-A, VREC-NAME-A (: NAME ( -- ptr ptr u8 ) NAME-P @ ; over a PERSISTED-PTR-VARIABLE head) and its pointer tables FAM-A (create ... cells allot), ATOMA-BOOT and PARAMA-BOOT (passed to REG-POINTERS-CLEAR ( ptr ptr a n n -- )) cannot be declared at all (engine-source conversion lane, 2026-09-18, measured). A rule-carrying engine cannot build the next generation until they are. The workaround 'NAME-P 0 ptr-field @' re-mints the pointee and is exactly the launder the rule closes; not taken. Acceptance: the declared-storage definers available in the prefix give the cell an ordinary (TVK-ANY) pointee chosen by the declaration (PTR-VARIABLE NAME ptr ptr u8, or a pre-arm pointer-table form), or the typed definers arm before checker.f loads; the seven checker.f sites declared; a rule-hosted generation build succeeding with them; byte fixpoint; bootstrap check; test/run.f. Files: src/core/pointer-storage.f, src/core/layout-buffer.f, src/core/include.f (TDECL-EVAL-ARMED), src/core/checker.f, test/pointer-storage-test.f.
