src/compiler/native/emit.f FALL-THRU? (emit.f:1256) asks whether the successor is the block laid out at the NEXT POSITION. A block laid strictly between home and the successor that emits ZERO instructions defeats it: the successor is two or more positions away and physically adjacent all the same, so the trailing unconditional branch is emitted and jumps over nothing. Measured case CODEGEN-CORPUS:FACT-N (: FACT-N ( n -- n ) dup 1 <= if drop 1 exit then dup 1- RECURSE * ;) - the emitter's own public readers report 5 blocks laid in order 0,1,3,2,4 with starts 0,6,6,15,15, so blocks 1 and 2 emit nothing, and the b at instruction index 14 targets index 15, the instruction that already follows it. tools/codegen-branch-inventory-run.f prints this as the 'idle' column: 1 across all 54 migrated corpus rows today, so the fix is worth 4 bytes on this corpus and is about the rule being right rather than about the size. Note this is NOT a layout/writer disagreement: CURSOR-CK is satisfied because the branch was counted as well as written, so nothing is red - the two are consistently missing one opportunity. Fix: ask the fall-through question about the next position that emits any instruction rather than the next position. A block emits zero instructions only when every op is elided (self-mov, dzero-move) and its terminator falls through, so the emptiness of position p depends only on positions after p and a single BACKWARD pass over the order resolves it with no fixpoint - compute emptiness and next-non-empty-position from the last position down, then FALL-THRU? compares against next-non-empty. Both callers (OP-INSNS/BLOCK-INSNS counting and PUT-BR/PUT-BRZ/PUT-CMPBR/PUT-FCMPBR/PUT-FCMPBRZ writing) keep asking the one shared word, so there is still no second statement of the rule. Verify: the idle column falls to 0, CURSOR-CK still green, test/compiler/native-emit.f and native-migrate.f green, codegen-compare answers bit-for-bit. Depends: none. Ownership: src/compiler/native/emit.f layout stage. Claim: unassigned.

RESOLVED by the branch-chain collapse on bookmark brcollapse, and by removing the cause rather than by changing FALL-THRU?. A block that emits NOTHING before its terminator is exactly a block control passes through, so ORDER-BLOCKS now redirects every branch naming it to the far end and leaves it out of the order entirely - which means there is no zero-length position left for a branch to jump over. Measured: the idle column of tools/codegen-branch-inventory-run.f fell from 1 to 0 across all 54 migrated rows, and test/compiler/codegen-branch-inventory.f asserts it at zero on CODEGEN-CORPUS:FACT-N, the row that had it. FALL-THRU? is unchanged and still asks about positions; it no longer needs to look past anything, because nothing occupying no bytes is laid any more. Close this on merge. Note the loss it leaves behind is tracked by habu-hand-built-fixture-a6a4efe7: the idle column can no longer be shown answering non-zero by any row a code generator emits.
