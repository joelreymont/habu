Problem: the checker parses generic output families while their type arguments are still open. Input unification can then close those arguments and determine a different physical width, but several execution paths install the stale logical output row without rebuilding it. The rejected candidate 6279afc7b3a4 created a second logical representation for closed one-cell layouts and omitted the general bind-then-materialize transition. Closed layouts must keep their single canonical hidden representation.

Invariant: a closed, non-linear layout may bind an ordinary value variable in non-strict value position only when its complete canonical representation is exactly one existing hidden cell. After all inputs that can bind an effect have unified, every output row installed as current state is rebuilt once through the existing PUSH-LOGICAL policy. Open layouts remain logical; closed zero-, one-, and multi-cell layouts materialize exactly as that policy already requires. Raw storage, pointers, linear layouts, strict positions, and effect variables remain fail-closed.

Implementation owner: src/core/checker.f. Move the existing PUSH-LOGICAL definition beside LAYOUT-ARGS-OPEN? without changing its behavior. Add one private ROW-NORM ( row -- row ): resolve the row, recurse through its tail, and rebuild each resolved term bottom-to-top with PUSH-LOGICAL. Add one private admission predicate beside LAYOUT-BLOCK?: CUR-STRICT is zero; exactly one operand is ISVAR; the other resolves to HIDDEN-PARAM?; its layout arguments are closed; it is not possibly linear; and T-WIDTH is one. LAYOUT-BLOCK? admits only that pair. RAW-BLOCK? still runs afterward.

Apply ROW-NORM at exactly seven output stores: CHECKER-STEP after data input unification; both EFF-APPLY return-enabled stores after return input unification, including re-normalizing the already installed data row because return inputs can close shared variables; both RSEXEC data and return stores after both quotation inputs bind; and both CF-RECURSE-EFF cached data and return stores after its data and optional return inputs bind. The complete caller census leaves RSCATCH, EFF-QUOT, CF-SEMIQ, and IS-APPLY unchanged because they do not perform this bind-then-install transition. The data half of EFF-APPLY and generated constructor application already flow through CHECKER-STEP.

Post-E5 production fixtures in test/type-ctor-suite.f use lib/adt/option.f and lib/adt/result.f plus one arity-zero compact ENUM tag. Prove tag through a generic ( a -- a ) identity; OPTION:SOME followed by MATCH; OPTION:SOME inside a quotation followed by execute and MATCH; and RESULT:OK and RESULT:ERR consumed as result<tag,tag> and matched through both arms. Use the final binder-head grammar and generated constructor packages. Add only three missing mutation anchors: ptr a versus ptr tag in both directions still rejects, a raw here ! / here @ value cannot mint tag, and a one-cell linear STRUCTURE cannot pass the generic identity. Existing wide, open, hidden, layout-transport, and foreign-family fixtures remain their owners.

In test/type-decl-suite.f, keep TDRV-RAWEQ rejected because = has only numeric and pointer overloads. Change TDRV-RAWZ to certified because 0= ( a -- bool ) is intentionally the generic one-cell case, and update its comment. Keep TD12-ZEQ rejected because tdres is wider than one cell.
