lib/task.f shares TCB.STATUS and TCB.STOP between the parent and pthread worker but accesses both with ordinary loads/stores. TASK-STATE@/! are TCB.STATUS @/! (:222-227); TASK:DONE? polls that plain load (:397-398), while the generated child trampoline writes RUNNING/DONE with ordinary AArch64 STR at :297-302. HALT writes TCB.STOP through plain ! (:364-379) and PAUSE reads it through plain @ (:361-374). docs/threads.md:66-71 explicitly requires shared task cells to use atomic@/atomic!/fence; tests use atomic@ for application counters but APP-WAIT-DONE polls the unsynchronized lifecycle cell (lib/task-test.f:124-128). Thus completion publication has no release/acquire edge: a parent may observe DONE without the worker's preceding writes, and a worker may fail to observe a halt request.

There is a second race even if each load/store becomes atomic: TASK-KILL (:381-395) rereads status up to five times in independent if clauses. A worker can move RUNNING -> DONE after the DONE comparison but before the RUNNING comparison, causing every branch to miss; KILL returns without pthread_join, without releasing mappings, and without restoring EMPTY. HALT can likewise overwrite a concurrently published DONE with HALT-REQ. Load-once dispatch alone does not make the transition safe because the observed state can become stale before the side effect; define a legal transition table and use compare-and-swap, a lifecycle mutex, or an equivalent single-owner protocol so every RUNNING/DONE/HALT race has exactly one join/release owner. ACTIVATE must not start or free a TCB while another lifecycle operation owns it.

An archived broad race-fuzz dot says it was superseded by a narrow task-state race dot, but an exact tracker search finds no live replacement. Make lifecycle publication explicit: release-store DONE and halt requests, acquire-load status/stop, and emit the matching STLR/LDAR instructions in the native task trampoline; keep parent-only pre-spawn/post-join transitions clearly separated or use the same atomic accessors. Define and enforce the single-controller rule for concurrent ACTIVATE/HALT/KILL calls, or serialize those transitions if multi-controller use is supported. Join before any TCB/stack release and prove no publication occurs after free. Add disassembly assertions for LDAR/STLR at exact trampoline offsets, a worker-payload-before-DONE visibility test, a deterministic barrier-driven RUNNING->DONE-between-branches regression, repeated halt/finish/kill races, concurrent lifecycle-controller stress if supported, injected pthread-create/join failures, and cross-platform task gates. Every completed/halting task must be joined exactly once, release mappings exactly once, and end EMPTY. Preserve TASK API behavior and trampoline ABI; measure code size. Files: lib/task.f, task-test.f, docs/threads.md, native task trampoline tests. Depends: none. Ownership: lifecycle memory ordering and transition atomicity only; TCB STRUCTURE migration stays habu-libs-migrate-runtime-c2738a4d.
