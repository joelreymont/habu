maki/model-ir.f:100-102 makes MIR-CAP=128, MIR-INCAP=384, and MIR-IN-CAP=64 private. At least fusion-plan.f, backward.f, checkpoint.f, executor.f, golden-artifact.f, gradcheck.f, lower/ew.f, lower/red.f, lower/mm.f, lower/launch.f, and batch-loader.f copy those numeric limits or state that their tables mirror them; LMM-ARENA/BL-ARENA similarly copy lower-launch/executor arena limits. There is no static equality assertion or single owner. Today the numbers happen to match, but increasing MIR admits graphs that copied smaller consumers reject, decreasing it leaves every copied table overallocated, and a partial edit cannot be found by the type checker because the relationship exists only in comments. The repeated per-node tables also materially amplify any accidental over-sizing across every loaded Maki image. Introduce a small package-owned model-limits module with public typed/named limits and derived byte/element bounds; make model IR and every true whole-model consumer allocate and validate from those exact definitions. Keep policy-specific caps distinct and named as such rather than falsely mirroring a global limit. Add a census/gate that rejects raw duplicate whole-model limits and compile-time/focused tests proving max-size graphs pass all consumers while max+1 fails at the common boundary before any store/allocation. Measure loaded DATA before/after and remove overallocated duplicate tables where a sparse/region-sized structure is sufficient; coordinate node-register table factoring with habu-factor-shared-maki-3151485f. Files: new package-owned Maki limits module, model-ir and listed consumers/tests, maki/test.f, FILEMAP.md. Depends: none. Ownership: capacity identity/derivation and capacity-sized storage only; no lowering algorithm factoring.
