Root-cause fix for TRUSTED growing linearly with declarations: every EXTENT: mints a TRUSTED injector (>#M), every NOMINAL: mints two trusted identity casts, because the checker cannot express a retype into a nominal family. Design target: one checker-known cast form so declaration-generated converters are CHECKED, not trusted. Sketch: a core declarer CAST: <name> ( n -- <family-tail> ) [guard-body] ; where the checker itself certifies the body under the rule 'input cell flows to output unchanged; the only allowed effect is a guard that throws' - i.e. the checker types the identity data-flow and the guard, and the retype is sanctioned by the declaration form rather than by trust. Extent injectors then declare their range guard in the open (n 0 < over #M >= or if E-EXT-RANGE throw then) and stop being trust rows; NOMINAL: converters become guardless checked casts; the roles.f built-in pairs (>IDX/IDX>N etc.) migrate too. This retires the largest class of TRUSTED rows and stops the per-declaration growth. Phase-0 priority: design the checker rule first (what exactly the certifier must prove: single-cell identity flow, no other writes, guard throws only), write the negative suite (a cast that mutates, drops, or swaps must be rejected), then implement. Depends on nothing in flight; touches checker.f, so serialize with any other checker.f lane.

DESIGN SETTLED 2026-07-19 (orchestrator). The certifier rule, v1:

  CAST: <name> ( in -- out ) <body> ;

(1) The body is certified by the ORDINARY checked-word certifier under the row ( in -- in ) - the declared input type on both sides. So an empty body certifies trivially; a guard body (dup 0 < over 128 >= or if E-EXT-RANGE throw then) certifies because dup/comparison/throw are ordinary checked operations; any net stack change, unbalanced branch, or type misuse is an ordinary reject. No purity rule beyond checkedness in v1: the body may do anything a checked word may do, because the cast then adds no unsoundness any checked word could not already contain. (2) At publication, the declarer swaps the certified row's output for the DECLARED out and records ( in -- out ) through the one publish choke (checker.f:456 E-ADD-EFFECT). (3) The retype legality check at that swap: exactly one input and one output term, and both in and out must be single-cell of the same machine class - a plain cell, an arity-0 family scalar, or a parametric family cell (type var allowed, so IX>N's generic ( ix<e> -- n ) projection works). Width or class reinterpretation (n -> ptr a, rc -> ptr u8) is REFUSED - those stay TRUSTED; CAST: covers exactly the nominal/family retype class. 

COVERS (retires these trust sites): extent injectors >#NAME with their range guards (maki/extent.f generated), IX>N, NOMINAL: converter pairs (lib/type/value-nominal.f generated), the report handle converters after stage A0, roles.f built-in pairs >IDX/IDX>N/>LEN/LEN>N/>FD/FD>N. DOES NOT COVER (stays TRUSTED): reinterpret casts (ARENA-RC>PTR, TOKBUF-RC>PTR, HIDX-RC>PTR...), evaluate boundaries (XG-EVAL/NG-EVAL/DTC-EVAL), machine-code emitters.

NEGATIVE SUITE (must reject): out arity != 1 or in arity != 1; out family undeclared; in/out different machine class (n -> ptr a); body with net stack effect; body consuming the input (drop swap games caught by ( in -- in ) certification); declarer used inside a checked body (top-level-interpret-only like the other definers).

IMPLEMENTATION SHAPE: a core declarer beside the existing definers (sumtype.f neighborhood), parsing name + signature + body source, running the standard certify with the substituted row, then publishing the swapped row. FEASIBILITY FIRST: probe how a definer can drive certify-then-publish-swapped through the existing choke; if the publication path cannot take an overridden row cleanly, STOP and report the actual mechanics plus the minimal seam - do not force it with a private checker fork. MIGRATION is separate follow-up changes per consumer (extent.f, value-nominal.f, roles.f), not part of the primitive's landing change.
