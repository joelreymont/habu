Problem: `DYNAMIC-BUFFER BYTES u8` throws E-CHECKER-LAYOUT-BUFFER (7121) at the declaration while `DYNAMIC-BUFFER CELLS n` loads (measured on eafd8a99). STORAGE-VALIDATE hands the element to CHECKER-STORAGE-INFO (src/core/checker.f:4718-4734), which admits no sub-cell element - STORAGE-STRUCT-CON? rejects CC-U8/U16/U32/CHAR (checker.f:4701-4706) - and answers its width as a cell count; DBUF-SOURCE (src/core/layout-buffer.f:527-545) scales the accessor's index and the reserve by `LBUF-W @ cells`, so the generator has no byte width either, although DYNAMIC-STORAGE:RESERVE ( n ptr ptr a n -- ) already takes its element width in bytes (src/core/dynamic-storage.f:114). For TYPED-BUFFER the refusal is the documented rule (docs/forth.md "A TYPED-BUFFER element is a storage type, never bare u8": a byte row is `n BUFFER: B`), but a growable byte row has no library form: Tender's scripts/marks-apply.f (lane Tender-size-tender-apply-4a2436b3, fb50baf8) needed four byte sinks sized from the input and doubled on demand, and fell back to lib/memory.f MEM:BYTES-ALLOC / RELEASE-BYTES with a copy on growth, a second allocation idiom beside its tables.
