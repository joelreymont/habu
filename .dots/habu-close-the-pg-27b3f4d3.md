Problem: src/lib/pg.f:1075-1077 SEND-FAILED ( res -- ) retires the result slot and throws E-EXEC but leaves the connection open, against the module contract at pg.f:1319-1320 ("A transport failure closes the connection and throws E-EXEC"); POLL-QUERY :935-940 and WAIT-PROGRESS :1006-1007 call ABANDON-SLOT (:843) before throwing. SEND-FAILED is called with the result slot from EXEC-START :1088 and :1101, :1116, :1133, :1148, :1182, so the fix must reach the connection's slot. Second defect (same module, reported by phil): CONNECT-REFUSED :891-895 hands back the refusal text as a pointer into the connection slot's message mapping, then CLOSE-SLOT releases the slot; another task's CLAIM-CONN-SLOT (:560-564) can take the slot and its refusal's MESSAGE-ROOM (:588-593) releases or overwrites that mapping before the first caller reads its text. The header (:1325-1326) promises the bytes only "until the next CONNECT takes it", which any task's CONNECT can be. Acceptance: (1) every send failure abandons the connection's slot before E-EXEC, as POLL-QUERY does; (2) a refused CONNECT's text stays the refusing caller's to read whatever other tasks connect (design by the lead before dispatch: the text the caller reads must not live in a slot another task can claim). Regression rows on the real load path against the private cluster (test/db/pg-cluster.f): a send that fails (for example after the backend is terminated, as test/db/pg-kill-test.f does) leaves the connection closed; two tasks, one refused, one connecting, and the refused text intact.
