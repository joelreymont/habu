Problem: src/compiler/native/select.f SEL-FUSE-OF fuses only the six comparisons of two GENERAL registers into a machine select; a float comparison keeps a64.fflag and the select is made on the number it answers, which costs a Cset, a negation and a compare-against-zero where an Fcmp and a Csel would do. The answers are already right - a64.fflag answers zero for a NaN because the conditions it is given are the three that are false under the unordered flag - so this is a cost item and not a correctness one. Acceptance: a64.fcmpsel and a64.fcmpselz in src/compiler/native/a64ir.f taking their compared values from the floating file and answering a general register, SEL-FUSE-OF extended to the freg and fzero kinds, and a case in test/compiler/native-select.f plus a NaN row in tools/codegen-compare-corpus3.f proving the fused float select takes the same arm the interpreted word does. Files: src/compiler/native/a64ir.f, src/compiler/native/emit.f, src/compiler/native/spill.f, src/compiler/native/select.f, test/compiler/native-select.f. Verify: bin/hb --load test/compiler/native-select.f, native-a64ir.f, native-chain.f, tools/codegen-compare.f. Depends: none. Ownership: the a64 dialect and the selector.

Scope refined 2026-08-04 by the fcsel lane, which landed habu-select-between-two-98a15305 and found this dot is a bigger piece of work than its two named forms. A select of this dialect is a pair (which instruction wrote the flags, which file the chosen value lives in), and the two axes are independent. The landed change added the second column: a64.selzd and a64.cmpseld, which test or compare CELLS and choose between DOUBLES. This dot adds the second ROW - flags written by an Fcmp - and it therefore needs FOUR forms and not two: a64.fcmpsel and a64.fcmpselz choosing between cells, which is what this text asked for and is the shape MAX-F has, plus a64.fcmpseld and a64.fcmpselzd choosing between doubles, which is the shape RELU-F has. Both bodies are in the corpus and both would reach SEL-FUSE-OF once it admits the freg and fzero kinds, so shipping only the two named forms would refuse half the shapes it was written for or, worse, select the wrong file. The naming is spelled out at the head of src/compiler/native/a64ir.f's select section: a leading `f` says the compared values are doubles, a trailing `d` says the chosen value is, and all four names are reserved there and unused. The NaN argument is also NOT the landed one and has to be made afresh: the landed forms never compare a double, so no unordered flag reaches them, whereas a fused float select reads the flags an Fcmp left and its correctness rests entirely on the condition table at the head of src/compiler/native/select.f - `mi`, `gt` and `equal` are the three that are false under the unordered flag, and a table that read the condition off the relation's name would take the other arm for a NaN. Per-form work: schema in a64ir.f, opcode slot and MATCH row in emit.f and spill.f, a PUT- word, an INSNS-OF row, a shape case in test/compiler/native-a64ir.f. Claim: RELEASED 2026-08-04 by the fcsel lane - the dot was claimed with its sibling and is not started. It stays active and is free to claim.
