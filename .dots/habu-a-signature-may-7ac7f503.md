Problem: the signature reader admits a row letter that names both a data row and the row after `|`: `: X ( U | U -- U | U ) ;` is accepted (PSIG and SIG-PARSE-QUOT share ROWMAP across one signature; RCLAUSE-NEUTRAL?, src/core/checker.f:7723, tests only that the return clause is one bare row, the same on both sides). A call of such a word unifies the caller's data row into its return row, so the return base is bound with no read token. `: T ( n | U -- n n | U ) X r@ swap swap ;` is refused as E-NONPARAMETRIC-EFFECT at the last `swap`, not at `r@`; `: T ( n -- n n ) X r@ ;` and `: T ( -- n ) 5 >r [: 7 X r@ swap drop ;] execute r> drop ;` are refused only by the seals (CHECK-NO-BORROW, QUOT-RSEAL), which pin the last token walked (`: T ( n -- n n ) X r@ dup drop ;` is pinned at `drop`), the second at `;]`, where docs/forth.md and docs/forth-card.md say a quotation literal that reads a return cell it did not push is refused at the read. Acceptance: the declaration is refused where it is written: a letter after `|` that also names a data row anywhere in the same signature, top level or inside a quotation type, is E-BAD-SIGNATURE fix_return_stack (E-BAD-STORED-SIGNATURE on the stored path; SGBAD-RETURN!); none of the 19 library signatures with `| U` is refused; docs/forth.md (after "the same on both sides") and the return-clause line of docs/forth-card.md state the rule; a T above without a quotation and the quotation T are cases in test/top-row-storage-test.f refused at the signature. Whether the seals' bound-base branches are then unreachable is asked only after this lands, by a proof or a census, not assumed. Depends: none. Claim: unassigned.
