Problem: a task that waits for another task or for the AIO loop has no way to park on its OWN wake-up: TASK:WAIT needs a semaphore the waiter and the signaller share, TASK:JOIN and the mailbox cover two fixed cases, and a loop that completes work for many tasks cannot hold one pooled semaphore per waiter (TASK-SEM-POOL-N is 64). docs/tasking-models.md Decision (2026-09-16) already fixes the hosted row: STOP blocks on the task's own semaphore, WAKE posts it. Design (decided): src/habu/task-abi.f gains a PARK-OFF semaphore record in the TCB (sem_t plus guard, the MSG-FREE/MSG-FULL shape; TCB-BYTES grows) created with the task and destroyed with its memory; lib/task.f: STOP ( -- ) parks the calling task on its park semaphore (EINTR retried as TASK:WAIT does), WAKE ( ptr a -- ) posts the named task's park semaphore; a WAKE before the STOP is not lost (the count), so the protocol is: WAKE is a hint, STOP waits for a hint, the caller re-checks its state after every STOP. The main thread has no TCB (TASK:SELF answers the null TCB there): STOP on the main thread parks on one MAIN-PARK semaphore package TASK defines, and WAKE of the null TCB posts it, so a program with no tasks can wait on the loop too. TASK:HALT also WAKEs its target, so a task parked in STOP returns and observes the request at its next TASK:PAUSE (document that a STOP loop must PAUSE). WAKE of an EMPTY, CONSTRUCTED or DONE task is E-TASK-STATE. Acceptance (lib/task-test.f): producer/consumer through STOP/WAKE with a shared cell; WAKE before STOP not lost; HALT releases a task parked in STOP and the task ends at its PAUSE; main-thread STOP woken by a task; WAKE of a never-activated task refused; TCB-BYTES pinned where the suite pins it. docs/threads.md: the two rows in the public list and a 'STOP and WAKE' section stating the hint protocol; docs/tasking-models.md Decision row marked landed.
