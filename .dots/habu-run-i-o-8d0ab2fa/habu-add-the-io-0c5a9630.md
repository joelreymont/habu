Problem: no runtime primitive lets a task wait for readiness, a timer or a cancellation without parking its thread in the host call (parent). Design (decided): package AIO, lib/aio.f, Linux only, requires lib/task.f. RING: io_uring_setup(AIO-ENTRIES 256, IORING_SETUP_CQSIZE, cq 512) and io_uring_enter through two FUNCTION: declarations over libc syscall in PROCESS-SYMBOLS (NR 425 and 426, /usr/include/asm-generic/unistd.h; the io_uring_params extent, 120 bytes, declared written; enter: fd to_submit min_complete flags 0 0); the SQ ring, CQ ring and SQE array mapped with the engine's mmap (MEM-PROT-RW, MEM-MAP-SHARED, the ring fd, IORING_OFF_SQ_RING 0 / IORING_OFF_CQ_RING $8000000 / IORING_OFF_SQES $10000000) and turned into ptr u8 views by ONE private TRUSTED: projection bounded by the sizes io_uring_params reports (lib/memory.f MEM-MAPPED>PTR is the pattern; document it as the module's one address crossing); SQE and CQE fields written and read with private LE16/LE32/LE64 accessors at the offsets of /usr/include/linux/io_uring.h (sqe 64 bytes: opcode 0, flags 1, fd 4, off 8, addr 16, len 24, op flags 28, user_data 32; cqe 16: user_data 0, res 8, flags 12); the sq tail store and the cq head store follow a fence, the cq tail read is followed by one. RECORDS: AIO-OPS, MAX-OPS 256 fixed records (state, owner TCB, res, flags, kind), user_data = record index, a record claimed free->submitted with atomic-cas and every other record access under one TASK:FACILITY; AIO:ticket is a nominal cell over the record (NEWTYPE plus private CAST:, the TASK:sem pattern). SUBMIT (any task, under the facility): claim a record, write the SQE at sq tail and mask, array[i] = i, fence, tail+1, io_uring_enter(fd 1 0 0). LOOP: TASK:TASK AIO-LOOP activated by LOOP-START ( -- ) (E-AIO-STATE when running); its body: io_uring_enter(fd 0 1 IORING_ENTER_GETEVENTS), drain the CQ: the record by user_data, store res and flags, state done, TASK:WAKE the owner (a forget record is freed instead); the loop and every submitter run compiled words only. LOOP-STOP ( -- ): E-AIO-BUSY while any record is not free, else set the stop flag, submit a NOP, TASK:JOIN the loop, munmap, close. A submission with no loop running is E-AIO-STATE: the loop is started explicitly (a live task forbids compilation, docs/threads.md, so the program decides when). PUBLIC: LOOP-START, LOOP-STOP, READABLE and WRITABLE ( -- n ) event masks, POLL-ADD ( fd n ms -- AIO:ticket ) (IORING_OP_POLL_ADD; ms >= 0 links an IORING_OP_LINK_TIMEOUT SQE with IOSQE_IO_LINK, ms -1 none), TIMEOUT ( ms -- AIO:ticket ) (IORING_OP_TIMEOUT, count 0), CANCEL ( AIO:ticket -- ) (IORING_OP_ASYNC_CANCEL on the ticket's user_data, submitted on a forget record; the target then completes cancelled), AWAIT ( AIO:ticket -- AIO:outcome ): the calling task must own the ticket (E-AIO-STATE); loop: state done -> take the outcome and free the record, else TASK:STOP and re-check; AWAIT-ANY ( AIO:group -- AIO:ticket AIO:outcome ) over a GROUP ( -- ) defined set of at most AIO-GROUP-MAX 64 tickets (GROUP+ ( AIO:ticket AIO:group -- ), GROUP- , GROUP-COUNT): the first done ticket of the group, the same STOP loop; the ticket leaves the group. AIO:outcome is a layout: ready ( n ) (res >= 0: the revents mask), timed-out (a TIMEOUT that fired, -ETIME, or a POLL-ADD ended by its link timeout, -ECANCELED with the link's -ETIME), cancelled (-ECANCELED by CANCEL), refused ( n ) (another -errno, positive). A task's in-flight tickets are cancelled and forgotten by a TASK:AT-EXIT AIO registers at the task's first submission, under the facility, so the loop never WAKEs a TCB that is gone. Errors: E-AIO-SETUP and E-AIO-ENTER (FFI:ERRNO on stderr), E-AIO-STATE, E-AIO-FULL (no free record or SQ full), E-AIO-BUSY, E-AIO-GROUP (group full or ticket not in it), new block in lib/errors.f. ACCEPTANCE (lib/aio-test.f, registered in test/gate-stdlib-cases.f beside lib/task-test.f; pipes only, no network): (1) POLL-ADD readable on a pipe from a task, main writes -> ready with READABLE set; (2) completion before AWAIT (write first) -> ready; (3) TIMEOUT 20 -> timed-out, elapsed >= 20 ms; (4) POLL-ADD ms 30 on a silent pipe -> timed-out; (5) CANCEL of a pending POLL-ADD -> cancelled; (6) 64 POLL-ADDs from 8 tasks completed by writes -> 64 ready, and the count of /proc/self/task entries during the run = before + 8 + 1; (7) AWAIT-ANY over 4 polls, one written -> that ticket ready, the other three then cancelled and awaited cancelled; (8) main-thread AWAIT (through STOP on the main park); (9) refusals: AWAIT by a task that does not own the ticket, AWAIT twice, submit with the loop stopped, LOOP-START twice -> E-AIO-STATE; LOOP-STOP with a pending ticket -> E-AIO-BUSY; MAX-OPS+1 submissions -> E-AIO-FULL; (10) a task HALTed while parked in AWAIT ends and its ticket is gone (LOOP-STOP then succeeds); (11) LOOP-STOP then LOOP-START again works. docs/aio.md: the model, the surface with effects, the two syscalls and the projection as the module's trust boundaries, the hint protocol, the kernel floor (5.10; the ops date from 5.5), x86-64 note (libc syscall is variadic: the x86-64 FFI must zero al); docs/threads.md points to it.
