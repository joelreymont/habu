Problem: lib/ffi.f is a compatibility loader that republishes RTLD-NOW, DLOPEN, and DLSYM globals; lib/ffi-abi.f leaves its whole implementation global and republishes P>N and >CSTR beside the canonical FFI package. The repository has no users requiring compatibility and aliases are forbidden. Result: delete lib/ffi.f; make lib/ffi-abi.f one package FFI from the first implementation definition, leaving all buffers, constants, raw pointer conversion, C-string copy, and dlopen internals private; keep only the current public FFI API. Replace every loader with lib/ffi-abi.f and every external P>N or >CSTR call with FFI:>CELL or FFI:CSTR, including production, tests, generated-source fixtures, and live docs. Update lib/ffi-abi.f to require its own string dependency. Remove RTLD-NOW, global DLOPEN/DLSYM/P>N/>CSTR completely; no aliases, shims, forwarding globals, versioning, fallback, or replacement package. Ownership: FFI implementation and exact caller migration. Checkpoint-discovered ownership migration: the exact-diff package gate requires the four closed legacy modules to gain package owners FFI-TEST, DEVICE-SMOKE, AD-GRADCHECK, and GRADCHECK; every test/seal-package.f definition belongs in one SEAL-TEST package, folding the test-only SPK-EXEC, SPK-PARITY, and SPK-TYPE-NAME seams into private definitions, preserving every production-observing seal/parity/type-name assertion, exposing only RUN, and invoking SEAL-TEST:RUN. These module owners are not a replacement FFI package. Acceptance: zero live lib/ffi.f loads and zero bare legacy names outside historical archives; existing negative lower-transaction fixtures still exercise FFI:>CELL; ffi, task, tensor, CUDA/PTX, protection/seal, Maki, exact diff, and full gates pass; device-only legs run when available and remain enrolled otherwise. Checkpoint: baseline focused FFI/task/tensor and host device-independent gates green; representative direct caller fails if the compatibility loader/global is deleted before migration.
