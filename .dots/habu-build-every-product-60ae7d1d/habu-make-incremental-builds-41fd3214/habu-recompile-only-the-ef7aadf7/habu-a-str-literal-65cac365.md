Problem: a facts text (a word's effect as text) is laid through the build's string table (src/core/checker.f PLACE-FACT, INTERN:TEXT) at the end of its part, after the part's D bytes, and only when no earlier part holds it. A later file's string literal with the same bytes resolves to that text (INTERN:STRING finds before it lays) and is saved as a tag-3 data reference: the part and an offset from its first data byte (src/habu/linker.f DATA-REF+). A check holds that offset only to the part's size (DATA-REF-CK), and nothing compares the texts a linked part lays with those it laid. So when an earlier file gains a word with one of the part's texts, the part links, lays one text fewer, and the holder links with an offset that now names other bytes.
