Design (Plan agent, 2026-11-10, read at carl-d6 2d5cdbe6; it stopped on its context limit before reading test/file-objects.f's cases, LINK-OBJECT's insides, DEF-SOURCE-END and where FILE-CELLS is set). Decisions, all in src/habu/linker.f:
1. LOAD (:4793) becomes the one loop over a file's parts, a private state machine with the turns link, compile and cut. Link turn: while a part links, REPLAY its request and go to the next part at the resume offset. Compile turn: open the part and run the source from its offset; when the reading returns, a cut goes back to the link turn at the part and offset NEST set, and a source's end closes the last part as today. COMPILED-N and LINKED-N keep today's meaning (a file with any compiled part counts as compiled).
2. NEST (:4853), at a clean cut, writes part k, loads the request and restores the requester's variables as today, then ends the requester's reading by storing INE into INP (as src/habu/packages.f:241 does), sets FILE-PART, FILE-OFF and the turn to cut, and returns without opening part k+1. At an unclean cut it behaves as today.
3. RESUME (:4832) gets a sixth clean-cut condition: the running reader is the file's own range reader, its start and end the source's and its cursor at the request token's end. Without it a loader word run from an evaluated slice of the file's own text would end that slice, not the file's reading.
4. Saved format: the object header gains START, the part's first byte as an offset into its source; WRITE-OBJECT writes it from FILE-OFF and HEADER-CK (:3148) requires it to equal where the reader stands. Without it a part that now ends at a different request (a require under [defined] X [if]) lets the old next part's object link over a different span, leaving source uncompiled. Hard cutover; it shifts PRIOR-READ's offsets (:3684) and test/file-objects.f HEADER-BYTES, PIECES-FIELD and FILES-LEN-FIELD (:156-158).
5. UNLINKABLE becomes per part: LOAD sets it for each part it opens; NEST carries it only across an unclean cut.
