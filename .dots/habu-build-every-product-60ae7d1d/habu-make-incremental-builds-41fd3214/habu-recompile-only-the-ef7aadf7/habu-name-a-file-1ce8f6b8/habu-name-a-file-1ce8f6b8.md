Problem: a data reference is a file and an offset from the file's first data byte (src/habu/linker.f DATA-REF+), a reference to an earlier file's data names its piece whole, and the run rule follows data by piece (DATA-EDGE+, STORERS). So a string made longer or a variable added mid-file gives every word naming later data a new time, and any new piece time compiles each file holding an address into the piece. Acceptance: the string and variable edits of the six-edit table, in src/core/util.f and src/habu/repl.f, compile the edited file and only files that use a word whose code, facts or data changed; warm equals cold unsigned; every reference of the census (.out/reports/census-data-anchors.md) has an answer. Files: src/habu/linker.f, test/fixtures/file-objects/build.f, what the design names. Verify: six.sh (~/.cache/tmp/carl-words/six), ev.sh. Depends: the design (brief carl-layout/.out/briefs/design-data-by-owner.md); lanes after habu-link-and-compile-e77aa1cb merges, since they rewrite the same words. Ownership: carl. Claim: agent=carl workspace=.jj-ws.noindex/carl-layout (design only; no lane workspace yet).

Design 2026-11-10 (Plan agent on Fable, read-only; carl-layout/.out/design-data-by-owner.md): a part's data is cut into extents at the anchors the linker already reads (a record's body start or dispatch cell, a string's length cell, the part's first byte); an extent takes its word's identity, a string the sum of its bytes and its count, the head its part; each extent has its own time, kept while its length, bytes and cell rows equal the old object's; a data reference is (file, extent identity, offset in the extent), tag 3 a word's data, 6 a string's, 7 a part's head; an object lists each earlier extent it names or reaches with its time (EXTENTS); a part has one changes time over its STORES rows and the rows that change earlier records, and REACHED lists each part that stored into a listed extent with that time. No public word, error code or flag. Lead's ruling on its one trade-off: one changes time per part, not one per storer and target extent; lane 4's six-edit run decides whether a finer one is needed. Read from the run4 base objects: ten of the eleven files an unused word appended to util.f still compiles hold util.f whole in REACHED (the run rule reaching its data by part); kernel-object.f compiles because it requests boot.f, which habu-link-and-compile-e77aa1cb removes. Lanes, each a child dot when briefed, after habu-link-and-compile-e77aa1cb merges: (1) save a part's data as extents with times; (2) name a data reference by its extent; (3) list the extents a part names; (4) reach data by extent and compare a part's changes time; tests and docs join the stack's last lane.

Joel 2026-11-10, shown the design's two not-determined items (whether the body-edit counts move; the one address in sumtype.f whose owner it could not identify): "figure it out!". Found so far (carl, from the run4 base objects): the sumtype.f address is TDECL-ADDR-SIZE-WORD's string literal `s" ( -- n ) "`, saved as a data reference to src/habu/boot-cells.f's part 0 at +8, once in the engine load and once in the kernel load (the census's "twice"); boot-cells.f's object holds `( -- n ) ` as a length-prefixed text and its sources lay no other data (constants and colon words), so the hypothesis is that the bytes are a facts text boot-cells.f laid after its data (the effect of BOOT:GLOBAL-WL, boot-cells.f:15) which the string literal shares. Not yet read: whether the intern table holds facts texts (src/habu/intern-table.f, linker.f LINK-FACTS, PIECE-PLACE) and so how many string literals resolve to a facts text; if so the design's inference "no reference names the facts texts a part lays after its D bytes" is wrong and a facts text needs an extent. Body-edit counts: six-edit run5 with the part-by-part engine (~/.cache/tmp/carl-words/six/run5.out) measures them after that lane.

Both items settled 2026-11-10 (carl). (1) The sumtype.f address is a facts text: a part lays each facts text no earlier part holds through the string table (src/core/checker.f PLACE-FACT, INTERN:TEXT) after its D bytes, and a later literal with the same bytes resolves to it. Read in the census log (~/.cache/tmp/carl-census/run.ylTS/hb2.log): of 1236 off-anchor references only two come from code, both this literal. So the design's inference that no reference names a facts text was wrong. Amendment (design section 3 "Facts texts"): each text a part lays is a string extent of the part, registered when it is placed, with a string's identity and no time; an extent with no time names its part whole, and the holder's check also needs the part to have laid that text in this build. It joins lane 2. The same hole links stale today: dot habu-a-str-literal-65cac365, with a reproducer, is an acceptance case of these lanes. (2) The body-edit counts moved with habu-link-and-compile-e77aa1cb, not with this design: run5 in the parent dot (util.f body 108 files to 96; repl.f 3).
