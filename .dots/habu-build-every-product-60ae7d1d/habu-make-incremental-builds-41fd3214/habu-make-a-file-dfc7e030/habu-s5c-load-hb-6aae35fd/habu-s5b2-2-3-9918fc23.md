Problem: after S5b2-1 a build still shares with hb the core stores DFER, CT, VREC, PIMM and UNSAFE and the type stores with the TFAM caches (/tmp/jerry-big/design-s5b2.md:119-134, census /tmp/jerry-big/s5b2-census-a-handoff.md and s5b2-census-a2.md), and NAV's location and pending-use rows (DL, PU, src/core/checker.f NAV block), keyed by record offset, which a rewind inside a build truncates (DL-TRUNCATE, PU-TRUNCATE) and so drops hb's rows; NAV's rows exist only while a source verifier visit has navigation armed (verify-source.f ARM-UNSEALED), which no LINKER:WITH caller does today (S5b2-1a review finding 5, /tmp/jerry-s5b2a/review/). Acceptance: each store switched by package CHECK's rows; the cases the design names through the real path (a defer and a DEFLINEAR declared in two builds with different effects; a STRUCTURE named like hb's frame, after which the host's ( frame -- frame ) is unknown as before); NAV switched or shown unreachable from any build. Files: src/core/checker.f, src/core/type-family.f, test/linker.f. Verify: bin/hb --load test/run.f -- linker on an hb rebuilt from the tree. Depends: S5b3 (a build reaches those definers only once it sees them). Ownership: jerry. Claim: unassigned.

Finding (2026-11-06, jerry): this dot's approach, switching the checker's own stores per build (design-s5b2.md, landed in part as S5b2-1 d6b69973), goes against DECISIONS "where the checker's facts live" (2026-11-05): a word's facts are stored on its dictionary entry and types in the declaring program's wordlists, found by the dictionary's own lookup. Today the checker still keeps them apart: its symbol table (src/core/checker.f:8323 SYM-FIND, USIGS :7535) and its type registry with its own hash and scope rules (src/core/type-family.f:617 TFX-HASH, :703 TFAM-FIND-IN, :772 TFAM-RESOLVE). Do not start this dot; the design that moves the facts onto entries replaces it and removes S5b2-1's store switch.
