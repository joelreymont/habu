Problem: a stripped image is refused with exit 74 when its closure holds a recorded address into DATA allotted before the capture window opened, and the commonest way to get there is a build driver that requires a library in the linker process before the window: Tender's scripts/build.f:9 requires lib/process-env.f, which loads src/os/env-base.f, so the application's later require is a no-op and its GETENV links against the pre-window instance whose scratch variable ENV-QU lies below BLOB-SRC (name-cell lane 1188f268, 2026-09-17: 'aot: address refers to data outside the restored span caller=GETENV region-off=3819088 value=13964069392 target=ENV-QU span=[13973298984,13980758384]'). This, not execution tokens in persistent data, is what refuses Tender's server/entry.f; aspen's bisection (/tmp/aspen-aot-server.md) pointed at xts because src/main.f hits that other refusal first. The 74 now names the caller and the target word but not the cause: nothing says the target's module was loaded before the window, which file it came from, or what the driver should change. Acceptance: the refusal names the source file that defined the target and states that it was loaded before the capture window opened; docs/aot (the stripped-image page) states the rule that a build driver must not load anything the application reaches before the window, with the two honest shapes (link in a child engine whose window opens first, as tools/hb-build does, or keep the driver's own requires disjoint from the application's); tools/hb-build's own driver is checked for the same preload and a regression builds an image whose driver preloaded a module the application requires and asserts the named refusal. Decide in the lane, with evidence, whether the linker can instead re-instantiate a preloaded module inside the window; if it can do so soundly that replaces the refusal. Files: src/habu/aot-closure.f, tools/hb-build*.f, docs, a test under test/compiler. Verify: the regression; Tender's server/entry.f build reports the named cause. Depends: habu-name-the-cell-740feb52. Ownership: AOT. Claim: unassigned.
