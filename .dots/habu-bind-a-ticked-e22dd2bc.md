Problem: a direct call binds a fresh name on the callee's plain inputs to the argument's identity (src/core/checker.f E-AK-BIND, :11587) and mints only the rest, but executing a ticked word mints every fresh name at the tick (TICK-QUOT :11480, EFF-QUOT :11464), inputs included, so a sound program is refused: with defer RR-OWN ( -- matrix<space-global,fresh-region-a,f32,f32> ) and defer RR-MFRESH ( matrix<space-global,fresh-region-b,f32,f32> -- matrix<space-global,fresh-region-b,f32,f32> ), ': X1A ( -- ) RR-OWN ['] RR-MFRESH execute drop ;' is refused ('expected matrix<...fresh-region-b-a...> actual matrix<...fresh-region-a-b...>'), while the direct ': X1D ( -- ) RR-OWN dup RR-MFRESH swap RR-MFRESH RR-UONE ;' is admitted.

Same class: an executed tick or literal shares its effect's value variables across executions, while a direct call instantiates them per call (E-I-TV); QUOT-INST (:4528) renews only the per-execution identities and keeps named rows shared (checker.f:146-148). With IDX ( x -- x ): V1T ['] IDX dup 1 swap execute drop RR-OWN swap execute drop is refused (expected n, actual matrix); the direct 1 IDX drop RR-OWN IDX drop is admitted. Y8SEP `[: RR-OWN swap RR-APPX ;] dup [: ;] swap execute RR-MFRESH drop [: ;] swap execute RR-MFRESH drop` and Y5SEP (the same through `['] RR-GIVEX`) are refused at the second execute: the quotation's quantifier x is bound by the first execution to its minted identity. Without per-execution instantiation of a quotation's quantifiers no rule tells them from the unsound Y8 (both executions into RR-UONE; test/rigid-region-suite.f C-QCBINLIT, C-QCBINTICK). The fix is one design: a quotation's type is instantiated per execution as a direct call instantiates a callee's effect, fresh inputs included; settle which variables are the quotation's own (not the enclosing definition's) before coding.

Body-side twin: a callee that declares a quotation input whose output carries a fresh region names that region once per call, so executing the quotation twice in its body yields one region twice. `: K-QOUT-BODY ( [ -- matrix<space-global,fresh-region-b,f32,f32> ] -- ) dup execute swap execute RR-UONE ;` is admitted; no checked caller can pass such a quotation, but the body itself is admitted. A defer declared `( -- [ -- M<fresh> ] )` whose quotation the body executes twice is admitted too.

Acceptance: a ticked word's fresh name on a plain input is a variable at every occurrence, as E-AK-BIND makes it at a direct call (share E-AK-BIND's rule, no second copy), so X1A, 'RR-OWN dup ['] RR-MFRESH execute swap ['] RR-MFRESH execute RR-UONE', V1T, Y8SEP and Y5SEP are admitted and every rigid-region case keeps its answer; the checker refuses a body that executes a declared fresh-output quotation input, or such a defer's quotation, more than once with region mismatch, or a design lets the declared type say it runs once (design first: lead, then Joel if a new declaration form, a 'run once' quotation type, is needed); test/rigid-region-suite.f shows X1A admitted and K-QOUT-BODY refused; docs/forth.md 'Rigid host-allocation identity domains' states the rule. Depends: none. Claim: unassigned.
