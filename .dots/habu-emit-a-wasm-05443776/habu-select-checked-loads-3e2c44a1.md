Problem: a Habu pointer is a canonical zero-extended offset in an eight-byte cell; before narrowing, an access must prove 0 <= p <= 2^32-1, n >= 0 and p + n within the memory, in wide arithmetic, and the null reservation is enforced by pointer operations because address zero is in bounds (wasm-backend.md §6.1-§6.3, §17.5). HIR stages load, store, bload, bstore and mem (src/compiler/native/hir.f:51-99), and address literals carry DATA or CODE kinds (hir.f:557-560). Acceptance: WSEL lowers load, store, bload and bstore to i64 checks then i32.wrap_i64 and the access; a failed check records the fault kind and address in ctx and traps with unreachable, as a native fault is fatal; the check is high bits zero and p >= $10000 before i32.wrap_i64; the engine's bounds trap covers p + n; an address literal becomes the padded `i64.const` address site with its HIR kind (DATA to a linear-memory offset, CODE to an xt descriptor written by the linker); effectful loads, stores and calls keep their order (§16 Control and type invariants). Rows: an upper-bit pointer, a last-byte access, a one-past-end access, a null-region access: the upper-bit and null-region accesses record the fault kind and address in ctx and trap, the last-byte access succeeds, and the one-past-end access of linear memory traps in the engine's bounds check. Files: src/arch/wasm/select.f, test/wasm/select-mem.f (new), test/gate-stdlib-cases.f (SUITE wasm-select-mem). Verify: bin/hb --load test/wasm/select-mem.f; a mutation that narrows before checking fails the upper-bit row. Depends: habu-select-calls-status-c567343c. Rule: the backend loads at run time on the sealed product engine and uses public words only (portability.md:348); no edit to any sealed package (CTARGET, CBIND, HIR, NBACK, NELAB, NCOMP, NEMIT, NSHADOW, IR-*) after habu-add-the-wasm-4c32353e. Ownership: src/arch/wasm/select.f (memory rows), test/wasm/select-mem.f. Lane: tim. Claim: unassigned.
