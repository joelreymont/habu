Problem: dynamic calls use a uniform (ctx: i32) -> status adapter over a per-context stack of eight-byte cells (wasm-backend.md §7.2); a stored xt is a nominal descriptor, never a function index, and Habu identities are checked before dispatch because Wasm's signature check cannot see them (§7.3, §9); catch restores depth and keeps the full code, and depth restoration is not rollback (§8.1). HIR stages execute, catch, finally, is and evaluate as a wordcall (src/compiler/native/elaborate.f:2152-2161) and a quotation as `quot` with its function's offset (src/habu/aot-shadow.f:172-180 FUN sites). Acceptance: per reachable word and quotation an adapter function; a table and elem segment through WLINK with no slot reused in an epoch; quot and CODE literals become descriptor handles; this dot adds the WSTRUCT form that names a function's address (a MINOR bump) and WENC's write of it, since the selector refuses HIR quot until then; descriptor = table slot in the low 32 bits, module epoch (1) in the high 32; execute and catch trap on a slot past the table or a foreign epoch and on a depth shortfall against the slot's arity; nominal identity beyond arity is the checker's static proof in one module (P7 revisits when modules compose); execute and catch are runtime functions that call the adapter, and catch restores depth and answers the full 64-bit code; quotations stay noncapturing. W06 (dynamic half): a 17-input word reached through execute agrees with its direct call. W07: catch observes a full-width throw; a trap passes through catch. Verify: bin/hb --load test/wasm/dynamic.f, executed through the harness on a WLINK-built module.
