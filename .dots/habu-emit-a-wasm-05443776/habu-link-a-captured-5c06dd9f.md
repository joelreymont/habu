Problem: the first slice links the whole set of routines from the capture (wasm-backend.md §10.1, §17.1); link-x64.f is the x86-64 twin, which lays the shipped records, routines, sites and code cells out and refuses everything it cannot place by name before writing a byte (src/habu/link-x64.f:1-60, 117-128 capture readers), and refuses a code record with no routine, such as a variable, created word or defer (:19-21). Acceptance: package WASMLINK in src/habu/link-wasm.f reads the capture's shipped records, AOT-SHADOW routines, sites and xt rows and the window DATA with its address cells; splits each routine into its Wasm functions by its function rows; resolves engine-prefix names through WKERNEL's map; builds the data segment from window DATA at WPROF's layout with every address cell rebased to its linear-memory offset and every code cell to an xt descriptor; names the entry function to WLINK, whose header must say in 0 out 0 (memory, run, throw-code, out-base and out-len are WLINK's wrappers); hands everything to WLINK and writes the module atomically. Refusals, by name and before the first byte: a code record with no routine, a name no kernel row answers, a site naming an unshipped record, a field past its width. Files: src/habu/link-wasm.f (new), test/wasm/link-capture.f (new), test/gate-stdlib-cases.f (SUITE wasm-link-capture). Verify: bin/hb --load test/wasm/link-capture.f; the linked module validates under the harness. Depends: habu-read-wasm-shadow-781e58d7, habu-assign-wasm-indices-6da85390, habu-provide-the-engine-d01ca805, habu-add-xt-descriptors-40679cdf. Rule: the backend is loaded at run time and calls only the public words of the engine's packages (the packages compiled into bin/hb); when it needs more, that package gains the word and the engine is rebuilt.
