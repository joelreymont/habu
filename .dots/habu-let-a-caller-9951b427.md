Problem: a plain fresh-region-* input is minted anew at every call site (src/core/checker.f E-INST), RECURSE included, so only a value whose region is a free variable satisfies it; a view from C2-MEM:ALLOC (a rigid region) never does. Since habu-pass-a-fresh-bb992e31 the body holds such an input as one identity, distinct from every other fresh input, but no checked caller can supply one: A-ALLOC-P5 (an ALLOC view into ': P5 ( mut-view<p,q,fresh-region-b,u8> -- mut-view<p,q,fresh-region-b,u8> ) ...'), K-CALLFWD, and ': R3 ( M_b -- M_b ) RECURSE ;' are refused on master and on the landed tree (frgn lane review finding 3; Fable feature review, probes /tmp/jerry-frgnrv-tmp, /tmp/jerry-fcrv-tmp). Words with a direct fresh input are therefore uncallable. Acceptance: at a call, each input-side fresh name binds to the argument's rigid identity of its domain, two names never to one identity (the call-side mirror of FRESH-CLAIM), so an ALLOC view passes to P5, one view passed as both inputs of '( M_b M_c -- )' is refused with E-RIGID-REGION-MISMATCH, and an argument whose region is the caller's own region variable is admitted only where two fresh inputs cannot receive one region; rows in test/rigid-region-suite.f for each, the accepted ones failing on the master engine. If binding at the call is unsound for some program, measure it and refuse a fresh name on a plain input at the signature instead, with a named reason.
