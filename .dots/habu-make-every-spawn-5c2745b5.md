Problem: the process library writes the C strings posix_spawn reads with its own terminators and its own NUL checks instead of FFI:CSTR, the library's one NUL check (E-FFI-NUL) and terminator writer (src/lib/ffi-abi.f:542-576: "FFI is the only library code that writes a terminator"). PROC-ZCOPY (src/lib/process.f:214) copies the program path (process-command.f:345), the cwd (process-command.f:270, process-cwd.f:41), PROC-PATHZ (process.f:224), the pty device path (process-pty-io.f:146) and PROC-ARGV+'s rows (process-argv.f:94) and appends a 0 without checking the bytes; CMD:ARG+ (process-command.f ~:248) appends an argument and a 0 the same way; the env row writers carry PROC-ENV-CHECK-NAME/-ENTRY (process-env.f:159-187), which refuse a NUL in a name but not in a value or entry. A NUL inside any of these cuts the string at the child: path '/bin/echo\0-x' runs /bin/echo rc 0, argument 'a\0b' reaches the child as 'a', entry 'HOME\0X=1' gives a malformed HOME row. Ruling relayed by tim 2026-10-30 (from Joel): one mechanism, FFI:CSTR. Acceptance: every C string the process library builds (program path, cwd, pty path, argv rows, env rows) is made by FFI:CSTR or FFI:CSTR! into its owner's buffer; PROC-ZCOPY, the hand-written terminators in CMD:ARG+, PROC-ARGV+ and the env row writers, and the per-writer NUL checks go (the env checks keep only their empty and '=' rules); a NUL in a path, cwd, argument, env name, value or entry refuses with E-FFI-NUL before any byte is written; rows in src/lib/process-command-test.f (NUL path, cwd, argument, env value, env entry) and process-argv-test.f (PROC-ARGV+) fail before and pass after; the PROC-ZCOPY length rows in process-test.f move to the FFI:CSTR refusals they become (E-SPAN-LENGTH, E-SPAN-CAPACITY). Supersedes habu-refuse-a-nul-4bfde9f3, habu-refuse-a-nul-017181ce, habu-refuse-a-nul-2d2fbc4b (closed). tim's unxpoqwt, ozlspozq, mzwptnlt are withdrawn (checks outside FFI). Files: src/lib/process.f, process-command.f, process-argv.f, process-env.f, process-cwd.f, process-pty-io.f and their tests. Verify: hb --load src/lib/process-command-test.f, process-test.f, process-argv-test.f, process-env-test.f (each </dev/null, bin/hb in the workspace); hb --load tools/check.f on each changed file. Depends: none. Ownership: the process library's C-string writers. Claim: unassigned.
