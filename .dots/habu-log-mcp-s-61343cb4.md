Problem: docs/forth-card.md section 6 (:467-469): a failure caused outside the program (a provider, the network, the OS) is logged once, with its text, by the library that saw it, just before it throws. MCP and BEARER throw with no LOG line, so a caller cannot say why: src/lib/net/mcp.f CHECK (:1181-1185, `failed OF drop E-TRANSFER throw` drops curl's code), PREPARE's CURL:INIT failure (:1305-1309), TRANSFER's CURL:NEXT failure (:1382); src/lib/net/bearer.f EXCHANGE's CURL:INIT failure (:705-714, answers -1), RECEIVED's failed or truncated transfer (:681-692, -1), REQUESTED?'s failed settings (:670-677), ISSUED's 2xx without access_token or expires_in (:760-766) and TOKEN's E-REFUSED for a 4xx and E-TRANSFER for a 5xx (:778-784): the issuer's status and its error text are lost. Seen from tenderd (kevin, Tender lead, 2026-11-06, /tmp/kevin-carl-log.md): when Zen or Entra is down its line can say only 'Zen could not be reached (E-TRANSFER ...)'. Acceptance: each of those sites writes one LOG:ERROR line just before it throws (or answers -1 that becomes a throw), tagged "mcp" or "bearer" (card: the package name in lower case), carrying curl's code and CURL:ERROR$ text as model.f CURL+ (:2212-2216) does, or the issuer's HTTP status and its answer text for a 4xx or 5xx; ISSUED's line names the status and the missing member and never the answer, which can hold a token; MCP's throw after CANCEL (PREPARE :1304, STOP@) is the program's own and logs nothing. Tests capture stderr as model-test.f CAPTURED (:2063-2066) and find the line: one MCP transfer past its limit (mcp-test.f :1028-1030 case) and one refused token (test-issuer-test.f :449 case).
