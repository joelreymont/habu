Prerequisite B for the direct-BL campaign (habu-aot-repl-bl-a71440da). Root cause of that dot's blocked stage: RBASE-VA = $300000000 (src/habu/layout.f:9) puts the live JIT code region 12 GiB from the engine __text (Linux VMBASE $400000, src/os/linux/elf.f:25; macOS VMBASE $100000000), versus BL imm26's +/-128 MiB reach - which is exactly why LP2VEXEC/LPROTSPAN emit the absolute movz/movk/movk x16; blr x16 chain (src/habu/habu2.f:4874-4875, :4901-4902). The gap is a layout CHOICE, not a constraint. Move the region into BL range of __text and every call becomes BL, dictionary and helper alike, collapsing the AOT capture wire format to ONE format instead of the dual format the gap would otherwise force. Constraints: (1) macOS is PIE (src/os/macos/macho.f:12) so __TEXT slides - the region must be mapped RELATIVE to the runtime-discovered text base (mmap hint, verify the returned address is within BL range, die named if not; NEVER silently fall back to the absolute chain), and the mechanism must be uniform across targets even though Linux is non-PIE; (2) MAP_FIXED at the current constant (habu2.f:3315) blindly clobbers - the new mapping must prove non-collision, not assume it; (3) RBASE-VA is baked into snapshots, so bump SNAP-FORMAT-VERSION (layout.f:11, currently 3) and handle old snapshots fail-closed; (4) consumers that derive from RBASE-VA (crash.f:108-109, tools/imgdump.f:197) follow the constant and must be re-verified, not just recompiled. Depends on the relocation-metadata dot (the magnitude heuristic in aot-lib.f CELL-TEXTPTR? stops being safe once the window sits near ordinary integer magnitudes). Acceptance: region provably within +/-128 MiB of __text on BOTH targets with the range asserted at boot and fail-closed otherwise; fixpoint x2 byte-identical; snapshot round-trip across the version bump; full cold gate; CODELEN rows same-commit. Territory: src/habu/layout.f, habu2.f region mapping, snapshot version, crash.f/imgdump.f verification.

Depends on habu-identify-code-pointers-b973e6cc (the magnitude heuristic must go first).
