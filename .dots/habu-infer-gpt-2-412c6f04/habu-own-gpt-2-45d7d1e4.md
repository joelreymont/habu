Problem: the landed byte-pair encoding implementation stores tables and work buffers in singleton globals and has no type distinction between incomplete construction and immutable use. Result: package BPE defines one checked allocation layout plus two linear owners: `BPE:builder` for an incomplete mutable table and `BPE:state` for a sealed immutable table with bounded encode/decode workspace. This leaf owns allocation geometry and both lifetimes; separate leaves own table population, encoding, and decoding. It is an unlandable foundation of the atomic BPE hard cutover: the combined stack deletes the singleton implementation before any new BPE surface reaches master. Owner: reusable byte-BPE allocation and lifetime only. Production red: two independently owned builders cannot coexist and an unbuilt table is accepted wherever an immutable table is required. Acceptance: two builders with different capacities expose distinct usable storage and close independently in both orders; exact and page-boundary one-short geometry, overflow, real allocation refusal, fatal release, and linear misuse are proved through the real public path. Builder-to-state retyping and static encode/decode rejection of a builder are owned by the table and codec leaves and must be green on the atomic combined tree before this foundation lands. The final combined tree contains no singleton BPE table or workspace. Forbidden: table insertion, encode/decode algorithm, asset I/O, model adapter, global storage, callback, fallback vocabulary, version, compatibility alias, runtime ready flag, or special result type. Smallest owning check: bin/hb --load maki/infer/bpe-state-test.f.
