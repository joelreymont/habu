Problem: a program whose top level calls AT-EXIT:ADD and then ends the process (`3 die`) during hb-build exits with the program's status: the program's action runs, hb-build's own exit actions do not (its line 'ended the process during the build', tools/hb-build-lib.f:536, is not printed; its temporary directory is left). Without the ADD the builder exits 74 with the line. Cause: the build space's copy of AT-EXIT writes the process-exit vector (src/lib/at-exit.f ADD :76-78) over the builder's, so two copies of the owner live in one process. Reproducer, x-die.f: 'require src/lib/at-exit.f' / ': BYE ( -- ) s" bye" type cr ;' / ': ARM ( -- ) [: BYE ;] AT-EXIT:ADD ;' / 'ARM' / 's" x" 3 die' / ': MAIN ( -- ) ;'. 'TMPDIR=<empty dir> bin/hb --load tools/hb-build.f -- x-die.f -o x-die.out' prints x and bye, exits 3 and leaves hb-build-native-<n>-0 in TMPDIR; without the require, ARM and its line it prints x and 'hb-build: x-die.f ended the process during the build' (tools/hb-build-lib.f:402), exits 74 and leaves TMPDIR empty. Source: Joel, 2026-11-10: "i want all issues identified to be dotted and fixed". Open, to settle from the code: what a build-time registration means. Ways seen: the copy's runner calls the vector it replaced after its own actions (needs a rule against two copies chaining to each other); the build's top level registers with the builder's AT-EXIT; AT-EXIT:ADD refuses while a build is open. Acceptance: the case exits 74 with hb-build's line and leaves no temporary directory, as a case in test/exit-hook-test.f that fails on the base; a state table of the vector for one and two copies is beside the code. Depends: none. Claim: unassigned.

The same answer settles three more cases. A file the build's top level registers with FS:CLEANUP+ is removed by neither the builder nor the target. If a step of src/habu/linker.f UNDO (:5296) above 'moved' throws (IMAGE-OUT, DISPOSE-OBJECTS, REQUIRE-RESTORE, CHECK:CLOSE), CLOSE ends before RESTORE and the space stays mapped with its runner in the vector (inferred from the code, not reproduced). ARM-EXIT (linker.f:4691) spends one of AT-EXIT's 64 slots, so with 63 hb actions a build fails 7122 where it would succeed; a design in which a space's AT-EXIT:ADD never writes hb's vector makes ARM-EXIT and SAVED-EXIT-HOOK removable.

Acceptance case: a build a FAIL-CLOSED exit refuses leaves its scratch directory in TMPDIR. tools/hb-build-lib.f HBB-PREPARE-TMP (:226) makes a private directory under TMPDIR that only the exit hook removes; a refusal that ends through FAIL-CLOSED (src/habu/interpreter.f:355: SEALED-FAIL, TASK-GUARD) clears EXIT-HOOK-CELL before it dies, so the hook never runs and an empty hb-build-native-<n>-0 directory stays. Reproducer: a build of test/fixtures/file-objects/seal-main.f with TMPDIR set to an empty directory. Hunt first: every exit path of a build that skips the hook, as path:line, and where the directory should be removed on each. Acceptance: a refused build leaves nothing in TMPDIR; test/file-objects.f SEAL-CASE asserts it, and TOOL-RUN (:513) drops its TMPDIR once Q's build (kept-zip.f's open archive) also leaves nothing in TMPDIR.
