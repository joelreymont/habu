Problem: a program whose top level calls AT-EXIT:ADD and then ends the process (`3 die`) during hb-build exits with the program's status: the program's action runs, hb-build's own exit actions do not (its line 'ended the process during the build', tools/hb-build-lib.f HBB-EXITED :400, is not printed). Without the ADD the builder exits 74 with the line. Cause: the build space's copy of AT-EXIT writes the process-exit vector (src/lib/at-exit.f ADD :76-78) over the builder's, so two copies of the owner live in one process. Reproducer, x-die.f: 'require src/lib/at-exit.f' / ': BYE ( -- ) s" bye" type cr ;' / ': ARM ( -- ) [: BYE ;] AT-EXIT:ADD ;' / 'ARM' / 's" x" 3 die' / ': MAIN ( -- ) ;'. 'TMPDIR=<empty dir> bin/hb --load tools/hb-build.f -- x-die.f -o x-die.out' prints x and bye and exits 3; without the require, ARM and its line it prints x and 'hb-build: x-die.f ended the process during the build' (tools/hb-build-lib.f HBB-EXITED :400) and exits 74. Source: Joel, 2026-11-10: "i want all issues identified to be dotted and fixed". Open, to settle from the code: what a build-time registration means. Ways seen: the copy's runner calls the vector it replaced after its own actions (needs a rule against two copies chaining to each other); the build's top level registers with the builder's AT-EXIT; AT-EXIT:ADD refuses while a build is open. Acceptance: the case exits 74 with hb-build's line, as a case in test/exit-hook-test.f that fails on the base; a state table of the vector for one and two copies is beside the code. Depends: none. Claim: unassigned.

The same answer settles four more cases. A file the build's top level registers with FS:CLEANUP+ is removed by neither the builder nor the target; and a temp file its top level makes for something the image keeps, such as the zip source snapshot (src/lib/zip.f SNAPSHOT-WORK :39) of the archive test/fixtures/file-objects/kept-zip.f opens, stays in TMPDIR. If a step of src/habu/linker.f UNDO (:5720) above 'moved' throws (IMAGE-OUT, DISPOSE-OBJECTS, REQUIRE-RESTORE, CHECK:CLOSE), CLOSE ends before RESTORE and the space stays mapped with its runner in the vector (inferred from the code, not reproduced). ARM-EXIT (linker.f:5063) spends one of AT-EXIT's 64 slots when its no-op is not yet registered; a design in which a space's AT-EXIT:ADD never writes hb's vector makes ARM-EXIT and SAVED-EXIT-HOOK removable.
