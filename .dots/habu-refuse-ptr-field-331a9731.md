Problem: the raw-storage rule (habu-refuse-a-ptr-5ad2734e, commit 1204d189) refuses ptr-field on a TVK-RAW base, but the base can be passed through a parameter first: 'create V 2 cells allot  : F ( ptr n -- ptr ptr u8 ) 0 ptr-field ;  : LAUNDER ( n -- n ) {: x:n :} x V ! V F @ c@ ;' certifies on the rule engine raw-rule-gen1 with no diagnostic (lib/tools conversion lane, 2026-09-17), because ptr-field on a base whose pointee is a scalar variable forges a free pointer pointee, the same reinterpretation the rule exists to stop; production uses of the shape: tools/lint/text.f:117 LINT-SLAB:BUF-FIELD over create SLAB (:173) and tools/build-fixpoint.f:222 BF-PTR-U8-FIELD. Acceptance: ptr-field admits only a base whose pointee is a nominal record type with a declared pointer field at that offset (the form src/core/structures.f PTR-FIELD: generates) or a declared pointer cell, and refuses a scalar or free pointee by name with the E-RAW-CELL-PTR family (a third MD- code naming ptr-field's base kind); the LAUNDER fixture and a ptr n parameter fixture rejected in test/compiler/raw-cell-pointer-refusals.f; the two production sites converted to declared forms; a census of ptr-field sites whose base is ptr n or ptr a measured on a rule engine before the rule lands. Files: src/core/checker.f (the ptr-field row's base check), src/core/render.f, tools/lint/text.f, tools/build-fixpoint.f, test/compiler/raw-cell-pointer-refusals.f, docs/effects.md. Verify: the fixtures; raw-rule-gen1 rebuilt with the rule; the affected suites; test/run.f. Depends: habu-convert-the-raw-8052992f. Ownership: checker. Parent: habu-refuse-a-ptr-5ad2734e. Claim: unassigned (the rule landed 2026-09-18; this hole waits on habu-design-a-declared-bcee616d).
Measured 2026-09-18 (rule lane): the acceptance above is not expressible as written. src/core/structures.f PTR-FIELD: generates ': NAME ( ptr a -- ptr ptr b ) <off> ptr-field ;' with a FREE pointee by design (there is no nominal record type in the language; BEGIN-STRUCTURE publishes only a size constant), and ptr-field's own row ( ptr a n -- ptr ptr b ) with b free is the loophole: both ': F ( ptr n -- ptr ptr u8 ) 0 ptr-field ;' and ': F ( ptr a -- ptr ptr u8 ) 0 ptr-field ;' launder an integer stored in a raw cell (measured on a rule engine), while the bare ': G ( ptr a -- ptr ptr u8 ) ;' is already refused with E-NONPARAMETRIC-EFFECT. Refusing only a scalar base pointee closes one fixture and leaves the one-character variant open; requiring a pointer-typed base pointee refuses essentially all ~180 call sites. Candidate rule (not yet designed): at the call, a pointer whose pointee is RAW may not enter a row that manufactures a pointer not derived from that pointee (a per-row 'manufactures a pointer' property checked when a RAW pointee binds), which refuses both launders and leaves ( ptr a -- ptr a ) accessors alone; its cost is a caller cascade over every record with a pointer field kept in create'd raw storage (lib/vector.f, lib/serial-xmodem.f SOURCE-FIELD/OUTPUT-FIELD, lib/byte-buffer.f DATA-FIELD, lib/db/pq.f, tools/lint/text.f LINT-SLAB:BUF-FIELD, tools/build-fixpoint.f BF-PTR-U8-FIELD), unmeasured. Root cause shared with habu-refuse-a-scalar-030be3ad: without a nominal record type, a record mixing a pointer field and scalar fields is expressed by casting one through ptr-field or through byte-view/cell-view; closing both holes needs a record facility (a campaign-level design). The rule landed without this hole closed; the LAUNDER fixture sits in test/typed-storage-structural-test.f SECTION-RAW-IS-VACUOUS as a documented-open row naming this dot.
