Problem: on the rule engine raw-rule-gen2, 'PTR-VARIABLE V  : POKE ( n -- ) V BYTE-VIEW CELL-VIEW ! ;  : READ ( n -- n ) POKE V @ c@ ;' certifies (prefix-form lane, 2026-09-18): BYTE-VIEW and CELL-VIEW are type-level renames (src/compiler/native/hir-word.f DEF-BYTE-VIEW/DEF-CELL-VIEW) that reinterpret a declared pointer cell's bytes as a scalar cell, so an arbitrary integer is laundered into the declared cell and read back as an address with no TRUST row; the same PEEK/POKE the raw-storage rule habu-refuse-a-ptr-5ad2734e closes, reached through the declared form the rule prescribes, so it defeats the rule for every declared cell. Sibling of habu-refuse-ptr-field-331a9731 (ptr-field over a scalar pointee). Acceptance: a view over a base whose pointee is a pointer (or a pointer-holding record head) does not admit a scalar store into the pointer's own cell: BYTE-VIEW/CELL-VIEW refuse a pointer-pointee base, or a store through such a view is refused, with a named diagnostic in the E-RAW-CELL-PTR family; the legitimate uses (reading a count cell behind a declared head, DYNAMIC-BUFFER's 'cell+ byte-view cell-view @', ARENA-SNAP-BOOT's zero pass) keep certifying, measured across the tree on a rule engine; the POKE/READ fixture and a view-over-declared-head fixture in test/compiler/raw-cell-pointer-refusals.f. Files: src/core/checker.f (the view rows or the store rule), src/core/render.f, test/compiler/raw-cell-pointer-refusals.f, docs/effects.md. Verify: the fixtures; a rule-hosted generation build; test/run.f. Depends: habu-refuse-a-ptr-5ad2734e's rule commit. Ownership: checker. Parent: habu-refuse-a-ptr-5ad2734e. Claim: agent=hazel-rule workspace=.jj-ws/hazel-rule.
Measured 2026-09-18 (rule lane): confirmed on a rule engine; the same chain over a RAW cell is already refused at c@, so it is specific to declared cells. Neither placement in the acceptance survives the tree: refusing byte-view over a pointer-pointee base meets src/core/dynamic-storage.f CTL ( ptr ptr a n -- ptr n ), the text DYNAMIC-BUFFER generates (NAME#base cell+ byte-view cell-view @), ARENA-SNAP-BOOT's zero pass over PTR-U8-TABLE boot buffers, and src/core/cell-effects.f's two stores through BYTE-VIEW CELL-VIEW; refusing the store cannot separate offset 0 (the pointer's own cell) from the count cells behind the head because the checker sees no offsets. byte-view's row drops the pointee and cell-view mints a concrete ptr n, so nothing downstream remembers the base was a pointer cell. Root cause shared with habu-refuse-ptr-field-331a9731: no nominal record type, so a record head followed by scalar counts is expressed by view casts; the fix is a record facility (a declared record with a pointer field and scalar fields, whose accessors carry offsets the checker knows), after which the view rows can refuse a pointer-pointee base. The rule landed without this hole closed; the POKE/READ fixture sits in test/typed-storage-structural-test.f SECTION-RAW-IS-VACUOUS as a documented-open row naming this dot.
