Problem: a type's generated words are rendered as source text that names engine words by spelling, and both the check (src/core/sumtype.f TDPLAN-PREFLIGHT :1347) and the compile (TDECL-EVAL-XT :1053, through the interpreter's FIND) look that spelling up through the declaring package's search order, so a package word of the same name captures it. Silently wrong: `=` before an ENUM or SUMTYPE with DERIVE eq inverts EQ; `+` before DERIVE init makes a getter read the wrong field; `drop` before an ARENA makes NAME-NEW call the package's word. A qualified spelling does not fix it: the checker gives intrinsic identity per bound symbol and none to a qualified token (src/core/checker.f TOK-IDENTITY :16900, SPELLED-STEP? :20742). Generators that still name engine words: DERIVE tag/eq/hash and init (src/core/sumtype.f), src/core/arena.f ARENA (SOURCE :27), src/core/heap.f HEAP (SOURCE :28), src/lib/fsm.f FSM:DEFINE, src/lib/ffi-abi.f FUNCTION:, src/lib/ffi-callback.f GEN-RUN and src/compiler/workspace.f CWORK DECLARE (habu-lay-cwork-s-08f4da91). The generated text must still resolve in the package: its own family and field types, private generated names, FSM user words, MATCH variant names. Nothing binds past the search order today: the own-package spelling `P:*` falls through to the global word when P has no public `*` (src/habu/habu1.f:5883-5884), but a public word still captures it and a qualified token has no identity, so `P:record-at` and `P:swap` over a sum value are refused.
Ruling (Joel, 2026-11-12), told that Forth compiles a defining word once in its own vocabulary and makes each child data plus that shared code, where Habu evaluates generated text in the declaring package: 'we should do what swiftforth does, prove me wrong!'. Not disproved. So: no generated source text; a declaration's words are entries made by definers compiled once in Habu's scope, each child given its typed effect from the type data the checker holds; words with per-declaration logic (DERIVE eq/hash, FSM, FUNCTION:) are compiled from words already found, not spelled. Open before a brief: the design of the typed child and of the logic words, and a measurement that a field access is no slower than today's.
Limit (Joel, 2026-11-12): 'i want to make sure that you DO NOT take habu apart with the above changes. they should not involve deep changes to the compiler'; told that had been recorded as a ban on touching the compiler: 'it's not that it should not touch it. it should work in a separate workspace and merge when ready.' So the whole feature is built in one workspace apart from master and merges when it is ready; a compiler change is allowed there. Then: 'otherwise, you are free to take the compiler apart but work in small chunks while taking the most direct route to the objective!'. Route (lead): `postpone` first, since binding a generator's engine words when the generator is compiled closes every case with the code each word compiles to unchanged; one generator per chunk, each shown by its reproducer; children as data follow only where they delete machinery. Shown a shorter route that keeps generated text and spells engine words as global (`:*`), Joel chose: 'take route 1' (no generated text: `postpone`, `define`, `body-append`, his names). Names (Joel, 2026-11-12): `postpone`, and `define-word` for the opener, chosen when `define` clashed with FSM's DEFINE, which Tender and Maki call bare. Found by the first lane: the checker gives every type variable of a create/does> child the raw-storage kind (src/core/checker.f TRUST-RAW, CREATED-RECORD-BUILD), so a plain does> field word is refused under `( ptr a -- ptr a )` and a named pointee, which today's field words accept; a child's own effect comes before any field moves.
Acceptance cases (lanes on define-word/postpone/body-append, 2026-11-13; each comes from text the route still parses): a package with a part named ARENA captures the type ARENA:arena in a generated signature; body-append keeps a line feed inside a token, so pending `key` then a line feed reads as one unknown name; DERIVE init renders TRUSTED: rows (src/core/sumtype.f :2132-2330), which habu-trusted-dies-prim-4fd12d60 retires. With no generated text none of them exists. A refused `postpone ;` abandons the definition (src/habu/interpreter.f POSTPONE-RUN); a throw between define-word and `postpone ;` that a catch takes leaves it open, which the catch case of habu-move-the-interpreter-d35780fa fixes. FSM's section in docs/forth.md says what FSM:DEFINE makes once it builds from found words. A warm rebuild equals the cold one, and a warm build where a compiled file names a linked file's `+FIELD` children checks. Tier 1 compiles a definer whose body uses `postpone` (today "ncomp: cannot compile ... at *" on the installed engine too). `literal` and `compile,` are in docs/forth.md and the card. The definition item cells (src/habu/layout.f BODY-ITEMS) are protected as BODY-TEXT's cells are.
Design (2026-11-13, Astra cut by the lead; the root checkout's .out/designs/design-no-text.md.settled): two paths, typed children whose effect the checker derives from the schema, and logic words the checker judges from bound items instead of text. postpone W keeps the found record; body-append is deleted. Names (Joel, 2026-11-13): `literal ( n -- )` appends a number to the definition being built; `compile, ( xt -- )` appends a word the definer found while running. A definer ends the word it builds with `postpone ;`: `;` is an ordinary dictionary word (Joel, 2026-11-14).
Acceptance: a generated definition binds the engine words its text names whatever the declaring package defines; each case above, as a test, answers right; no name is reserved for it.
