# The x86_64 backend

The design reference for the x86-64 backend. It fixes what is shared with
ARM64, so that nothing is forked by accident. [INTEL.md](../INTEL.md) holds the
campaign state, the hosts and the dot tree.

## What a "backend" is in this tree

Habu is native all the way down. The engine (`src/habu/habu1.f`,
`habu2.f`) is written in Habu's own ARM64 assembler; the compiler lowers HIR
to a machine IR (`src/compiler/native/a64ir.f`), selects, allocates and emits
ARM64; the OS seam under `src/os/linux/` holds aarch64 image constants and an
ELF writer; the FFI (`lib/ffi-abi.f`) marshals for AAPCS64; the task entry
(`BTASK-ENTRY`) is ARM64 code. A second architecture therefore touches five
layers, not one:

| Layer | arm64 today | x86_64 needs |
| --- | --- | --- |
| Assembler | `src/arch/arm64/asm.f`, nominal operand types, `ENC-*` constructors | `src/arch/x86-64/asm.f` in the same discipline: typed registers, immediates, memory operands; variable-length encoding |
| Engine primitives | `habu1.f` primitives in ARM64 assembly, `habu2.f` compile-time emitters | the same primitive set in x86_64 assembly, from one primitive specification (below) |
| Compiler | `hir.f`, `hir-word.f`, `elaborate.f`, `loop.f` are target-free; `select.f`, `regalloc.f`, `spill.f`, `prune.f`, `emit.f`, `a64ir.f` name ARM64 registers and forms | `x64ir.f`, `select-x64.f`, `emit-x64.f`; register allocation, spill and the instruction selector's own folds parameterised by a register-file description instead of ARM64 constants |
| OS seam | `src/os/linux/{layout,elf,sys,repl-term,sign}.f` with aarch64 constants and syscall numbers | `src/os/linux-x86-64/` with the same file set and the same word names, selected by the target predicates `docs/porting.md` describes |
| Runtime ABI | AAPCS64 FFI, task entry, guard pages, signal frames | SysV AMD64 FFI, task entry, the same guard-page model |

`src/compiler/target.f` already carries architecture, ABI, byte order, pointer
width and features as one immutable contract with a digest, and refuses only
incoherent combinations, so an x86_64 contract can be declared before any
instruction is emitted. The backend registry
makes each backend a module that
registers its lowering and emitter when loaded, so `bin/hb` for one host does
not carry the other backend.

A backend occupies one row, keyed by the architecture's wire code and reached
through `CTARGET:ROW`. `src/compiler/target.f` holds the row's two acceptance
predicates — can this backend lower for, and emit for, this exact contract — and
`src/compiler/native/backend.f` holds the same row's pass quotations, each with
its own typed effect: declare, select, prune, lower fixpoint, emit, release,
retire, prototype, forget and capture-prepare. `src/compiler/native/compiler.f`
names no backend package; it runs each stage through the row the compilation's
own target contract resolves to, and an architecture whose rows are unfilled is
refused with `E-CTGT-UNLOADED` at the first stage. An x86_64 backend therefore
registers exactly the way `src/arch/arm64/backend.f` and
`src/arch/arm64/passes.f` do, and the driver needs no edit to reach it. There
is no `--target` flag: the registry is the single resolution point.

`src/arch/x86-64/backend.f` (`X64BACK`) requires only `lib/prelude.f` and
`src/compiler/target.f`, nothing under `src/os/`, so no engine prefix grows a
compiler dependency. It registers `SERVES?` (x86-64, little-endian, 64-bit)
as both of its row's predicates at load.

## Machine model

- **VM registers.** ARM64 gives the VM dedicated registers for the data
  stack pointer, data base, dictionary, code pointer, user area and the
  interpreter state, with 31 general registers to spare. x86_64 has 16. The
  design reserves: `rbp` user area, `r12` data stack pointer, `r13` data base,
  `r14` dictionary, `r15` code pointer; `rbx` the interpreter register; and
  `rsp`, the machine stack pointer, which the lowering lane added on
  2026-09-18: `call` pushes the return address through it, so a routine that
  allocated it would destroy its own return. ARM64 has no equivalent slip to
  make, because its stack pointer is not one of the thirty-one registers an
  operand field can name. **Seven registers are reserved and nine are
  allocatable** (`rax rcx rdx rsi rdi r8 r9 r10 r11`), all of them
  caller-saved by the internal convention. The callee-saved set under SysV
  (`rbx`, `rbp`, `r12`..`r15`) is exactly the reserved set less `rsp`, so a
  foreign call preserves the VM for free and the FFI needs no
  save-and-restore block. The data base is ARM64's `DBASE`, the code region
  the dictionary records live in (`habu2.f EM-SEED-DICT`), not the DATA
  region, which is the user area; the dictionary register holds the record
  count, ARM64's `NDICT`. The engine's six are declared once, by name, in
  `src/habu/layout.f`: `ENGINE-GPR:X64-INTERP` (`rbx`), `X64-RBASE` (`rbp`),
  `X64-DSTACK` (`r12`), `X64-DBASE` (`r13`), `X64-NDICT` (`r14`) and `X64-CP`
  (`r15`), and `ENGINE-GPR:X64-MASK` is derived from them, beside ARM64's
  `A64-DSTACK` and `A64-MASK`. "Kernel inventory" below gives each one's boot
  value and ARM64 twin.
  `ENGINE-GPR:DSTACK` and `MASK` select the running target's pair and die on
  a target that has neither, so the x86-64 compiler and runtime, which run on
  the ARM64 engine when it cross-builds x86-64, name the `X64-` pair.
  `src/compiler/native/x64ir.f RESERVED-MASK` adds `rsp` to `X64-MASK`,
  `REGFILE` states the register file from it, `src/arch/x86-64/machine.f
  X64M:DSTACK-GPR` reports `X64-DSTACK`, and `test/compiler/x64ir.f` asserts
  `rsp` is not allocatable.
- **Calls between compiled words** use the same internal convention as arm64
  (stack cells in memory, live values in registers within a routine); the
  register-passing work parked under C1 is out of scope here.
- **Immediates and addresses.** ARM64 builds constants from `MOVZ`/`MOVK`
  runs that the relocation writer patches; x86_64 uses `mov r64, imm64` for
  the same relocatable literal, one site to patch. The relocation writer
  (`src/habu/address-carrier.f`) has one site kind for it, exercised by `test/x86-64-seam.f`.
- **Guard pages and traps** are the same mmap protections; the trap decoding
  in the signal handler reads `RIP` and `RSP` instead of `PC` and `SP`.

## The assembler

`src/arch/x86-64/asm.f`, package `X64ASM`, holds the `ENC-*` encoders: the
integer ALU, move, extension, multiply and divide, shift and rotate, branch,
call and return, `setcc`/`cmovcc`, push/pop/`xchg`, the locked `xadd` and
`cmpxchg`, `mfence`, `syscall`, `nop`/`ud2`, and the scalar SSE2 double forms.

- **Operand nominals** are `r64 r32 r16 r8 imm8 imm32 imm64 condition rel
  mem`.
  - The sixteen words `RAX`..`R15` are `r64`, and the sixteen words
    `C-O`..`C-G` are `condition`.
  - `r32`/`r16`/`r8` are made with the generated `>R32` casts. An `r8` of
    4..7 means `spl bpl sil dil`: a REX prefix is forced, and the legacy
    high-byte registers do not exist.
- **Memory operands** are one packed cell, built only by these words, and
  every encoder re-screens the fields:
  - `MEM-AT ( r64 -- mem )`;
  - `MEM-OFF ( r64 n -- mem )`;
  - `MEM-IDX ( r64 r64 n n -- mem )`: base, index, scale 1/2/4/8 and
    displacement; the index is never `rsp`;
  - `MEM-RIP ( n -- mem )`.
- **Output.** Every encoder takes a `lib/byte-buffer.f` `BUF` header as its
  last operand and appends bytes; there is no instruction value.
- **Operand order** is destination first, then sources. Memory forms take the
  data register first. The suffixes are `-RR`, `-RM`, `-MR`, `-RI8`, `-RI32`
  and `-RI64`.
- **Sizes** are deterministic: they depend on the word chosen and the
  displacement magnitude. To size an instruction, encode it into a scratch
  buffer.
- **Relative operands.** A `rel` is measured from the end of the instruction.
  `ENC-JCC-REL8`/`ENC-JCC-REL32`, `ENC-JMP-REL8`/`ENC-JMP-REL32` and
  `ENC-CALL-REL32` are separate words. `call rel32` and `jmp rel32` carry
  their field at `CALL-REL32-OFF` (1), where a writer that links a call it
  did not encode patches it.
- **The relocatable literal** is `ENC-MOV-RI64`: 10 bytes, with the imm64 at
  `MOV-RI64-IMM-OFF` (2).
- **Refusal.** `E-X64ASM-OPERAND` (-8830) is screened before any byte is
  emitted.
- **Tests.** `test/compiler/x86-64-asm.f` (`SUITE compiler-x86-64-asm`) pins
  every encoder's bytes, each case with the `llvm-mc -triple=x86_64
  -show-encoding` line that produced it, plus runtime and checker refusals. The encoding notes are in
  [embedded-encoders.md](embedded-encoders.md), section x86_64.
- **Atomic forms.** Only the memory form of `xchg` is implicitly locked, so
  `ENC-XCHG-MR` carries no prefix and `ENC-XCHG-RR` is a plain register swap.
  `ENC-LOCK-XADD-MR` and `ENC-LOCK-CMPXCHG-MR` put the `F0` lock prefix ahead
  of REX and screen both operands before it. `ENC-MFENCE` is `0F AE F0`.
- **Not yet encoded**, until a caller needs them: 32-bit ALU forms beyond
  `ENC-XOR32-RR`, 8/16-bit ALU forms, memory-destination immediates other than
  `ENC-MOV32-MI32`, `lock` forms other than `xadd` and `cmpxchg`, the
  accumulator short forms and the `D1` short forms.

## The emitter's sink

Decided before any emitter code was written:
**the x86_64 emitter is a separate emitter, `src/compiler/native/emit-x64.f`
(package `X64EMIT`), writing through the `lib/byte-buffer.f` `BUF` sink that
`X64ASM`'s encoders already take as their last operand; `src/compiler/native/emit.f`
stays the ARM64 four-byte word sink and is not parameterised.** The reason is
what the two files are made of. `emit.f` is 1,743 lines, of which the layout,
the block order and the source map are a few dozen; the rest is eighty
`WORD-*` builders that construct one ARM64 word each and a placement pass whose
`INSN-BYTES 4`, `INSN-CAP` (instructions, not bytes), `WORD@` and `MAP-OFFSET@`
all assume a fixed-width instruction. Parameterising it would rewrite the
layout, the branch reach and the source map in bytes, leave the eighty word
builders unshared anyway, and put the arm64 path's byte identity at risk for no
reuse; the shared part is small enough to write again and the risk is not. The
`BUF` sink is also the shape the rest of the port already agreed on: every
`X64ASM` encoder appends into one, and `X64CODE:ASM-SINK ( -- ptr u8 )`
(`src/arch/x86-64/icode.f`), the stream the OS seam appends into, is that same
byte stream. **The layout pass therefore works in BYTES:** an operation's size
is measured by encoding it into a scratch
`BUF` and reading the length back (`X64ASM` sizes are deterministic but not
uniform), block starts are byte offsets, and a branch is laid out in the widest
form it may need (`rel32`, `ENC-JMP-REL32` / `ENC-JCC-REL32`) so one pass is
enough; shortening a branch to `rel8` is a later, separate relaxation and not a
condition of correctness. Relocatable literals stay `mov r64, imm64`: ten bytes,
the imm64 patched at `X64ASM:MOV-RI64-IMM-OFF` (2). `src/habu/address-carrier.f`
states that site's shape: `ADDRESS-CARRIER:MOVABS-SITE?`, `MOVABS-BYTES` and
`MOVABS-IMM-OFF`.

## The machine dialect

`src/compiler/native/x64ir.f` (package `X64IR`, dialect name `x64`, version
0.1) is the closed set of operations that stand for real x86-64 instruction
forms, the way `a64ir.f` is for ARM64. Three facts about the machine shape it,
and a lowering that forgets any of them is wrong in a way no later pass
catches:

- **Most forms are two-address.** `add rd, rs` overwrites `rd`, so every
  arithmetic form declares a schema TIE naming the operand it destroys. The
  tie is a must-share constraint the register allocator reads and refuses when
  it cannot satisfy, so the SELECTOR makes it satisfiable: it copies operand 0
  through `x64.mov` before the form whenever that value is LIVE AFTER the
  operation, and the allocator coalesces the copies it can. Liveness and not a
  count of uses: a value defined above a loop and read once inside it is read
  again when the backedge brings control round, and no operand of that branch
  names it. The selector computes live-in and live-out over the function's
  blocks for this (`select-x64.f`, "which values are live where"). A value
  read or live out in any block laid AFTER this one counts as live after too:
  the allocator's range is a hull over the blocks in ordinal order, so the
  value read on the arm a branch did not take still reaches past the form
  (`select-x64.f LATER-LIVE?`).
- **The flags are not a value.** Every use of `RFLAGS` is fused into one
  operation - `cmpset` (compare and set the 0/-1 flag), `cmpsel` (compare and
  `cmov`), `cmpbr` (compare and branch), `brz` (`test` and branch) - because
  no SSA value may stand for a single architectural resource.
- **One literal instruction, and no link register.** A literal is
  `mov r64, imm64` with the `MOVABS` site at offset 2, so there is no
  `movk` chain; `call` pushes the return address, so there is no `linksave`
  or `linkload`; and x86-64 has no write-back addressing, so a data-stack
  store and the pointer move after it are two operations where ARM64 fuses
  them into `dpush`/`dpop`.

Sixty-one opcodes (dialect MINOR 2), thirteen attribute keys, six signed conditions taken from the
assembler's own `C-L`/`C-LE`/`C-G`/`C-GE`/`C-E`/`C-NE` words rather than
written again. Two forms name a register the machine chose and the schema
declares each one as the form's own fixed operand and result: `shl`/`shr` read
their count from `rcx`, and `idiv` divides `rdx:rax` and leaves the quotient in
`rax` and the remainder in `rdx`. The selector makes them satisfiable the way it
makes a tie satisfiable - the count and the dividend are copied with `x64.mov`
immediately before the form and the copy is the operand the schema fixes. The
allocator pins that copy to its register and forbids the register to every
other value the form reads or lives across, the rule a fixed result already
has, so a value live across the form cannot keep the copy out of it. A pin is
placed where its class opens, and the register is forbidden as well to every
value whose range spans that opening (`regalloc.f MB-FORBID-PINS`). When the
copy coalesces into a source that dies at it, the class opens at the source's
definition, so a value that holds a register there and dies before the form is
kept out of `rcx` or `rax` too: `( a b n -- x ) -rot + swap lshift` under the
data-stack convention loads its count straight into `rcx`.
`idiv` carries the runtime `throw` entry as its `x64.throw-entry`
attribute, because the branch a zero divisor takes is part of the form's
render. The emitter writes the two
shifts as `shl`/`shr r64, cl`, and `idiv` as three pieces behind a screen of
its divisor: zero pushes `E-DIV-ZERO` and calls the `x64.throw-entry`, minus one
negates the dividend and zeroes the remainder, and any other divisor is
`cqo; idiv`. The routine images of `test/x86-64-peer-routines.f` run the
quotient, the remainder with the divisor kept out of `rdx`, and the zero
divisor's call.

The emitter writes `cmpsel` as `cmp` then `cmovcc`, and `selz` as `test`
then `cmovz`. Each result is tied to the answer for a failed condition:
operand 2 of `cmpsel`, whose operand 3 is the answer when it holds, and
operand 1 of `selz`, the nonzero answer. The move of the other answer is the
only write, so any aliasing the allocation makes is safe: the compare reads
before the move writes. ARM64's `cmpsel` names the holding answer first. The
routine images run a general case of each and every aliasing identity: the
result tied to a compared operand, a compared operand moved in, and both
sources one value.

The doubles are SSE2 scalar forms over values of `FPR-TYPE`, which the sixteen
XMM registers hold:

- `movsd` is the XMM copy. The vocabulary names one copy opcode, `x64.mov`, so
  the allocator coalesces general copies only.
- `addsd subsd mulsd divsd andpd xorpd cmpunordsd` tie their result to
  operand 0, as the general arithmetic does. `cmpunordsd` leaves all ones where
  its two doubles are unordered. None of them traps.
- `sqrtsd`, `cvtsi2sd`, `cvttsd2si` and `movq-xr`/`movq-rx` (general to XMM and
  back) take one operand and leave one result, untied. `cvttsd2si` answers
  `$8000000000000000` for a NaN or a double outside a cell, where ARM64's
  `fcvtzs` saturates and answers 0 for a NaN, as `f>s` does.
- `fstore`/`fload` are the frame pair for a double. Every contract of this
  machine destroys the XMM file at a call, so a double live across one goes to
  the frame through them.
- `fcmpset ( fpr fpr -- gpr )` compares with `ucomisd`. `x64.cond` is `gt`
  (`seta`) or `equal` (`sete` and `setnp`): ucomisd sets ZF, PF and CF on an
  unordered pair and every HIR float comparison answers false there. `equal`
  carries a second general result nothing reads, the `setnp` byte, as the
  schema's variadic result tail. The render joins the two bytes with a
  cell-wide `and` and makes the all-ones flag with `movzx` and `neg`. A schema
  cannot tie a result count to an attribute, so the render refuses, with
  `E-X64EMIT-FORM`, any other condition and any count but one for `gt` and two
  for `equal`.

The routine images of `test/x86-64-peer-routines.f` run every double form:
the four arithmetic forms, a double copied with `movsd` before an add destroys
it, `fnegate`, `fabs` and `fsqrt`, the five comparisons with a NaN on each
side, `s>f` and `f>s` at the ends of a cell, the bits there and back, a double
literal, and two doubles live across a call to a callee that writes every XMM
register, each in its own frame slot. Where IEEE 754 fixes an answer the image
expects the bits the host engine's own float word leaves; where Habu states it
(`f>s` saturated and 0 for a NaN, a comparison false on a NaN) the image
expects the stated answer and the host word is held to it first.

`src/compiler/ir/context.f` decodes wire code 5 (`x86-64`, `sysv-amd64`).
Error ranges: `-8740..-8759` are `X64IR`'s, `-8760..-8779` `X64SEL`'s and
`-8780..-8799` `X64EMIT`'s.

## The machine description a contract is written against

The register allocator and the routine-effect contract it reads are
target-neutral: `src/compiler/native-effect.f` (`NEFF`) states the vocabulary -
ordered interface, register sets, frame, flags, exits - and every contract
carries the MACHINE it is about, a one-cell `NMACH:mach`
(`src/compiler/native/machine.f`) the backend supplies. `src/arch/x86-64/machine.f`
(`X64M`) is this machine's description and reads every fact off the dialect:
`X64IR:REGFILE` for the two register files, `X64IR:SP-GPR` for rsp,
`X64IR:SP-ALIGN`, `X64IR:FRAME-LIMIT` and `X64IR:DISP-LIMIT` for the frame and
the displacement, widths 1/2/4/8, and an offset field counted in BYTES rather
than scaled by the access width - which is the one reading ARM64 does
differently, and why `NMACH:SLOT-REACH` takes a width at all.

There is no link register here, so a contract of this machine says
`NEFF-LINK:ABSENT`, and the two ARM64 answers (`preserved`, `clobbered`) are
refused on it; the ARM64 machine refuses `absent` for the same reason. A
register number the schema can write down - it packs five bits - is still
refused unless THIS machine says a routine may hold state in it, so rsp and
anything past r15 are refused at `NEFF:ROUTINE`. `test/compiler/x64ir.f` builds
those contracts.

The register file is `src/compiler/native/regfile.f`, package `NREGFILE`:

- `regs` is a one-cell set; bit i is register i.
- `file` is a seven-field record: `gpr-size`, `gpr-reserved`,
  `gpr-clobbered`, `fpr-size`, `fpr-reserved`, `fpr-clobbered` and
  `slot-width`. The reserved set is stored and the allocatable set derived;
  the clobbered set is stored and the callee-saved set derived.
- The one checked constructor is
  `FILE ( n regs regs n regs regs n -- file )`. It refuses an incoherent
  description with `E-NREGFILE`.

The allocator takes the machine and the dialect's vocabulary together:
`A64RA:BIND-DIALECT ( ctx builder NMACH:mach NDIALECT:vocab -- )`, and the
verifier binds the vocabulary with
`A64RAV:BIND-DIALECT ( IR-CTX:ctx IR-BUILD:builder NDIALECT:vocab -- )`. Nothing
allocates without a description, and the register file is derived from the
machine (`NMACH:REGFILE`). The vocabulary (`src/compiler/native/dialect.f`,
built by `X64IR:VOCABULARY`) carries every name the passes need: the types,
the keys, the copy and remat opcodes, the address-carrier lane count, the slot
width, and the architecture the allocation is for. `test/compiler/x64-regalloc.f` allocates and validates real
x86-64 leaves through `X64IR:VOCABULARY` and `X64M:MACHINE`.

## Selection

`src/compiler/native/select-x64.f` (package `X64SEL`) lowers HIR to X64IR in a
separate pass with A64SEL's shape:
`BIND-SOURCE` / `RELEASE` / `SELECT ( ctx module builder routine -- module )`.

- **The table.**
  - `const` becomes `movi` (with `x64.addr`), and `quot` becomes `codeaddr`.
  - `+ - and or xor` become the tied form, or its `*i` immediate form when
    the right operand is a literal that fits an imm32. The literal's own
    `movi` is dropped only when every use in the function folds.
  - `*` becomes `imul`, literal-count shifts `shli`/`shri`, and `invert`
    `not`. The six signed comparisons become `cmpset`/`cmpseti`.
  - `@ ! c@ c!` become `aload/astore/abload/abstore`.
  - `br`/`brz` split their edges through the copy of the value's own file,
    `x64.mov` or `x64.movsd`.
  - A double is a value of the XMM file. `f+ f- f* f/` become the tied
    `addsd subsd mulsd divsd`; `fnegate` and `fabs` become `xorpd` and `andpd`
    with a sign-bit mask double; `fsqrt` becomes `sqrtsd`. The five
    arithmetic forms are followed by the NaN rule ("The NaN an operation
    makes"). `intreal`,
    `bitsreal` and `realbits` become `cvtsi2sd`, `movq-xr` and `movq-rx`.
    `realint` is `f>s` without a branch: `cvttsd2si`, xored with the `gt` flag
    against `$43DFFFFFFFFFFFFF` (the largest double below 2^63) to turn the
    MIN-CELL it answers past the top into MAX-CELL, then anded with the flag of
    the double `equal` to itself to answer 0 for a NaN. A double literal is
    `movi` of its bits and then `movq-xr`. `fgt` and `feq` become `fcmpset` under `gt` and `equal`, `flt`
    is `gt` with its operands exchanged, and `fltz`/`feqz` compare against a
    zero double.
  - The data-stack boundary is `dtake`, one `dload` per argument, one
    `dstore` per result, then `dpublish`. The pointer stands at the entry
    base. In a routine that leaves through its callee it never moves, so a
    tail call reads its arguments at negative displacements.
  - `call`, `wordcall`, `tailcall`, `trap`, `reserve` and `release` complete
    the table.
- **Unfused.** A comparison feeding a branch selects `x64.cmpset` then
  `x64.brz`. Nothing selects `cmpbr`, `cmpbri`, `cmpsel` or `selz` yet: the
  dialect declares the fused forms, and selecting them is a later slice.
- **Fixed registers.** A computed shift count selects `shl`/`shr`, with the
  count's `x64.mov` copy as the operand the schema fixes to `rcx`. `/` selects
  `idiv`:
  - the dividend's copy is the operand fixed to `rax`;
  - the results are the quotient and an unread remainder;
  - the runtime `throw` entry is its `x64.throw-entry` attribute.
- **Division semantics** the render must keep:
  - Habu's `/`, `mod` and `/mod` truncate toward zero;
  - a zero divisor throws `E-DIV-ZERO`;
  - `MIN-N -1 /` wraps to `MIN-N`, where `idiv` raises #DE;
  - `lshift`/`rshift` mask the count to 6 bits, and `rshift` is logical.
- **Refusals**, each with a case:
  - `E-X64SEL-TRAP`: a trapping-overflow unit, or no `throw` in the target
    dictionary for a division's cold side;
  - `E-X64SEL-MACHINE`: a contract of another machine;
  - `E-X64SEL-OPCODE`, `-BIND`, `-SOURCE` and `-MEM`.
- **No `neg`.** HIR has no `negate`, so `neg` has no source form.
- **The ABI.** `src/arch/x86-64/abi.f` (`X64ABI`) is the Habu word convention
  on this machine:
  - the link is `absent`;
  - there is no prologue slot, because the return address is on the machine
    stack;
  - the pool is the nine registers from `X64M:MACHINE NEFF:GPR-ALL`;
  - frames hold spills alone.
- **Target check.** `src/compiler/ir/fun.f` `TARGET-CK` ties a calling
  convention to a kind of architecture (kernel or PTX, otherwise native),
  not to AArch64 by name.
- **Suite:** `test/compiler/x64-select.f` (`compiler-x64-select`).
- **Untested:**
  - edge splitting is covered for a carried forward edge, not a permuting
    back edge;
  - the internal shape refusals (`-SHAPE`, `-ATTR`, `-CAP`, `-PLACE`,
    `-CALL`, `-TAIL`, `-ORDER`) have no case.

## The pass chain

`src/arch/x86-64/passes.f` (`X64PASS`) fills this backend's row in
`src/compiler/native/backend.f`, the way `src/arch/arm64/passes.f` fills the
other one, and `X64PASS:INSTALL` runs as that file loads. What it installs:

- **declare** and the routine contract it composes, over `src/arch/x86-64/abi.f`
  — leaf, calling, tail-calling and no-return, each with the spill count the
  lowering settled on;
- **select**, `X64SEL:SELECT` over the frozen HIR module `NBACK:FREEZE` hands
  every selector, the target-free counted loop fold (`src/compiler/native/loop.f`)
  already applied; the driver retires that module after its last selector;
- **prune**, a pass-through: `src/compiler/native/prune.f` rewrites nothing on
  the whole corpus and this machine has no prune pass of its own, so the row
  hands the module selection wrote back as it is — rebuilding renumbers values,
  and a routine that gained nothing would still come out with other bytes;
- **fixpoint**, which allocates and, while the plan is not empty, lowers it
  through the SHARED spill pass. `src/compiler/native/spill.f` names no dialect:
  it is bound with `X64IR:LOWERING` and with `X64IR:ENSURE-NAMED`, so this
  machine's reserve, release, store, load, copy and re-emit are the forms it
  writes. There is no x86-64 spill file and there is no second walk;
- **release**, **prototype**, **forget** and **prepare**, each over the passes
  this backend really binds.

The last two rows are filled as well:

- **emit**, `X64EMIT:PLACE-AT` and then `X64EMIT:EMIT` over the accepted module.
  WHAT A PLACEMENT MEANS: the driver names the slot the routine will be written
  at, and the emission resolves every displacement against it — a `wordcall` is
  the callee's absolute entry less that slot less the end of the call
  instruction, a `trap` is the pointer moved over its cells and the same call to
  its `x64.trap-entry`, a branch is the distance between two blocks of this
  emission and needs no slot at all, and a self `call` is measured from the
  function's own start. A `codeaddr` is the other way round: the slot plus where
  the named function starts, in a `mov r64, imm64`. A relocatable literal and a
  `codeaddr` record the byte offset of that instruction and the kind of address
  it carries (`ADDR-CODE` for a `codeaddr`) in a site list. Every `wordcall`,
  `tailcall` and `trap` records a call row: the byte offset of its `call` or
  `jmp`, the kind `NEMIT:CALL` or `NEMIT:TAIL`, and the absolute entry it goes
  to. A self `call` stays inside the emission and records none. What comes back
  is a sealed byte image plus both lists, read through `SIZE`, `BYTES`,
  `BLOCKS`, `BLOCK-START@`, `FUNS`, `FUNCTION-OFFSET@`, `ADDR-SITES`, `ADDR-SITE@`,
  `ADDR-SITE-KIND@`, `CALL-SITES`, `CALL-SITE@`, `CALL-KIND@` and
  `CALL-TARGET@` — every one of them in BYTES, where the ARM64 emitter answers
  instruction indices. The span is exact: `SIZE` is the whole routine whether it
  ends in a return, a tail branch or a call that never comes back, and a `does>`
  body is `SIZE` less `FUNCTION-OFFSET@ 1`. A slot is refused unless it is a
  whole multiple of `X64IR:SP-ALIGN`, the unit a code region hands slots out in.
  `EMIT` without `PLACE-AT` is a SHADOW emission: every `wordcall`, `tailcall`
  and `trap` rel32, and `idiv`'s call to `throw`, is zero with no reach check
  (a self `call` keeps its displacement inside the emission), a `codeaddr`
  holds the function's offset in the emission, and the rows are what a linker
  writes the fields from. The row then states the sealed emission as `NEMIT`'s
  rows (`src/compiler/native/emission.f`), the only emission
  `src/compiler/native/publish.f` reads: the image with no trailing return,
  because the span is exact, the slot, a function row for each of `FUNS`, and a
  call or address row for each site at its instruction's first byte. A refusal
  inside `X64EMIT:EMIT`, such as `E-X64EMIT-REACH`, comes before any row is
  stated. `X64PASS:EMIT-UNPLACED ( IR-CTX:ctx IR-BUILD:module -- )` is the
  row's acceptance and a shadow `EMIT`, stating the same rows with no
  placement, for a writer that lays the routine into its own stream and links
  it there ("Pure rows") and for a shadow target ("Dual emission"). It is
  installed as `NBACK:EMIT-UNPLACED`;
- **retire**, `X64EMIT:RETIRE` and then `NEMIT:CLEAR`, nonthrowing, which gives
  the sink, the placement, both site lists, the sealed flag and the rows back.
  The driver calls it on the accepting and the refusing path alike, so calling
  it twice is harmless.

So the whole chain runs end to end in the order `src/compiler/native/compiler.f`
runs it — `test/compiler/x64-chain.f` drives it through `NBACK` exactly as the
driver does, pins the prune pass-through by identity, places a routine at a
slot and reads its image back, and reads the rows back off `NEMIT`.
Publication decodes nothing: it records the whole span as an exact
`CODE-SPAN` length, which counts bytes, and hands each site's first byte to
`callmap-set` or `addrmap-set`, which on x86-64 insert the band rows ("Live-region
sites"). Nothing commits on the ARM64 host: `NEMIT:OPEN` takes the machine
the emission is for, and publication refuses one for any machine but
`NABI:BINDING`'s with `E-NPUB-TARGET` before its window. The commit is the
x86-64 engine's.

Deferred, and refused by name with `E-X64EMIT-FORM` until it is written: the
negate. So is `rel8`
relaxation — every branch and call this emitter writes is the wide `rel32` form,
which is a size question and not a correctness one — and so is the source map.

### The row installers

`src/arch/x86-64/passes.f` requires `src/compiler/native/backend.f`,
`src/arch/x86-64/backend.f` and the pass modules it wraps. It ends with
`X64PASS:INSTALL`, eleven calls of the form `arch quotation NBACK:<STAGE>!`. An
installer throws `E-CTGT-UNLOADED` if the arch never registered, so
`backend.f`'s `CTARGET:REGISTER` runs first.

| installer | quotation effect | obligation |
| --- | --- | --- |
| `NBACK:DECLARE!` | `[ n n NBACK:linkage -- ]` | record in-cells, out-cells, linkage; reset per-definition state |
| `NBACK:SELECT!` | `[ IR-CTX:ctx IR-BUILD:module -- IR-BUILD:module ]` | the frozen HIR module `NBACK:FREEZE` folded in, machine module out; the driver retires the HIR module |
| `NBACK:PRUNE!` | `[ IR-CTX:ctx IR-BUILD:module -- IR-BUILD:module ]` | may hand the module back untouched |
| `NBACK:FIXPOINT!` | `[ IR-CTX:ctx IR-BUILD:module -- IR-BUILD:module ]` | lower until the allocation seals empty |
| `NBACK:EMIT!` | `[ IR-CTX:ctx IR-BUILD:module n -- ]` | write at the code slot the driver passes (`NPUB:NEXT-SLOT`) |
| `NBACK:EMIT-UNPLACED!` | `[ IR-CTX:ctx IR-BUILD:module -- ]` | write for no slot and state the rows unplaced; a shadow target's last stage |
| `NBACK:RELEASE!` | `[ -- ]` | give back every pass binding still held (failure path); `NBACK:RELEASE` gives the loop fold's back first |
| `NBACK:RETIRE!` | `[ -- ]` | end-of-definition emitter reset (success and failure) |
| `NBACK:PROTOTYPE!` | `[ IR-CTX:ctx IR-ARENA:arena IR-ARENA:arena IR-ID:ir-module-key -- ]` | intern the dialect vocabulary into the session prototype |
| `NBACK:FORGET!` | `[ -- ]` | clear that prototype flag at session stand-down |
| `NBACK:PREPARE!` | `[ -- ]` | scrub code buffers and pass scratch before an image capture |

`NBACK:PREPARE` resets the loop fold's scratch before it runs the rows, since
`NBACK:FREEZE`, not a row, binds that pass.

`NBACK:linkage` is a one-field nominal (`L-NONE L-DEAD L-CALLED L-TAIL L-BACK`,
`WITH`, `HAS?`) carrying how control reaches and leaves a routine.
`test/compiler/target-registry.f` drives a fake backend through these rows.

## Dual emission

A cross-build runs the target's whole prefix on the host, so each definition
has to be the host's routine and the target's at once; its names are bound
against the dictionary as it compiles, so the target's routine cannot be
lowered later from the tape. `src/compiler/native/shadow.f` (`NSHADOW`) is the
second target:

- `NSHADOW:OPEN ( CBIND:binding -- )` opens a shadow for a binding, for example
  `X64ABI:BINDING`; `CLOSE` gives the map back and is nonthrowing, and
  `NCOMP:CAPTURE-PREPARE` runs it, so no capture carries an open shadow.
- While one is open, `NCOMP` runs, after `NBACK:FREEZE`, declare, select, prune,
  fixpoint and `NBACK:EMIT-UNPLACED` for the shadow's binding in a context
  nested inside the definition's (`IR-CTX:WITH-CONTEXT`), so `NBACK:ROW@` and
  `X64SEL:MACHINE-CK` see that machine. Builders are minted there; the frozen
  HIR module is only read. `NSHADOW:TAKE` (`TAKE-DOES` for a definer) copies the
  sealed NEMIT bytes, function, call and address rows and trailing return into
  `DYNAMIC-BUFFER`s; the row's `RETIRE` runs in that context on both paths and
  `RELEASE` on a refusal, then the context leaves and the engine's own chain
  selects from the same module. A shadow refusal refuses the definition, and an
  aarch64 shadow refuses at the unplaced stage with `E-CTGT-UNLOADED`.
- `NPUB:PUBLISH-PENDING(-DOES)` calls `NSHADOW:PUBLISH ( idx -- )` after its
  commit. It files the copy under the record, and a `does>` companion under
  `idx+1` at the clause function's offset. It is nonthrowing because `TAKE`
  refused what could be refused and made the room. The driver's
  `NSHADOW:ABANDON` drops a copy no publication claimed.
- The map: `RECORDS`, `RECORD@`, `EMISSION@` and `ENTRY@` per record row;
  `EMISSIONS`, `SIZE`, `BYTES`, `RET-BYTES`, `FUNCTIONS`, `FUNCTION-OFFSET@`,
  `CALL-SITES`, `CALL-SITE@`, `CALL-KIND@`, `CALL-TARGET@`, `ADDR-SITES`,
  `ADDR-SITE@` and `ADDR-SITE-KIND@` per emission. Offsets are bytes from the
  emission's start. A call target is the callee's host entry, and a `codeaddr`
  holds the function's offset in the emission, for the linker to resolve.
  Refusals: `E-NSHADOW-STATE`, `E-NSHADOW-ROW` and `E-NSHADOW-TARGET`, an
  emission for another machine than the binding's.

With no shadow open the driver runs exactly the stages it ran before, so the
engine compiles every definition to the same bytes: an engine built from this
tree rebuilds the previous tree to that tree's own product.
`test/compiler/shadow.f` compiles words with an x86-64 shadow open on the ARM64
host and reads the map back.

The capture carries the map. `src/habu/aot-shadow.f` reopens the capture's
package, and `AOT-CAPTURE:SHADOW-CAPTURE`, run right after
`AOT-CAPTURE:CAPTURE`, walks the map into the four tables of
`src/habu/aot-decl.f` package `AOT-SHADOW`. `src/habu/aot-file.f` writes them as
four sections after the closure list; that is format version 14 with 22
sections, and a version 13 artifact is refused by its version.

- **Records**: (shipped record row, emission start in the code, emission
  bytes, entry offset), one for each map row whose record the capture ships,
  in window order. A `does>` definer and its companion share one emission, and
  the companion enters at the clause function's offset.
- **Code**: each emission's bytes once, with no host address left in them. A
  call's or tail branch's rel32 stays the zero an unplaced emission writes, and
  a code literal naming a word holds 0. A DATA literal holds its window
  coordinate, the value an ARM64 DATA site holds. A `codeaddr` keeps its
  function's offset in its own emission.
- **Sites**: (byte offset in the code, kind, target). The kinds are `CALL`,
  `TAIL`, `CODE` (a MOVABS of a word's entry), `DATA` and `FUN`. A target is
  a shipped window record (`SITE-REC-TAG` beside its shipped row) or a word of
  the engine's own prefix (`SITE-NAME-TAG` beside its name's pool offset). Both
  are resolved through the capture's xt -> record index, `ACAP-TGT>REC`.
- **Code cells**: (address-cell row, shipped record row) for each declared
  address cell whose target is window code. The image writer keys such a cell
  by its record, not by the ARM64 blob offset the address-cell row carries.

Every record index is a shipped row, the row of the artifact's record table,
never a window index. That table holds only the records the capture ships, in
capture order, so a stripped private word moves every later record down one
row. The capture gives a record a compact row exactly when it sets the record's
named bit, so one pass over those bits numbers the window's records, and the
count must equal the table's. Those bits are indexed by capture record, and the
capture does not record a retired (`undefine`d) record at all, so past one a
record's dictionary index is not its capture index either: a map row's record
reads a capture table only through `ACAP-DICT>CAP`. The map's rows are in
publication order, so one walk keeps them. A row whose record the capture
strips or retires files no row of its own:

- a stripped or retired record is live when live code reaches its body, and
  its routine goes with it when none does. ARM64 retention cannot say which:
  it scans every gap as a root, and a retired body is a gap, live or not, so
  it keeps that body and what it calls. A separate reach decides
  (`ACAP-SHADOW-REACH`, `ACAP-SHADOW-LIVE?`). It starts from the graph's
  roots, which are the named records, the declared code cells and every gap
  but a retired body, and walks ordinary and retired bodies alike, following
  an edge only out of a body it reached. Reached code reaches the record that owns it and
  the retired record over it, so an `EXPORT` alias sharing a stripped or
  retired body makes it live, and a word only dead retired code calls is
  dead even when ARM64 keeps its code;
- a retired record has no name to ship, and a site or code cell that reaches
  a stripped or retired record is refused by name;
- a shipped row over the same emission carries a live one's routine: a private
  `does>` definer whose load-time children keep its clause live ships only its
  companion, which enters the emission at the clause;
- a live one that no shipped row carries is refused. Carrying it needs a key
  the format does not have, since no record table row names it.

Each refusal is by name, exit 74:

- the map's records do not ascend, as in a map filed before a logical reset;
- a live routine whose record the capture strips or retires, with no shipped
  row over its emission;
- a site target is neither a window record's entry nor a prefix word;
- a site target is a window record the capture strips or retires;
- a DATA literal lies outside the window's DATA span;
- an address site is not a MOVABS;
- a site has a kind the format does not carry;
- a code cell holds window code that no shipped record enters. This is a
  quotation's entry: the map keys code by record, and nothing yet maps an ARM64
  function to its x86-64 twin.

The reader checks every row against the shadow code, the name pool and the
artifact's record count: every record index names a shipped record. MERGE
refuses a shadow on either side, because the merged engine is the ARM64 seed.

The reader is its own file for two reasons. `aot-capture.f` also loads in the
stdin metabuild and the recovery bootstrap, which have no `NSHADOW`. And the map
must be read through the host's `NSHADOW`: after a native build's logical
reset, a name looked up at capture time finds the target window's own
instance, which was never opened. A host that opens a shadow loads the reader
before its window and runs it after `CAPTURE`. That is before anything closes
the host's map: the target's `NATIVE-RUNTIME:CAPTURE-PREPARE` closes the window
compiler's shadow, not the host's. With no shadow open the four sections are
empty, and the ARM64 product does not change. `test/aot-shadow-capture.f`
captures a window compiled with an x86-64 shadow open and reads every kind
back, through WRITE and READ. Its window strips a dead private word between
two shadowed records and a live private `does>` definer whose companion ships,
and it finds every record by the name the shipped table carries. It also writes
artifacts with one row field forged, and a reader child must refuse each by
name; MERGE must refuse the shadowed artifact.

## The dictionary layout

`src/habu/link-x64.f`, package `X64LINK`, lays a capture out where an x86-64
image holds it. It is the write-time twin of the ARM64 seed's boot passes
(`habu2.f` `EM-SEED-DICT`, `EM-AOT-REGISTER-RECS`, `EMIT-AOT-PROT-RESTORE`):
the region and DATA are fixed, so what that seed computes at every boot is
computed once. `LAYOUT` runs after the kernel's rows are emitted into the
`X64CODE` stream and before `elf.f` `ASM-CODE` links it, since a primitive's
entry is its first label's offset (`X64CODE:LABEL-AT`) past `TEXT-VA`.

| what | where | rule |
|---|---|---|
| `DICT$` | `REGION-VA`, record n at `REC-VA` | the kernel's `ENGINE-PRIMS` rows, then the capture's shipped records in capture order; a primitive's flags are `ENGINE-PRIMS:DNAME`, with its min-in |
| `CODE$` | `CODE-VA`, `REGION-VA + DICT-SIZE` | the long names, zero-filled to a `CODE-SLOT`, then each shadow emission from a slot, int3 to the next; `PLACED` maps a shadow code offset to its band offset |
| wids | record `[40]`, a package row's `[0]` and `[8]` | 0 stays 0; any other window coordinate w becomes `T0 + w - WID-REL-BASE`, `T0` being `FIRST-DYNAMIC-WID`; `WIDN` is `T0` plus the window's span |
| `BITS$` | DATA `PROT-BITS-OFF` | the bit of `T0 + row` for each protected-wid row |
| `INDEX$` | DATA `INDEX-OFF`, `DATA-START`; `HIDXP-CELL` holds `INDEX-VA` | `HIDX-SLOTS` u32 slots filled from records `[0, RECORDS)` as `REBUILD-HELPER` fills them, `CLAIMS` one per record; the heap floor moves to `HEAP-FLOOR` |
| the window's DATA | DATA `DATA-AT` | `HEAP-FLOOR` moved up to `AOT-DATA-D0`'s 8-residue, as `EM-AOT-RELOC-DATA` moves the seed's DP; `AOT-DATA-SIZE` bytes |

A code record enters its routine; a `does>` companion enters its definer's
emission at the clause and spans the rest of it, as on ARM64. A code record
the shadow has no routine for is refused, not built: the kernel's `create` and
`does-patch` refuse, so no x86-64 routine shape for a created word exists yet.

`LAYOUT` links every site in `CODE$` once the routines are copied. Two passes
precede the first laid byte: one places each emission, and one resolves every
site and code cell against those places and refuses what it cannot resolve;
the bytes are patched after the records are laid, as `X64CODE:ASM-LINK`
checks every site before it patches one.

| site | field | value |
|---|---|---|
| `CALL`, `TAIL` | rel32 at `X64ASM:CALL-REL32-OFF` | the target's entry less the instruction's end |
| `CODE` | imm64 at `X64ASM:MOV-RI64-IMM-OFF` | the target's entry |
| `DATA` | imm64 | `DATA-VA + DATA-AT` plus the literal's window offset |
| `FUN` | imm64 | the function's address inside its own routine; a `does>` definer's clause is its companion's entry |

A target is a shipped record's routine at its entry, or, for a name of the
engine's own prefix, the kernel body of that name: the first global
`ENGINE-PRIMS` row, folded, which is the record the index finds in wordlist 0.
`CELL-XT` answers the xt a declared code cell holds: the entry of the record
its shadow xt row names, or of the kernel body a named cell names.

The writer builds the index because it is a function of the records alone:
the window of `test/x86-64-link-records.f` captured by a host with one record,
one wordlist and one DATA cell more ahead of it lays out the same records, code
band, bitmap and index, by digest. The kernel's own probe reads it: the same
test stages the records, code band, count and index in the booted image
`hb-x64-link-index`, where `xref-search-wl` (`FIND-HELPER`) finds every record
by its own name and wordlist, finds a name folded and misses a name in another
wordlist and an absent one. The image exits 0 on an x86-64 host.

Every refusal is by name, exit 74, before the first byte is laid: a code record
the shadow has no routine for (a variable, a `create`d word, a defer or a tier-0
word), a routine that lands on a package row or past the shipped records, a wid
outside the capture window, a protected wid at `PROT-WID-MAX`, more records than
`DICT-CAP`, names and routines past `X64KERNEL:CODE-CEILING`, a site naming a
record with no routine, a site or code cell naming a word no kernel body
carries, a call or branch whose displacement does not fit its rel32, a code
cell no xt row keys, and a code cell whose xt row names a record with no
routine. A refusal dies and `LAYOUT` writes only its own buffers, so no byte
leaves the process ahead of one. A refusal in a `does>` definer's routine names
the definer, the first row of the emission. The fixed segments put every band
byte within `$3400000` of the text, so no capture this tree writes reaches the
rel32 refusal; it names the boundary as `X64CODE:ASM-LINK` names its own. A
code cell holding a quotation's entry is refused earlier, by the capture.

The shadow keys every routine by its shipped record row ("Dual emission"), so
one walk beside the shipped records pairs each code record with its routine. A
routine on a package row or past the last shipped record comes from no capture
this tree writes. The capture refuses a stripped word's live routine, or a call
to a stripped word, before any layout: those are the `strip` and `callee`
children of `test/x86-64-link-records.f`.

Load order: the x86-64 files bind `using X64CODE`, whose tails
`src/arch/arm64/icode.f` defines as globals, and `src/habu/aot-decl.f` reads
that file's `AOT-SECTION-CAP`. So `link-x64.f` requires the x86-64 side first,
`elf.f` bringing `src/os/image-bytes.f` in under `using X64CODE`, then
`src/arch/arm64/icode.f` and `aot-decl.f`.

## The OS seam

- **Target.** The target is `linux-x86-64`, with predicate
  `HB-TARGET-LINUX-X86-64?`. Every `src/os/<target>/target.f` defines all
  three target predicates, and `HB-TARGET-KNOWN?` is closed over the three.
  Every selector in the tree has an explicit linux-x86-64 arm or a named
  refusal: `src/habu/prof.f` refuses at load, and
  `src/compiler/native/abi.f` answers `sysv-amd64`. The source-list owners
  know the target: `tools/bootstrap.sh`, `tools/build-fixpoint.f`,
  `src/habu/habu2.f` with `bootstrap/cg/forth.fs`, `src/habu/stdin.f`,
  `tools/hb-build-lib.f`, `tools/lint/shadow-lint.f` and `tools/native-emit.f`.
- **Files.** `src/os/linux-x86-64/` holds:
  - `target.f`;
  - `layout.f`: `DATA-VA $340000000`, `DATA-SIZE $2000000`, `CODE-OFF $1000`
    and the ARM64 guard-page model. Every definition is the same as in
    `src/os/linux/layout.f`, so captured DATA pointers need no translation
    between the two Linux hosts;
  - `target-layout.f`: package `X64LAYOUT`, the one replay of `layout.f`
    that cross-built code reads, "Fixed segments" below;
  - `elf.f`, detailed below;
  - `sys.f`, detailed below;
  - `repl-term.f`, `sign.f`, `proc-watch.f` (`BPROCWATCHOPEN` is
    `pidfd_open`) and `proc-control.f` (`BKILLERRNO`, `BEXECVE`, publishing
    `rax`).
- **ELF.** `elf.f` writes ELF64 `EM_X86_64` with `VMBASE $400000` and entry
  `$401000`. It has six phdrs, "Fixed segments" below: LOAD RX, LOAD RW,
  INTERP (`/lib64/ld-linux-x86-64.so.2`), DYNAMIC, and fixed LOADs for the
  code region and DATA. `dlopen`/`dlsym` bind through `R_X86_64_GLOB_DAT`.
  The output is validated with `readelf`.
- **Syscalls.** `sys.f` holds the x86-64 syscall numbers, using the *at*
  family as aarch64 does.
  - `SYS, ( n -- )` emits `mov eax, NR / syscall / mov rcx, -4096 / cmp rcx,
    rax`, so **CF set means error**. `X64RT:SYS-PUSH`
    (`src/arch/x86-64/rt.f`) follows it with `mov rcx, -1 / cmovb rax, rcx`
    and a push of `rax`: the result, or -1 on error ("Syscall rows" below).
  - `OS-OPEN-RD` uses `openat` with `AT_FDCWD` in `rdi`.
  - `OS-OPEN-FLAGS` and `OS-MMAP-FLAGS` are branchless. They clobber `rax`,
    `rcx` and `r11`.
  - The stencils `SYS-EMIT-WRITE/EXIT/SVC ( -- ptr u8 n )` are byte strings
    of whole instructions. `X64RT:EMIT-STENCIL` (`src/arch/x86-64/rt.f`)
    appends each one as it stands to `X64CODE:ASM-SINK`; it is the twin of
    `src/habu/jit.f C-EMIT-STENCIL`, which reassembles the ARM64 ones from
    four-byte words.
  - The seam's register arguments are x86-64 register numbers, as
    `X64RT:G-POP`/`G-PUSH` take them: 7 is `rdi`, 6 `rsi`, 2 `rdx` and 0
    `rax`. They move through `ENGINE-GPR:X64-DSTACK`, which stands just past
    the top cell of an upward-growing stack: a push is `mov [r12], r` then
    `add r12, 8`, a pop `sub r12, 8` then `mov r, [r12]`. `proc-watch.f` and
    `proc-control.f` import them with `using X64RT`.
- **`X64CODE:ASM-SINK ( -- ptr u8 )`** (`src/arch/x86-64/icode.f`) is the
  byte buffer the current code stream appends into: a `lib/byte-buffer.f`
  `BUF` whose `BUF:INIT` and `BUF:DISPOSE` the driver owns, linked at the text
  address by `elf.f ASM-CODE` and restarted by `ASM-RESET`, which also forgets
  the stream's labels and sites. The seam files and `elf.f` bind to it with
  `using X64CODE`, and `src/os/image-bytes.f` sizes `MSIZE` from a bare
  `CODE-CAP-BYTES` at load. So the x86 build's driver, `tools/native-emit.f`'s
  x86 arm, must load `lib/byte-buffer.f` and `X64CODE` before any x86 seam
  file, and must load `src/os/image-bytes.f` under `using X64CODE`. That arm
  does not do this yet; X4d (`habu-resolve-x86-entry-cb671d4d`) makes it do
  so.
- **Contract.** `CTARGET` has arch `x86-64` (wire code 5), ABI `sysv-amd64`

## Fixed segments

An x86-64 image places its code region and DATA by `PT_LOAD`, where the ARM64
boot maps both itself: the region wherever the kernel gives it near a hint,
DATA `MAP_FIXED` at `DATA-VA`. `elf.f` writes six program headers, the loadable
ones ascending by address as ELF orders them. "Text" is the header page and
the stream behind it, rounded up to `PROT-PAGE-MAX` (`$10000`), the alignment
of every `LOAD`.

| # | type | offset | address | file size | memory size | flags |
|---|---|---|---|---|---|---|
| 0 | LOAD | 0 | `VMBASE` | text | text | R X |
| 1 | LOAD | text | `VMBASE` + text | `$C0` | `$C0` | R W |
| 2 | INTERP | `$190` | `VMBASE + $190` | 28 | 28 | R |
| 3 | DYNAMIC | text | `VMBASE` + text | `$B0` | `$B0` | R W |
| 4 | LOAD | 0 | `VMBASE + REGION-OFF`, `$1400000` | 0 | `REGION`, `$2000000` | R W |
| 5 | LOAD | 0 | `DATA-VA`, `$340000000` | 0 | `DATA-SIZE`, `$2000000` | R W |

- **No file bytes.** The two fixed segments have file size 0 and offset 0,
  which every page-aligned address matches modulo the alignment. The kernel
  maps each zeroed and read-write at exec: under `gdb`'s `starti`, before the
  loader runs, Linux 7.2.5 shows both mappings. The file is as long as before,
  the text plus `$C0`.
- **The break.** The kernel starts the brk past the highest `LOAD` end,
  DATA's (`brk(NULL)` measured `$3610F6000`), so brk randomisation cannot land
  inside the region span.
- **The boot still maps them.** `boot-x64.f` `CODE-REGION,` and
  `DATA-REGION,` map the same spans `MAP_FIXED`, which replaces a zeroed
  mapping with a zeroed one. Once the linker (X4b-X4d) writes region or DATA
  bytes into the file, the boot must stop replacing them.
- **The target's layout.** `DATA-VA`, `DATA-SIZE`, `CODE-OFF`,
  `IMAGE-TEXT-SIZE-OFF` and `LINUX-DLSYM-SLOT-OFF` are the Linux target's, not
  the host's: a macOS host places its own DATA at `$44000000000`.
  `target-layout.f` replays `layout.f` once, privately, in package
  `X64LAYOUT`, and publishes copies of those five, which x86 code reads
  qualified, `X64LAYOUT:DATA-VA`. A bare read binds the host's global, and a
  Linux host gives it the target's value, so only a macOS host builds
  different images: with macOS values stood in for the globals on the Linux
  engine, a bare `DATA-VA` in `DATA-REGION,` put `$44000000000` into
  `hb-x64-skel`. So `elf.f`, `boot-x64.f`, `kernel-x64.f`, `link-x64.f`,
  `prof-x64.f` and the x86 tests that read the layout open `using X64LAYOUT`
  after their last load and close it before their end, and a host file loaded
  later (`snapshot-format.f`, `aot-arm.f`) still reads the globals. Under that
  guard a bare `DATA-VA`, `DATA-SIZE`, `CODE-OFF` or `IMAGE-TEXT-SIZE-OFF`
  refuses the load by name on every host: `E-USING-SHADOW-GLOBAL` (rc 67) in
  a definition, `ENGINE-ERROR:USING-SHADOW-GLOBAL` (rc 105) at top level. A
  macOS host has no `LINUX-DLSYM-SLOT-OFF` global, so a bare one there reads
  `X64LAYOUT`'s value, the right one. `TRUSTED:` and `0 set-check` bodies keep
  global-first, outside the guard; the guarded files hold one,
  `x86-64-kernel-prof.f` `>ARENA`, which reads no layout name.
  `x86-64-link-records.f` stays unguarded: it reads the host's `DATA-VA` bare,
  beside the target's, to turn a host pointer into its captured offset.
  `REGION`, `REGION-OFF` and `PROT-PAGE-MAX` come from `src/habu/layout.f`
  and are the same on every host. Packages do not nest, so `target-layout.f`
  and `elf.f` load at top level, the peer harness included.
- **Order.** `ELF-FIXED-CHECK` refuses at load, rc 73, a layout in which the
  largest text window and its read-write tail reach the region, or the region
  reaches DATA.
- **Metadata.** The interpreter string, hash, symbol, string and relocation
  tables start at `$190`, past 64 + 6 * 56 header bytes, where the ARM64
  writer's four headers leave them at `$120`. `M-PAD-OFF` only pads forward, so
  an offset left inside the headers would misplace its table silently;
  `test/x86-64-seam.f` pins each offset, the dynamic table's pointers and the
  bytes they name.

## Live-region sites

The live code region records its sites - the calls and address literals a later
pass rewrites or resolves - where the code is built, and never finds them again
by decoding bytes. On ARM64 the record is two bitmaps in engine DATA, one bit per
four-byte region word (`src/habu/layout.f`, `SNAP-RELOC:CALLMAP-OFF` and
`ADDRMAP-OFF`). An x86-64 site starts at any byte, so on this target the same
2 MiB, `[CALLMAP-OFF, ADDRMAP-END)`, hold a site-row band instead:

| `SNAP-RELOC:` | meaning |
| --- | --- |
| `SITE-N-CELL` | the row count, a u64 at `CALLMAP-OFF` |
| `SITE-ROWS-OFF` | the first row, eight bytes on |
| `SITE-ROW-BYTES` | 5: the site's region byte offset as a little-endian u32, then its kind as a u8 at `SITE-KIND-OFF` (4) |
| `SITE-CAP` | the rows that fit, 419,428 |
| `SITE-CALL`, `SITE-ADDR` | the kinds, 1 and 2, so a zeroed row is neither |
| `SITE-RC` | 103, the status of a full or corrupt band |

- **A site's offset is its instruction's first byte** on both targets: the BL
  word or a chain's first MOVZ on ARM64; the `call rel32` opcode (displacement
  at +1) or the REX byte of `mov r64, imm64` (immediate at `MOVABS-IMM-OFF`, 2)
  here.
- **The rows are strictly ascending by offset, one per offset.** `callmap-set`
  and `addrmap-set` take the instruction's address, find the new row's place by
  offset and move the rows above it up by one. A site above the last row is an
  append, the common case of code published at the code pointer; a site below
  it costs a move of the rows above it. Neither writer refuses a site below the
  last row, so a caller records its sites in any order and merges nothing.
  `code-publish` removes the rows of both kinds over the bytes it writes, the
  span and its `int3` fill to the next code slot, and `reloc-maps-clear` those
  of the span it reclaims. `src/habu/prims.f` states each primitive for both
  targets.
- **The kind byte says call or address, nothing more.** Every address literal
  is a `SITE-ADDR` row whatever address class it carries; the class lives in the
  emission's site list (`X64EMIT:ADDR-SITE-KIND@`), not in the band's kind byte.
- **Both views are declared on every target.** `src/` has no load-time target
  selection, so `layout.f` declares the bitmaps and the band over the same bytes
  and the running engine picks one by `HB-TARGET-LINUX-X86-64?`.
- **One reader.** `src/habu/sites.f`, package `SITES`:
  `EACH-IN-SPAN ( n n [ n n -- ] -- )` takes a span of region byte offsets and
  yields each site whose first byte is inside it, offset and kind, in ascending
  offset order. It hands the engine's band to `ROWS-EACH` here and to
  `BITMAP-EACH` on ARM64; both arms are public and take the band as `ptr u8`.
  The ARM64 call map holds region-to-text calls only: no compiler records a call
  from one region address to another. Every refusal throws `SITE-RC` before the
  first yield - a span outside `[0, REGION]`, a count above `SITE-CAP`, a row at
  or after `REGION`, a row of no known kind, a row not above the one before it.
  `test/sites.f` drives both arms over scratch bands and `EACH-IN-SPAN` over the
  engine's own maps.
- **Snapshot relocation does not apply.** The region and DATA are mapped at
  fixed addresses on x86-64, so no call displacement or address literal differs
  between the run that writes an image and the run that restores it, and the
  `SNAP-RELOC` passes have nothing to rewrite. The rows serve publication and the
  AOT capture.

## The primitive table

`src/habu/prims.f`, package `PRIM-SPEC`, is the one machine-independent list of
engine primitives. It loads before `src/core/checker.f` as pure data. The
checker replays its effect stream at the table position, so each primitive's
effect exists only in `prims.f`. Each backend supplies bodies under exactly
these names; the ARM64 bodies in `habu1.f` are one implementation of the table.

- **Row forms:**
  - `EPRIM: name atoms [REF word] EPRIM;`;
  - `EPPRIM: pkg name atoms ECLOSE-PRIVATE`;
  - `ETRUSTED-ONLY!`, which flags the row before it;
  - `n EMIN-IN!`, which states the minimum input depth of the row before it
    when its atoms state no input (`execute`, `catch`, `evaluate`, `?dup`,
    `2>r`, `finally`);
  - `ELAB: name`, elaborated by the checker;
  - `UNROWED: name`, with no declaration.
- **Atoms** are the checker's `PE-*` spellings, encoding these codes:
  `A-IN 1`, `A-OUT 2`, `A-VAR-A..E 3..7`, `A-NUM 8`, `A-BOOL 9`, `A-REAL 10`,
  `A-U8 11`, `A-PTR 12`, `A-RAW 13`, `A-QUOT 14`, `A-QUOT-END 15` and
  `A-FINALLY 16`. Composites are sequences: `PE-PTR-A` is `A-VAR-A A-PTR`.
- **Two gates close the fork:**
  - `ENGINE-PRIMS:SPEC-CHECK` (`src/habu/primitive-registry.f`, called by
    `habu1.f FP-ARGS`) refuses a machine body whose name has no row;
  - `ENGINE-PRIMS:COMPLETE` (called by `habu2.f
    ENGINE-EMIT:EMIT-PRIMITIVE-SECTIONS`) refuses a `KEEP?`-kept row
    that no section registered.
    `X64KERNEL:KERNEL,` calls it after its last section.
- **Readers**, with checker rows, callable from checked Habu: `COUNT`,
  `KIND@`, `NAME$`, `PKG$`, `REF$`, `TRUSTED-ONLY?`, `CODE-LEN@`, `CODE@`,
  `FIND ( ptr u8 n -- n )`, `MIN-IN ( n -- n )`, and the kinds `K-PRIM
  K-PKG-PRIVATE K-ELAB K-UNROWED`.
- **Minimum input depth:** `MIN-IN` answers the inputs a row's atoms state
  (an input inside a quotation atom is the quotation's), or its `EMIN-IN!`
  depth. `ENGINE-PRIMS:DNAME` folds it into the seed record's
  `DNAME-MIN-IN`, so a seed writer that takes its name/flags cell from
  `DNAME` bakes it, and the interpret band refuses a bare primitive on a
  shallower stack before the body runs.
- **The parity gate** is `test/prim-parity.f` (`SUITE prim-parity`). The
  x86-64 engine runs this file unchanged, and its first green run there is the
  primitive-parity acceptance.
  - Each `CASES <name> … ;CASES` block is a column of inputs and expected
    outputs (`3 4 7 NN-N`).
  - The integer sets are data in `test/prim-cases.f`, which defines no word.
    A runner includes it (`include`, never `require`) with everything its
    header lists in scope: `CASES`, `;CASES`, the fourteen shape words,
    `MAX-N`, `MIN-N`, `E-DIV-ZERO`, the `+!` scenario and a declared byte
    fixture. A kernel test then runs the same cases without copying them. The
    float sets are data in `test/prim-float-cases.f`, whose runner passes
    each input through `s>f` and each real answer through `f>s`.
  - The shufflers get the sentinels 1 2 3 4 and expect the digit spelling of
    the window they leave: `swap` is 1243.
  - The only place a primitive is spelled is a name-keyed dispatcher arm.
  - Rows carrying `REF PRIM-REF:<X>` (`src/habu/prim-ref.f`: checked Habu,
    never baked, never using the primitive it stands for) run beside the
    body.
  - Rows with neither a case nor a reference (I/O, syscalls, process, code
    publication, profiler, engine state, FFI) are printed by name on every
    run.
- **Porting rules:** [porting.md](porting.md), "Engine Primitives".

## Kernel inventory

The text window (`X64CODE:CODE-CAP-BYTES`, 1 MiB) holds this hand-written
kernel alone: `_start`, the helpers and every row. The captured engine is the
code region, its own mapping at the image base (`VMBASE`) plus `REGION-OFF`,
never text.

`src/habu/boot-x64.f`, package `X64BOOT`, emits `_start` with `START,`: the
twin of `src/habu/habu2.f EM-STARTUP` up to its first run-time state. In
`EM-STARTUP`'s order it takes the text base, maps the boot data stack, the code
region and DATA, fills the DATA cells, maps the return and DO/LOOP stacks and
installs the crash handler ("Crash handler" below), then falls through into
whatever the stream emits next. It never calls or pushes, so `rsp` stays where
the kernel left it, at `argc`; each install builds its action below `rsp` and
gives it back. A failed mapping names itself on fd 2 and exits 78, as the ARM64
boot does. Each guarded stack is mapped the way `STACK-GUARD:EMIT-MAP`
(`src/habu/rt.f`) maps one: two mmaps, the capacity read/write with at least
one inaccessible page on each side.

| x86-64 | `ENGINE-GPR` | ARM64 twin | boot value | primitive |
|---|---|---|---|---|
| `rbp` | `X64-RBASE` | x20, `XREG-RBASE` then `DATA` | the text base, then DATA: `DATA-SIZE` bytes fixed at `DATA-VA` | `data-base` |
| `r12` | `X64-DSTACK` | x19, `A64-DSTACK` | the base of the boot data stack, `STACK-ABI:BOOT-BYTES` guarded | the stack moves |
| `r13` | `X64-DBASE` | x26, `DBASE` | the code region: `REGION` bytes fixed at the image base plus `REGION-OFF` | `dbase@` |
| `r14` | `X64-NDICT` | x27, `NDICT` | 0: no records yet | `ndict@`, `ndict!` |
| `r15` | `X64-CP` | x28, `CP` | `r13` plus `DICT-SIZE`, the code area past the records | `cp@`, `cp!` |
| `rbx` | `X64-INTERP` | none | 0 | none |

The region and DATA are fixed `PT_LOAD`s of the image ("Fixed segments"), and
the boot maps each `MAP_FIXED` where the kernel already placed it; ARM64 takes
whatever address the kernel gives near its hint.

| DATA cell | holds | ARM64 source | primitive |
|---|---|---|---|
| `RBASE-CELL` | the text content base, taken rip-relative | x20 before it becomes DATA | `rbase` |
| `STACK-ABI:BASE-CELL`, `CAP-CELL` | the data stack's base and `BOOT-BYTES` | `EM-DATA-INIT` | |
| `STACK-ABI:RETURN-BASE-CELL`, `LOOP-BASE-CELL` | the return and DO/LOOP stack bases | `EM-FRAME-STACKS` | |
| `ARGC-CELL`, `ARGV-CELL`, `ENVP-CELL` | `[rsp]`, `rsp + 8`, past argv's null | x13, x14, x15 (`EM-ENTRY-ARGS`) | |
| `BOOT-LAYOUT:HEAP-START-CELL` | `DATA-START` | `EM-DATA-INIT` | |
| `DP-CELL` | DATA plus `DATA-START` | `EM-DATA-INIT` | |
| `SIGNAL-ABI:STUB-CELL` | the signal stub's address | `LSIGH` (`EM-STARTUP-RUNTIME-STATE`) | |
| `SIGNAL-ABI:FD-PTR-CELL` | `DATA-VA` plus `SIGNAL-ABI:FD-CELL`, the word the stub reads | `EM-STARTUP-RUNTIME-STATE` | |

The primitives are the rows of `src/habu/prims.f`; their x86-64 bodies belong
to the kernel dots (K5-K9). The skeleton seeds no records and calls no `MAIN`;
`EM-SEED-DICT`'s record copy, the protection window, the snapshot restore and
the seeded runtime come with the kernel and the linker.

`test/x86-64-skel-image.f` writes two images through the peer harness's plain
`X64HARNESS:WRITE`. After the boot, `hb-x64-skel` pushes the data stack full,
writes one cell through each address the boot published and exits with `argc`
read back through `rbp` from `ARGC-CELL`: `./hb-x64-skel a b` exits 3.
`hb-x64-skel-negative` pushes one cell more, onto the guard page, and the crash
handler names the data stack on fd 2 and exits 102. This file must load before
the harness: it loads the x86-64 seam, which the harness would otherwise load
into its own private wordlist.

`src/habu/kernel-x64.f`, package `X64KERNEL`, holds the bodies, written
through `X64ASM`, and the helpers they share. A body is entered by `call` and
leaves by the `ret` the definer appends, so it calls a helper without a frame;
`rax rcx rdx rsi rdi r8-r11` are its scratch.

- `PRIM ( ptr u8 n [ -- ] -- )` registers a body as `habu1.f FPRIM` does:
  `ENGINE-PRIMS:SPEC-CHECK`, nothing more when `KEEP?` drops the row, then the
  first label, the body, `ret` and the last label. `PRIM-WID ( ptr u8 n [ -- ]
  n -- )` also stamps the record's wid, as `FPRIM-WID` does.
  `PRIM-HIR ( ptr u8 n n n [ -- ] -- )` registers the body the x86-64 chain
  compiles from a staged HIR function of n cells in and n out, with no `ret`
  of its own ("Pure rows").
- `REFUSE ( ptr u8 n -- )` registers a row the kernel does not carry. Its body
  writes `hb: <name> is not in the x86-64 kernel` on fd 2 and exits
  `REFUSE-RC` 76, the rc of `ENGINE-EMIT:TARGET-UNKNOWN`; the text lies inside
  the record.
- `REFUSE-WID ( ptr u8 n n -- )` is `REFUSE` whose record carries wid n, for a
  row ARM64 registers through `FPRIM-WID`.
- `ENTRY-LABEL ( ptr u8 n -- label )` answers a registered body's first label
  by name, and dies 76 for a name with no body.
- `HELPERS,` emits the shared helpers once. `KERNEL,` is `HELPERS,` and then
  each section below.
  - `(PROT-SPAN)`, the twin of `habu1.f GUARD-SPAN`, registered through
    `ENGINE-PRIMS:HELPER-REGISTER`, takes the address in `rdi` and the length
    in `rsi`. It passes while `FRIEND-LATCH-CELL` is zero and for an empty
    span. A span that wraps, meets the open transaction blob or meets a band
    of `src/habu/data-bands.f` exits `SEAL-VIOLATION` 83; that table and its
    hull are the ones `GUARD-SPAN` reads. `PROT-SPAN-CALL, ( r64 r64 -- )`
    moves any register pair into `rdi`/`rsi`, aliasing-safe as
    `PROT-GUARD:CALL`, and calls it. The call clobbers
    `rax rcx rdx rsi rdi r8-r11` and no VM register.
  - `LPROTREC`: `PROT-REC, ( r64 n -- )` sets the two `$1000` pages at the
    register's page to prot n, as `habu1.f LPROTREC` flips two host pages.
    The register survives, and a register the helper clobbers
    (`rax rcx rdx rsi rdi r11`) is refused with `E-OPERAND`.
  - `LTASKLIVE`: `TASK-LIVE-GUARD,`, the twin of `B-TASK-LIVE-GUARD`, exits 79
    while `TASKS-LIVE-CELL` is nonzero. It reads the cell through `rax`,
    because `X64ASM` has no compare of memory with an immediate.
  - The dictionary index, the twins of `habu1.f EMIT-HIDX` and
    `C-HIDX-INS`, and the one-wordlist search, the twin of
    `WLFIND:LENTRY`. A record's cells are `REC-CODE` 0, `REC-FLAGS` 16 (the
    flags or'd with the name's length), `REC-NAME` 24 (the name inline up to
    `DNAME-INL` bytes or, with `DNAME-EXT`, a pointer) and `REC-WID` 40. The
    table at `HIDXP-CELL` holds `HIDX-SLOTS` u32 slots, each 0 or a record
    index plus one, keyed on `C-HIDX-HASH`'s FNV-1a hash of the name folded
    A-Z to a-z, XOR the wid.
    `HIDX-BUILD, ( -- )` maps the table once and rebuilds it,
    `HIDX-ADD, ( -- )` indexes record `r14 - 1` and compacts the table at
    `HIDX:LOAD-MAX` claims, and `HIDX-REBUILD, ( -- )` refills it from
    `[0, r14)`; these are the calls `ndict!` and the definers make. Each
    call keeps every VM register and clobbers `rax rcx rdx rsi rdi r8-r11`.
    A refused mapping exits 74 with `hb: dictionary index alloc failed`, and
    an index that cannot be kept exits 74 with
    `hb: dictionary index exhausted`.
    The search takes the name in `rdi` and `rsi` and the wid in `rdx`, and
    answers the record, or 0, in `rax`. With a table it probes the key's
    chain, and an empty slot means absent. With no table, for
    `DICT-WL:RETIRED`, or after a chain walked through every slot, it scans,
    and the last matching record wins.
  - The code-provenance band's set and query, `X64PROV:EMIT-HELPERS`
    ("Code provenance").
- `KERNEL,` ends with `ENGINE-PRIMS:COMPLETE`, so building the kernel dies 76,
  `prims: no backend body for specified primitive <name>`, at the first
  `KEEP?`-kept row of `prims.f` that no section registered. A row the kernel
  does not carry yet is a `REFUSE` or `REFUSE-WID`.

`test/x86-64-boot-harness.f` reopens `X64HARNESS` for cases a body can run
in. The peer harness's entry cannot run one: its `rbp` is a 1 KiB window of
the machine stack, `CASE1,` resets `r12` to it and `CLOSE,` pins `r13`-`r15`.
A booted image is `BOOT-OPEN,`, one case, `BOOT-CLOSE,`:

| word | emits |
|---|---|
| `BOOT-OPEN, ( bool -- )` | `ASM-RESET`, fresh labels and registry rows, `X64BOOT:START,` and a jump over `X64KERNEL:KERNEL,` to the case, which first marks the kernel's text native (`X64PROV:TEXT-NATIVE,`) |
| `PUSH, ( n -- )` | one cell |
| `PUSH-TEXT, ( ptr u8 n -- )` | a string's address and length; its bytes sit behind a jump |
| `PUSH-SCRATCH, ( n -- )` | the address n bytes past `BOOT-SCRATCH-OFF`, `DATA-START + $10000` |
| `CELL!, ( n n -- )` | an immediate into a DATA cell, to arm the latch, a live task or the exit hook |
| `CALL-ROW, ( ptr u8 n -- )` | a `call` to the row's `ENTRY-LABEL` |
| `EXPECT-POP, ( n -- )` | pop a cell and check it |
| `EXPECT-DEPTH, ( n -- )` | check `r12` = `[rbp+STACK-ABI:BASE-CELL]` + 8n |
| `EXPECT-BALANCED,` | check `rsp` = `[rbp+ARGV-CELL]` - 8, where the boot left it |
| `EXPECT-SCRATCH, ( n n -- )` | check that the scratch cell at an offset holds n |
| `BOOT-CLOSE, ( ptr u8 n -- )` | exit 0 and write the image |
| `RECORD, ( ptr u8 n n n -- )` | seed dictionary record `r14` with a name, a wid and flags, its code cell the record's index plus one, and count it |
| `EXPECT-ROW, ( n -- )` | pop a cell and check it is the address of record n |
| `PUSH-LABEL, ( label n -- )` | the address n bytes past a label |

The checks exit 21 (`FIRST-CASE`) upward, as the peer harness's case checks
do, and a negative image (`true BOOT-OPEN,`) exits 21 at its first check. Each
section below has a test file with a `SUITE` row. The file writes
`$HB_TMP/hb-x64-kernel-<name>` and its `-negative` twin, and the peer runs them.
An image holds at most ten checks: status 31, `CASE-END`, starts the harness's
own.

A numbered check that fails, and the exit 0 after the last, leave through the
peer harness's one `exit_group` (231), as `CHECK-RCX,`'s `die` row does, so
the status ends every thread. A thread-local `exit` (60) would not: on Linux
7.2.5 a main thread's `exit(21)` followed by a task thread's `exit(0)` ends
the process with 0.

### Syscall rows

`SYSCALLS,` registers one row per line. A row pops its arguments into the
syscall registers `rdi rsi rdx r10 r8 r9`, the order `sys.f` maps `x0..x5`
onto, stages `AT_FDCWD` and the flags the *at* family takes, traps through
`SYS,` and pushes through `X64RT:SYS-PUSH`. That is `mov rcx, -1 / cmovb rax,
rcx` and a push of `rax`: the result, or -1 when the kernel refused, as
`habu1.f SYS-PUSH` pushes `x0` or -1. `OS-OPEN-FLAGS` and `OS-MMAP-FLAGS`
translate the caller's BSD-shaped flags after the pops. They clobber `rax`,
`rcx` and `r11`, none of which carries an argument.

A row whose kernel call writes through a caller's span guards it first. The
guard clobbers every argument register, so the row reads the span from the
data stack before it pops.

- **ioctl.** The guard is `habu1.f GUARD-IOCTL`'s. `TCGETS` writes a 36-byte
  termios and `TCSETS` only reads. An `_IOC` request with `_IOC_READ` has its
  size in bits 16-29, and a write-only one needs no guard. Any other request
  has no size to check, so it fails closed with 83.
- **stat.** x86-64's `struct stat` has three u64s before `st_mode`, so the
  mode sits at 24, where aarch64 has it at 16. The size and the two times sit
  where aarch64's do. On success the row rewrites the buffer into the layout
  `lib/fs.f` reads: the mode at 4, the modification time at 48 and 56, the
  change time at 64 and 72 and the size at 96. That is the fix
  `habu1.f LINUX-STAT-FIX` applies.
- **time.** A time call cannot fail with the arguments these rows pass. One
  that does stops on `ud2`, as the ARM64 twins stop on `brk`. ARM64's
  `mono-ns` reads `CNTVCT_EL0`.
- **realpath.** The row resolves symlinks through libc, as
  `test/realpath-test.f` requires, and keeps the `habu1.f REALPATH` contract:
  -1 for a resolution or loader failure, and -2 for a capacity with no room
  for the whole C string. `free` runs after a copy and after a result that is
  too long. Two public emitters serve it:
  - `DLSYM, ( -- )` is the twin of `LIBC-OS DLSYM`. It sets
    `rax = dlsym(0, [rsi])`, reading the loader slot at
    `[rbp+RBASE-CELL] - CODE-OFF + [text size] + LINUX-DLSYM-SLOT-OFF`.
  - `C-CALL, ( -- )` calls `rax` under SysV with its integer register
    arguments only: `SYSV-CALL,` ("FFI rows") with no stack cells and `al` 0.
- **spawn.** `SPAWN,` is the twin of `habu1.f LINUX-SPAWN`, emitted into each
  spawn row and `run-rc`, as `LINUX-SPAWN` is. It works on a 112-byte frame on
  the machine stack whose first seven cells are the path, argv, envp, the
  working directory and the three descriptors, -1 meaning none; the rows fill
  the cells a caller does not pass with argv `path 0`, an empty environment
  or -1. It opens an `O_CLOEXEC` pipe and moves the write end to 3 or above,
  then `clone(SIGCHLD, 0, 0, 0, 0)`. The child makes its own process group,
  changes directory, dups each descriptor onto 0, 1 and 2 (skipping a
  negative one or one already in place) and calls `execve`; any failed step
  writes one byte to the pipe and exits 127. The parent reads the pipe once:
  end of file is a successful `execve` and the answer is the pid. A byte is a
  failed child, which is reaped, and the answer is -1, as it is for a pipe or
  a clone the kernel refused.
- **fcntl.** Command 73 is `lib/process.f F-SETNOSIGPIPE`, the macOS command
  Linux lacks. The row runs `rt_sigaction(SIGPIPE, {SIG_IGN, 0, 0, 0}, 0, 8)`
  instead, as `habu1.f LINUX-IGNORE-SIGPIPE` does. The x86-64 kernel's
  `struct sigaction` has the same four 8-byte cells (handler, flags, restorer,
  mask).
- **poll.** Before the call, the row guards `nfds * 8` bytes at `fds`. An
  `nfds` of `2^61` or more, whose byte length wraps, becomes the all-address
  span. A timeout of `ms` milliseconds becomes a timespec, and a negative one
  becomes none, which waits without end. The row pushes `rax` unchanged: poll
  is the one call the kernel never restarts after a signal, so its caller
  needs `-EINTR` (`habu1.f`'s errno rule).
- **The seam's emitters.** `proc-watch-open`, `kill-errno` and `execve`
  register the emitters in `src/os/linux-x86-64/proc-watch.f` and
  `proc-control.f`, which `kernel-x64.f` requires. `BPROCWATCHOPEN` publishes
  through `X64RT:SYS-PUSH`, and the other two push `rax` as `-errno`.

`test/x86-64-kernel-syscalls.f` guards `TIER-PROV:N-CELL`.
`hb-x64-kernel-syscalls` exits 0 with the latch open, and
`hb-x64-kernel-syscalls-armed` seals the latch first and exits 83. Its row
images call every row through `CALL-ROW,` and check what each row pushes.
They exit 0, and the peer runs them in a writable scratch directory:

| `hb-x64-kernel-sys-link` | `symlink readlink lstat64 rename` |
| `hb-x64-kernel-sys-dir` | `getdirentries64`, and `realpath` through a link to `/`, short, zero-capacity and missing |

### Control rows

An xt is a code address a body enters by `call`. The code it runs owns every
scratch register, so what a body needs after the call waits on the machine
stack.

| row | body | ARM64 twin |
|---|---|---|
| `execute` | pop the xt and call it | `BEXEC` |
| `execute-floor` | call the xt; below `[rbp+S0-CELL]`, reset `r12` to it and push true, else push false | `BEXECFLOOR` |
| `2>r`, `2r>`, `2r@` | move or copy two cells to or from the return stack, `RSP-CELL` cells deep from `STACK-ABI:RETURN-BASE-CELL` | `B2TOR`, `B2RFROM`, `B2RFETCH` |
| `catch` | call the xt under a catch frame; push 0 on its return, a throw's code on a throw | `BCATCH` |
| `throw` | with a handler, admit its frame, restore it and resume; with none, call the reporter xt in `UNCGH-CELL` if set, then exit with a code in [1, 255], else 67 | `BTHROW` |
| `finally` | the body under a catch frame, then the cleanup outside it, then rethrow a nonzero code | `BFINALLY` |
| `run-in-stack` | admit the extent or throw `E-STACK-UNGUARDED` over the three cells; call the xt on it; admit and restore the caller's stack | `BRUNSTACK`, `GUARDED-EXTENT?` |
| `die` | the message and LF on fd 2 when its length is positive; the exit hook, its cell cleared first; exit with an rc in [0, 255], else 67 | `BDIE`, `(LEXITHOOK)` |
| `evaluate`, `evaluate-closed`, `create`, `parse-name`, `num-parse`, `tok-imm?` | `REFUSE`: each jumps into `habu2.f`'s interpreter on ARM64, which this engine never has, and lane I provides it in Habu | |
| `unit-compile-run` | `REFUSE-WID` with `GLOBAL-INT-WID`: it arms the unit hook `habu2.f`'s interpreter calls | `BUNITCOMPILE` |

- **The catch frame** is `STACK-ABI:CATCH-BYTES` on the machine stack, chained
  through `HND-CELL`, at `BCATCH`'s offsets: `X64KERNEL:CATCH-PREV` through
  `CATCH-SENTINEL`, then `STACK-ABI:CATCH-BASE` and `CATCH-CAP`. `CATCH-RET`
  holds the cell at `CATCH-MSP`, and a throw writes it back before it resumes,
  as `BTHROW` reloads x30.
- **A throw admits a frame before any store**: the sentinel, both depths within
  `RETURN-CELLS` and `LOOP-FRAMES`, and the descriptor with room for the code.
  A frame that fails writes `hb: catch frame corrupt` on fd 2 and exits 87,
  `CATCH-STACK`. There is no `EVALD-CELL` arm and no REPL route: `LEVALREC`,
  `LREPLROUTE` and `LUNCAUGHT` are `habu2.f` routines, and Habu's `evaluate`
  recovers through `catch`.
- **The stack guard's twins** are in `src/arch/x86-64/rt.f`, package `X64RT`.
  `CHECK-CURSOR ( r64 r64 r64 n label -- )` takes the base, capacity and
  cursor registers that `STACK-GUARD:CHECK-CURSOR` fixes as x14, x10 and x12.
  `EXIT-BOUNDS` writes `hb: stack bounds exceeded` and exits 102,
  `STACK-BOUNDS`. For its syscalls `rt.f` loads the x86-64 seam globally.

`test/x86-64-kernel-control.f` writes one image per case, and its header gives
each one's status. `evaluate`'s refusal exits 76 and its negative twin 21. The
execute, catch, finally and run-in-stack images exit 0. The uncaught throws exit
42 and 50, the unguarded extent exits 67 and a corrupt frame exits 87. The die
images exit 5, 6 and 67.

### Atomics and publication rows

A store through a caller's address calls `PROT-SPAN-CALL,` first, and a flag
poke brackets its write with `PROT-REC,`. `ATOMICS,` holds the twins of
`habu1.f` `BATFETCH` to `BFENCE`. x86-64 orders memory as total store order: a
plain load already has `LDAR`'s acquire order, but a plain store may pass a
later load, which `STLR` followed by `LDAR` forbids, so `atomic!` is the
implicitly locked `xchg`. A row that writes guards the cell whose address is
on top of the data stack, then pops its operands: the guard preserves no
scratch register.

| row | effect | x86-64 body | ARM64 twin |
|---|---|---|---|
| `atomic@` | `( ptr a -- a )` | `mov` | `LDAR` |
| `atomic!` | `( a ptr a -- )` | guard, `xchg [m], r` | `STLR` |
| `atomic-add` | `( n ptr n -- n )` | guard, `lock xadd`, push the old value | `LDADDAL` |
| `atomic-cas` | `( a a ptr a -- a )` | guard, `lock cmpxchg` with `rax` the expected value, push `rax`, the value the cell held | `CASAL` |
| `fence` | `( -- )` | `mfence` | `DMB ISH` |

`PUBLICATION,` emits the protection window and the site-row helpers, then the
rows that write code, records and sites. The window is the twin of `habu1.f
EMIT-PROT-WINDOW` over the same `PROT` cells: the record band `[DBASE,
DBASE+CFSTK-OFF)` in `RLO`/`RHI`, the control-flow band `[DBASE+CFSTK-OFF,
DBASE+DICT-SIZE)` as the latch `CF`, and the code band `[DBASE+DICT-SIZE,
DBASE+REGION)` in `WLO`/`WINDOW`. A declared span is intersected with each
band, a band only grows while it is open, and the close clears each record
before it flips back exactly the recorded range. A flip covers whole `$1000`
pages, the one x86-64 page size, where ARM64 rounds to `PROT-PAGE-MAX` for its
4, 16 and 64 KiB kernels, so the control-flow band is one page and no two bands
share one.

| call site | takes | ARM64 twin |
|---|---|---|
| `WINDOW-SPAN,` | `rdi` the address, `rsi` the length | `PROT-EMIT:LSPAN` |
| `WINDOW-OPEN,` | `rdi` one past the last byte: `[CP, rdi)`, or CP's byte for an end at or below CP | `PROT-EMIT:LOPEN` |
| `WINDOW-CLOSE,` | nothing: every open band flips back read-execute | `PROT-EMIT:LCLOSE` |

Each call keeps every VM register and clobbers `rax rcx rdx rsi rdi r8-r11`;
a section that calls one follows `PUBLICATION,` in `KERNEL,`. The rows keep
x86-64 spans byte-granular: `src/compiler/native/publish.f` passes byte sizes
and a routine may end in a one-byte `ret`, so no guard traps a length or an
address that is not a whole four-byte word. Nothing flushes, since x86-64
keeps its instruction cache coherent.

| row | effect | x86-64 body | ARM64 twin |
|---|---|---|---|
| `patch32` | `( n n -- )` | guard the four bytes, `X64PROV:INVALIDATE,` them, then `mov [addr], r32` between two `PROT-REC,` flips | `BPATCH32` |
| `code-publish` | `( ptr u8 n n -- )` | exit 83 for an empty, wrapping or out-of-code span or a destination other than CP; `WINDOW-OPEN,` over `[CP, slot)`, the slot the first `CODE-SLOT` multiple at or past `CP+len`; copy, `int3` over `[CP+len, slot)`, `WINDOW-CLOSE,`, drop the site rows of both kinds in `[CP, slot)`, CP to the slot, `X64PROV:UNKNOWN-RANGE,` over `[dst, slot)` | `BCODEPUBLISH` |
| `callmap-set` `addrmap-set` | `( n -- )` | exit 83 for an address outside the region; insert a `SITE-CALL` or `SITE-ADDR` row at its offset | `BCALLMAPSET` `BADDRMAPSET` |
| `reloc-maps-clear` | `( n n -- )` | drop the rows of both kinds in `[start, start+len)` | `RELOC-EMIT:BCLEAR-MAPS` |
| `xref-retarget` | `( n n n -- )` | exit 83 for an index past NDICT, the pending record, or a length past `CODE-SPAN:RAW-MAX` or equal to `CODE-SPAN:FULL`; between two `PROT-REC,` flips the length, then the address | `BXREFRETARGET` |
| `int-mark` | `( n -- )` | or `DNAME-INT` into record n's flags between two `PROT-REC,` flips; wid `GLOBAL-INT-WID` | `BINTMARK` |
| `min-in-mark` | `( n n -- )` | the same with the depth's eight bits at `DNAME-MIN-IN-MASK` | `BMININMARK` |
| `native-unit-publish` | `( ptr u8 n ptr u8 n -- )` | `REFUSE-WID` with `GLOBAL-INT-WID` until its body lands | `NPUBWIN:BNATIVEUNITPUBLISH` |
| `does-patch` | `( n ptr u8 n -- )` | `REFUSE` until the definer rows land | `DOESPATCH:PRIM` |
| `does-record` | `( n n -- )` | record NDICT+1 for the parent `PEND-CELL` points at: the entry, the length, the parent's name and `;does` at CP zero-padded to a `CODE-SLOT` multiple, and its wid; the code band opens over the padded name and the record band over the record, and CP moves past the pad, to a slot, before the close | `DOES-REC:NATIVE-PRIM` |

- **Code slots.** CP is always a multiple of `X64KERNEL:CODE-SLOT`, 16:
  `X64IR:SP-ALIGN`, the only placement `X64EMIT:PLACE-AT` accepts, since the
  driver places each definition at CP (`NPUB:NEXT-SLOT`). Every CP writer
  keeps it one: the boot starts it at the page-aligned `DBASE+DICT-SIZE`,
  `code-publish` fills to the next slot with `int3`, `does-record` and the
  record writers of "Definition rows" zero-pad the names they write at CP to
  one, and `cp!` refuses any other address. The fill belongs to the span:
  `code-publish` records `[dst, slot)` unknown, a record writer marks a long
  name's `[CP, slot)` native, and a compile's `1 X64PROV:CLOSE,` covers
  `[OPEN's CP, slot)`, so the native
  evidence `src/habu/snap-lib.f` requires for every byte below CP
  covers the padding. `src/compiler/native/publish.f` does not model the
  slot: its room checks count the routine's exact bytes and the `;does` name
  rounded to four, against a ceiling `CODE-RESERVE` (16 KiB) below the
  region's end. One publication pads at most 15 bytes and its `does-record`
  15 more, so the reserve absorbs the padding, and the next room check
  refuses a CP past the ceiling.
- **Site rows** stay strictly ascending by offset ("Live-region sites"). The
  insert scans down from the last row, so a site above every row is an append
  and the rows above a lower one move up. The same row again changes nothing;
  the other kind at a recorded offset, a row past `SITE-CAP` or a count above
  it exits 103, `SITE-RC`. The removal compares offsets signed, so a span
  below the region removes nothing.
- **Publication order.** `xref-retarget` stores the address after the length
  with a plain `mov`: under total store order it publishes after the store
  before it, where ARM64 needs `STLR`. `int-mark` and `min-in-mark` check no
  index, as their ARM64 twins do not.

### Engine-state rows

A body that moves engine state, such as `cp!` and `ndict!`, begins with
`TASK-LIVE-GUARD,`. `test/x86-64-kernel-engine.f`: `hb-x64-kernel-engine`
passes the guard and exits 0, and `hb-x64-kernel-engine-armed` marks a task
live first and exits 79. `hb-x64-kernel-window` carries a `PROT-PAGE-MAX` of
text behind the kernel, as the whole kernel will, so its read-write segment
lands a page further on; it exits 0.

| `search-wl` | `( ptr u8 n n -- n )` | `BSWL` | the record's code cell, or 0; 0 for wid `OWNER-API-PRI-WID` before the search and for a `DNAME-INT` record |
| `xref-search-wl` | `( ptr u8 n n -- ptr n )` | `BCOMPILERSWL` | the record, or 0, with neither refusal; registered with `GLOBAL-INT-WID` |

Three images seed five records with `RECORD,` and exit 0.
`hb-x64-kernel-search` asks both rows with no index, so the search scans:
a name found with its case folded on both sides, the same name in another
wordlist, a name past `DNAME-INL`, an absent name, the private wid refused
where `xref-search-wl` finds the record, and a `DNAME-INT` record refused
where `xref-search-wl` finds it. `hb-x64-kernel-search-index` builds the
index first and asks the same, so it probes. `hb-x64-kernel-index-upkeep`
also seeds `eccwbv` and `hktfoj`, two names of one length whose keys share a

not told of: one stays absent until `HIDX-ADD,`, one until `HIDX-REBUILD,`,
and one under `DICT-WL:RETIRED` is found by the scan.

- **DP bound.** `DP-CHECK,` admits a DP in
  `[DATA + DATA-START, DATA + X64KERNEL:DP-CEILING]`, with signed compares
  as on ARM64. `DP-CEILING` is `X64LAYOUT:DATA-SIZE PROF-CNT-BYTES -`,
  computed from the target's `DATA-SIZE`. A DP outside the bound reaches
  `LDPBAD` with the DP in `rdi`.
- **`LDPBAD` refusals.** `LDPBAD` is a helper emitted by `HELPERS,`. It writes
  `hb: data space out of range: DP <dp> of <ceiling> bytes` and a newline on
  fd 2, then exits 76. Both numbers are offsets from DATA, written by
  `DIAG-U,`, the kernel-local twin of `LDIAGU`. The ARM64 line then continues
  into `LCOMPILEDIE`, which appends ` at <path>:<line>` and throws inside
  `evaluate`. This engine has no interpreter yet, so the refusal always exits.
- **Hook refusals.** A refused hook writes the ARM64 row's text on fd 2, with
  no newline, and exits 70. The texts are `set-check: invalid checker xt`,
  `set-top-check: invalid top-row hook xt`,
  `set-preflight: invalid or replaced hook` and
  `set-preflight: invalid hook`.
- **Output funnel.** `X64RT:G-OUT` takes `rsi` as the span and `rdx` as its
  length. It loads `GENIO-ABI:OUT-CELL` into `rdi`. When the cell is 0, it
  writes fd 1 in place; otherwise it calls `X64RT:LGENIOOUT`. The call
  clobbers `rax rcx rdx rsi rdi r8-r11` and no VM register.
- **`(GENIO-OUT)`.** `HELPERS,` emits this helper at `LGENIOOUT` and
  registers it through `ENGINE-PRIMS:HELPER-REGISTER`, as `habu2.f
  EMIT-GENIO-OUT` does. The helper takes the device index in `rdi` and the
  span in `rsi` and `rdx`. It writes fd 1 when `BUSY-CELL` is set, when the
  index is above `DEVICES` (8) as an unsigned value, or when row
  `[WRITE-OFF + 8*(index-1)]` is 0. Otherwise it:
  1. pushes `ACTIVE-CELL` on the machine stack;
  2. stores the index into `ACTIVE-CELL` and sets `BUSY-CELL` to 1;
  3. pushes the span and its length on the data stack;
  4. calls the row's xt;
  5. clears `BUSY-CELL` and pops `ACTIVE-CELL` back.

  A device's own output finds the funnel busy and so reaches fd 1.

### Code provenance

`src/habu/code-origin-x64.f`, package `X64PROV`, is the twin of
`src/habu/code-origin.f` over the same `TIER-PROV` band (`layout.f`). Its
rows `(first, end, origin)` are sorted, disjoint and normalized, with
coordinates relative to DBASE; -1 is unknown, 0 JIT and 1 positively native,
and missing coverage is unknown. `EMIT-HELPERS` (called from `X64KERNEL:HELPERS,`) emits its two helpers, registered
under the ARM64 names: `engine-code-origin-set` records a span, and
`engine-code-origin-query` answers the origin of the one row that covers a
span, else -1. A table that cannot take another row exits 101,
`ENGINE-ERROR:CODE-ORIGIN-FULL`, with `hb: code-origin table capacity` and a
newline on fd 2.

| call site | does | ARM64 twin |
|---|---|---|
| `NATIVE-RANGE,` `UNKNOWN-RANGE,` | record `[rdi, rsi)` with origin 1 or -1 | `CODE-ORIGIN:NATIVE-RANGE,` `UNKNOWN-RANGE,` |
| `INVALIDATE,` | `[rdi, rsi)` turns -1 where rows lie; a span where none lies records nothing | `CODE-ORIGIN:INVALIDATE,` |
| `QUERY,` | `rax` = the origin of `[rdi, rsi)` | `CODE-ORIGIN:QUERY,` |
| `OPEN,` | `OPEN-CELL` = CP | `CODE-ORIGIN:OPEN,` |
| `CLOSE, ( n -- )` | with a window open, `[OPEN-CELL, CP)` takes origin n and `OPEN-CELL` clears | `CODE-ORIGIN:CLOSE,` |
| `TEXT-NATIVE, ( label label -- )` | the text between the labels is native | `EM-STARTUP-RUNTIME-STATE`'s `[LANCHOR, LSRC)` |

A span is two absolute addresses. `OPEN,` keeps every register; every other
call keeps every VM register and clobbers `rax rcx rdx rsi rdi r8-r11`, where
the ARM64 call sites keep every register. `patch32` invalidates the four bytes
before it writes them, `code-publish` records its span and its fill unknown,
and only a compile's successful return certifies code: `OPEN,` before it,
`1 CLOSE,` after, as `habu2.f` brackets it. `X64HARNESS:BOOT-OPEN,` marks the
kernel's text native at the case's entry, as the ARM64 boot marks the
engine's. The snapshot words `CAPTURE-ORIGIN!`, `CAPTURE-RANGE,`, `ABANDON,` and
`RESTORE-REGION,` have no twin: x86-64 refuses `snap-rebase`.

### FFI rows

`FFI,` holds the SysV trampolines. The integer rows are the twins of
`habu1.f` `BFFI-CALL`, `BFFI-CALL-N` and `BFFI-CALL-BOUNDED`. `argbuf` holds
at least eight cells, the contract ARM64's unconditional load of `x0..x7`
sets. SysV takes six in `rdi rsi rdx rcx r8 r9`, so the other cells go on the
stack.

The ABI-planned rows are the twins of `BFFI-CALL-ABI(-R)` and
`BFFI-CALL-ABI(-R)-BOUNDED`, the rows `lib/ffi-abi.f` plans a call for. The
descriptor carries no per-argument tag: integers sit in `argbuf`, doubles in
`fpbuf` (`FFI-FBUF`), and the stack arguments come prepacked in `stackbuf`.
`rdi..r9` take `argbuf[0..6)`, `xmm0..7` always take `fpbuf[0..8)`, and the
stack takes `max(nstack, 0)` `stackbuf` cells and nothing else. `argbuf[6..9)`
pass nowhere, but the twins' guards over them stand. No input carries a count
of doubles, so `al` is 8, the upper bound the psABI admits. The plain rows
push `rax`, the `-r` rows the bits of `xmm0`.

| row | effect | stack cells | guard, before the pops |
|---|---|---|---|
| `ffi-call` | `argbuf nargs fn -- ret` | `argbuf[6..8)` | one byte at `argbuf[i]` for each `i < nargs` |
| `ffi-call-n` | `argbuf nargs fn -- ret` | `argbuf[6..max(nargs, 8))` | none, as `BFFI-CALL-N` |
| `ffi-call-bounded` | `argbuf extents nargs fn -- ret` | `argbuf[6..max(nargs, 8))` | `extents[i]` bytes at `argbuf[i]` for each `i < nargs` |
| `ffi-call-abi(-r)` | `argbuf fpbuf stackbuf nstack nint sret fn -- n\|r` | `stackbuf[0..max(nstack, 0))` | one byte at `argbuf[i]` for each `i < nint`, and at `argbuf[8]` when `sret` is nonzero |
| `ffi-call-abi(-r)-bounded` | `argbuf fpbuf stackbuf regext stkext nstack fn -- n\|r` | `stackbuf[0..max(nstack, 0))` | `regext[i]` bytes at `argbuf[i]` for each `i < 9`, then `stkext[i]` bytes at `stackbuf[i]` for each `i < nstack` |

- **The guard.** `GUARD-ARGS,` walks the count its caller loads into `rcx`
  over the buffer the cell n below the top holds; `EXTENT-LEN,` names the
  extents' cell. `PROT-SPAN-CALL,` clobbers every scratch register, so the
  index and the count wait on the machine stack across each call and every
  turn reads the buffer and the extents again through `PEEK,`. The compare is
  signed, so a count <= 0 guards nothing. A span that meets a band exits 83
  before the call.
- **The clamp.** `nstack` is the caller's data and `SYSV-CALL,` copies `r10`
  cells, so the ABI rows turn a negative count into 0 first, as
  `BFFI-COPY-ABI-STACK` skips it; a negative count would raise `rsp` and run
  the copy loop off the buffer.
- **`SYSV-CALL, ( n -- )`** calls the function in `r11` with the register
  arguments already in `rdi..r9` and `xmm0..7` and the `r10` cells at `rax`
  (a count >= 0) as its stack arguments; the answer is in `rax` or `xmm0`. It:
  1. pushes the entry `rsp` on the data stack, which `r12`, callee-saved,
     keeps across the call, as `BFFI-CALL-N-CORE` keeps the frame sp in
     `x20`; every callee-saved register here is a VM register;
  2. parks the function in the machine-stack cell below the entry `rsp`,
     while `r11` carries the copy;
  3. drops `rsp` by the cells and aligns it down to 16, so the cells fit
     below the parked function;
  4. copies the cells to `[rsp]` upward, sets `eax` to n, the caller's bound
     on its vector arguments, which a variadic callee reads in `al` to decide
     whether it saves `xmm0..7`, and calls `r11`;
  5. pops the entry `rsp` back.

  The VM registers survive by the callee-saved rule. `C-CALL,` is its
  zero-cell case with n = 0, and the integer rows pass 0.

`test/x86-64-kernel-ffi.f` seals the friend latch in every image, so each
guard walks its whole span test. `hb-x64-kernel-ffi` calls libc `getpid`
through `ffi-call`, the pointer from `DLSYM,`, and checks it against the
`getpid` row. A SysV stub the image carries folds its argument places in
order, one hex digit each, then `rsp & 15` at its entry and `al` as a byte;
argument cell i holds i + 1. `ffi-call` (8 cells), `ffi-call-n` (3 and 9) and
`ffi-call-bounded` (9) call it, each but `ffi-call-n`'s 3 also a cell deeper,
so both `rsp` parities cross the alignment. It exits 0, and
`hb-x64-kernel-ffi-negative` exits 21. `hb-x64-kernel-ffi-armed` names a band
cell in `ffi-call-bounded`'s ninth argument, and
`hb-x64-kernel-ffi-call-armed` in `ffi-call`'s eighth; each exits 83. No libc
symbol takes nine integer arguments, so the stub stands in, as
`lib/ffi-test.f FFI-T-SUM10` does on ARM64.

`hb-x64-kernel-ffi-abi` exits 0. A second stub folds the bits of `xmm0..7`
and `al` the same way and answers the fold in `xmm0` and its complement in
`rax`; `fpbuf` cell i holds i + 1, and all four ABI rows call it, so a
register out of order, a wrong `al` or the wrong answer register changes what
a row pushes. The nine-place stub takes its last three places from `stackbuf`
through `ffi-call-abi` and, a cell deeper, `ffi-call-abi-bounded`, with junk in
`argbuf[6..9)`; a stub of register places only takes `nstack` -1 through
both. `hb-x64-kernel-ffi-snprintf` exits 0: libc `snprintf(buf, 8,
"%.1f %.1f", 1.5, 2.5)` with the 64 cells below `rsp` zeroed prints `0.0 0.0`
through `ffi-call-n`, whose `al` of 0 leaves the doubles unsaved, and

### Pure rows

`PURE,` holds the 52 arithmetic, comparison, shuffle and memory rows of
`habu1.f EMIT-ARITH-PRIMS` to `EMIT-MEMORY-PRIMS`, less the return-stack pairs
and the atomics, and last, in `FLOAT-ROWS,`, the 15 float rows of
`EMIT-FP-PRIMS`. 62 are the compiler's own lowering: `PRIM-HIR` stages each as
one HIR function and lays the routine the x86-64 chain emits into the record
whole, `ret` included, so a row and the code a compiled word inlines for the
same word come from one lowering.

- **The seam** is `src/habu/kernel-hir-x64.f`, package `X64KHIR`.
  `COMPILE ( ptr u8 n n n [ -- ] [ -- ] -- )` takes the name, the cells in and
  out, the stager and `use`. It opens a context under `X64ABI:BINDING`, the
  SysV binding `NABI:BINDING` answers on an x86-64 host, and a HIR module
  whose source text is the name. The stager builds the one function with
  `ARG ( n -- v )` (0 the deepest cell), `LIT`, `OP1`, `OP2` and `FETCH`
  (`load` or `bload`, threading the memory token) and names each answer,
  deepest first, with `RESULT ( v -- )`. `OP1` and `OP2` answer the type the
  opcode's schema declares, a real for a float operation, since the verifier
  refuses any other. The function then takes the driver's
  order through `NBACK`: declare with `L-NONE`, select, prune, fixpoint, and
  `X64PASS:EMIT-UNPLACED`, since `NBACK:EMIT` always places. `use` reads the
  sealed emission before retire and release. A result count other than `out`
  dies 76.
- **The stagers** follow the word model: the rows of `hir-word.f` `DEF-ARITH`
  to `DEF-BYTE-VIEW`, and `elaborate.f` `EXPAND-CELL-INDEX`, `EXPAND-MODULO`
  and `EXPAND-MAXIMUM` for `ptr-field`, `mod` and `max`. Words the model has
  no row for are staged from operations it has: `-rot`, `2swap` and `2over`
  are picks, `chars` the identity, `char+` `x 1 add`, `negate` `0 x sub`,
  `0<` `x 0 lt`, `abs` `(x xor m) sub m` with `m = x 0 lt`, `min` `max`'s
  sequence with `lt`, `/mod` one `div` with the remainder `a q b mul sub`,
  and `count` `x 1 add` and `x bload`. The float rows are `DEF-FLOAT` and
  `DEF-FCOMPARE`'s operations, `fadd` to `real>int`. A double travels as its
  bits in a cell, so each argument crosses into a real with `bits>real` and a
  real answer back with `real>bits`, as a compiled word's values cross
  (`elaborate.f COERCE1`, `CELL-CROSS`); `s>f` takes its cell and `f>s`
  answers one as they stand.
- **Links.** A compiled body calls out only from the divide's zero-divisor
  side, to `X64SEL:THROW-ENTRY`: that call's field, at the site plus
  `X64ASM:CALL-REL32-OFF`, becomes `X64CODE:REL32-SITE ( n label -- )` of the
  `throw` row's label, and `ASM-LINK` patches it. Any other call row or an
  address site dies 76.
- **Hand-written** are five: `!`, `c!` and `+!`, the guarded twins of
  `habu1.f BSTORE`, `BCSTORE` and `BPLUSSTORE`, which compiled stores call
  rather than inline (`elaborate.f DO-STORE`); each guards its 8 or 1 bytes
  through `(PROT-SPAN)` before the pops. `?dup`, `BQDUP`'s twin, whose
  depth depends on its value. And `f.`, `BFDOT`'s twin: one `write` on fd 1,
  never the output device, of `-` when bit 63 is set, the decimal of
  I = fcvtzs(|x|), `.`, the six low digits, zero-padded, of
  fcvtzs((|x| - I) * 1e6), and a newline. `cvttsd2si` answers MIN-N for a NaN
  and past a cell, where fcvtzs answers 0 and saturates to MAX-N; both inputs
  are a NaN or not negative, so smearing MIN-N's sign flips it to MAX-N and
  `ucomisd` of the value with itself zeroes a NaN's.

### Task entry

`TASK,` holds `task-entry ( -- n )`, the twin of `habu1.f BTASK-ENTRY`. The
row answers the address of a SysV function, not a Habu execution token:
`lib/task.f` hands it to `pthread_create` with a `TASK-ABI` descriptor as the
argument. The body pushes that address and jumps over the function, so the
function lies inside the row's record, as on ARM64. With the descriptor in
`rdi`, the function:

1. pushes `rbx rbp r12-r15`, the SysV callee-saved set, which is exactly the
   VM's registers, so nothing twins `BTASK-ENTRY`'s `d8..d15` save;
2. loads `rbp` from `REGION-OFF`, `r12` from `STACK-OFF`, `r13` from
   `DBASE-OFF`, `r14` from `NDICT-OFF` and `r15` from `CP-OFF`, and zeroes
   `rbx`;
3. stores the descriptor at `[rbp+TASK-TCB-CELL]` and calls the xt at
   `XT-OFF` as `execute` calls one;
4. reads the TCB back through `rbp` and publishes `DONE` at `STATUS-OFF`
   with `xchg`, the release `atomic!` gives, where ARM64 uses `STLR`;
5. zeroes `eax`, pops the six registers in reverse and returns.

It never writes `RUNNING`: `ACTIVATE` stores that before `pthread_create`,
and a store here could put `RUNNING` back over the `HALT-REQ` that a
`TASK:HALT` in the create window leaves. The six pushes leave `rsp` 8 bytes
off 16-byte alignment at the call. Habu code does not need that alignment,
because `SYSV-CALL,` aligns `rsp` before any C call.

`test/x86-64-kernel-task.f` hands every image the same descriptor, its
status `HALT-REQ`, and the same body. The body is a `ROUTINE,` that records
`r13`, `r14`, `r15`, `rbx` and the status it finds through the TCB its
region holds, then pushes one cell through `rax` and zeroes every other
scratch register, as an xt may (see "Control rows"). An entry that reads the
descriptor from one of them after the call faults.

- `hb-x64-kernel-task` runs the function on a thread through
  `pthread_create` and `pthread_join`, found by `DLSYM,` and called through
  `ffi-call`. Both answer 0 and the thread answers 0. The status is `DONE`,
  the region's `TASK-TCB-CELL` holds the descriptor and the stack base holds
  the pushed cell.
- `hb-x64-kernel-task-call` calls the function through `ffi-call` with a
  nonzero `rbx`. It answers 0, and the caller's `rbp`, `rbx`, `r13`-`r15`,
  depth and balance survive.
- `hb-x64-kernel-task-body` makes the same call and checks the body's
  records: the descriptor's `r13`-`r15`, `rbx` 0 and `HALT-REQ`.

Each exits 0. `hb-x64-kernel-task-negative` is the thread case expecting a
wrong `pthread_create` answer, which it checks before the join while the
thread may still run, and exits 21: the failed check's `exit_group` ends the
thread too.

### Signal install and frames

`src/habu/boot-x64.f` holds the x86-64 twins of `src/habu/crash.f`'s
sigaction frame, `INSTALL-SIGACT` and ucontext offsets. The crash handler
and the profiler's handler install through them; a program installs the
signal stub through `lib/signal.f`'s libc `sigaction`, and
`test/x86-64-boot-signal.f` through `SIGACTION-AT,`.

- `SIGACTION, ( n n label label -- )` installs the handler at the first label
  for signal n with the given flags, returning through the restorer at the
  second. It builds the kernel's own `struct sigaction` on the machine stack:
  the handler at 0, the flags at 8, the restorer at `$10` and a zero mask at
  `$18`, whose 8 bytes are rt_sigaction's fourth argument. `rsp` comes back
  where it was. It adds `SA_RESTORER` (`$04000000`) to the flags, because
  x86-64 has no default restorer. Given an action without one, the kernel
  never enters the handler and kills the process with SIGSEGV. It clobbers
  `rax rcx rdx rsi rdi r10 r11` and, as `SYS,` does, leaves CF set when the
  kernel refused.
- `SIGACTION-AT, ( n n r64 label -- )` is the same with the handler's
  address in a register. It stores that register before it clobbers any, so
  every register but `rsp` may hold it. `SIGACTION,` loads its label into
  `rax` and calls it.
- `RESTORER, ( label -- )` binds the restorer, `mov eax, 15; syscall`
  (rt_sigreturn), where no other control falls in. A handler's `ret` enters
  it.
- `SA-SIGINFO` (4) enters the handler with the signal number in `rdi`, the
  siginfo in `rsi` and the ucontext in `rdx`, and has the kernel fill the
  siginfo.
- `UC-GREG ( r64 -- n )` answers the ucontext offset of the slot holding a
  register as the signal interrupted it, and `UC-RIP` is rip's. The kernel
  restores every register from its slot when the handler returns, so a
  handler also writes a slot to change the resumed context.

|---|---|---|
| `UC-GREGS`, r8's slot: struct sigcontext holds r8-r15, rdi, rsi, rbp, rbx, rdx, rax, rcx, rsp, rip | `$28` | `LINUX-MCTX-X0-OFF` |
| `RBP UC-GREG`, DATA | `$78` | x20 |
| `R12 UC-GREG`, the data stack | `$48` | x19 |
| `R13 UC-GREG`, DBASE | `$50` | x26 |

`START,` carries the signal stub out of line, after its `FAIL,` blocks. It is
the twin of `crash.f EMIT-SIGNAL-HANDLER` (`LSIGH`) with the same contract.
It is a `void (int)` `sa_handler`: it pushes `rdi` and makes one four-byte
write of the number's low bytes to the fd word. It reads that word at the
absolute address `DATA-VA + SIGNAL-ABI:FD-CELL`, never through `rbp`, which
is the interrupted thread's own DATA. It ignores the write's result, absorbs
the signal when the word is zero, touches no Forth state and returns through
whatever restorer its installer named. After `DATA-INIT,` the boot stores the
stub's address in `SIGNAL-ABI:STUB-CELL` and the word's address in
`SIGNAL-ABI:FD-PTR-CELL`, as `EM-STARTUP-RUNTIME-STATE` does. `lib/signal.f`
installs it through libc `sigaction`, which supplies `SA_RESTORER`. The word
needs no clear at boot: DATA is a fresh mapping.

`test/x86-64-peer-routines.f` writes `signal` into `x64-routines`, listed

returns; the image checks every resumed register. The failures exit 21 when

the SIGKILL install is not refused, 24-28 for the handler's checks in that

register. Without
the install the image dies of SIGUSR1 (138 in a shell), and without

`test/x86-64-boot-signal.f` runs on the booted harness. Each image installs

### Crash handler

`START,` installs the twin of `src/habu/crash.f EMIT-CRASH-HANDLER` once the
stacks it classifies are published: `SIGACTION,` with `SA-SIGINFO` for
SIGILL, SIGTRAP, SIGBUS, SIGFPE and SIGSEGV (4, 5, 7, 8, 11), unchecked, as
crash.f installs it. The handler, its printer, their texts and the restorer
`SIGACTION,` requires sit behind `_start`'s jump with the boot failures. The
handler never returns, so it owns every register. It keeps the signal, the
siginfo, the ucontext and the text base in `r12`, `r13`, `rbx` and `r14`,
which neither its printer nor `syscall` writes. It takes the text base
rip-relative, as `TEXT-BASE,` does for `_start`.

- **Guard pages.** A SIGSEGV or SIGBUS whose saved rip lies from the text base
  to the code region's end is classified as crash.f classifies one. Only in
  Habu's own code is the saved `rbp` DATA; foreign SysV code keeps a frame
  pointer there. The fault address, `si_addr` at siginfo + `$10`, is compared
  with the page below each VM stack's base and the page at the base plus its
  capacity, in crash.f's order: data (capacity `STACK-ABI:CAP-CELL`), return
  (`RETURN-BYTES`), DO/LOOP (`LOOP-BYTES`). A base that is zero or not
  `PAGE-BYTES` aligned is no stack and is skipped. A hit writes
  `hb: stack bounds exceeded (data)`, `(return)` or `(loop)` and a newline in
  one write and exits 102, `ENGINE-ERROR:STACK-BOUNDS`.
- **The dump.** Anything else writes `habu-crash regs [sig rax rcx rdx rbx rsp
  rbp rsi rdi r8..r15 rip] code [rip-8 rip rip+8], hex one-per-line:` and a
  newline, then 21 lines of sixteen lowercase hex digits and a newline, one
  write each: the signal, the sixteen registers by number from their
  `UC-GREG` slots, rip from `UC-RIP`, and the 24 bytes from rip - 8 as three
  cells in memory order. A cell reads 0 unless its eight bytes lie in the code
  region, whose base is the text base plus `REGION-OFF - CODE-OFF`, never the
  saved `r13`, so the handler reads no address it cannot prove mapped. It
  exits 134. One printer serves both orders: it writes the value's nibble n,
  counted from the least significant, at digit n xor a mask, 15 for a value's
  most significant nibble first and 1 for a cell's bytes in address order.

| signal | saved rip | outcome |
|---|---|---|
| SIGSEGV, SIGBUS | text base to the region's end, `si_addr` in a guard page | its line, exit 102 |
| SIGSEGV, SIGBUS | anywhere else, or `si_addr` in no guard page | the dump, exit 134 |
| SIGILL, SIGTRAP, SIGFPE | anywhere | the dump, exit 134 |

### Definition rows

`DEFINITION,` holds the eleven definition writers of `src/habu/prims.f` ("the
definition writers"), the rows an interpreter written in Habu publishes
definitions, namespace rows, aliases and package scope through: the twins of
`habu2.f` `DEFWRITE`'s bodies and of `C-IMMEDIATE`, in each twin's check
order, each registered with `ENGINE-PRIMS:GLOBAL-INT-WID` as on ARM64. Every
refusal comes before the first store and writes nothing on fd 2: 79 while a
task is live (`TASK-LIVE-GUARD,`, in the five dictionary rows), 84,
`ENGINE-ERROR:SEAL-PACKAGE`, for a protected wid after the seal, and 83,
`ENGINE-ERROR:SEAL-VIOLATION`, for every other refusal. Past the checks two
helper exits can still end a row: 74 when `HIDX-ADD,` cannot keep the index
and 101 when `X64PROV:NATIVE-RANGE,` finds the origin table full.

- **The record writers**, `namespace-record`, `alias-record` and `def-open`,
  keep their arguments in a machine-stack frame, since every helper call
  clobbers the scratch registers. Each refuses a pending definition, whose
  record occupies slot NDICT, NDICT at `DICT-CAP`, an empty name, a long name
  whose slots at CP reach the code ceiling (`X64KERNEL:CODE-CEILING`,
  `REGION - $4000`, compared unsigned) and a live record of the folded name in
  the wid, which the one-wordlist search's probe (`FIND-LBL`) finds. One
  emitter, `NAME-STORE,`, stores the name: up to `DNAME-INL` bytes inline, a
  longer one at CP, zero-padded to the next `CODE-SLOT` inside `WINDOW-OPEN,`
  over `[CP, slot)`, `X64PROV:NATIVE-RANGE,` over the same span and CP moved to
  the slot. `WINDOW-SPAN,` declares the record, and `WINDOW-CLOSE,` closes
  both bands after the row's last write.
- **The seal.** With `SEAL-NDICT-CELL` nonzero, `alias-record` and `def-open`
  judge the wid as `habu1.f` `LPROTWIDQ` does: wids 1 and 2 are always
  protected, one at or above `PROT-WID-MAX`, unsigned, never, and any other
  by its `PROT-BITS,` bit.
- **`def-open`** leaves record NDICT unpublished with `PEND-CELL` pointing at
  it, and stores `X64PROV:OPEN,` after the name, so the open provenance window
  and `[0]` take the same slot. At tier 0 it opens the record only: the JIT's
  own head is not this row's.
- **`def-close`** ends the definition `;` compiled, as `habu2.f`
  `DEFWRITE:NATIVE-CLOSE` ends the engine's tier-1 one: `X64PROV:CLOSE,` with 1, so
  only a definition whose `DEF-TIER-CELL` is 1, as `ndict-append` requires,
  certifies its code native.
- **`imm-mark`** is the engine's `immediate`: `NEWEST-MARK,`, which
  `wide-mark` shares, ors `DNAME-IMM` into record NDICT - 1 between two flips
  of its pages. It refuses nothing.
- **`def-cast`** publishes the `cast:` declaration `def-open` opened with
  `DKIND:CAST`, as `habu2.f` `DEFWRITE:DEF-CAST` publishes `C-CAST`'s: the
  identity is one code slot at CP, a `ret` and `int3` to the slot's end, with
  `[8]` its exact length (`CODE-SPAN:EXACT`). CP moves past the slot before
  `X64PROV:CLOSE,` with 1, which closes `[open, CP)`. The caller registers the
  cast with the checker before the row counts the record, and stores the
  checker's facts after it (`src/habu/definers.f`).

### Profiler rows

`PROFILER,`, last in `KERNEL,`, holds `src/habu/prof.f`'s eight rows:
`prof-on`, `prof-off`, `prof-reset`, `prof-rate`, `prof-pc>rec`,
`prof-report`, `prof-json` and `prof-row`, the bodies of
`src/habu/prof-x64.f`, package `X64PROF`. It first calls
`X64PROF:HELPERS,`, which emits the SIGALRM handler, its own restorer, three
index helpers, the sync, the printers and the reports where no control falls
in. The band and the arena are `PROF-ABI`'s (`src/habu/prof-abi.f`): the band
at `PROF-BAND-AT` of `X64LAYOUT:DATA-VA` and `DATA-SIZE`, read at that
absolute address because DATA is mapped fixed, and the arena wherever the
band's `PROF-ARENA` points.

The helpers keep every VM register and clobber only what the table names, so
a body calls them without a frame, as the sync does:

| call | in | out | clobbers | twin |
|---|---|---|---|---|
| `FIND,` | `rdi` a pc, `rsi` the arena | `rax` its index entry or 0 | `rcx rdx r8 r9` | `LPROFFIND` |
| `EDGE,` | `rsi` the arena, `rdi` the sampled record, `rdx` the caller's | one edge counted | `rax rcx r8-r11` | `LPROFEDGE` |
| `INDEX,` | `rsi` the arena, `r13` DBASE, `r14` NDICT | the sorted index and its header | `rax rcx rdx rdi r8-r11` | `C-PROF-INDEX-BUILD`, `C-PROF-SORT` |

- **Find** answers the entry with the greatest start at or below the pc when
  the pc lies below that entry's end, and 0 for an empty index or a pc outside
  `[ARN-LO, ARN-HI)`, in at most sixteen halvings.
- **Edge** keys the pair `(sampled << PROF-REC-BITS | caller) + 1` and probes
  `PROF-CALL-PROBE` slots from the top 16 bits of the key times `PROF-HASH`.
  A free slot takes the key with a count of 1 and a hit counts one more. A
  full window counts `ARN-DROP`, and a negative sampled record keys nothing.
- **Index** writes one entry per record of `[0, r14)` with code of its own:
  its wordlist cell is neither `DICT-WL:NAMESPACE` nor `RETIRED`, its span is
  not empty (an exact span is its body, a legacy one its body and
  `CODE-SPAN:INSN-BYTES`) and its code cell is not 0. A stable bottom-up merge
  through `ARN-SCR` sorts the entries by start and lands them at `ARN-IDX`,
  and the header takes `ARN-COUNT`, `ARN-LO`, `ARN-HI` and `ARN-NDICT`. It
  borrows `rbx rbp r12 r15` on the machine stack.

`prof-on` installs the handler for SIGALRM through `X64BOOT:SIGACTION,` with
`PROF-ABI:LINUX-SA-PROF-FLAGS`, SA_SIGINFO, SA_ONSTACK and SA_RESTART. It is
`EMIT-PROF`:

1. A context whose saved `rbp` is `DATA-VA` and whose saved `r13` is
   `PROF-DBASE` is a Habu sample. Any other counts in `PROF-FOREIGN`, unsearched.
2. With no arena the sample counts in `PROF-OTHER`.
3. The saved rip goes to FIND. An indexed rip counts in its record's counter
   and, once, in its inclusive count. A rip at or above `ARN-HI` is deferred
   with the cell at the saved rsp, a leaf's return address, where ARM64 keeps
   x30. Any other rip counts in `PROF-OTHER`. All three walk.
4. The walk is `C-PROF-WALK` without its x30 step. It reads at most `ARN-WALK`
   cells up from the saved rsp and never leaves rsp's 4 KiB block. A cell is
   searched one byte back, inside the call that pushed it, so a call that
   ends its record's span still names that record. Each record the walk meets
   that differs from the one before counts once inclusive and in
   `ARN-FRAMES`, the first names the caller edge, and a walk that names none
   keys `PROF-CALLER-NONE`.
5. `PROF-TOT` counts the sample. A foreign sample returns. A Habu sample
   returns when `PROF-LIM` is 0 or `PROF-TOT` is below it, compared signed;
   otherwise the handler prints the text report and exits `PROF-LIMIT-RC` 99.
   A limit reached on a foreign sample reports at the next Habu one. `ret`
   enters the restorer.

The handler reads the ucontext and never writes it, and rt_sigreturn restores
the whole interrupted context. It leaves `rbp` alone, so a fault inside it
would still reach the crash handler with DATA in `rbp`. The action has no
SA_NODEFER, so SIGALRM stays blocked through the handler and its restorer and
no tick samples them.

The report half prints what `prof.f` prints, byte for byte:

- **Sync**, `LPROFSYNC`, runs first in each report body and never in the
  handler, since INDEX reads `r13` and `r14`, which only Habu code holds
  live. It keeps `ARN-HI` in `ARN-OLDHI`, folds each entry's inclusive count
  into the per-record `ARN-INCL`, since INDEX zeroes the entries, runs INDEX
  and replays each deferred sample. The pc names the sampled record, which
  takes an exclusive and an inclusive sample. The kept cell, searched one
  byte back as the walk searches a return address, names the caller edge; a
  cell that is 0, names nothing or names the sampled record keys
  `PROF-CALLER-NONE`. A caller whose start is at or above `ARN-OLDHI` takes
  an inclusive sample too. A pc that names no record counts in `ARN-NEW`,
  and `ARN-DEFER` ends at 0. The limit's dump does not sync, so its deferred
  samples stay in the header's `defer`.
- **The reports**, `LPROFDUMP`, `LPROFJSON` and `LPROFROW`, save `rbx` and
  `r12-r15`, walk in them and in a frame on the machine stack, and never
  touch `rbp`. They read the dictionary base from `PROF-DBASE` and the record
  count from `ARN-NDICT`, never from `r13` and `r14`, which the handler's
  walk reuses before the limit's dump. Rows are chosen by repeated maximum,
  the first entry on a tie, and a row's callers the same way from the edge
  table, where a count equal to one already printed is skipped.
- **The printers**, `LPROFNUM`, `LPROFPCT`, `LPROFNAME` and `LPROFQUAL`, write
  fd 1 directly and clobber every scratch register. A name's length is its
  flags cell, record offset 16, under `DNAME-LEN-MASK`, and its bytes sit at
  offset 24, or at the address there under `DNAME-EXT`. `X64KERNEL:REC-*`
  loads after this file, so it states the two offsets itself. A qualifier is
  the first package row whose public or private wid is the record's.

| row | body |
|---|---|
| `prof-on ( n -- )` | stores n in `PROF-LIM`, the limit the handler tests, and `r13` in `PROF-DBASE`; clears `PROF-TOT`, `PROF-OTHER`, `PROF-FOREIGN` and the counters of `[0, r14)`; maps the arena once; runs INDEX; clears the arena's counts, edges, inclusive array and stamps; maps the `PROF-STACK-BYTES` alternate stack once and registers it with sigaltstack; installs the handler; arms ITIMER_REAL at `ARN-USEC`, or 1000 us written back, split into whole seconds and the microseconds below `USEC-PER-SEC`; sets `PROF-ARMED` |

## Build and bootstrap

Order: cross-build first, self-host second.

1. **The engine is tier-1 only.** It has a small hand-written kernel bound to
   the `src/habu/prims.f` names. The outer interpreter, the definers,
   packages, source loading and `MAIN` are checked Habu, captured into both
   products. The seeded boot calls `MAIN` through the DATA cell
   `ENGINE-MAIN:XT-CELL` (`src/habu/layout.f`, `$3808`), which is declared
   and claimed and which no boot reads yet. There is no x86 twin of `habu2.f`
   or `jit.f`.
2. **The ARM64 engine cross-builds by dual emission.** Loading the prefix
   executes on the host, so the host cannot simply switch its contract.
   Instead each definition's one HIR is lowered and emitted twice: ARM64 into
   the live region, and x86-64 into a shadow keyed by record. The capture
   carries the shadow.
3. **A host-side Habu linker writes the x86-64 image.** The code region and
   DATA are fixed `PT_LOAD`s, and the linker resolves every record, call,
   `MOVABS` literal and DATA cell at write time. No relocation runs at boot
   or at snapshot restore.
4. **The cross-built engine self-hosts.** It rebuilds itself on the x86-64
   host to a byte fixpoint, which becomes the second release artefact.
5. **Recovery.** The Gforth recovery chain (`bootstrap/cg/forth.fs`) emits
   ARM64 only and refuses x86-64 by name. x86-64 recovery is a cross-build
   from a working ARM64 engine ([bootstrap.md](bootstrap.md)). x86-64 has no
   cold route: `tools/native-build.f` is its only build route.

## Build target

`tools/native-build.f -- <out> [whitebox] [--target <target>]` builds for
`linux-aarch64`, `macos-aarch64` or `linux-x86-64`; without `--target` it builds
for the engine running it. The target is one cell, `tools/build-target.f`,
which the building engine's seams read: `tools/native-build-core.f
NB-TARGET-CORE-FILES` gives the window that target's `target.f` and
`layout.f`, and `tools/build-fixpoint.f`'s stage-source appenders choose by it.
The building engine's own `HB-TARGET-*` predicates are not touched. Inside the
window the window's `target.f` answers them, so `NATIVE-RUNTIME:PROVIDE-TARGET`,
`LOAD-REPL-TERM` and `compiler.f LOAD-PASSES` follow the target with no read of
their own.

The entry refuses a target whose architecture has no backend registered in the
building engine (`CTARGET:REGISTERED?`), before the build closure loads. It loads
none itself; an ARM64 product carries only its own, so a cross-build loads the
x86-64 backend module ahead of the driver:
`bin/hb --load src/arch/x86-64/backend.f tools/native-build.f -- <out> --target linux-x86-64`.

`src/arch/arm64/machine.f` loads in that window, because the shared compiler
requires `a64ir.f` on every target: the ARM64 description names the `A64-`
engine pair rather than the target-selected one, and reserves x18 on x86-64,
where no AArch64 platform releases it.

## The NaN an operation makes

One rule holds on both targets (`src/compiler/native/hir-word.f` `DEF-FLOAT`):
an operation that makes a NaN from numbers - infinity minus infinity, zero
times infinity, zero over zero, infinity over infinity, the root of a
negative - answers `$7FF8000000000000`, the positive quiet NaN, and a quiet NaN
operand passes through unchanged, the left one of two. `f.` prints `-` exactly
when bit 63 is set, so `-1 fsqrt f.`, `0 0 f/ f.` and `inf inf f- f.` print
`0.000000` on both.

ARM64 answers the rule as it stands. SSE answers its default NaN,
`$FFF8000000000000`, whose sign is set, so `X64SEL` clears that sign after
`addsd subsd mulsd divsd sqrtsd` (`EMIT-FARITH`, `EMIT-FSQRT`). It cannot test
the answer alone: an operand NaN passes through with its own sign, and may be
`$FFF8000000000000` itself. Before the operation, `x64.cmpunordsd` masks the
operands unordered; after it, the answer unordered. The two masks differ
exactly when the operation made the NaN, and `andpd` with the sign mask and
`xorpd` into the answer clear its sign. Nothing branches.

The cost, counted per operation beside the SSE instruction: two `movsd` copies
(`cmpunordsd` destroys its first operand), two `cmpunordsd`, one `xorpd`
joining the masks, the sign mask's `movi` and `movq-xr`, one `andpd` and one
`xorpd` - nine instructions on each of `f+ f- f* f/ fsqrt`. The conversions
add none: `s>f` makes no NaN and `f>s` answers 0 for a NaN of either sign;
nor do `fnegate`, `fabs` and the comparisons. The ARM64 engine adds nothing.

The rule was chosen over a NaN-sign-blind `f.`, which costs no instruction on
any operation but changes the output both engines already pin: the `f.` rows
of `test/x86-64-kernel-pure.f`, measured from ARM64 `BFDOT`, print
`$FFF8000000000000` as `-0.000000`. Making ARM64 answer SSE's NaN would cost
the ARM64 engine the same test on every operation.

`test/prim-float-cases.f` pins the rule on both targets with its bit shapes,
`RR-R` and `R-R`: the NaN each of the five operations makes, a
`$FFF8000000000000` operand passing through each side of an operation and
through `fsqrt`, and the left of two NaN operands. `test/prim-parity.f` runs them
on the engine and `test/x86-64-kernel-pure.f` against the kernel's rows in
`hb-x64-kernel-pure`.

The rule does not cover a signalling NaN beside a quiet one, which only a bit
cast or memory can supply: ARM64 answers the signalling one, quieted, and SSE
the left one.
