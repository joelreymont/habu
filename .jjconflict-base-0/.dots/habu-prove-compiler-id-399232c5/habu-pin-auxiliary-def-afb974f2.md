Full context: the theorem-statement pin (landed with the type-ascription design: manifest carries a type row per theorem, gate emits 'Definition pinned_statement_k : <manifest type> := <theorem>' so Rocq's kernel enforces it up to conversion) closes name-only binding, but the pin is on the type AS AN EXPRESSION. Where that expression names an auxiliary definition declared in the proof files, changing the auxiliary's BODY changes what the theorem means while the pinned text still type-checks - both sides unfold the same way and the pin never saw the old body. Sharpest case: IdAllocatorLaws.trace_laws - pure_run_trace_laws states 'trace_laws (cur (shared w)) es', nothing executes trace_laws, and redefining it as 'fun _ _ => True' leaves the pinned row type-checking and the proof trivial. Same class: issued_serials, event_serial, IdAllocator.two_threads, the IdAllocatorLaws counterexample definitions (next_serial_weak_domain, cas_stuck_success, stuck_success_attempt, cas_loses_retry, lost_retry_attempt, next_serial_wrap, wrap_attempt) and the IdLaws mutation witnesses (cell/serial/local_fits_at_widthb, pack_at_shift, owner_at_shift, local_at_mask, make_trunc, check_without_owner_eq, check_with_nonstrict_bound, owner/local_projection_expectedb, foreign_owner/equal_bound_rejectedb). The witnesses are partly constrained by their own executable Examples but only to what each Example asserts - check_without_owner_eq could become 'fun _ _ _ => true' and its counterexample would still hold while no longer being about dropping the owner equality. The Ids.* and IdAllocator.* core definitions are NOT in this class - 68 vector rows execute them. Required result: a 'defn' row kind in test/compiler/ir-id-axioms.txt beside the type rows, with the gate emitting 'Example : <name> = <committed body>. Proof. reflexivity. Qed.' per bound auxiliary, and the declaration inventory counting Definition/Fixpoint so an auxiliary cannot arrive unbound. Acceptance: the trace_laws-to-True mutation fails the gate; the check_without_owner_eq-to-true mutation fails; gate green unmutated; existing mutations still fail. Note the destruction-review dots habu-freeze-and-model-08e0f69d and habu-pin-ir-id-9ad7f383 are siblings on the same gate - coordinate ownership so the manifest format changes once, not three times.
