Current master bloat and state-model defect in new lib/process-pty-handle.f: one logical PTY authority slot is split across 15 parallel arrays (generation, three lifecycle flags, owner, three process roles, four ordinary descriptors, and three watch descriptors), roughly 100 trivial array accessors, a ten-value STORE call, and a 21-comparison DISTINCT-FDS? chain. ACTIVE/LIVE/DRAIN independently represent impossible combinations even though the real lifecycle is closed: free | reserved(owner) | live(resources) | teardown(remaining-resources). The DEFLINEAR public tokens do not make their backing registry structural or transactional. Teardown accessors at 378-415 write -1 and return the prior value without rejecting an already-moved resource, so a repeated take returns a typed invalid descriptor/watch instead of E-PROC-PTY-HANDLE. COMMIT at 276-337 also accepts ordinary duplicable fd/watch values; aliases can remain outside the supposedly linear authority, be closed and reused, then cause teardown to close an unrelated resource number. TEARDOWN-DONE at 429-432 consumes the DEFLINEAR teardown token before checking DRAINED?; premature completion throws while leaving an active draining slot, but the caller has lost its only authority and cannot continue taking resources or release the slot. Define STRUCTURE pty-resources for named linear-owned process/watch/descriptor roles and payload-bearing ENUM slot-state carrying reserved/live/teardown payloads; store one STRUCTURE slot row with generation plus state in a typed row buffer. Make RESERVE, COMMIT, TAKE, each resource take, DONE, CANCEL, and validation exhaustive state transitions that publish one row. Each take must require present(resource), transition it to absent, and reject a second take; COMMIT must consume transferable linear descriptor owners, not duplicable numeric fds. Completion accepts only a distinct statically drained linear state, or returns a payload-bearing ENUM result incomplete(still-owned-teardown) instead of throwing away ownership. Derive completeness/distinctness from the resource structure rather than handwritten columns/pairs. Declare the three linear tokens and six role families inside PROCESS-PTY package scope once habu-scope-declared-types-984c5202 permits it; their current pre-package global declarations are not an acceptable final boundary. Preserve generation/owner-PID stale-handle defense, exact errors, descriptor liveness checks, capacity, zero-image initialization, fork rejection, and teardown ordering. Prove impossible flag combinations cannot compile or be stored; double-take for every resource; premature DONE followed by successful continued teardown; external alias close/reuse; every transition and stale/cross-owner token; duplicate process/descriptor roles; partial teardown; slot reuse/generation exhaustion; canaries/bounds; exact resource inventory so adding a field breaks completeness tests. Measure source definitions/lines, dictionary-name/JIT/DATA/CODELEN, and operation latency before/after, with a required material reduction. Coordinate minting with habu-checked-nominal-and-94be09c9, declared-type scope with habu-scope-declared-types-984c5202, package enforcement, and the PTY integration lane; this dot owns backing slot/resource representation and transitions.

Delete or justify the dormant private surface while restructuring. HANDLE-CHECK, HANDLE-MASTER@, and the three teardown PID accessors have no current Forth consumer; ROOM? appears only in the held integration lane. Recover only helpers proved necessary by the rebased PTY integration, and commit no speculative compatibility API. Add dictionary-name and loaded-code measurements for every removed helper.
