tools/kernel-perf-lint-core.f marks a watched producer at SECTION level (MARK/NEW! in EVENT), so ANY diff touch of lib/ptx/cg*.f, tools/ptx/*-cg.f or src/arch/ptx/emit.f demands a profile or waiver row - including a change that provably cannot alter emitted PTX. Measured 2026-08-20 in lane prune-2: a one-line comment fix in lib/ptx/cg-mma.f (dropping a reference to lib/ptx/opt-test.f, deleted by habu-delete-the-nimm-329100c9) failed the lint with E-PERF-ROW-MISSING, while the whole rest of that deletion passed rc 0. The finding text says 'kernel codegen changed', which was false. The two escapes both cost more than they buy: a WAIVER row is defined in tools/ptx/perf-rows.tsv's own header as device-gated with value 0, so writing one for a comment puts a non-measurement into a measurement registry and makes the next real cg-mma.f change bump a version for nothing; leaving the comment alone leaves a source comment naming a file that no longer exists, which is the live defect today - lib/ptx/cg-mma.f:55 still lists lib/ptx/opt-test.f among the consumers its default knobs keep byte-identical. FIX SHAPE: mark a producer only when its section carries at least one added or deleted line that is not a comment or blank - the DIFF library already delivers add and delete events with content, so the flag can be set in ADDED/deleted handling instead of in SECTION. Falsify by mutation and with adversarial fixtures, per the repository's lint-test rule: a comment-only touch of a watched emitter stays clean; a code line with a trailing comment still fails; a comment whose text LOOKS like a knob definition stays clean; a backslash inside a string literal on an otherwise-code line still fails; a pure deletion of code with no additions still fails. Then drop lib/ptx/opt-test.f from the lib/ptx/cg-mma.f comment in the same change and show the lint green. This dot owns both halves; do not split them, because the comment fix is exactly the lint's first honest consumer.
