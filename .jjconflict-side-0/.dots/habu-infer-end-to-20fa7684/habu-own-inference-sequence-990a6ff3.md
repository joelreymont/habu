Why: engine lifetime and request-sequence storage are independent owners and the combined leaf is too broad. Result: extend package INFER engine with one fixed row table and preallocated prompt-token, logit, random, output, descriptor, and close-list storage. Public `MAKI:SMP-CHECK ( n n r r -- )` consumes valid-count, top-k, temperature, and top-p in that order. It checks temperature first and throws `E-SMP-TEMP` for a negative or nonfinite value, then checks top-k in `[1,valid-count]` and throws `E-SMP-TOPK` outside it, then checks finite top-p in `(0,1]` and throws `E-SMP-TOPP` outside it. Existing MAKI:SMP-NEXT calls this word before any table read. INFER alone owns one private `CAST: SMP-IC>N ( CAD-NUM:item-count -- n )` for active valid-count and top-k at this raw MAKI seam; it has no public projection. `OPEN-SEQ ( INFER:engine ptr u8 CAD-NUM:byte-len CAD-NUM:item-count r CAD-NUM:item-count r n -- INFER:engine result<INFER:seq,n> )` takes engine, prompt, maximum output, temperature, top-k, top-p, and seed in that order. It uses SMP-IC>N on the engine's active valid-count and the input top-k, then calls the same MAKI:SMP-CHECK before allocation or mutation. This runtime reuse is the single sampling-domain authority, not duplicate validation logic. OPEN-SEQ then tokenizes once through the active model arm, proves prompt plus output capacity, reserves exact KV capacity, initializes the explicit random state, stores only the validated raw scalars in the private row, and mints one opaque copyable seq handle through the existing generic result. CLOSE-MANY ( INFER:engine ptr INFER:seq CAD-NUM:item-count -- INFER:close-result ) copies one or more distinct handles into engine scratch, validates that every row belongs to the engine and has no pending work, calls KV:CLOSE-MANY once, and only after success clears every row by total stores. It returns closed(engine) or refused(engine,seq,code) without mutation. There is no separate CLOSE-SEQ; batch-of-one callers use the same transition. Dependencies: the engine lifetime owner and existing MAKI:SMP-NEXT. Owner: public MAKI:SMP-CHECK, private INFER SMP-IC>N, INFER sequence rows, OPEN-SEQ, and CLOSE-MANY only. Production red: no request can own prompt, validated sampling scalars, random state, output, and KV reservation under one handle, and SMP-NEXT's current inline guards are not one reusable authority. Acceptance: temperature zero and maximum finite are valid; negative, NaN, positive infinity, and negative infinity temperature throw exactly E-SMP-TEMP. Top-k one, greater than 31, and active valid-count are valid; zero and active valid-count plus one throw exactly E-SMP-TOPK. Top-p minimum positive and one are valid; negative, zero, one-beyond, NaN, positive infinity, and negative infinity throw exactly E-SMP-TOPP. Mixed-invalid inputs prove exact temperature-then-top-k-then-top-p precedence through both OPEN-SEQ and SMP-NEXT, and the shared check runs before OPEN-SEQ mutation or SMP-NEXT table reads. Exact capacity and one-over, one and many closes, pending-close, duplicate, stale, copied, cross-engine, double-close, tokenization refusal, reservation refusal, injected Nth-row failure, and row reuse preserve every owner; two engines interleave; CLOSE-SEQ is absent. No sampling config, sampling result, public sampling type, special result type, or public cast is introduced. Forbidden: sampling algorithm, NEXT-MANY, synchronization, caller token count, second tokenization pass, public row fields, per-request engine, allocation after engine start, callback, version, compatibility API, or second close policy. Smallest owning checks: bin/hb --load maki/sampling-test.f and bin/hb --load maki/infer/engine-sequence-test.f.
