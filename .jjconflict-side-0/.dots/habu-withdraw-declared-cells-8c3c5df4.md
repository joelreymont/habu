---
title: Withdraw declared cells from an abandoned arena block
status: open
priority: 3
issue-type: task
created-at: "2026-07-30T15:40:37.346755+02:00"
---

The engine's address-cell table (src/habu/layout.f SNAP-RELOC:XTCELL-*) is a set of DATA offsets that is only ever added to. That was harmless while every declared cell belonged to a deferred word, because a dispatch cell lives as long as the word does. It is no longer exactly harmless now that a table of dispatch cells can declare its cells at run time through `xt!` (dot habu-declare-persisted-cb-b150b5d5). src/core/declaration-transaction.f GROW-TABLE asks its allocator for a bigger block and copies the rows across; the allocator is src/core/checker.f ARENA-BYTES-GROW, which is a bump allocator over the DP heap and never gives the old block back. The old block's callback cells stay in the table for the life of the image. Nothing is corrupted -- the abandoned memory is never handed out again, so the loader shifts dead cells that nobody reads -- but every grow spends rows that are never recovered, against a fixed capacity of 4096. Measured 2026-07-30 on this workspace: a cold bin/hb declares 89 cells and a dev snapshot image 182, of which 27 come from the five boot participants, so nothing is close to the limit today and no ordinary boot grows the participant table at all (its arena is sized for exactly the five). The failure mode if a program did register enough participants is loud, not silent: the engine writes 'hb: snapshot address table full' and exits XTCELL-RC (96). Two ways out, and the dot should pick one from the code rather than by preference: give the table a withdraw operation that the grow path calls for the block it is leaving, which means the set has to tolerate holes; or have a coordinator declare its cells once against a stable base by allocating row storage that does not move. Acceptance: a fixture that grows a coordinator table several times shows the declared-cell count returning to the live table's own cells rather than accumulating one dead block's worth per grow, and test/snapshot-xt-cell-decl.f keeps its existing rows.
