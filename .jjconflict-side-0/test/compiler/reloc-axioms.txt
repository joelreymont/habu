# What the snapshot relocation proofs state, and what they rest on.
#
# One `theorem` row per published result in formal/Common/Reloc.v - every
# `Theorem` and `Corollary` it declares - in the order the file declares them,
# which is also the order the file's own `Print Assumptions` commands query
# them. Every `theorem` row is followed by exactly one `type` row and then by
# its assumption rows.
#
# There is one assumption row per result and it is always `closed`, which is
# Rocq reporting "Closed under the global context". The relocation proofs rest
# on nothing at all, so the gate in test/compiler/reloc-proof.f reads this
# manifest with assumption rows FORBIDDEN: an `axiom` row cannot be written
# here, and the empty set is checked a second time against what Rocq printed.
# This is the same strength the interning and storage manifests ask for.
#
# A `type` row is this file's copy of what that result states, written in the
# environment the generated obligations file sets up: Stdlib ZArith, Lia, List
# and Bool imported, list notations imported, Z scope open, and
# Habu.Common.Reloc imported last so a bare name resolves to the model's own.
# The parity gate turns each row into
# `Definition pinned_statement_<k> : <type row> := @<theorem name>.` in the
# file it asks Rocq to compile, so Rocq's own type checker decides whether the
# statement in the proof file still is the statement written here. It decides
# that up to conversion, so renaming a bound variable is not a change but
# weakening, strengthening, or trivialising a statement is. These rows are the
# authority: the generated file is a build output and never reads a statement
# out of the proof source, so changing the proof file alone cannot move the
# target it is checked against.
#
# Lines starting with `#`, and blank lines, are commentary. A `type` row is
# handed to Rocq. Every other row is compared byte for byte.
